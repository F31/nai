## 决策

工作台的独立 OBS 模式明确启用，接收地址只允许本机回环，并要求本轮隔离 OBS 启录回执。复用普通备播、同一设备和现有 Stop。工作台仅显示配置和发送状态，接收成功须以 OBS 实际查看或录制确认。插问与自动循环保留现有本机模式，独立 OBS 首版先覆盖固定讲稿。

独立 OBS 连续讲稿对照复用已有备播缓存。先在单 TTS 和单 GPU 工作进程上有界准备已知原稿，实际播放仍逐句校验身份，并保留一个下一句校验快照。静音引导与最后尾部只在整场边界使用。此对照用来从句间等待中移出在线生成，不授予动态问答的实时吞吐结论。

已通过校验的备播计划在正常换句等待中允许输出现有静音待机人像。每次提交前复检任务权限、素材期限、计划代次和工作进程活性，缺失时使用黑场。真实语音结束后仍走既有的整场黑场收尾，停止和断开仍立即撤权。

独立 OBS 旁路单独保留校验通过的 0 号起始帧，首个正向设备时钟观测后才交付。若一次观测跳到第 1 帧，可按序交付两帧，主窗口继续只呈现时钟选中的最新帧。旁路帧缓冲最多两帧，后续缺口仍拒绝，不填造旧帧。

独立 OBS 输出先在引擎旁路对齐同源媒体。画面时间使用已选帧的源样本位置，按帧元数据采样率换算到设备时钟的样本域。PCM 按播放会话、设备代次和连续样本偏移校验，缓冲有界；错会话、缺块、超限及撤权终止旁路。先验证时间轴再接本机编码传输，独立源不得阻塞主播放。

隔离编码验证采用独立 FFmpeg 子进程和本机 MPEG-TS 输出，以 25fps BGRA 与 24kHz 单声道 PCM 的 960 样本块配对。有界输入、子进程退出或背压导致旁路终止。初次验证只送合成夹具，临时回环输入的连接没有对端认证，业务素材接入前须改用私有继承句柄或认证传输。

编码输入已切换为私有继承 stdin，以流式 AVI 封装交错传递 BGRA 与 PCM。一个有界队列同时承载一对音画块，不开放媒体输入监听端口。OBS 输出仍使用本机 MPEG-TS。主动撤权结束编码子进程，正常完成排空另行验收。
播放循环结束后，最后一次成功窗口提交也要复检客户区，因为该调用仍处理原生窗口消息。若此时客户区归零，取消操作并拒绝完成；先前故障优先保留原错误。
零区域故障验收允许保留status=failed的script.json；禁止的是成功回执，不是失败记录。受控窗口操作被用户Esc中断时保留interrupted状态，不授予故障通过。恢复开发后使用新目录补验，保留原测试断言错误与中断记录。
L06e7短复现已证实OBS长黑段对应原生客户区0×0，且同时间提交缓冲区仍非黑。先补显示区域准入：零宽/高不能签作有效呈现，渲染/模型等待消息泵发现后取消共同Operation、停止音轨并反馈OUTPUT_WINDOW_UNAVAILABLE，不继续报告完成或自动恢复。不靠焦点判断可见（普通遮挡/失焦允许），不擅自置顶、恢复窗口或修改电源。此修复使输出不可用明确失败，不承诺最小化时可供OBS捕获；窗口为何被最小化及非零区域捕获能力仍独立验证。
L06e7像素见证仅为本机诊断报告，不新增控制/媒体协议或播放权限：在成功update_with_buffer之后每秒抽样固定16×16位置，记录UTC/单调时间、非黑采样数、源/原生尺寸、焦点状态及动态/待机类别。每个记录器最多保留128条，内存有界，结束时最佳努力写入；不在逐帧路径同步写盘、不记录密钥/正文、不作截图上传。原生提交非黑不等于OS显示或OBS捕获成功；与同次OBS黑段时间对齐后才归因，停止后的安全黑帧必须保留。
诊断可辨识性：捕获色条与灰色遮挡窗口必须使用明确的诊断专用标题，禁止复用“数字人讲解”标题；诊断profile精确绑定该标题。用户未观察正式窗口时记录未观察，不将后续色条反馈算作人物听感或正式窗口故障证据。
L06e7录制复核发现原生帧回执不代表OBS实际捕获。先用测试专用动态像素窗口、同minifb路径和固定遮挡阶段，有限比较WGC/BitBlt捕获；无模型、无麦克风、无推流，不作为实际数字人验收。保留整份30分钟黑段，不删除守门或以重试改绿；确认边界后另行修复/短回归。
2026-11-19长稳复测在原稿准备阶段失败，尚未录制。补充L06e6安全诊断：逐句准备失败记录句序、实际累计耗时、失败阶段和白名单WorkbenchError；根保留共同Operation状态与安全原因，不输出原始异常、正文或凭据，不放宽45秒/不自动重试。其他异常统一unknown，不从GPU空闲快照推断负载期间限频。
L06e5隔离录制控制：仅为本次专用collection安装仓库固定Lua看门狗，其他脚本继续拒绝。启动器生成随机run nonce并写独立控制清单；Lua有界读取stop.request，匹配nonce且录制实际开始后才调用OBS正常停止API，仅在RECORDING_STOPPED事件写同nonce回执。停止脚本同时验证本次进程、日志、回执及录像文件后才写obs.stopped；超时保留录像，不强杀。提供运行器finally停止路径，失败不等定时器；无网络监听、不修改用户OBS。定时器仍为兜底，实际短录制及错误nonce验证独立于30分钟音画验收。
用户选择优先于ADR0204旧新回答首声硬门；ADR0205记录适用范围。新回答允许数秒等待，现有模型45秒deadline仅是取消上限，不是体验目标，不擅自把45秒授予可接受。未得到新的数值上限前记录首声分布和人工体验，不授数值预算通过。

首切片不新增消息字段：现有Starting/PLAYING只能证明操作活动，不能区分等待生成和设备正在播放。界面明确显示“本机生成或播放”，实际已用时间采用performance.now；不输出虚假百分比、预计完成秒数或精确阶段。已备播放仍明确零模型调用，不显示新回答等待说明。停止沿现有独立控制取消，不新增重试。

后续root协调器才拥有一个问题槽、原讲解句游标及恢复意图；LLM/TTS/视觉仍独立适配，UI不承担自动恢复状态机。停止/换内容/失联撤销恢复意图；错误不自动重试或擅自重播，迟到结果按任务/epoch拒绝。恢复同一有效缓存，从被打断的完整语义句重播，已完成句不从头重播。原稿过期或身份变化则拒绝恢复。完整协议由schemas先行生成后实施，不创建第二套核心或多模型并发。

本轮不以提前缓存新问题、固定答案、静音夹具替代真实AI。外部GPU、降分辨率与换模型不在范围。
