# Design

Raw RGBA assets remain outside the control database under the workbench data root. The earlier page-to-command in-memory upload is an unfinished prototype and SHALL NOT be exposed in the production permission set. The replacement SHALL use a native user-selected directory and a bounded native file-reading path; canonical containment and reparse-point rejection must be enforced on the actual opened files, not only on page-supplied names. The owner validates filenames, byte limits and the existing avatar manifest/config schemas through `nai-avatar-2d`, renders the neutral admitted frame, and atomically installs an immutable digest directory. Raw pixels and preview images SHALL NOT pass through JSON/Protobuf control messages; a bounded dedicated media path is required. A selected directory or checkbox is not, by itself, proof of ownership or a public playback grant.

The existing `put_preparation` CAS object stores an `avatar_profile_draft` document containing display name, package/version/digests, license identity and selection/revocation state. No raw pixels, filesystem path, or playback permit crosses the foundation control contract. Storage allows the new kind and continues to apply workspace ownership, revision, audit and purge semantics.

The UI lists profiles in the current workspace, imports a package using a directory input, requires an explicit rights acknowledgement, previews the native-admitted neutral frame, and persists selection or revocation as a new object revision. The built-in avatar remains selected when no active custom profile exists.

## Windows handle review

The candidate reader uses `cap-std` / `cap-fs-ext` 4.0.3 inside the desktop process, not in the kernel or as a new service. It opens the selected root as a directory handle, then resolves each path component relative to the held handle with no-follow operations; the final opened handle is checked as a regular file before bounded reads. The dependency contains platform-specific unsafe implementation; the application remains `unsafe`-free. A root selected through a reparse point is rejected. This is an internal preparation step, not a file-dialog authorization or a grant. Before production exposure, Windows junction and concurrent replacement tests, independent media transfer, trusted rights recheck and transactional selection are required.

The Windows-only native folder picker uses the `rfd` dialog inside the desktop owner and passes its selected path directly to the internal reader. The command accepts no path and returns metadata only, not image bytes. It is currently unregistered and has no webview permission: the separate preview transport and authoritative workspace binding are not ready. Dialog cancellation makes no package. The picker is an OS dialog rather than a resident service; its existing process authority is not elevated.

The private preview transport candidate uses a single bounded immutable PNG slot keyed by workspace, package digest and rights digest. The internal native picker admission now places the resulting PNG in that slot and returns metadata only. Replacement and clear reject subsequent reads under the prior identity; they cannot recall bytes already delivered to a reader. Its caller must check current trusted workspace and rights before delivery, and revocation must separately stop public output. The slot is not a protocol endpoint and must not be exposed until those checks and native binary delivery are wired; the candidate command is unregistered and its workspace input is not authoritative.

## Authority and transaction boundary (planned)

The existing generic `PutPreparation` can write `selected` and `revoked` in `avatar_profile_draft`; those page-controlled fields are not authority and MUST NOT be used to grant playback. Introduce a dedicated engine-owned workspace binding and a durable rights record with CAS revision and an append-only audit event in the same transaction. A select verifies actor role, current workspace, exact admitted package and rights identity and current expected binding revision; there is at most one binding per workspace. A revoke fences media first, invalidates the relevant current binding and rights, then persists the audit and state transaction. Failed or stale transactions never restore an earlier media grant; after restart output stays disarmed until fresh checks. Replay with the same idempotency key and payload returns its prior result; reuse with different content is rejected. Selection or a checkbox does not constitute a license verification or playback grant. Readiness and UI consume this authoritative state only after the schema, migrations and authenticated IPC are implemented. Existing databases need a documented backup and crash-safe migration; no silent reinterpretation of draft flags.

The existing `PutPreparation` path now enforces atomic single-selection for private avatar drafts using the existing object/version and audit transaction, preserving immutable package identity and refusing reversal of a draft's revoked flag. The UI prototype submits just the target selection, rather than separately deselecting rows. This avoids a migration for private draft management, but is not the planned durable rights authority: a newly created or deleted draft and the live output remain outside this invariant, and a page-supplied identity cannot establish admission or actual rights. Public output continues to use the built-in avatar until the trusted owner and media checks are implemented.

An isolated SQLite prototype and proposed schema now exercise one binding per workspace, revision checks, persistent revoked package/rights pairs and audit rollback. They are not installed into existing databases and are not called by production Store/IPC. The caller must still authenticate, establish actual admission/rights evidence, fence output before mutation, check deadline and roll back on all errors; no prototype return value grants media authority.

The isolated mutation wrappers own and commit their transactions, so caller error handling cannot accidentally commit an incomplete audit/state update. The candidate identity, mutation and view messages are generated from `schemas/workbench/foundation.proto` but are not attached to the command oneof or IPC. Before installing the tables, workspace purge must explicitly account for both new workspace-scoped tables; its existing unknown-table rejection is intentional and is not bypassed. Migration requires a verified consistent backup and crash recovery journal before any production schema change.

An isolated SQLite backup test confirms the snapshot contains committed revocation and audit facts and leaves later source commits intact; it is not a production migration or rollback implementation. The purge path recognizes only the exact complete candidate table pair: partial or altered definitions fail closed; empty candidate tables do not block a purge, while any binding or revocation produces `AVATAR_CLEANUP_UNAVAILABLE`. It cannot delete a workspace with avatar authority records until package-file ownership/refcount cleanup and rights retention are implemented. A future migration must install its table definitions with a verified backup and recovery journal; restoring an old snapshot must account for later committed rights/audit rather than silently discarding them.

An internal isolated package-copy primitive reopens installed material under a directory handle, checks size and package digest, and runs the normal admission into a caller-owned backup root; the preview is regenerated rather than trusted as a source file. It does not determine the complete database-referenced package set, provide a backup manifest or prove that source and destination are distinct. Therefore it cannot be exposed as a migration backup until an owner-controlled destination and closure verification are integrated.

A separate, not-yet-wired inventory candidate scans bounded object-version content and, when the exact authority schema is present, binding and revocation rows. It deduplicates package identities and rejects inconsistent rights digests, missing/corrupt source objects, partial authority schema and exhausted limits. It must run against the exact verified database snapshot and its result must be tied to independently verified package copies and a durable manifest; it does not itself read package files or establish a complete production backup.

Generated `AvatarBackupInventory` metadata binds a database SHA-256 to package and rights SHA-256 pairs. An isolated comparison rejects an incorrect snapshot, missing or extra pairs, duplicates, invalid digests and cancellation. The comparison treats both inventory and copy receipts as inputs; it does not independently verify the database or package bytes and is not wired to the copying path. Owner-side snapshot verification, copy receipts, closure enumeration, durable manifest and journal remain mandatory before production use.

Installed-package reinspection opens the package directory once and reads declared installed files with no-follow handle-relative operations and explicit bounds; an existing directory junction is rejected. This is an integrity check, not evidence that rights remain in force.

The offline `same-file` dependency can compare open handles, but does not supply a root-relative open operation or prove that every intermediate directory remained beneath the selected root. Its Windows implementation also documents file-identity limitations on ReFS. Comparing a file handle with a subsequently reopened path therefore does not close the ancestor replacement race. The current `read_selected_file` remains a non-production prototype; do not enable its command until a safe directory-handle-relative implementation and adversarial junction/replacement tests are available. Introducing a new native dependency or isolated helper requires recording its privilege and dependency boundary.

## 2026-10-28 private management integration

The Windows folder picker and bounded binary `avatarpreview` protocol are now registered for the main workbench. The picker checks the workspace through authenticated engine IPC before and after selection. Preview staging reloads the workspace draft, rejects revoked records and reinspects the installed package and license-file digests; raw PNG does not travel over the JSON/Protobuf control bus. The UI can import, list, preview, privately select and revoke draft records. Selection is atomic in the existing preparation transaction. The binary preview slot is cleared on relevant workspace and draft changes; bytes already delivered cannot be recalled.

This is private draft management only: a checked declaration is not authoritative license verification, a new draft can bypass an earlier draft revocation, and package installation and draft persistence are not one transaction. Public output remains the built-in avatar. A durable rights authority, trusted identity and license recheck, output fencing, real-time rendering and real licensed-material acceptance remain open. Earlier statements in this document that the picker and preview endpoint are unregistered describe the historical prototype, not this integration.

A snapshot-inventory primitive shall derive the package closure from the same SQLite snapshot created through the existing bounded backup operation, not from the live database after copying. It must fail on cancellation or missing/corrupt referenced bodies and must not itself activate a migration or grant playback. A later owner must independently verify the snapshot bytes, copy and verify the packages and journal activation.

Backup-copy receipts must be derived from a fresh read of the installed destination package, and the source license digest and destination digest must equal the snapshot inventory entry. Mismatch must fail and never serve as a migration receipt. This check alone does not establish destination isolation or backup durability.

Until a verified avatar-package closure is included, the existing model migration backup must refuse creation when its source database references avatar packages, including historical versions and authority records. A failed check must not create a backup directory or modify existing facts. Empty avatar inventories continue through the existing flow; this guard is not a replacement for complete backup and recovery.

The existing model backup must enumerate all live object-version bodies from its own SQLite snapshot, before closing the snapshot; it must not enumerate the live connection after snapshotting. This is necessary but insufficient for an avatar-complete backup: the avatar-package guard remains in place.

A shared package-files library shall provide the existing handle-relative bounded reader to both the desktop import path and the engine-side backup implementation, without coupling storage to the desktop or avatar plugin. Moving the reader does not itself authorize playback or remove the incomplete-backup guard. Windows path and junction checks remain mandatory.

Installed package identity verification shall use the shared bounded reader, recompute the package and license digests from actual file bytes, and return only after both match the supplied inventory identities. It is not a license grant, a backup copy, or a migration activation.
The desktop preview and future backup verifier shall share one installed-package reader that returns only bytes whose package digest was recomputed. License digest checking can be applied to those same bytes; callers must not use a successful integrity check as a public grant.
The engine backup inventory may use the shared installed-package verifier to check every referenced identity, under the existing operation deadline and cancellation. Successful verification is only a prerequisite for copying; it must not remove the incomplete-backup guard or grant public playback.
Installed package verification must descend from a held data-root directory handle to `avatar-packages` and then the digest directory using no-follow opens. A replaced intermediate junction must not redirect the package read. This does not validate legal rights or make the backup durable.
A package copy into an owner-created empty isolated destination must use handle-relative no-follow directory creation and create-new files, verify the original package and rights digest, check cancellation between files, and re-read the destination to verify both identities. Identical source and destination paths must be rejected. Failure does not certify a backup or authorize deletion of partial files; activation, durable manifest and production recovery remain separate requirements.
The isolated backup candidate shall copy all identities from one bounded snapshot inventory into one newly created destination, reject duplicate identities and missing or altered source packages, and recheck every destination package. No success result may be returned after cancellation or partial copy. This alone does not constitute a production backup, durable commit or live restore.
An isolated backup directory may be located under the data root, as in the existing model-migration layout. Reject the data root itself and any overlap with the actual source `avatar-packages` subtree; acceptance does not prove protection against concurrent ancestor replacement, which remains a separate requirement. Preserve the preview file as untrusted derived material; desktop admission must regenerate and compare it after restore.

A model migration backup containing avatar references shall enumerate identities from its SQLite snapshot, copy all fixed package files, add each file and digest to its existing manifest, then verify the snapshot inventory and copied bytes before producing a receipt. Verification and isolated restore shall reject a missing, extra, damaged or mismatched package, and a previously generated backup that predates current avatar identities must not be reused. Activation remains gated by journal/recovery and native fault validation.

## 2026-10-29 backup integration candidate

The existing model migration backup source now snapshots and inventories avatar identities, verifies source packages, copies fixed files, records their hashes in the manifest, validates the snapshot closure against the current inventory and checks copied packages; isolated verification restore copies the recorded files. Existing pre-avatar receipts are rejected when the current avatar inventory differs. This supersedes the earlier unconditional source guard in the code. These source changes are not yet released: native process-failure, concurrent directory replacement, actual user package/credential preservation and journal recovery with avatar data remain required. This is not a public playback or license grant.

The shared model migration journal must be exercised with an actual avatar package present: after a verified backup and partial credential rewrapping, a reopened store must resume from its durable stage and preserve the original model credentials and avatar package identity. This is restart testing, not a process-kill or hardware guarantee.
The migration journal must also survive an actual child-process termination after its avatar-inclusive backup is recorded. A subsequent owner restart must not publish before re-verifying the backup, and the test must run only in an isolated root using synthetic data.
The Windows adversarial check shall repeatedly replace the avatar-packages directory with a junction to an outside directory while reads occur through the held data-root handle. The test must establish that replacement occurred and that successful reads never return the outside marker.
Backup verification must reject a missing asset or modified preview in an otherwise complete avatar backup, without modifying the original package or treating the copy as restorable.
When an isolated copy process is terminated after writing only part of a package, subsequent verification must reject the partial destination and the original source must remain verifiable. This test does not by itself exercise the migration journal or cleanup partial destinations.

A Windows native authenticated engine IPC test shall exercise avatar-inclusive model migration using a synthetic package, terminate the engine after the backup is recorded, restart it and complete migration; it must verify that the backup files and original package remain intact. This does not prove legal rights or real credential preservation.
Native credential migration verification shall use a unique isolated data root, a synthetic Key and a loopback-only provider. It shall remove only credential entries associated with that synthetic root and verify the rewrapped Key after engine restart without touching user credentials or calling a paid provider.
The isolated native migration check shall cover multiple LLM and TTS model credentials using separate credential services, and verify both after restart using a loopback-only provider. Cleanup shall remove only entries scoped to the random test root.
When a journaled model-migration backup has no manifest after interruption, the owner shall retain it by atomically moving only that journal-referenced UUID directory into a bounded incomplete-backup area before retrying. A directory with a manifest or an existing conflicting destination must not be moved or overwritten. A restart after the move must be idempotent; no user backup content is deleted.
