# 单房间AI插问与归位

## 现状与职责
当前PreparedPlan负责完整资产，设备回执确认每句实际播放；纯核心`v561_narration::Plan`可用于调度参考，但commit调用方必须证明真实播放完成，不得把生成完毕等同提交检查点。该队列的interject参数是待播文本，本需求的外部输入则是问题，两者不能混用。

I/O-free核心只处理讲解检查点、问题代次和状态迁移；LLM Provider只负责API传输，TTS/视觉生产者及设备消费者保持独立；composition root负责单实例、上下文绑定和取消。React只提交意图/展示事实，不从浏览器直接调模型。复用已有V5.6.1凭据能力前必须核对源码/实际新数据根，不自动导入旧Key/DB；秘密不进入命令行、控制消息或日志。

## 状态与边界
讲解上下文绑定当前会话、确切已备计划实际资产身份、资料内容及许可/参考版本。checkpoint仅由设备EOS且最后样本真实播放推进。问题在当前讲解句完成后处理；只存一个最新问题意图，非额外待执行模型队列。替换意图须向UI显式报告被替代；新问题取消旧回答的子Operation，旧回答不得提交音画或推进检查点。停止立即取消整体作用域并清意图，不等句边界。

回答内部仍串行：LLM→短语义句→单TTS→单视觉实例→当前音画执行；最多一个未来句，禁止为了回答并发启动第二个模型/设备所有者。供应商计算不能真正取消时只停止本机等待，必须有界等待TTS实际空闲再派发下一次请求，不将HTTP取消当作GPU已停止，不自动重试生成。

回答成功后只在原上下文仍有效时自动回到首个尚未完成的讲解句，用新epoch重新绑定资产。回答失败/超时保留暂停与安全待机，由用户明确继续；停止/接管/资料或形象改变后禁止旧检查点自动恢复。不得因重播缓存而绕开当前所有者、TTL或事实复检。没有可用资料时明确资料不足，不播放历史无关回答当作命中。

## 契约与配置
先在schemas定义必要配置和Protobuf提问/状态/可信进度字段，再生成Rust/TS/Python/C++消费者。UI不传任意cursor/epoch/路径或许可；根进程签发问题上下文和检查点。配置只包含能力参数/凭据引用，单价/预算/工作区不进入个人主线。缺少LLM配置仅使提问Unavailable，现有已备内容仍可显式播放；不是旧格式兼容层。

## 验证
先状态机、代次替换/父取消、错误不推进、真假设备EOS及过期归位故障测试，再测实际LLM响应、CosyVoice/FlashHead、同窗口输出和OBS问答后归位。保留真实调用次数与安全失败分类；模型返回成功不能替代设备或人工音画证据。已有长稳记录不授予新回答首声或中断恢复通过。完成后记录实际命令及非零测试数量，不以空过滤器成功占位。
