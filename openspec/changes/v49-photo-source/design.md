# 设计

JPEG 数据仅通过受限原生文件路径读取，探测器限制字节数、图像尺寸和像素数量，检查基本 JPEG 头、帧与结束标记（尾随数据不超过 4096 字节）并计算 SHA-256；此步骤不解码像素，不能证明文件可完整解码或授权有效。禁止通过 JSON/Protobuf 承载图片。后续导入必须提供受控持久化与备份、显式授权、撤销和解码资源限制；静态照片不得授予公共播放许可。

验证采用离线合成数据、损坏与资源上限测试；用户提供的本地照片只用于显式本机探测，不复制或上传。已有目录句柄读写与现有媒体隔离保持不变。

工作区的照片草稿以 `avatar_photo_draft` 记录摘要与尺寸，不含文件路径或图片字节。内容身份与尺寸必须在可信存储侧通过有界文件重新检查；该对象不直接允许选择或播出。备份清单纳入 `avatar-photos/<sha256>.jpg`，备份校验须匹配快照引用和实际字节，原照片及派生文件不以 JSON 或 Protobuf 传送。撤销声明仅属私有状态，不能替代后续持久权利账本。

### 共享照片清理设计约束

清理必须以数据库事务中的持久引用为依据，而非仅扫描当前版本的 JSON：同一摘要可被多个工作区和历史版本引用。导入完成、草稿保存与引用登记必须具备可恢复的阶段记录；目录中无引用文件也不能仅凭缺失引用立即删除，因为导入可能尚在进行。工作区清理事务删除该工作区引用，并仅为确认无其他引用的摘要生成持久清理任务；实际删除前再次复核引用、受限目录句柄、文件身份与摘要。并发导入、备份和清理必须在同一存储权威下串行或显式租用，不能让检查到删除之间产生新引用。清理失败和崩溃须保留任务并可重启恢复，不能报告全部文件已清理。迁移旧草稿时先建立一致备份及可恢复 journal，缺失、损坏或歧义时拒绝清理。实现和验证完成前继续保留现有阻断。

### 基础二维包自动组装

先提供纯内存组装器：输入已解码的 RGBA 底图和人工或后续生成器提供的闭嘴、张嘴图层以及嘴部位置，校验尺寸、字节预算和画布边界，确定性生成现有三层格式的配置与素材摘要。组装器不声称照片已识别人脸或产生张嘴图像；不读取文件、不签发许可，输出仍必须经过现有形象准入。后续另接受控解码、人脸定位、张嘴生成与可视化调整；不能用重复底图或虚构嘴部效果充当真实自动生成。
