# 设计

## 视频形象与智能体统一工作流

以 `docs/v52-agent-avatar-creatorbox-optimization.md` 为 V5.2 体验增补：个人首页围绕有权真人视频形象、已配置声音、主题/资料、可选互动及直播控制；常用动作提供选择和默认，正常检测结果收起，异常直达修复。打开画面和明确开始是两项不同操作；OBS 控制连接、采集源、音轨、实际信号与平台开播分别观测。公屏不可用不阻塞主题独讲。

统一直播智能体依据目标、资料、已实际完成内容及问题池选择讲解、回答、等待或建议接管，渲染后端只执行可信音画意图；服务连接或模型生成不作为真实播放完成。视频底版、语音驱动嘴型和有限素材动作须明确能力范围；照片生成和麦克风驱动口型独立验证。保留可替换渲染边界、独立输出安全控制和真实音画回执；可选 Python 外部服务须另行 ADR/规则裁决，不能伪装成 NativeOnnx。导入或公共输出仍须身份、素材许可与场次授权，个人模式与旧规格冲突按 ADR 0191 工作流裁决，未经实现不通过隐藏控件放宽。

## 与写实数字人共同适用的架构与完成标准

个人模式和 `v49-realistic-avatar` 共用以下可验证原则。职责按变更原因划分：领域策略、存储适配、界面、模型/平台适配、媒体执行与组合根分别负责；新增功能不得将领域决策、SQL 和 UI 塞入同一入口。大文件或代码行数只是排查线索，不单独触发拆分；对热点文件记录本次职责与依赖影响，围绕交付功能逐步提取，不进行无收益的大规模重写或创建空组件。

领域和 kernel 依赖契约/端口而非 Tauri、具体数据库、模型实现或平台 SDK；具体适配器在组合根装配，插件实现不得直接依赖其他插件实现。替换接口须通过独立消费者或第二个实际实现验证；mock 只验证边界，不能替代真实模型/平台认证。模型、平台、形象按所选能力启动；无需要时不新增常驻服务、模型副本或必需云基础设施。每个新增进程/依赖记录职责、资源成本、失联行为与适用 profile。

首页围绕选择人物/声音、目标资料、开始、互动和接管，采用可选优先、合理默认和必填前置；后台状态正常不打断，异常提供可执行修复入口。用真实用户的任务成功率、操作步骤、耗时和求助/错误记录验证；不能仅以按钮数量或自动化页面测试宣称易用。

按本轮改动闭包运行架构依赖、契约、相关模块与 IPC/状态机/迁移/取消故障测试；仅发布组合执行其完整适用门槛。定向验证与完整验收分别记录，测试缺失、外部能力不可用和未实现分别标注，不以某测试通过扩大结论。拟发布组合实测冷启动、首可播音频、端到端帧率/卡顿、音画同步、停止响应、CPU/RAM/VRAM 峰值与释放；标明测量边界、设备、负载、样本与目标阈值，长稳按 30 分钟→2h→8h→候选 24h 递进，不能以局部基准冒充整机能力。性能不达标先定位瓶颈，不以降低权限或跳过安全门换取性能。

## 统一直播智能体（优先于下文流程描述）

用户配置直播目标、主题与资料、表达风格、人物声音、互动开关及比例；这些是智能体的外围配置。一次明确开始后建立受工作区、场次和 epoch 约束的直播智能体会话。一个共享 Harness 使用备播、互动和场控等任务 profile，不默认创建多个常驻进程或多轮模型互聊。复用现有 AgentTaskContext、问题池和句边界归位能力，补齐统一决策、上下文、编排与工具权限；现有局部能力不等于完整智能体。

闭环为：获准输入与实际播放反馈 → 构造有界 LiveContext → 根据目标、资料、已实际播出内容、主持状态、问题、时间及能力选择下一步 → 生成结构化讲解、答复、等待或建议接管意图 → 可信执行器复核授权与事实 → TTS/数字人呈现 → 根据真实回执更新进度。意图可提出受支持的动作，但模型不得直接操作设备、改变权限或把生成当作播出完成。

无互动时智能体依据主题和资料规划、调整讲解并控制重复；不是要求用户写完整稿，也不能把固定循环称为自主讲解。公屏抽样比例是候选入口流量控制，不是回答成功率；抽样后智能体依据相关性、重复、时效、当前讲解和有界语音队列选择回答或跳过，记录抽中、选择和完成的不同计数。下文凡称“抽中问题自动进入回复链”均解释为抽中后经上述智能选择并满足执行条件的问题进入回复链；100% 抽取不保证全部回答。资料不足时明确说明、等待或建议真人处理；自由生成不能把推测标为已验证事实。

实时路径优先规则、检索或一次有界生成；工具只在允许列表、共享 deadline 和调用配额内执行，个人预算无限不意味着无界循环。用户更改目标、切话题或更新资料时，安全取消不适用任务并以新上下文决策；未知结果不自动重播。真人接管、停止、切场或撤权优先取消任务树及媒体权限。当前场记忆只依据实际完成的播出及用户输入，跨场偏好须用户明确保存、可查看删除；不自动建立观众画像或跨平台关联。

## 产品行为

个人模式首页按形象和声音、讲解内容、互动、直播控制排列。默认工作区由系统自动准备；多个工作区按上次有效选择进入，设置中可管理。主题、资料和输入文本映射至内部内容与场次对象，用户使用“保存并使用”，不需逐项手工创建或打开发布页面。公开输出仍依据系统构造并持久化的当前版本/场次事实执行，不以静态界面文案或模型自报替代。

回答由 AI 生成并可由数字人语音播出，不要求真人撰写答案。用户可选择自动 AI 回答或点击触发 AI 回答；点击“回答”或“发送并回答”表示用户对当次范围发起操作，不额外要求勾选和逐句批准。自动 AI 回答须由用户显式开启并记住偏好；默认资料范围为“仅依据我的资料”，未找到答案则说明未找到。用户可选择允许模型自由回答，界面显示选择；选择不授予平台权限或改变内容来源标识。自动回答只对当前明确开始的场次和授权渠道生效，重启、重连、切换工作区/场次、撤权或接管后不自动恢复旧场输出。暂停、静音、真人接管和停止始终可见；重复、未知提交和超时不得自动重播。

直播问题优先从实际获准的平台公屏接口取得，按平台、账号、房间和连接代次绑定当前场次；手工输入是补充，不冒充平台消息。用户在互动区域配置 0–100% 的抽取比例并可随时修改；该比例针对通过来源校验、去重、有效期及内容过滤后的合格问题作概率抽样，独立随机抽样不保证短时间内精确达到比例，0% 不抽取、100% 全部进入有界处理队列。界面展示收到、合格、抽取、因容量/过期跳过和实际完成回答的计数，比例不保证全部抽中问题都会回答。队列、并发、TTL 和节流有界，超载明确丢弃或跳过并计数；无消息时不触发问答。比例变更只影响变更后到达的合格问题，不重新抽取历史或已经入队的消息。

抽中问题自动进入 AI 生成、语音合成和数字人输出链，语音与画面使用当前场次、来源和许可绑定；讲解中在可中断的句边界插入并回到可信进度。用户可暂停自动回答、调整比例、静音或真人接管；停止、切场、断线和撤权取消待处理任务、阻止旧结果播出。仅在真实官方或获准连接器提供问题事件及用途权限时运行；OBS 画面、虚拟摄像头或账号名称本身不能证明公屏接口可用。支持的平台和账号按实际接入情况展示；平台/房间/权限未知时显示不可用及手动补充入口，不伪造公屏或自动回复成功。

互动方式提供“仅主题讲解”和“主题讲解＋公屏互动”两个选择，用户可在界面切换并记住偏好。“仅主题讲解”允许人工填写主题、直接提供讲解内容或选择已保存资料；用户可选择让 AI 根据主题和资料生成讲解，也可直接使用人工内容。保存并开始后按有界节目队列连续讲解，允许暂停、调整内容、停止及真人接管；无公屏连接或比例配置不影响该路径。生成内容须在界面可查看和修改，事实来源不足时明确提示，不将未核实内容冒充已验证资料。

切换至仅主题讲解时停止接收用于自动回答的新公屏问题，取消尚未提交的互动任务并阻止迟到结果播出；已进入媒体提交的回答按现有停止和未知结果语义处理，不假称已撤回。切换至公屏互动时单独检查当前平台、房间和用途权限，不满足时保留主题讲解并显示互动不可用；不会重放旧公屏消息。两种方式均由用户明确开始播出，不因保存主题或连接平台自动开播。

个人模式隐藏预算表单，新建个人工作区默认无限制；个人策略不要求单次预留上限或每次额度确认。未知价格/费用保持 unknown，保留可获得用量及实际费用，不以零代替。历史禁止或有限预算不得因升级或切换模式自动改写；明确修改工作区限制后才改变。费用记录和可选提醒放设置；失败/欠费直接提示。用户已开启的限制应实际生效，不能只隐藏界面。

## 权限、边界与迁移

### 偏好存储的实施约束（待实现）

偏好按工作区保存，缺省表示尚无用户选择；读取缺省时使用主题独讲、用户触发 AI、仅依据资料的有效默认，抽样比例默认 100%，但主题独讲不会消费公屏。默认值只决定界面与候选策略，不能开始场次或授权媒体。已有工作区的预算模式按现有权威记录读取，不能在首次保存偏好时改写。显式选择自动回答只保存意愿，重新进入或重启仍需当前场次授权。

存储采用有界版本记录和期望 revision 比较交换；首次写入要求 revision 0，重复请求须有稳定幂等键并校验请求摘要，竞态不得覆盖另一端修改。读取、写入和删除均复核工作区生命周期及角色；进入回收站后不可写，永久清理时删除所属偏好，恢复工作区保留偏好。策略对象与预算、审批、费用账本分离。变更影响活动任务时，可信组合根先令相关旧上下文失效，再提交新策略；取消失败或上下文无法失效时不得声称新策略已生效。比例仅影响随后到达的合格事件，不重抽既有事件；变更知识范围时取消未提交的相关生成，变为主题独讲或关闭自动回答时取消未提交的相关公屏回答。媒体已提交或结果未知时遵循既有回执与撤权语义。

既有 `foundation.sqlite` 打开流程严格要求 schema 2，启动时追加无版本表不能代替迁移。实施前须设计新版本 schema、SQLite 一致备份及经校验的清单，持久 journal 记录源/目标版本、备份身份及阶段；写入目标与版本切换须可恢复，重启按 journal 和完整性校验确定继续、回滚或安全拒绝，禁止用旧备份静默覆盖已提交的新事实。仅在维护窗口激活，覆盖备份失败、阶段中断、重复启动、版本不匹配和提交后恢复。完成协议生成、迁移故障测试和角色/工作区清理测试后，才接认证 IPC 与 UI；此段不是已完成的迁移实现。

个人模式是可信后端策略和用户操作，不依赖页面自报。普通交互可以由受认证的单人操作在后端形成绑定本次内容、版本、会话和用途的授权依据；不创建虚假的人工复核记录，不将自动策略标成他人审批。自动策略与权限、来源、明确场次、当前 epoch、资源实例、有效期和撤权绑定；源内容/许可/对象变更使旧授权失效。对外目标、账号与平台权限未知时不启动相应自动外发；本地输出窗口、OBS 捕获和平台实际开播分别显示。私有预览不发公共许可，P0 不等待数据库、模型或普通队列，keeper 失联后撤权与静音。

一键准备是可取消、有界状态机：检查引擎、模型、形象、内容和输出；仅报告实际观测到的事实。自动创建工作区/场次/版本必须幂等且可恢复，创建失败不得留下假完成或覆盖用户数据。OBS 检测区分进程、场景/来源、音轨和实际信号；未观察到为未知，不自动启动平台直播。先契约、生成与迁移，再改消费者；对原策略和数据做一致备份、版本 journal、失败回滚及断点恢复；个人模式采用显式策略版本，历史审批、预算、费用和账本不被删除或改写。功能在独立 profile 下上线，未完成时不得通过隐藏表单绕过后端。

## 验证与边界

按改动选择契约生成检查、策略/状态机、迁移及故障注入、存储和认证 IPC、UI 真实交互及 Windows 音画回归；发布组合执行相应完整门槛。覆盖自动/手动切换、旧 epoch、资料变化、外发权限缺失、Qwen 失联、费用未知、预算限制保持、重复调用、崩溃恢复与 P0。使用隔离数据；真实平台/OBS、付费调用和实际人工体验单列证据，不以模拟结果标通过。实现本变更前先完成 ADR 0191 采纳及现有规格差异的明确裁决；现阶段设计不改变现行守门或注册表状态。
