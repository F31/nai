# Design
仅显式候选开启：复制返回条件字典，对flow_prompt_speech_token及其len、prompt_speech_feat及其len按模型token_hop_len/flow.token_mel_ratio同步对齐；截去不足一个hop的尾部，而非填充假token。llm_prompt_speech_token及其len、prompt_text、LLM/Flow speaker embedding保持完整且不变。缓存原条件不修改，切片独立owned张量，跨请求不得污染。注册音色/未知条件结构不静默猜测；最小参考上下文显式配置并校验，当前87→75须满足至少3秒等效上下文的候选门。不得把该3秒门硬套所有模型，需校验token帧率/模型声明。

当前基础25、lookahead3、mel比例2；参考87→75时首块理论41→28（减少13个待生成token），Flow输入参考+首块合计128→103。该计数上限不是时延保证，参考补齐并非全部首块等待。按历史首块等待约1.46秒/首段解码约0.78秒，单项不足以保证800ms，需要与后续Flow计算/调度优化共同闭合，预算不放宽。

顺序：CPU闭包/长度/最小上下文/原缓存与LLM字段不变/取消 → 单TTS维护候选原/对齐同音色短句与首块计数/质量 → 联合GPU原生三句/停止/插问 → 人工连续与OBS。保持原服务与独立候选、单TTS、240秒维护窗与45秒请求，不扩大队列。失败恢复原服务，不自动重复合成。人工音色/发音/重复/断句未过不激活；未得到数据不得称算法收益。
