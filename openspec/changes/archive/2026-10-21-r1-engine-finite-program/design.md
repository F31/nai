## Context
动机见 proposal.md。PitchRunner 已实现，但此前没有真实 operator lane 消费者；设备状态只能证明提交，不能证明听完。

## Goals / Non-Goals
使用既有生成和预览记录建立引擎有界生产者。桌面接线、自动播放完成和五面归位生产者留给后续任务。

## Decisions
节目读写复用已鉴权路由、共享命令账本、CAS、seq 和 TTL 准入。每 epoch 仅一个内存节目，恰四条固定顺序提示，每段一次尝试，最长15分钟。重启丢弃进度，不自动恢复。PitchRunner 判定进入顺序与间隔；派发失败消费尝试并终止本轮，防止隐式重试。原持久会话/工作区金额和单位预算继续执行；四次上限是生产者附加约束，不是金额估算。

start/next/confirm 使用 event.manual.write 权限，只有 next 调用生成链路。活跃节目拒绝普通手工问题，插问须先静音/接管。节目锁不跨模型/网络 await，存储确认用 try_lock 和有界 Operation；P0 不获取节目锁。陈旧或过期节目读为暂停。匹配设备提交才可人工确认，确认不写硬件 ACK 或已完成句；五面重检生产者未齐前不提供 resume。

## Risks / Trade-offs
- 在途失败仍可能计费 → 消费尝试且不重试。
- 进度仅内存 → 明确不承诺重启恢复。
- 客户端提示不是事实证明 → 绑定实际快照，要求有效的定时检索证据，保留所有守门。

## Migration Plan
新增 API，不迁移数据库。原桌面保持明确标注的人工辅助流程，后续直接接新消费者。
