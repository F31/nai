# 设计 · W81 台账字段集的封闭性

## 1. 问题：W80 的修法把边界从「字段」移到了「清单」

W80 的断言「`CITATION_FIELDS` 里的每个字段，其 `§NNN` MUST 可解析」是**对的**，但它是一个
**开世界扫描**：遍历一份清单，对清单之外的键**不做任何假设、也不报任何错**。

于是清单成了新的边界，而**边界的补集仍然是盲区**：

| 层 | 洞 | 挡得住 | 挡不住 |
| --- | --- | --- | --- |
| W80 修掉 | 清单内字段漏扫 | 清单**内**字段被编造 | —— |
| W81 本轮 | 清单**外**的字段 | —— | **新增字段**可无检查地通过 |

两者是同一个形状的不同层：**「有断言」与「断言有覆盖」是两件事**（W80 §九结论 1），
而「覆盖」这件事对**新出现的东西**永远需要一条**闭世界**断言来兜。

## 2. 决策

### 决策 1：`LEDGER_FIELDS` 逐字写死，不由三类派生

```js
export const STRUCTURAL_FIELDS = ['id', 'disposition'];
export const LEDGER_FIELDS = ['id', 'question', 'introduced_in', 'also_in', 'disposition',
                              'basis', 'recommendation', 'precondition', 'closure', 'note'];
```

**为什么不用 `[...A, ...B, ...C]` 派生**：派生出的「三类别之并 == `LEDGER_FIELDS`」是**恒真**的
——它一个字都没说。W80 §九结论 5 已立过同型裁定：**只钉「关系」不够**，`LEDGER_FIELDS` 必须是
**独立的一份**声明，`shapeErrors()` 的「并集 == `LEDGER_FIELDS`」才是**内容断言**。

这三份声明各有职责，且**必须互相印证**：

- `LEDGER_FIELDS`——「**允许出现**哪些字段」（数据侧闭世界的基准）；
- `CITATION_FIELDS`／`ID_LIST_FIELDS`／`STRUCTURAL_FIELDS`——「每个字段**由谁负责**」；
- 两者之间由 `shapeErrors()` 与闭世界断言**双向**连起来。

### 决策 2：闭世界断言**不看值**

```
PD-01: unknown field rationale — a field the checker does not know can carry §NNN unchecked
```

报错 MUST 在**仅凭字段名**时触发。若写成「未知字段**且**其值含 `§NNN`」才报，那么一个
含引用的字段会在**将来某次**被扫到时无声通过——**判据的输入 MUST 等于被断言的对象**
（这里断言的对象是「字段集封闭」，不是「这条引用坏不坏」）。

⇒ 注入 MUST 含一次**值干净**的未知字段（`rationale: "见 §40.4"`）——**它同样要失败**。
少这一条，判据只是在测「未知字段里有没有坏引用」，不是在测「字段集是否封闭」。

### 决策 3：`question` 进引用扫描

`question` 是**复述字段**——它复述基线各章的提问。W80 的推理「复述处可以随便编」对它**最直接适用**；
它此前只有「非空」检查，却**不扫引用**。

- 实测**当前 0 条** `question` 含 `§` ⇒ 纳入扫描**不引入红**；
- 方向为**安全侧**：将来某条 `question` 引用了不存在的章节，MUST 被抓，而不是放行。

**为什么归 `CITATION_FIELDS` 而不是「结构字段 + 禁含 `§`」**：后者会**禁止**一个合法引用
（假阳性方向）；前者只在**该引用不可解析**时失败。**假阳性与假阴性不对称 ⇒ 永远选安全方向**，
而这两条路的失败面不同：纳入扫描失败的都**真是缺陷**。

### 决策 4：三类两两不相交

`shapeErrors()` 新增：任一字段同时出现在两类里（如把 `id` 也塞进 `CITATION_FIELDS`）⇒ 具名失败。
否则「这个字段由谁负责」不再是单一回答——两个检查都以为对方在管。

## 3. 不改什么

- **不改台账数据**：实测当前字段集**恰好**等于 `LEDGER_FIELDS`、`question` **0 命中** `§`
  ⇒ 基线**保持全绿**（「本轮不引入红」的判据）。
- **不改基线正文、不改任何 Rust、不新增依赖边。**
- **不与 `baseline.mjs` 的引用检查合并**：那边扫的是**基线表格**，这边是**台账字段**；
  共享的只有 `sectionRefs` 这个正则本身。
