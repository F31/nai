# 设计（w54 桌面壳形态与 Tauri 边界）

## 1 本轮的本体是「裁决 + 可判定边界」，不是「把壳搭起来」

形状**已经在基线里定了**（§1248 明文 Tauri 2；§1260 产物含 `desktop-shell`），用户也已拍板。真正缺的是两样东西：

| 缺的东西 | 现状 |
| --- | --- |
| **一条裁决** | `docs/adr/` 44 篇里**没有**桌面壳形态这一条；「为什么是 Tauri、壳的边界在哪」无处可查 |
| **可判定的边界与可查的落点** | §1151（capabilities/CSP）、§1259（sidecar/生命周期）、§900（数据根）、§1101（受保护 IPC）在仓库**零命中** |

注意一条**不是**缺口的事实：INV-18「内核不依赖 Tauri」**已经**被 `xtask/src/deps.rs` 强制
（`dependency.starts_with("tauri")` + 单测夹具 `&["windows-sys", "tauri"]`）。本轮**不重复实现它**，
只在新 ADR 里引用它，避免把已就位的东西再说一遍。

⇒ 本轮的产出是一篇 ADR + 一份**真实格式**的声明式配置 + 一组把两者钉住的校验。

## 2 为什么不引入真实 Tauri 依赖（本轮最关键的一取舍）

直觉上「形态既然是 Tauri，就该 `cargo add tauri`」。**否决**，理由是**门控不能依赖主机与网络事实**：

- `tauri-build` 在 Windows 上需要 WebView2 的导入库；`tauri` 的构建链会访问网络获取平台组件。
  把这些拉进 workspace ⇒ `cargo xtask check --profile portable|full` 的结论将取决于**本机是否装了 WebView2、
  网络是否可达、nuget 是否响应**。那是主机事实，不是仓库事实。
- 这正是 [ADR 0041](../../../../docs/adr/0041-engineering-profile-frontend-boundary.md) 已经裁过的禁忌：
  「让门控依赖『pnpm 在 PATH 且垫片与本机 ABI 匹配』，等于把**主机环境事实**混进门控结论」。
- 而且 workspace 成员数会从 19 变化 ⇒ 历轮报告的 `check-deps` 口径、测试目标数、通过数全部需要重新解释。

**取舍的代价如实登记**：不引入真实依赖 ⇒ 本仓库的校验**自建**，它读的是配置文件的**形状**，
不能证明这份配置能被某个 Tauri 版本接受；`tauri.conf.json` 的 `$schema` 指向官方 URL，**离线不可校验**。
这个代价写进 ADR「已知后果」与 A12 notes，不藏。

**将来引入的条件**（写进 ADR，不是本轮做）：真实依赖与壳体的引入属于**设备与发布里程碑**，
需要 WebView2 构建能力、网络、Windows 代码签名链，且**必须**同时给出「这份构建如何不污染 portable 门控」的方案。

## 3 壳的范围：四件事，以及「什么不算壳」

§17.5/INV-18 规定了**内核不依赖谁**；本轮补的是**壳自己做什么**——这在基线里是散落的（§10.1 四个入口、§1260 产物、§1259 supervisor），
从未被合成一句话。本 ADR 合成如下：

| 壳**做** | 依据 |
| --- | --- |
| 窗口与托盘及其生命周期 | §1259、§10.1 |
| 受保护 IPC 的**宿主侧** | §1101 |
| 数据根解析（交 OS 路径 API） | §900 |
| sidecar 的拉起与监督 | §1259 |

| 壳**不做** | 依据 |
| --- | --- |
| 会话、守门、审批、知识、媒体编排等业务逻辑 | §17.5（内核职责）、§181（UI 不访问数据库与凭据） |
| 任意 shell 执行、任意文件系统、SQL | §1151 |
| 后台进程的存活性（归 supervisor / 托盘，**不归 WebView**） | §1259 |

「什么不算壳」这一半同样要可判：校验会按**业务语义关键词**（会话/守门/审批/知识/媒体编排）扫描壳的能力声明，
命中即失败——防止壳随时间把内核职责再吸回来。

## 4 最小权限为什么是「逐一相等」而不是「包含」

§1151 说的是「**只**开放必要的命令与资源」。「只」是一个**上界断言**，而「包含」只能证明下界——
`["core:app:allow-version", …, "shell:allow-execute"]` 显然「包含」了必要权限，却完全违反 §1151。
所以判定必须是**集合相等**：多授一项失败（超界），少授一项也失败（声明与配置漂移）。

同时**禁止聚合权限集**：Tauri 2 的 `core:default` 之类的权限集会在一条标识符里展开成一组权限，
使「最小」无法被逐条检查。故权限标识符一律要求形如 `core:<模块>:allow-<动作>` 的**具体**权限
（判定用 `^core:[a-z]+:allow-[a-z0-9-]+$`，不匹配 `:default` 与裸 `core:default`）。

**声明集（本轮钉住，5 条）**：

```
core:app:allow-version         界面显示版本
core:event:allow-listen        接收壳推送的状态事件
core:event:allow-unlisten      取消监听
core:window:allow-start-dragging   自定义标题栏拖动
core:window:allow-set-title    更新窗口标题
```

加权限时必须**同时**改配置与声明，否则校验红——这是特性，不是负担。

## 5 受保护 IPC 是生产路径，loopback HTTP 是测试适配

§1101 的原文把两者分得很清楚：同机优先受保护 IPC，HTTP 只用于「已启用的手机、轻云与**测试适配**」。
现有桌面面走的是 `ControlClient` 的 loopback HTTP（`apps/desktop/src/control.ts`），并且已有测试钉住
「只接受显式 loopback URL 与内存凭据」。**本轮不改这条通道**——它是既有实现，且确实是测试适配。
本轮做的是**把它在声明里定性**：CSP 的 `connect-src` 只含受保护 IPC 的源（`ipc:` 与 `http://ipc.localhost`），
不含任何通配协议源；且 ADR 明确「HTTP 端口 MUST NOT 被表述为对外接口」。
这样「HTTP 是正式通道」这个误读在**声明层面就无法成立**。

## 6 生命周期与 sidecar：两条都与「不依赖 WebView 保活」同源

§1259 一句话里其实有两个要求，本轮都落：

1. **UI 生命周期与后台解耦**：需要在 UI 关闭后继续运行的引擎与 keeper 由独立 supervisor 或托盘管理。
   判定：生命周期声明 MUST NOT 把「界面关闭」与「后台进程终止」绑定。
2. **sidecar 按目标三元组命名**：`bundle.externalBin` 声明的是**不含三元组**的逻辑名（如 `binaries/nai-engine`），
   实际文件为 `binaries/nai-engine-<target-triple>[.exe]`。判定：每个声明的 sidecar 必须能对应出带三元组的目标文件名。

两条同源：都来自「壳是**可随时关闭的呈现层**，不是后台的监护者」。

## 7 一次裁决三处：桌面、macOS、移动端路线 B

§10.2 路线 B（原生壳 + 局域网直连 + 证书固定）与 §10.3（Lite-Mobile 需原生壳）用的都是原生壳，
且 §1248 的栈里 Tauri 2 本就有移动端目标。若三处各写一套边界，同一套权限面会被写三遍并必然漂移。
故 ADR **一次裁决**：**边界共用，差异只允许落在目标与分发上**（Windows 安装器 / macOS 签名与公证 / 移动端分发），
MUST NOT 落在权限面或 IPC 形态上。macOS 与移动端本轮**只登记边界与前置**，实现分别属第 4 项与第 5 项。

## 8 已有先例与复用

- **写法复用 W53**：新能力（`desktop-shell`）+ ADR + 机器可查的结构事实 + 非空洞守卫，是 W53 已验证的形状。
- **不重复实现已就位的**：INV-18 的依赖方向检查已存在，本轮只引用。
- **门控入口复用**：校验放进既有 `test:ui`（根 `package.json` 的 `scripts`），
  `scripts/frontend-gate.mjs` 是**按 scripts 驱动**的，故新文件自动进门控的 `full` profile，**不需要改门控代码**。

## 9 已知后果与风险

| # | 后果 | 处置 |
| --- | --- | --- |
| R1 | 配置按**形状**校验，**不能**证明被某个 Tauri 版本接受 | 如实写进 ADR 与 A12 notes；不声称「配置已验证可构建」 |
| R2 | Tauri 大版本改动配置字段时，本仓库检查**不会自动发现** | 同上；引入真实依赖时应改为由构建产出物校验 |
| R3 | `$schema` 为官方 URL，**离线不可校验** | 校验**自建**，不依赖网络；不把 schema 拉取放进任何门控 |
| R4 | 权限集合被钉死为 5 条，加功能时需同改两处 | 这是 §1151「只开放必要」的落地方式，不是缺陷 |
| R5 | A12 只有 `pending`，容易被读成「没做事」 | notes 明确列出**本轮落点**与**缺失前置**，区分「未开始」与「已奠基」 |

## 10 验收与不升级

- 相关验收新增 **A12「桌面壳宿主边界」**，`status: pending`。**MUST NOT** 因配置出现而升级——
  §1248/§1260 的真值是**可运行、可打包、可签名的壳体**，本轮没有。
- 本 ADR 只裁决边界；**不**改动任何既有验收的状态，**不**触碰内核，**不**改动 workspace 构成。
