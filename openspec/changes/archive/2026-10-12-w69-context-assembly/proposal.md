## Why

V3.9 §41「上下文装配与预算（L1 信息边界层）」是**每一次调用付费模型前的必经之路**：给模型看什么、按什么顺序、
各段多少预算、裁剪从哪一端发生、每个片段带什么标注。§41.5 把这套东西的验收定为 **H01、H02**，
§51.3 又把它列为**留在 R1 的「基础纪律」**而非可选子系统——理由写得明白：**没有它，默认组合无法正确调用模型**。

**实测缺口（不是印象）**：本轮对仓库逐项核对——

| 核对项 | 实测 |
| --- | --- |
| `crates/nai-kernel/src/evaluate/` 是否有装配判定 | **没有**。九个文件里没有 `assembly`；`harness.rs` 里出现的 `Assembly` 全部是**层名与字段名**（`ObservationLayer::Assembly`、`FailureLayer::Assembly`、必需字段 `segment_budget`/`cropped_items`/`crop_reason`），它判的是「记录能否进日志」与「失败落到哪一级」，**不判装配本身是否合法** |
| `tests/registry.yaml` 里 H01/H02 的状态 | `pending`，且两条 `notes` 至今写着「**未开始（W56，V3.9 §41、§48.5）**」 |
| §47.6 的工作项表 | `W56` 行的目标写的正是「上下文装配器：固定顺序、分段预算、片段标注与裁剪记录」／验收 `H01、H02`／线 `R1` |

⇒ **W56 实际交付的是设计基线升 V3.8 与新能力规格（10 条需求 / 27 个场景），零实现**（见
`docs/reports/2026-10-11-w56-agent-harness-and-interop.md`）。同一轮的 `W57`（H03/H04）、`W63`（H15/H17）、
`W64`（H18）随后都补上了判定面，**只有 W56 那一行的 H01/H02 没有落点**。结果是 R1 的七条 harness 基础纪律里，
有两条**至今不可判定真伪**——「装配顺序对不对、裁剪有没有裁到不可裁段」今天只能靠人读代码回答。

这与 W54 之前的桌面壳、W55 之前的平台维度、W68 之前的讲品循环是同一类缺口：
**门槛定义里有它、验收清单里也有它，但仓库里没有落点，而登记状态掩盖了这一点。**

## What Changes

- 新增 `crates/nai-kernel/src/evaluate/assembly.rs`：把 §41.1–§41.3、§41.5 落成**纯逻辑判定面**，输出具名拒绝。
- **H01（§41.1 顺序与不可裁段）**：九段固定顺序（系统策略 → 人设与场景 → 任务与输出契约 → 事件摘要 →
  已批准事实与检索证据 → 记忆片段 → 技能与工具描述 → 最近播完的句子 → 工具结果与外部返回）逐项写死；
  未定义段名、缺段、乱序各自具名。**不可裁剪段（1–3）MUST NOT 被裁**；预算压力 MUST 只从后段裁剪，
  故「被裁的段」必须是可裁序列的一个**后缀**——一个只判「有没有裁剪记录」的实现会让「裁了策略段、
  留着记忆段」通过，本模块必拒。裁剪 MUST 记录**被裁项与原因**，缺任一项即拒（**静默裁剪不是裁剪**）。
- **H01（§41.2 分段预算）**：预算**按段**分配，MUST NOT 以一个总上限顶替；不可裁剪段还 MUST 带固定下限；
  Token 与字符 MUST 同时计入（两维度互不替代）且**条数**作为第三个可判定的维度参与判定。
  与 §48.7 的既有纪律一致，**阈值的取值一律由调用方给定**，模块不内建数字、不采外部观察值。
- **H02（§41.3 标注 + §41.5 落日志与重建）**：每个片段 MUST 携带来源类型（七类）、来源标识、作用域；
  「数据或指令」的标注以**类型**表达，故其**错值**（把观众文本、检索片段、工具返回、外部智能体返回标为指令）
  是可构造的拒绝。「时效（如适用）」原文自带限定，**本轮明确不判其缺失**并写明理由。
  装配记录 MUST 可由决策日志**重建同一序列**：片段内容只在当时活动内存里、日志没记的，重建 MUST 被拒——
  这是 H02 的「**不依赖当时的内存**」的可判定形式。装配记录 MUST NOT 含明文凭据（INV-11），
  **复用 `harness::CREDENTIAL_MARKERS` 而不新建第二张标记表**。
- **不接线**：真正喂给模型、真正把记录追加进哈希链是 runtime 工作；本模块判的是**装配是否合法**与
  **这份日志够不够重建**，MUST NOT 被读作装配已可运行。

### Modified Capabilities

- `agent-harness`（**修改 2 条既有需求**）：H01/H02 的需求在 W56 已建立，本轮**只做加强、不做削弱**——
  ①`Context is assembled in a fixed order under per-segment budgets` 补上「预算按段分配、条数是第三个维度、
  不可裁段带固定下限」与三个可判定的新场景（裁剪跨过前段、无原因的裁剪、一个总上限顶替分段预算）；
  ②`Every assembled fragment is sourced, scoped and reconstructible` 补上「来源标识不得为空白、
  不可信四类标为指令即拒、内容未落日志则不可重建」与两个新场景。
