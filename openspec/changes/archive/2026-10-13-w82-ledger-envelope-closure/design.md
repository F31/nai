# 设计 · W82 台账信封的闭世界

## 1. 问题：W81 的闭世界只在一个层级上成立

W81 的断言「条目里出现的每个键 MUST ∈ `LEDGER_FIELDS`」是**对的**，但它把**层级**当成了背景。
台账有**两个**层级：

| 层级 | 键 | 谁在管 |
| --- | --- | --- |
| 信封（顶层） | `schema_version` | `schema_version must be 1` |
| 信封（顶层） | `baseline` | `ledger declares baseline … but the current baseline is …` |
| 信封（顶层） | `entries` | `entries must be a non-empty list` |
| 信封（顶层） | **（第四个键）** | **没有人** |
| 条目 | 十个字段 | W81 的闭世界断言 |

三个已知信封键**各有**具名检查——所以这不是「检查漏写」，而是**键集不封闭**：
**已知键各有人管，新增的第一个键就落进盲区**。实测 UB1/UB2/UB3 全部返回**空错误**。

**UB3 是最尖锐的一条**：把一个**条目字段名**（`question`）放到顶层，两个闭世界都放行——
条目闭世界没看见它（它在顶层），信封闭世界还不存在。这一条同时暴露了「层级」这件事：
**闭世界的完整性不只要求每个层级封闭，还要求两个层级的字段名集不相交。**

## 2. 决策

### 决策 1：`TOP_LEVEL_FIELDS` 逐字写死

```js
export const TOP_LEVEL_FIELDS = ['schema_version', 'baseline', 'entries'];
```

与 W81 的 `LEDGER_FIELDS` 同理：它必须是**独立的一份声明**，不能由「现有检查读了哪些键」
派生——派生出来的「闭世界 == 声明集」是**恒真**的，一个字都没说（W80 §九结论 5：
只钉「关系」不够，要**逐字钉内容**）。

### 决策 2：信封闭世界断言**不看值**

```
unknown envelope field revision — a top-level field the checker does not know can carry §NNN unchecked
```

与 W81 决策 2 同型：若写成「未知键**且**其值含 `§NNN`」才报，判据的输入（值）就**不等于**
被断言的对象（键集）。⇒ 注入 MUST 含一次**值干净**的顶层未知键——**它同样要失败**。

### 决策 3：信封字段必需

```
envelope field baseline is missing — a declared envelope field with no value is a field nobody reads
```

为什么需要它：闭世界断言只保证「**不认识的**键被拒」，它对「**认识的**键没人读」是瞎的。
一条 `TOP_LEVEL_FIELDS` 里被错加的幽灵字段，若只靠闭世界，会让**每个**真实台账都失败
（因为台账里没有它）——那其实是**好事**（响得早）；但若有人「为了让它绿」而往台账里补上
那个键，就再没有信号了。把「必需」也写成断言，等于把 `TOP_LEVEL_FIELDS` 的每个成员
绑到**数据上**：**声明一个字段就必须在台账里有它**，否则基线立刻红。

⇒ 三条信封键各有一条**具名**的值检查 + 一条**具名**的必需检查；**新增的键没有任何一条**——
这正是`shapeErrors()` 要提前挡住的形状。

### 决策 4：两个层级不相交

`shapeErrors()` 新增：`TOP_LEVEL_FIELDS` ∩ `LEDGER_FIELDS` MUST 为空，**具名**报出既属信封、
又属条目的那个字段名。

**为什么这不是「装饰性断言」**：正因为 UB3 的形状（把条目字段名写到顶层）**两个闭世界都不管**，
所以一旦某次编辑顺手把 `question` 也加进 `TOP_LEVEL_FIELDS`（意图是「让那个顶层 `question`
合法」），UB3 的洞就**原样重开**——而且重开得**完全无声**。这条断言是那个洞唯一的守卫。

**方向**：这里选的是**互斥**（拒绝），不是「两边都允许」。理由同 W81 决策 3：一个字段名
**只属于一个层级**这件事本身是可判定的，而「既属信封又属条目」会让「这个字段由谁读」
不再是单一回答。

## 3. 不改什么

- **不改台账数据**：实测顶层键**恰好**等于 `TOP_LEVEL_FIELDS`（三个）⇒ 基线**保持全绿**
  （「本轮不引入红」的判据）。
- **不改基线正文、不改任何 Rust、不新增依赖边。**
- **不与 W81 的条目闭世界合并**：两层各自的键集不同、报错措辞不同（一个报**条目 id + 字段名**，
  一个报**键名**）——合并会让「错在哪一层」在措辞上消失。
- **不动 `entries` 内部的检查**：本轮的边界在**信封**，条目内容一字未改。
