# 提案（w75 仓库受限的消费证据：判据的输入必须等于被断言的对象）

## Why

本轮从 **W74 §八遗留 1** 出发。那条遗留写的是：

> 未跟踪文件若落进「非 dot、非具名排除」的目录仍可能造出消费者……彻底消除需要「仓库文件集」
> 这个输入，而**取它需要派生 `git` 子进程（宿主禁止）**。

**核实之后，这条陈述被证伪**：

1. **`.git/index` 可以纯 JS 解析。** 它是 DIRC 格式（`magic=DIRC version=2 entries=922`），
   探针**完整解析 922/922** 条路径。⇒「取仓库文件集」**不需要任何子进程**。
2. **探针实测三者关系**：工作区扫描集 **282**；`.git/index` 里代码扩展名 **283**；
   - 【A】工作区扫描到、但**不在 index**（即未跟踪）= **0**（当前仓库干净）；
   - 【B】在 index（代码）但不在扫描集 = **1**（`.github/workflows/foundation.yml`，dot 目录，
     符合 W74 的结构性跳过）；
   - 【C】工作区 ∩ index = **282** = 扫描集。

⇒ F2（W74 自己认定**最严重**的缺陷：「一句临时脚本就能把一个真孤儿洗绿」）**可以根除**，
而不必停在「结构性收敛 + 登记残余风险」。

另牵出一条**新缺陷 F6**：`codeFiles()` 用 `dir.replace(/^\.\//, '')` 构造路径，而初始调用
`dir === '.'` 时该替换**不生效**（`'.'` 不匹配 `^\.\/`）⇒ **根目录下的文件路径带 `./` 前缀**，
子目录下的不带。当前无可观测影响（`SELF` 恰在子目录、现有断言比较的都是子目录路径），
但**任何「与仓库路径集比较」的判据都会因此假阴性**——而本轮正是要做这个比较。

## What Changes

1. **仓库文件集 = `.git/index` 的路径集**：新增纯 JS 解析器（DIRC v2/v3/v4；`.git` 为文件时
   读 `gitdir:` 指针）。它取代「结构性收敛」成为这条判据的输入。
2. **消费证据的来源 MUST ⊆ 已跟踪路径集**：一个**未被版本控制**的文件 MUST NOT 成为消费者。
   这是 F2 的**精确**修复（不是「缩小面」，是「关掉入口」）。
3. **扫描集路径 MUST 是 POSIX 相对路径**（无 `./` 前缀），并加断言钉死——修 F6，
   让「扫描集」与「index 路径集」可比。
4. **`index` 不可解析 MUST 失败**，并给出可诊断的消息（区分「`.git` 不存在」「坏 magic」
   「版本不支持」「条目截断」四类）。「判据的输入等于被断言的对象」是这条守卫的前提，
   前提缺失时**必须红**，而不是静默退化成「看起来还在跑」。

**为什么是「仅已跟踪」而不是「git 会发布的内容」**（本轮最关键的一处裁定）：

- `cargo xtask check --secrets` 用的是 `git ls-files --cached --others --exclude-standard`
  （=「git 会发布的内容」）。它**含未跟踪但未被忽略的文件** ⇒ **修不了 F2**：
  那个未跟踪的伪造消费者**也在这个集合里**。
- 守卫跑在**提交前**，此时「未跟踪」正是「**尚未承诺**为仓库内容」⇒ 判据必须用**已跟踪**。
- 且「已跟踪文件的**路径**恒在 index 里」（与工作区内容是否已修改无关）⇒ 不会误伤
  「改了但还没 `git add`」的老文件——本轮改动全发生在已跟踪文件上，闭环顺序不受影响。

## 范围

只动：消费守卫本身、它的输入面（扫描集 + 新增的「仓库文件集」读取器）、以及订正既有不实陈述。
**不改基线正文、不改任何 schema 文件、不改任何 `acceptance`、不改 Rust、不新增 xtask 步骤**
（解析器的测试并入既有 `tests/contracts/schema.test.mjs`，故 `engineering_checks` 零改动）。
