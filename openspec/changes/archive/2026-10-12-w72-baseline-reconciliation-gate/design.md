# 设计（w72 冻结基线与注册表的对账门控）

## 1 为什么断言必须是「对账」，不是「相等」

基线文档一旦被 ADR 批准即**不可变**（`AGENTS.md`：被批准的基线产物保持不可变，换版本号换来的是证据可复查）。
于是出现一个结构性事实：

> **注册表是活的，基线是冻的。** 任何一次新增验收项都会让两者不一致，而实现轮次**没有权限**去改 §57.3。

W68 新增 B07 就是这个形状。若断言写成「§57.3 == 注册表」，W68 只有两条路：跳过门控，或者开一个升基线轮次。
两条都不可接受——前者让门控失效，后者让「加一条验收项」的成本变成一次 ADR。**这不是严格，是死锁。**

所以断言写成：

```
在册 == 基线声明 ∪ baseline_deviations
```

关键在于**偏差不是豁免**：

| 性质 | 落实方式 |
|---|---|
| 具名 | 每条 MUST 给 `id` + `registered`（登记轮次）+ `reason`（非空） |
| 相称 | 每条 MUST 对应一处**真实**差异；张冠李戴时，真实差异与该条目**两条都失败** |
| 自清理 | 基线收录后不清空 ⇒ 该条目不再对应差异 ⇒ 按**陈旧条目**失败 |
| 不空洞 | 台账形状非法（非列表 / id 非法 / 缺轮次 / 缺理由 / 重复）逐项具名失败 |

⇒「**已登记但尚未收录进基线**」从一个在几份文档里各写一遍的**说法**，变成一个**可判定**的状态。
这正是 ADR 0042 的教训（「在册」与「测得」是两个不同的陈述）在**文本**上的同一形式。

## 2 判据来源：§48.5 而不是一份写死的家族表

`registry.mjs` 里已有 `COMPLETE_FAMILIES = {M: 18, H: 18}`，它挡的是「M01–M18 只在册一半」。
本轮**保留**它，并新增一条来自 §48.5 的判据。两条都留，因为两者挡的不是同一件事：

| 守卫 | 挡什么 | 判据来源 |
|---|---|---|
| `COMPLETE_FAMILIES` | **§48.5 被改小**（例如 M 行被改成 `M01–M12`） | 写死的 18 |
| §48.5 家族索引对账 | **注册表少了 §48.5 声明的某一项**（例如 B07 未收录） | 基线正文（逐行读出） |

**只有后者能覆盖 S/R/A/B/O/P/X 七族**——`COMPLETE_FAMILIES` 从头只覆盖 M 与 H。
这正是**缺口①**的实质：`admission-registry` 的需求写「每个『基线已定义完整编号段』的家族」，
括号里写「（当前为 M01–M18 与 H01–H18）」。裁定：**括号是示例，不是枚举**；
「基线已定义完整编号段」的取值 MUST 从 §48.5 的家族索引逐行读出（当前 **9** 族，全部是连续段）。

⇒ 缺口①不需要单独的实现轮——**它被②的实现顺带关掉了**，只需把规格里的判据来源写清楚。

## 3 非空洞：解析失败必须区别于设计漂移

最容易让这条门控变成废纸的失败模式不是「漏改」，而是**解析悄悄落空**：§57.3 的标题被改一句、
章节号被调，解析结果就是空集——而空集会让「对账」产生两种相反的假象：

- 若实现成「声明 ⊆ 在册」⇒ 空集**恒真**，门控永远绿；
- 若实现成「在册 ⊆ 声明」⇒ 空集让 88 条全部报错，**很吵但正确**（把解析失败读成「注册表多了 88 条」）。

本实现取后者（宁可吵），**并把两类错误分开报**：`§57.3 heading not found` 单独一行，
使「找不到这一节」不会被误读为「设计漂移」。另外：

- 定位按**章节号**（`^#+\s*57\.3\b`）而非标题文本 ⇒ 改措辞不影响解析，改号码必然失败（有专门用例）；
- 家族列与发布线列**逐项钉死**（`familiesInOrder`、`rowLabels`），因为它们**照抄基线**——
  §57.3 的「线」列写 `Slice-0`、而 `release_lines` 的键是 `slice_0`，这张映射改小就是静默失效。

## 4 用例里的锚点必须**恰好命中一次**

注入用例的价值全在「我改的确实是我以为的那一处」。用 `replace` 改到第一处就改了 §1.4 的表而 §57.3 没动，
用例会**假装通过**。所以 `replaceOnce` 先数出现次数，不等于 1 就直接失败。

这个守卫**当场开火**：`\`r1\` **37**` 命中 **2** 处——§57.3 的计数行，以及 **§58.5 逐字复述的同一条计数行**。
后者本身很有意思：**W71 已经把这条断言用散文写在了 §58.5**（「正本仍是 §57.3……与 `tests/registry.yaml` 逐条一致」）。
本轮做的是把它**变成机器可读的**。锚点因此加上 `计数：` 前缀。

## 5 规格订正：被先例否证的规则仍在规格里

见 `proposal.md`。要点：**规格不是历史记录**（§56.2 的历史记录只列 `docs/reports/`、`docs/adr/`、
`openspec/changes/archive/`），它是**活的主规范**，故**就地订正**；而 ADR 里同类的残留用**追加勘误段**。
这条分界本身就是 §56.2 的应用，不是新规则。

## 6 本设计明确不做

- **不做「规格 vs 基线」的自动对账**：§56.2 的四情形是**语义**规则（「这句是在声明当前基线，还是在陈述某一版」
  只能靠读）。本轮只覆盖**可机读**的那一半（编号与计数）。残余风险**如实登记**：本轮发现的规格矛盾
  正是靠人读出来的，下一次仍可能靠人读。
- **不给 §16 增行**：插入行会位移其后全部行号（W71 已裁定，§58.3）。
- **不删 `COMPLETE_FAMILIES`**：见 §2，它与新判据挡的不是同一件事。
- **不改任何 `status`**：H18 与 B07 仍 `pending`。
