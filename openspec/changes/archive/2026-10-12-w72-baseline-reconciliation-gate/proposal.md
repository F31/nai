# 提案（w72 冻结基线与注册表的对账门控）

## Why

W71 的报告在「未做与遗留」里**如实登记了两处门控缺口**，本轮的形状由这两条决定：

| # | 缺口的原文 | 本轮处置 |
|---|---|---|
| ② | **没有任何断言能发现「基线文本 vs 注册表」的漂移**——W68 新增 B07 之后，§48.5 说 `B01–B06`、§57.3 说 `= 87`，**两轮之后才被人读出来** | 本轮补上断言 |
| ① | `admission-registry` 的「逐号在册」只说「每个『基线已定义完整编号段』的家族」并在括号里写「（当前为 M 与 H）」，而 §48.5 声明**九个**连续编号段——括号是「当前清单」还是「示例」没有裁定 | 本轮裁定：**判据来源改为 §48.5 逐行读出**，括号是示例；缺口①随②一并关闭 |

② 的性质值得写清楚：**它要抓的不是「有人改了东西」，而是「改完之后没人说」。**
W68 把 B07 加进注册表是**正确**的动作；错的是它没有让任何机器可读的地方发现 §48.5/§57.3 已经落后。
所以断言不能写成「基线与注册表必须相等」——基线被 ADR 批准后**不可变**（`AGENTS.md`），
实现轮次**无法**就地改 §57.3，硬相等会把实现轮次锁死。正确形状是：

> **在册 == 基线声明 ∪ 已登记偏差**，且台账里的每一条 MUST 具名、MUST 对应一处真实差异。

### 核实中另发现一处缺陷（本轮一并订正）

在核实「哪些地方已经声明过这件事」时发现：**W71 自己的 E5 订正没有传播到它自己的规格差量。**

- 基线 **§56.2 第 1 行**（权威）把「就地订正的对象」写成**四情形**，其中**情形②**明确：
  **`§NNN` 的版本前缀是行号契约的锚点 ⇒ 随基线更新**；
- 而 `openspec/specs/spec-driven-delivery/spec.md` 里 W71 **新增**的需求写着：
  「**版本归属引用**（形如「V3.9 §51.3」）……MUST NOT 随基线号变更」，其场景甚至明确要求
  「把「V3.9 §51.3」改写为「V3.10 §51.3」MUST 被拒绝」——**与 §56.2 情形②和 W71 的实际落地直接相反**；
- W71 实际落地的形状是 `【V3.10 §51.3（V3.9 收缩：自 rN 降为能力包）；INV-33/34】`（**29** 条）：
  `§NNN` 前缀**已按情形②更新**，归属以括号保留。

这不是措辞问题：**规格是下一个升基线轮次的行为依据**，留着它会把被先例否证过的规则再执行一遍。
（同类的**历史记录**残留——ADR 0048 的勘误段与 ADR 0049 的「后果」行——按 §56.2 用**追加勘误段**处置，
不就地改写原文。）

## What Changes

1. **新增门控**：`scripts/contracts/baseline.mjs`，由 `tests/registry.test.mjs` 驱动（因此自动进入
   `check --profile portable` 与 `full`，不需要新的 xtask 步骤）。它做四件事：
   - 取 `docs/` 里**版本号最大**的基线文档，并与 `openspec/config.yaml` 声明的指针核对；
   - 解析 **§48.5 家族索引**与 **§57.3 发布线正本**（表格 + 计数行）；
   - 断言 §57.3 **表内自洽**（计数行 == 表格展开；合计 == 各行之和）；
   - 与 `tests/registry.yaml` **逐 id 对账**（发布线归属 + 家族完整性），豁免项只认具名台账。
2. **注册表新增台账** `baseline_deviations`（**当前为空**——W71 已把两处偏差全部收录）。
3. **`§48.5` 成为家族完整性的判据来源**：`COMPLETE_FAMILIES`（M、H 两张写死的表）**保留**作为独立
   的第二重守卫（它挡的是「§48.5 自己被改小」），新断言覆盖 §48.5 声明的**全部九族**。
4. **规格订正**：`admission-registry` 的家族完整性需求（判据来源）+ 新增对账需求；
   `spec-driven-delivery` 的「订正只作用于不符事实的陈述」需求**改写为四情形**。

### 不改什么

- **不改基线正文**（`docs/直播数字人 + 智能体系统技术方案 V3.10.md` **零改动**）——本轮是**加断言**，
  不是升基线；基线一旦被 ADR 批准即不可变。
- **不改 `tests/registry.yaml` 的任何 `acceptance` 条目**：88 条、六条发布线、全部 `status` 原样。
- **不改 Rust 行为**：`xtask/src/registry.rs` 与其输出串一字未改；新代码全部在 `scripts/` 与 `tests/`（Node）。
- **不改 `schemas/`**：能力目录与生成物零漂移。

## Capabilities

- `admission-registry`（MODIFIED）：家族完整性的**判据来源**改为 §48.5 的家族索引逐行读出；
  括号里的旧文降为示例。新增一个场景把「把判据缩成一份写死的清单」判为不满足本条。
- `admission-registry`（ADDED）：**冻结基线与注册表的对账**——等式、具名台账的三条性质、
  基线文档的选取与指针自洽、以及「对账 MUST NOT 是空洞的」。
- `spec-driven-delivery`（MODIFIED）：「就地订正只作用于与当前事实不符的陈述」改写为**四情形**，
  并新增场景处理「**本规则自己的一份旧草稿仍在被引用**」。

## Impact

- 交付：`scripts/contracts/baseline.mjs`、`tests/registry.test.mjs`（**4 → 11** 用例）、
  `tests/registry.yaml`（+台账段）、`openspec/specs/{admission-registry,spec-driven-delivery}/spec.md`、
  `docs/adr/0050-*.md`、`docs/adr/0048-*.md` 与 `0049-*.md` 的追加勘误段、活文档与报告。
- 验证：`node --test tests/registry.test.mjs`（11 用例）；注入验证 **21 组**（改计数、改合计、漏线、
  多线、移线、增删 id、缩/扩家族范围、章节号被改、陈旧/张冠李戴/形状非法的台账条目、指针失配）；
  `cargo xtask check --profile full`。
- 基线契约不受影响：本轮**不触碰**基线文档，`diff` 三件套自然不变。
- **已知代价**：门控依赖基线的**章节号**与两张表的**写法**；两者被改时门控**报解析失败**而非静默通过
  ——有意取舍，且解析失败与设计漂移在错误列表里**分开具名**。
