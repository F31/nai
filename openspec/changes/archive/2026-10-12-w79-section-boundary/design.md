# 设计 · W79 节界

## 1. 现状：`sectionTable` 的搜索域是无界的

```js
const start = lines.findIndex(headingPredicate);
let index = start + 1;
while (index < lines.length && !isTableLine(lines[index])) index += 1;   // ← 会一直走到文件末尾
```

「向后找第一张表」在**表确实在本节内**时看不出问题；一旦表不在本节内（被删、被挪、被一个更浅的
标题挡开），它取到的是**别人**的表，而且返回值形状**与成功时完全一样**。

实测（探针，公开 API）：

| 输入 | `found` | `errors` | `lines`（§57.3 的行） |
| --- | --- | --- | --- |
| 真实正文 | `true` | `[]` | 从 §57.3 自己的表来 ✅ |
| 「§57.3 无表 + §57.9 有表」 | `true` | `[]` | **从 §57.9 来** ❌ |

⇒ 两行的返回值**无法区分**。这正是「索引不可解析 ⇒ 失败并分类，不静默降级」的反面。

## 2. 边界怎么定：按标题层级，不按「下一个标题」

- **层级 ≤ 本节**（`##`/`###`）⇒ 本节结束。这是 Markdown 的结构语义，也是「§57.3 是 §57 的
  一个子节」这句话的形式化。
- **层级更深**（`####`）⇒ **不截断**。写成「遇到任何标题就停」会把一个子标题误当成节界，
  于是本节里明明有表却报「本节内无表」——**方向不安全**（假阳性）。

实测 V3.10 的标题层级直方图：`h1 = 1 / h2 = 59 / h3 = 259`，**当前无 `####`**。
⇒ 层级语义在当前正文上**不可观测**，故它由**合成存根**验证（`####` 不截断 / `###` 截断）。

## 3. 三态，及其为什么必须分开

| 状态 | 含义 | 谁的错 |
| --- | --- | --- |
| `found:false` | 该节标题不存在 | 章节号被改指 / 被重排 |
| `found:true, hasTable:false` | 章节在，**本节内没有表** | 表被删 / 表被挪 / 被更浅的标题挡开 |
| `found:true, hasTable:true` | 解析成功 | —— |

把后两者合成一个（「解析出的表是空的」）会让**上层**报出误导性的错：§57.3 会去报
「计数行为空」，§51.3 会去报「declares 0 capability packs」——**错误的措辞会把定位引向错误的方向**。

## 4. 判据（全部具名）

| 编号 | 判据 | 非空洞性从哪来 |
| --- | --- | --- |
| B-A | 三张表（§48.5／§51.3／§57.3）**本节内确有表**，且表行落在 `[start, end)` 内 | 边界若被收得过紧（例如把标题行本身当节界），三条会同时报「无表」 |
| B-B | 有表节 + 邻节有表 ⇒ 取到的 MUST 是**本节**的表（合成存根：§57.3 无表 + §57.9 有表 ⇒ 具名报「本节内无表」，`lines` 为空） | 这就是实测出的那段 `errors = []` |
| B-C | 更深标题**不**截断本节（合成存根：`### 57.3` + `#### 57.3.1` + 表 ⇒ 仍解析成功） | 若写成「遇标题即停」，这条立刻红 |
| B-D | 散文节的前提：§51.2／§57.5 本节内**无表** | 任一节被加上表即红；W78 的「刻意不读 §51.2」因此有了判据 |

B-D 是**前提断言**：它不断言「§51.2 不重要」，只断言「按当前正文，对 §51.2 取表取不到东西」。
若某次基线修订给 §51.2 加了表，这条会红——**那正是应该回去重读 ADR 0056 遗留 2 的时刻**。

## 5. 落点

- `scripts/contracts/baseline.mjs`：`headingLevel()` + 重写并 `export` `sectionTable()`；
  三个解析器各加一个 `hasTable` 分支。**新依赖边：无**（只用 `node:fs`／`node:path` 与既有 import）。
- `tests/registry.test.mjs`：+3 个用例（**24 → 27**），随 `engineering_checks` 既有条目自动进
  `portable`／`full` ⇒ **接线零改动**。
- **上层的对账逻辑一字未改**：三张表的名字、位置、断言都不动；变的只是「表在不在本节内」。
