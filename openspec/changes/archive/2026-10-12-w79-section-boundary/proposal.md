# W79 · 节界（按章节号取表需要一条边界断言）

## Why

W78 的 `parseCapabilityPacks` **刻意不读 §51.2**。理由写在 ADR 0056 遗留 2 与 `AGENTS.md` 里：

> §51.2 是散文、没有表格，而 `sectionTable` 取的是「标题之后第一张表」
> ——对无表章节调用它会静默取到 §51.3 的表。

这条限制**只靠文档与记性维持**——它是一条写给人的告诫，不是一条判据。而 `sectionTable` 是
三个解析器（§48.5／§51.3／§57.3）共同的地基，地基上的错会**同时**污染三张表。

**实测（本轮探针，只用公开 API，不改被测文件）**：给一段「§57.3 标题在、本节内没有表」的文本，
`parseReleaseLines` 返回——

```
found = true
errors = []                      ← 一条错都没有
lines  = [["slice_0",["S01","S02","S03","S04"]]]   ← 这四行来自紧随其后的 §57.9
```

⇒ 它把**邻节的表**当成了 §57.3 自己的表，并且**没有任何一条错误**。这不是「解析器还不会读一段
散文」，而是**解析器会读错一段散文并且读得很自信**。

三种后果，彼此原因不同，因此必须**分开具名**：

1. **章节号找不到**（如 §57.3 被改成 §59.3）——已有具名失败，且是「设计漂移」与「解析失败」
   分开报的先例（W73）；
2. **章节在、本节内没有表**——目前**完全沉默**，回落到邻节的表；
3. **表被更浅的标题挡开**（表仍在文档里，只是不再属于这一节）——同样沉默。

## What Changes

1. **`sectionTable` 的搜索域被封闭**（`scripts/contracts/baseline.mjs`）：域 = `[标题行, 下一个
   层级 ≤ 该标题的行)`。层级更深的标题（`####`）**不**截断本节。
2. **三态具名**：`{found:false}` / `{found:true, hasTable:false}` / `{found:true, hasTable:true, rows, after}`。
   三个解析器在第二个状态下各报一条**具名**错误（`§57.3 has no table inside its section`），
   MUST NOT 回落到邻节的表，也 MUST NOT 用「解析出一张空表」代替。
3. **`sectionTable` 导出**：使「本节内无表」这条**前提**可以被断言，而不只是被文档声明。
4. **真实正文上的前提断言**：`§51.2` 与 `§57.5` 是散文节（本节内无表）。前者是 W78
   「刻意不读 §51.2」的依据；后者是「邻节有表」的典型形状（`## 58` 就带着两张表）。
   ⇒ W78 的理由从**记性**变成**会被检查的前提**。

## 范围

- **不改基线正文**。§51.2／§57.5 是**被断言的前提**，不是被订正的对象。
- **不改 `tests/registry.yaml`、不改任何 Rust、不新增依赖边。**
- **不合并 `pending-decisions.mjs` 的章节抽取**：它按**正则**抽章节号、不取表（W76 立），
  与本节界是两件事——绑在一起会让任一方调整牵动另一方（W66「不合并不同维度」）。
- **不重排 W 编号**：本版为 **W79**。
