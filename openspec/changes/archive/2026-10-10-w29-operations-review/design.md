## Context

B04/R06/B06 被标为「设备里程碑」，于是「真值需要设备」被当成了「机制不用做」。但三件事的**判据口径**本来就该先落地，否则到了真机上，同一个数字会被两种口径算出两个结论：

1. §12.5 明写「整条路径实测分位数，不把各阶段 P95 相加」，这是一条可判对错的口径；
2. R06 说「无持续资源增长」但没说怎么判，不定义规则就只能人眼看曲线；
3. B06 依赖的 R07 已 implemented，数据源就位，缺的是投影规则与「缺测怎么标」。

本设计的目标是让这三件事在 portable 下有**可执行、可反驳**的判据，并让「没测」与「测到 0」保持类型上的区别。

## Goals / Non-Goals

- Goal：端到端分位口径唯一；目标判定不假设；长播判定有规则且抗噪；报告自洽且缺测可见。
- Non-Goal：不接真实采样器；不做长播；不做报告 UI；不做模型质量评测（B01 是独立主线）。

## Decisions

### 决策 1：落 `crates/nai-kernel`（`metrics.rs` + `review.rs`）

| 方案 | 结论 |
|---|---|
| 放进 `nai-upgrade-core`（shared） | **否决**：语义无关；且「评估与运营闭环」§5.9 紧跟 §5.8 决策日志，而决策日志相关内核在 kernel 的 `evaluate/`。 |
| 新增 `nai-operations-core` | **否决**：改动 18 包与依赖方向，而这两块只依赖 `ErrorCode` 与 `std`。 |
| 放进 `nai-kernel` | **采用**：kernel 只依赖 contracts，满足；`xtask test --suite kernel` 在 portable 下可测；与 `evaluate/` 的决策日志同层。 |

代价：kernel 只能依赖 contracts，故自带 `MetricsError { code, reason }`（`report.rs` 复用同一类型）。与 `UpgradeError`/`MultiplexError` 同形。

### 决策 2：nearest-rank 分位，不插值

| 方案 | 结论 |
|---|---|
| 线性插值（更「平滑」） | **否决**：报告要可复现；插值引入一个报告里不存在的值，复核时对不上任何一条样本。 |
| nearest-rank `ceil(p/100·n)` | **采用**：返回的永远是**真实存在**的一条样本，报告与原始数据可逐条对照。 |

### 决策 3：端到端与阶段分位分开，阶段之和**存在但被标注**

| 方案 | 结论 |
|---|---|
| 只提供端到端分位，不提供阶段之和 | **否决**：报告仍会想知道「时间花在哪」，把阶段数据浪费掉。 |
| 提供一个「取端到端或阶段之和」的开关 | **否决**：开关迟早被拨到错的一边；§12.5 要的是**不把两者混为一谈**，不是禁止观察后者。 |
| 两者都提供 + `stage_sum_gap()` 显式给出差 | **采用**：阶段之和只能作为具名对照出现，差距被算出来而不是被解释掉。 |

### 决策 4：样本门槛是常量 20，`Insufficient` 而非 `Stable`

| 方案 | 结论 |
|---|---|
| 有多少样本算多少分位 | **否决**：10 条样本的「P95」实际上就是最大值，读起来却是「P95 达标」。 |
| 低于门槛返回 `Ok` 但标注低置信 | **否决**：标注会被忽略，数值不会。 |
| 低于门槛返回 `Err(CAPABILITY_NOT_READY)` | **采用**：没有数字可误读。 |

### 决策 5：长播判定用「双半中位数 + 窗口下界」

| 方案 | 结论 |
|---|---|
| 首尾两点比较 | **否决**：一个末端尖峰就会判成增长，一个末端低值就会掩盖增长。 |
| 线性回归斜率 | **否决**：斜率对离群点敏感，且「多少算大」缺少自然阈值；中位数漂移更稳健也更易解释。 |
| 窗口按名义标签（跑了 40 分钟也叫「2h 测试」） | **否决**：窗口是**下界**——不足即 `Insufficient`，并如实报出真实跨度。 |
| 双半中位数 + `max_drift_pct` 阈值 + `min_samples` | **采用**：抗噪、可解释、可测。 |

### 决策 6：报告是投影，自洽由 `build` 把关，缺测由 `unmeasured` 显式

| 方案 | 结论 |
|---|---|
| 允许任意计数直接构报告 | **否决**：回答多于入选的报告会一路印到最后。 |
| 比例算成浮点百分数 | **否决**：无法复核分母，也无法表达「分母为零」。 |
| `Ratio { numerator, denominator }` + `Option` + `unmeasured` 清单 | **采用**：分母为 0 → `None` 且列入清单；成本缺失 → `CostView::Unknown`。 |
| 让 `build` 检查就够了，不做审计 | **否决**（W25 教训）：字段公开后仍可被绕过，审计是最后一道防线，且必须**可构造**才有意义。 |

### 决策 7：守门分类对齐 §5.4，不另造枚举

守门用 `GuardStage`（4）× `GuardVerdict`（4），与 §5.4 逐字对应；`is_hit()` 定义「非通过即命中」。不引入 §5.4 之外的分类（如按检查项细分），避免两个真相。

## Risks / Trade-offs

- **门槛常量 20**：小场次拿不到分位。这是刻意的——小样本分位比没有分位更容易误导。场次复盘可以把多次场次合并后再算。
- **`max_drift_pct` 由调用方给**（默认 10%）：不同资源（RSS、显存）的自然波动不同，写死一个阈值会让一端过松或过紧。
- **审计与 `build` 的重叠**：与 W28 同样取舍——重叠是为了防绕过。

## Migration Plan

无迁移。两个模块是新增，不改既有公开 API。真实采样器（RSS/显存/时延探针）与报告呈现是后续接线，本轮不做。

## Environment Boundary

两个模块是纯逻辑，不读时钟也不读系统指标——样本由调用方给（`at_ms` 与采样值），所以 portable 与 Windows 行为一致、结果可复现。真实验收（真实长播 2h/8h/24h、真实设备时延分位、真实场次数据）需要设备与长时运行，本轮记为未完成而不是通过。
