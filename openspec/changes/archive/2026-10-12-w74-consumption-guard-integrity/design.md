# 设计（w74）

## 0. 复核结论先行

W73 的守卫在**结构**上是对的（派生而非清单、注释不算消费、例外必须付理由、注入覆盖五类形态），
错在**边界**：它把「扫描集」定义成了「工作区里所有匹配扩展名的文件」，于是判据的输入不再等于仓库。
四条缺陷里 F1/F2 的根因是**同一个**——路径字面量来源是唯一会读任意扩展名文件的来源，
而它**零独有覆盖**。⇒ 移除它，F1 与 F2 的主要面一起消失。

## 1. 决策：扫描集是结构性的，排除必须付得起理由

**取**：扫描集 = 结构规则（从仓库根递归、**跳过所有以 `.` 开头的目录**）＋ 具名排除（4 条：
`node_modules`/`target`/`graphify-out`/`dist`）。**每条具名排除 MUST 被 `.gitignore` 忽略。**

**理由**：「这条排除为什么无害」必须有个**可执行的**答案。`.gitignore` 恰好就是那个答案——
一个目录被声明为「不是仓库的一部分」，把它排除掉就不可能藏起仓库内容。这让排除从「豁免」
变成「有证据的陈述」，且证据本身是活文档（改 `.gitignore` 会立刻反映到判据上）。

**否证过的备选**：

- *枚举 `SKIP_DIRS` 字符串*（W73 的做法）：那是**第二张会过期的清单**；W73 里 `build`/`.venv`
  两条既不在 `.gitignore` 也不在磁盘上，纯属抄来的。
- *`git ls-files`*：**这条路不可行**——实测本机 node 对 `git`（裸名与绝对路径）、`process.execPath`、
  `cmd.exe`、`sh` **一律 EBUSY**。这是**宿主**约束（不是「node 自旋 node」那么窄），
  **据此订正既有记忆里的归因**。
- *把 `CODE_EXTENSIONS` 收窄到几个「可信」目录*：会变成第三张会过期的清单，且「可信」无法判定。

**无害性断言**（非空洞的形式）：**跳 dot 段与不跳 dot 段的消费集合 MUST 相同**。
实测两侧唯一差异是 `.github/workflows/foundation.yml`，它的**非注释行不含任何 schema 路径**
⇒ 两侧集合相同。若有人把 schema 路径写进某个 dot 目录里的非注释代码行，这条断言立刻红，
逼人决定「是不是该把那个目录移出排除」——**这正是我们想要的反应**。

## 2. 决策：语言闭包（可扫描扩展名由语言表派生）

**取**：`CODE_LANGUAGES`（ext → `'slash'` | `'hash'`），`CODE_EXTENSIONS = [...CODE_LANGUAGES.keys()]`。

**理由**：F3 的形状是「扩展名清单与语言判断分居两处、各自漏了一点，于是互相掩盖」。
让**前者从后者派生**，这类缺陷在结构上就不可能出现——想扫新扩展名，就必须顺手声明它的注释语言。

**为什么 `.yaml` 必须进来**：`.yml` 与 `.yaml` 是**同一种语言**。判据既然按扩展名判断注释语法，
那么「不扫描的格式」与「误判注释语法的格式」就是同一类缺陷。实测把 `.yaml` 纳入扫描集后
消费集合**不变**（`tests/registry.yaml` 里那两处提及不带引号，不够格当「路径字面量」；
而字面量来源本轮已被移除），所以这是**零行为变化的正确性修正**。

**非空洞断言**：扫描集 MUST 收录 `tests/registry.yaml`（具名）。若有人把 `.yaml` 从语言表里删掉，
这条立刻红——这就是语言闭包的守卫。

## 3. 决策：移除路径字面量来源，其余两条各自自负其责

**取**：来源 = ① Ajv 校验器清单 ② Rust `include_str!`。判据是**独有覆盖**：

| 来源 | 独有找出的 schema | 实测 |
| --- | --- | --- |
| Ajv 清单 | `config/binding-plan`、`catalog/catalog`、`plugin/ui`、`platform-matrix/platforms`、`tests/registry` | 5 份 |
| Rust `include_str!` | `config/upgrade-package` | 1 份 |

**理由（移除字面量）**：它零独有覆盖（它找到的每一份都被 Ajv 清单覆盖），且是唯一会读**任意
扩展名文件**的来源 ⇒ 它是 F2 的全部入口。按「假阳性与假阴性不对称，永远选安全方向」，
保留它换来的是**假阴性**（未跟踪文件洗绿），移除它换来的是**假阳性**（将来若有 schema 只被
脚本加载，会被报成孤儿，加进 Ajv 清单即可）⇒ 后者安全。

**否证过的备选**：*保留它、但要求它有独有覆盖*——当前无法满足，只能靠造一个假案例满足，
那是自欺。*保留它但只作「发现工具」不参与 pass/fail*——同一份扫描仍在读任意文件，
入口没关，只是把结论藏起来。

**为什么把「各自都被行使」换成「独有覆盖」**：前者可被**单一来源**满足（F1 实测），
后者不能——一条来源只要没有别人找不到的东西，就什么也没证明。

## 4. 决策：生成器与校验器读同一份清单

**取**：`validation.mjs` 导出 `TS_GENERATED_SOURCES`（10 条）；`generate.mjs` 导入它，
删除自己的 `jsonSources`。断言三件：**生成面 ⊆ 校验面**、**basename 互异**、
**生成目录的 `.ts` 与清单双向相等**。

**理由**：两份清单不可能「都不出错」，只能「互相牵制」。`TS ⊆ AJV` 是**交叉**断言（这正是
F4 缺的那一条）；生成物已入库 ⇒「双向相等」把生成器**实际做了什么**与清单钉在一起，
而不是核对一份自我声明的数组。

**防回退**：断言 `generate.mjs` 的源码 MUST 引用 `TS_GENERATED_SOURCES`——若有人改回硬编码，
就必须先删掉这个引用，断言会红。

## 5. 残余风险（本轮不消除，如实登记）

1. **未跟踪文件若落进**「非 dot、非具名排除」的目录（如 `scripts/`），仍可能凭空造出消费者。
   缓解：**CI 从干净 checkout 跑**（`actions/checkout`）⇒ **CI 上「工作区 == 仓库」成立，
   该风险不存在**；它只存在于本机有人手工放置文件时。彻底消除需要「仓库文件集」这个输入，
   而取它需要派生 `git` 子进程（宿主禁止）。
2. **语义类漂移仍只能靠人读**：本轮修的全是「可机读的那一半」（集合、名字、来源）。
   `§56.2` 四情形那种判断不在判据内。
3. **`` `.github` `` 被结构性排除**：代价是「工作流里的 schema 引用」不再算消费证据。
   实测损失为零（不含路径），但这是一次**有意的**取舍，不是遗漏。
