# Design

原生库只在 keeper 的 Windows 目标编译，内核无平台依赖。固定锁定 cpal 0.16.0/minifb 0.28.0，分别提供安全的 WASAPI 输出和像素窗口 API，工程自身继续 forbid unsafe。主线程更新窗口，音频回调只处理预分配 PCM 和原子诊断；不等待主线程。第三方内部线程属于 keeper，不增加服务。额外维护成本为两个原生库与传递依赖，适用 Local Windows 演练；无需 Node/Python。

演练只合成固定 440Hz、幅度 0.025 的测试音，使用显式 Rehearsal 守门/审批演练对象，不读取生产审批。一次最多600ms，首个设备入口选择48kHz单/双声道f32；不支持即具名拒绝。原生设备流创建完成后才生成授权音频，通过容量1的内部媒体通道交给回调，未取得音频时清零。音频设备预测排队时间与 callback 时间差加入门控时间，未知/超100ms静音。原生缓冲超过100ms拒绝，其余按采样位置拆成≤10ms门控分片；提交整个缓冲前再次复检撤权，清除先前分片前缀。窗口显示原创测试图案，播放时彩色，静音后黑色。正常输出观察约1.5秒，主线程 stall 场景暂停900ms，音频回调仍须独立静音；暂停期间画面可能冻结，不宣称其独立待机。关闭窗口/Esc走 P0。原生API可能阻塞，父进程10秒期限是进程级兜底，不假设同线程取消可终止SDK。

CPAL playback timestamp 是预计交付时间，不是实际 DAC 完成，报告明确 actual_local_playback_completed=false。真实回调有样本、静音后为零、窗口提交成功只是工程设备证据。没有声学回环、目标直播工具、生产IPC或批准候选接线；不升级registry。报告先失效旧文件，成功/失败都写结构化事实，单进程外部测试有10秒期限兜底原生API卡住。
