## 1. 本轮判定的到底是什么

§53 的表格有四行，**四行的主语各不相同**，必须分开落，否则「这次拒绝属于哪一类」重新不可判定：

| §53 行 | 判的对象 | 可判定形式 |
| --- | --- | --- |
| 段落编排 | **一整个编排序列** | 四段是否齐备且顺序正确 |
| 插问后归位 | **一个检查点 + 一次恢复** | 检查点内容是否越界、恢复位置是否落在检查点段落 |
| 重复冷却与段落切换 | **一串进入时刻** | 同段冷却与相邻切换间隔是否满足 |
| 事实约束的行动提示 | **一条行动提示里的若干断言** | 受约束断言是否绑定当前有效事实版本 |

§53 原文明说这四项是「**确定性脚本与规则**，不依赖工具规划，因此不引入 §51.3 的任何能力包」。
这句话正是本模块能成立的理由：**确定性的东西可以被机器判定**，而 INV-33 也因此不被触碰
（本模块不消费任何能力包，判据全部是本地数据）。

## 2. 为什么是 `evaluate::selling`，而不是并入 `evaluate::show`

`show.rs`（195 行）已经在判 §5.7：但它的输入是契约 `ShowPlan` + `ShowRequest`，判的是
**单个 ShowPlan 自身是否合法**——场景 id 与请求一致、版本一致、段落 id 非空、时长在范围内、
三类引用不超上限、打断策略在已知三值内、检查点存在且与请求一致、敏感场景必须有证据绑定。

本模块判的是**跨段落的编排规则**：段落顺序、归位语义、冷却、事实绑定。两者的输入形状与
失败类别都不同。这是 W66 不复用 `bridge::Degradation`、W67 不复用 `session::change_mode`
的**同一条理由**——把两个维度合进一个函数，等于让「这次失败是哪一类」重新不可判。

也**不**并入 `scheduling-and-budgets` 的判定面：那里的「冷却」是**观众/任务维度**的
（单观众占比上限、欠服务阈值，防止被刷屏者垄断），本模块的冷却是**段落维度**的
（同一讲解段落重复进入的间隔）。两者用同一个词、指不同的东西，合并会制造歧义。

## 3. 四段与顺序：一个必须逐项写死的常量

§53 原文：段落编排 = 「**卖点 / 规格 / 适用场景 / 售后说明**的固定段落与顺序」。

可判定形式是 `SEGMENT_ORDER: [SegmentKind; 4]`，**逐项照抄**，并配一条
`segment_order_matches_the_baseline_line` 把它写死（W66 的教训：只校验「四条、label 互异」
的守卫，对「内容被改小」是瞎的——实测悄悄删一项，全部测试照样绿）。

判定的**顺序**本身也是设计的一部分（W66/W67 的教训：先命中的断言会短路，用多组注入分别验证）：

1. 先逐项判**类型是否已知** ⇒ `UnknownSegment`（未定义的段落名没有被表示的机会）；
2. 再判**齐备性** ⇒ `SegmentMissing`（缺哪一段要**指名**，不是只报数量）；
3. 最后判**顺序** ⇒ `SegmentOutOfOrder`（同时乱序又缺段时，两类别都必须报出）。

「顺序断言不能少」：§53 写的是「固定段落**与顺序**」，一个只判集合不判顺序的实现
（排序后比较）能让 `[规格, 卖点, 场景, 售后]` 通过——这正是要防的坏实现。

## 4. 检查点：把「不保存未播出的生成文本」变成可构造的拒绝

§5.7 原文：「检查点保存段落与已完成句，**不保存未播出的生成文本**；恢复前重新校验产品、价格、
活动、素材与授权，重启默认待机。」

前半句可判定：检查点结构**只**允许两类内容——所指段落、已完成句 id。

```
pub struct Checkpoint {
    pub segment: SegmentKind,           // 恢复位置
    pub completed_sentence_ids: Vec<String>,
    pub carried_text: Option<String>,   // 未播出的生成文本；MUST 为 None
}
```

`carried_text` 是必要的**建模选择**：如果结构里没有这个字段，「检查点带了未播出文本」这件事
在类型上根本表达不出来，测试也就无从构造 ⇒ 守卫会变成恒真。有了它，
「一个把生成文本顺手存进检查点的实现」才会被 `checkpoint_holds_unspoken_text` 具名拒绝。

**恢复位置**：请求里的 `resume` 段落必须等于 `checkpoint.segment`，否则 `resume_diverges_from_checkpoint`
（「回答插入后**回到讲解位置**」的可判定形式——归位不是「随便落在一个段落」）。

**不能覆盖的一半，如实标注**：「恢复前重新校验产品、价格、活动、素材与授权」中的**校验动作**
由 §5.4 守门与知识层执行，本模块只判「检查点的内容边界」与「落点一致」。
本轮报告 MUST NOT 称「讲品循环已可恢复」。

## 5. 冷却与切换：判据是「按给定阈值成立与否」，不是阈值本身

§53 原文：「段落级冷却与最小间隔」。§5.3 给的是播报容量的**初值**（20–40 字、3 字/秒、
待播 ≤20 秒…），并明确这些是「场景策略初值，不是固定标准」。§48.7 也把三项阈值列为
**待本场景回放实测**、MUST NOT 采外部观察值。

所以本模块的处置是：

- 阈值来自 `PitchPolicy`（调用方给），模块**不内建**一套「看起来合理」的数字；
- 模块判的是两条**不同**的规则，不合并：
  - `cooldown_not_elapsed`：**同一段落**两次进入的间隔 < 冷却；
  - `switch_too_soon`：**任意相邻两次**进入的间隔 < 最小切换间隔。
- 序列必须**非降序**（`entrance_times_decrease`）：冷却与切换两条规则都是关于**间隔**的陈述，
  而间隔在递减序列上没有定义。故先判前置条件、再判规则，且前置条件失败本身**具名**——
  不会被读成「通过」。这也顺带堵死一类实现缺陷：直接相减在递减序列上会下溢。
  （R06 的 `SoakSamples::record` 以「拒绝乱序」防止趋势被重排制造，同源的防守思路。）

## 6. 事实约束的行动提示：受约束断言的封闭集

§53 原文：「只基于**有效事实版本**；禁虚构优惠与承诺」，并指向 §5.4（守门）与 §45.2 的禁用域。

§45.3 的禁用域原文给了**封闭的五类**：「价格、库存、优惠与活动条件、承诺与售后政策、
以及任何个体化承诺」，并说明它与 §5.3「涉及价格、库存、优惠、承诺的回答不参与合并复用」一致。
这五类是常量 `CLAIM_KINDS`，逐项对照而非「一个看起来像的集合」。

判定两条，分开报：

- **无绑定** ⇒ `action_cue_without_fact_binding`：受约束断言没有事实引用。这与 §45.2
  「**语义相似度不构成证据**：价格、规格等只信 KB0」同源——嘴上有数字不等于有依据。
- **引用过期** ⇒ `action_cue_fact_stale`：有引用，但引用不是**当前有效版本**。
  §5.4 的 evidence 阶段要求「来源、版本、有效期」，§45.4 也规定「事实…任一 revision 变化 ⇒
  相关作用域条目**立即失效**」。判据：`fact_ref.revision` 必须等于 policy 里的当前版本。

这两条**必须分开**：一个只有「检查 fact_ref 非空」的实现会让「引用了三天前的价格」通过。
非空洞守卫的两个样本分别落在这两条判据上（W67 的教训：**样本必须先落在判据上**）。

## 7. 具名拒绝与 `ALL`

`PitchRejection` 是一条扁平枚举 + `ALL` 常量 + `label()`（house style，见
`MemoryRejection` / `RampRejection`）。测试断言「构造出的拒绝集合**恰为** `ALL`」——
既证每条可构造，也防未登记的名字。

| 拒绝 | 触发 |
| --- | --- |
| `UnknownSegment` | 出现未定义的段落类型 |
| `SegmentMissing` | 四段不齐（指名缺了哪些） |
| `SegmentOutOfOrder` | 段落齐备但顺序错 |
| `CheckpointHoldsUnspokenText` | 检查点带了未播出的生成文本 |
| `ResumeDivergesFromCheckpoint` | 恢复位置不是检查点所指段落 |
| `EntranceTimesDecrease` | 进入时刻序列非降序 |
| `CooldownNotElapsed` | 同段重复进入早于冷却 |
| `SwitchTooSoon` | 相邻切换早于最小间隔 |
| `ActionCueWithoutFactBinding` | 受约束断言无事实绑定 |
| `ActionCueFactStale` | 受约束断言引用了非当前版本 |

## 8. 新增能力而不是扩展既有能力

`openspec/specs/` 下没有以讲品为对象的能力。既有最接近的三个都不是它的家：

- `media-basics-timeline`：判时间线与播放 ACK 的时序；
- `scheduling-and-budgets`：判观众/任务维度的公平与预算；
- `agent-guard-evaluation`：判守门四阶段。

§53 是新版**前移**进 R1 的一块，它的四条规则是一个整体的、可独立验收的性质，
故新建能力 `basic-selling-loop`。这也让 registry 的 **B07** 与规格**同名**，
「条目 ↔ 能力规格」的对应关系保持一一。

## 9. 登记 B07，以及一个必须如实写下的偏差

`tests/registry.yaml` 新增 **B07「基础讲品循环」**（`r1`、`status: pending`）。
B 系列的语义是「业务质量」（B01 知识质量门槛、B05 真人接管音轨与回声、B06 场次复盘报告…），
「能不能持续讲清一件商品」正在这一列上——§53 自己说「后者才是付费理由」。

**偏差（如实登记，不掩盖）**：V3.9 §48.5 的家族索引写「B | B01–B06」，§57.4 的计数行写
「slice_0 10 + r1 36 + … = **87**（本版只改归属，不加条目）」。新增 B07 之后这两处陈述
**不再等于实际值**。本轮的处置：

- **不改基线文本**——改基线是升基线轮次的事，且 MUST 是 1:1 行替换（§56.2）；本轮的改动
  是**新增条目**，不是订正既有句子；
- 在**报告**与**活文档**（`docs/development-plan.md`、`AGENTS.md`）里写明「B07 为 W68 就地新增，
  基线 §48.5/§57.4 的家族范围与计数陈述留待下一轮升基线一并收录」；
- 这与 W54 新增 A12、W55 新增 A13 的处置一致（A12–A14 是在 V3.9 升基线时才被 §48.5 收录的）。

## 10. 边界：本轮**不**声称什么

| 不声称 | 理由 |
| --- | --- |
| 讲品循环已可运行 | 段落内容、话术、TTS 时长、回放采样都是内容创作与运行时的事 |
| 阈值已验证 | §48.7：三项阈值待本场景回放实测，MUST NOT 采外部观察值 |
| 检查点恢复已端到端可用 | 恢复前的产品/价格/活动/素材/授权重校验由 §5.4 与知识层执行 |
| B07 已达标 | 交付的是**判定面**；`status` 保持 `pending`，`notes` 说明理由（同 W57/W66/W67 惯例） |
| 基线已同步 | 见 §9 的偏差登记 |
