## 背景

S11 的验收名是「IPC 模糊与路径穿越」，`automation: unit`，状态 `tested`，notes 却写着「模糊测试待建」。
仓库内 `grep -ri fuzz` 零命中。本轮补上这半个验收，并把口径写进规格。

为什么值得单独立一轮：**定向测试证明「已想到的形状」被正确处理**，而 IPC 解码面吃的是**攻击者完全自由的字节**。
这两件事的证明力不同，不能相互替代。定向测试再多，也不蕴含「任意输入不 panic、不越界分配、错误具名」。

## 发现

### F1 面上有三个攻击者可控的解码入口，其中两个此前**没有任何**测试

- `frame::read`（`frame.rs:41`）：6 项定向单测，覆盖超长长度、截断、合并帧、partial read、期限/取消。
  这些用例的形状是**人想出来的**；`length` 字段的取值空间是 `0..2^32`，手写用例只碰了几个点。
- `Envelope::decode` / `CapabilityInvocation::decode` / `CancelRequest::decode`（`host.rs:154,181,195`）：**零测试**。
  它们的输入是帧 body，即对端完全可控的字节；prost 对未知字段宽容，但不等于「任意字节都安全」。
- `handshake::accept`（`handshake.rs:33`）：2 项定向单测（身份拒绝、版本无交集），**没有**畸形 body 的用例。

### F2 路径面只有 1 项手写用例

`boundary.rs:119` 手写了三类形状（词法穿越、绝对逃逸、符号链接）。`verify_within_root` 的输入是**插件的路径声明**，
同样是对端可控的字符串。手写三个用例说明不了「任意字符串都出不去」。

### F3 顺序是有意的，但**没有被测试钉住**

`frame::read` 的 `read_exact` 在**每次读之前**检查 `cancelled` 与 `deadline`（`frame.rs:88-96`），
`parse_manifest` 也是先查取消/期限再看内容（`lib.rs:45-53`）。这个顺序是安全性质——**撤权/过期优先于内容解释**——
但现有测试只各钉了一个方向（`deadline_and_cancellation_abort_read` 用一个特定输入），没有钉「**任意**输入下都不例外」。

## 决策

### D1 确定性种子 PRNG，零新增依赖

自带 splitmix64（几行），种子**固定**并写在测试里。理由：
- `cargo-fuzz`/`libFuzzer` 需要 nightly 工具链、新增依赖与独立语料目录，本项目 portable 门控跑在钉住的 stable 上；
- 固定种子 ⇒ **可复现**：失败时同一个种子一定复现，符合本仓库「证据可复算」的一贯要求；
- 代价是**没有覆盖率引导**，探索能力显著弱于真 fuzzer —— 这一点在报告与 registry 中**如实写明**，不掩饰（见 D6）。

### D2 断言的是**全域性与有界性**，不是「找到了漏洞」

随机测试**不能**证明「没有漏洞」。它能证明的是三条**可判定**的性质：
1. **全域性**：任意字节 ⇒ `Ok(Some)` / `Ok(None)` / `Err(具名 code)`，**不存在** panic、**不存在**第四种结局；
2. **有界性**：长度前缀超过 `MAX_FRAME_BYTES` 时**在分配前**拒绝（`ResourceExhausted`），即分配量不由输入无界决定；
3. **顺序不变式**：取消/期限到期时，任意输入都返回 `Cancelled`/`DeadlineExceeded`。

措辞上**不**把它叫「覆盖率导向模糊测试」——它是随机输入测试。名字骗人就是证据骗人。

### D3 非空洞性守卫（本设计的关键）

harness 最容易死法：生成器只产**合法**输入 ⇒ 全绿，但什么也没证明。故：
- 语料生成器**结构化**构造危险形状（而不是纯随机 `rand_bytes`）：随机长度前缀（含 `2^32-1`）、截断 body、
  合法帧 + 随机 body、**合法 `Envelope` 前缀 + 随机 `message_type`/payload**（这样才真的走到 invocation/cancel 解码）、
  以及由 `{正常段, "..", ".", 绝对路径, 空段, 长段, unicode}` 组合出的路径串；
- 每类断言维护**计数器**，测试末尾断言计数 **≥ 阈值**：例如 raw 语料必须至少命中 `ResourceExhausted`、`InvalidArgument`（截断）、
  `Ok(Some)`、`Ok(None)` 各一次；envelope 语料必须至少命中 `VersionIncompatible`、`InvalidArgument`（未知消息类型）、
  以及**至少一次进入 `CapabilityInvocation` 解码分支**；路径语料必须至少命中 `PermissionDenied` 与 `Ok` 各一次。
- 计数不足 ⇒ **测试失败**。这把「语料有效性」也变成了一条被断言的性质，与既有「构造描述的审计并集**恰为** N 条标记」同形。

### D4 四个入口各自独立断言，不合并成一个「跑通了」

合起来跑会让读者无法判断哪个面被覆盖。四个 test 函数：raw 帧流、结构化 envelope 流、路径串、顺序不变式。

### D5 复用既有装配，不发明测试替身语义

`serve` 的驱动用 `Cursor<Vec<u8>>` 作读端、`Vec<u8>` 作写端（`serve` 对 `R: Read, W: Write` 泛型），
身份校验用与 `tests/e2e.rs` 同形的固定 `IdentityValidator`，注册一个 `EchoPlugin`。
**不引入** mock 传输、不假装对端身份——被 fuzz 的是**解码与分发**，不是传输。

### D6 实现预期零改动；若发现真实缺陷则修并记录

本轮先写 harness 再跑。若 harness 发现真实缺陷：**修实现**，在报告里如实记录缺陷与其修复，**不**为了让测试变绿而放宽断言。
若未发现缺陷：**明确写出「未发现」而不是「已验证安全」**——随机测试的阴性结果不是安全证明。

## 后果

- S11 的 `tested` 这次有据可依（补齐 notes 中自我承认的缺口）。
- 代价：没有覆盖率引导，探索强度弱于 libFuzzer；未来若引入 nightly 工具链可另立变更升级，本轮不做。
- 依赖方向不变（hosts → sdk → contracts），18 包不变，零新增依赖。
