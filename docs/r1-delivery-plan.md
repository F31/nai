## 审视结论与目标

当前交付是能配置 API、提交知识约束问题、审批候选和试播短句的工程控制台；尚不是能准备商品、持续讲解并接入直播的完整数字人产品。下一交付单位改为：**不用改 JSON 或命令行，准备一个商品，数字人连续讲解，插入一个问题，经人工审批回答后恢复讲解，并由直播软件录制到音画。**

依据 V3.11 §51.2、§53，基础讲品循环就是 R1 内容，不等真实平台 SDK、写实人像或能力包。知识发布、常驻输出、真人接管和可理解的运行状态均是产品主线。工程安全约束继续执行，不用反复增加提示代替业务功能。

## 与直播软件的结合方式

音画路径：商品事实/节目 → 守门与审批 → LLM/TTS API → 2D 渲染 → 常驻 output-keeper 窗口及独立音频 → OBS/直播伴侣采集 → 本地录制 → 满足目标平台要求后人工开播。

互动路径：官方 SDK/桥接宿主 → 身份、房间、权限和代次校验 → 有界事件队列 → 检索/候选/审批 → 同一输出链路。早期手工问题应明确标为“人工录入”，演练回放不冒充真实评论。首版无需自己开发推流器或虚拟摄像头驱动。

按 §52 分三轨取得证据：①官方输出入口与音画采集；②官方事件接口 PoC；③账号、类目、用途及自动互动准入。三者互不替代；未获准自动互动时只做允许的人工辅助/录制，并另行验证这种形态是否符合用户需求。P01 正式平台生命周期属 R2，但准入核对和 PoC 应尽早进行，不能等 R1 完成才发现路线不成立。

OBS 支持窗口采集及应用音频采集，但本项目窗口、系统、设备和目标版本的兼容性尚须实测。外部参考：[窗口采集](https://obsproject.com/kb/window-capture-sources)、[应用音频采集](https://obsproject.com/kb/application-audio-capture-guide)。默认避免同时采集同一设备的桌面与应用音频造成重复声音；实际路由以录制证据为准。

依 §10.1 收敛为“直播台 / 知识 / 形象与 Provider / 运行记录”；右上设置容纳低频连接、路由、升级等。直播台呈现真正的画面、当前讲解、插问、候选与播放队列，显著保留暂停讲解、立即静音、人工接管。形象页提供合法2D包/背景/声线预览与选择；写实推理 B02 属 R2，本轮不以其阻塞 2D 闭环。

## 检查纪律与发布边界

- 常规改动只跑变更模块及直接依赖：知识迁移/发布测存储事务与事实失效；keeper测队列/取消/租约和 Windows 设备；ShowPlan测检查点、插问、重启和预算；UI测实际客户端交互。
- 改契约时运行生成无漂移与相关跨语言互通；改共享状态机扩大到实际消费者；里程碑集成做一次上述完整用户路径。仅发布组合/跨层大改触发完整门槛，不每次全仓复跑。
- O01 的10分钟首句要求已有可用付费凭据及计费理解，不含平台审批时间；本地录制、人工直播、真实自动互动分别验收。
- R06 长播认证、B02 写实、P01 正式平台属 R2；R1 常驻输出仍必须做与实际使用时长相符的稳定性验证。O03 手机包仍属 R1，不能悄悄删除。能力包、市场、多步工具、多会话等不挤占默认闭环。
- 本轮不修改 registry 的 implemented/tested/blocked/pending 状态。特别是 B07/B05/B06 的 implemented 不能解读为整机 UI 已交付；S12 当前 NotApplicable 的适用前提，进入真实直播前须重新核对。

1. **连续讲品与插问归位（B07/S02/S05/R07）**：把已有PitchRunner接入engine生产者及节目UI，启动时支持无Provider调用的合法中性输出预热。单商品有限轮次/成本预算，逐句守门审批和播放；插问保存段落与可确认的已播句，回答后重新检查商品/价格/活动/素材/授权五面，未知必须暂停。提交观测不得冒充硬件完成检查点。撤权/知识热发布/断线禁止自动恢复旧候选，队列有界；定向验证正常归位、过期事实、插问中接管、预算耗尽及不重复计费。
2. **真人麦克风接管（B05/S01/R03）**：复用mixing核心，接真实单路cpal输入、设备选择/拔插、独立人声音轨；接管优先清TTS，真人停说不自行恢复自动。完成真实回声检查才能放行需回声证据的路径；只模拟按钮不算交付。测试断设备、双采集拒绝、P0不等模型锁及显式恢复。
3. **OBS本地录制（A01/B05/B07/O01）**：前两卡接通后，使用已授权素材与明确本地测试音频，录制“讲品→插问→回答→归位→真人接管→显式恢复→静音/失联”。保留录制文件、音轨与帧/时钟观测，核对窗口不重建、人声/TTS不串音、撤权后无旧语音。未拿到录像证据保持未验收，不自动推流。

每卡先OpenSpec，运行改动和直接依赖范围检查；合并发布组合才运行完整发布门槛。以上未实施任务保持未开始，不写成外部Blocked。
