# V5.2 技术路线审视与后续实施规划

日期：2026-10-29。范围：现有仓库、V5.2 及已有报告；本文件为实施建议，不自动切换设计基线、修改验收注册表或授予功能认证。

## 结论

主线聚焦用户现有 Windows、RTX 5090 Laptop、一个直播软件、API LLM、现有本地 Qwen-TTS、单人物真实画面和真人接管。路线 A（授权真人动作视频＋音频驱动口型）优先验证；单照片只作为肖像输入，不承诺自然手势和全身动作。轻量二维保留现有功能，不再作为写实主线前置。真实视频素材、模型完整闭包及可发布运行时均尚未具备；真实效果和 30 分钟写实体验尚未验证。

## 技术路线与决策

1. **单机写实主路线**：先用少量明确许可的真人动作视频验证自然度、姿态衔接和口型；以 `jjf.jpg` 做单图参考仅证明肖像能力。需要一个有可见嘴部的授权短视频才能完成动作底版验证。模型首选 MuseTalk 1.5，但只有实测与依赖许可闭包通过才确定；不得把图像处理或预录片段宣称任意动作生成。
2. **参考与生产分离**：研究环境可使用 Python/PyTorch；正式 Avatar 默认 NativeOnnx，逐段比对参考画面和耗时。NativeInterop 只有在明确依赖与 ADR 后作为另一已命名方案，不能悄悄引入 Python。现有 Qwen 是外部本地服务，允许保留其真实运行时，不自动重启或复制模型。
3. **以可靠性为基线**：首版可采用有界 CPU 帧传输并实测，再决定 D3D11 同适配器共享纹理；P0、音频门及撤权与渲染器隔离。绘制、许可、样本时钟、OBS 观测和实际直播权限分开记录。
4. **保留 React，不迁移 Vue**：用户已确认继续使用 React。V5.2 §42.2 的 Vue 表述应在基线采纳时通过 ADR 修正；当前代码和测试继续以 React 为准。V5.2 前文保留的二维优先描述与用户直接推进真人效果的指令冲突，以用户优先级和 §42 当前主组合为准。
5. **数值先消歧**：V5.2 的 600ms/200ms 是设计初值，既有真人麦克风 500ms 等有独立作用域与实测；不能直接改所有现有租约。按计时器用途梳理代码和证据后通过 ADR 与配置源冻结。资源余量、720p/25fps、P95 目标均是待验证目标，不是已经达到。
6. **统一来源而不覆盖历史**：V5.2 所称 primary、runtime defaults、文档生成器和 C52/CGPU 注册项当前未见落地。先建立带迁移映射和冲突检查的方案；保留 V4.8 注册表和所有证据，未完成迁移前它仍是实际验收正本。V5.2 的采纳需 ADR、指针和相关 OpenSpec 一致，不能仅修改文档标题。

## 源码复核补充

- `openspec/config.yaml` 和 `tests/registry.yaml` 当前均仍指向 V4.8，桌面上下文为 React；V5.2 为新设计输入，尚非实际执行注册表。采纳时必须追加映射，不重写或假定旧验收结果。
- `adapters/llm-openai/src/tts.rs` 中本地 Qwen 请求绕过代理、请求 WAV，响应分块读取后汇集为完整结果；网络读取分块不证明服务支持可播放流式输出。取消当前请求与服务端真正停止推理需要分别验证。
- `crates/nai-workbench-host/src/public_output.rs` 存在 500ms 租约，V5.2 的输出租约 600ms/200ms 是另一设计初值；首先核实各租约类型、刷新/截止和相关故障证据，不能简单全局替换。
- `apps/workbench-desktop/ui/tts.ts` 有 Qwen3-TTS 1.7B 和九种音色的预设；这不是用户实际服务型号、版本与能力的可信探测，应通过服务或用户确认补充事实来源。

## 暂不占用主线

3D/生成手势、其他平台自动商品权益、跨卡/WSL 正式媒体传输、多用户多场、最低硬件适配、MCP 市场作为独立能力保留；按用户需求和实际授权进入后续发布闭包。ASR 与公屏连接属于明确需求，但须在首个稳定写实链路之外分别完成官方渠道/输入权限和真实认证，不能用虚拟摄像头证明已接入。

## 测试与交付策略

每次对受影响的组件、契约、IPC/迁移和故障运行定向测试；不对普通修改重复全量。发布组合才执行适用全门槛；真实模型/设备/OBS/用户体验与 fixture 分开。每次记录 run_id、版本、资产和许可摘要、设备、输入输出、取消与失败、资源轨迹及人工结论。构建与缓存留在 E 盘；不覆盖用户数据库、Key、合法素材或已授权服务。完整结果以新增注册表迁移及具名复核为准。
