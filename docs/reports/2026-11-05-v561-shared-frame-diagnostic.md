# FlashHead 有界共享帧交付诊断

为 M0 准备，`scripts/flashhead-bounded-diagnostic.py` 新增可选共享内存诊断；`scripts/flashhead_shm_diagnostic.py` 使用 Python 标准库 spawn 一个仅核验的独立消费者。帧载荷在固定数量共享槽中，以 BGRA8 写入；控制队列有界，仅传槽位、代次、epoch、序号、计划源样本位置、计划时间戳及哈希；发送侧收到对应确认后才复用槽，消费者核对顺序和 SHA-256。消费端退出或确认超时会失败退出并清理。Windows 共享映射长度按系统粒度取整，逻辑槽范围仍严格校验。

本地 Windows 真实模型诊断：使用已授权肖像、既有 Qwen 语音，3 个共享槽、每槽 1048576 字节；5 个模型块共 120 帧，消费者确认 120 帧，进程退出 0。按块统计从 GPU 转 uint8、复制及发送的平均耗时约 0.058 秒，最大 0.0713 秒；确认可能在下一块或结束时等待，不能把这一数字当完整端到端交付延迟。ready 至全部确认约 7.38 秒、音频计划跨度 4.8 秒；短样本和回退后端下没有实时保证。原始记录 `target-windows/flashhead-acceptance/shm-real-20261105.jsonl`。

Windows 子进程定向测试 5 项通过：跨槽复用与真实子进程确认、消费者退出、活跃但不响应的确认超时、RGB 转 BGRA 字节、异常尺寸拒绝。真实模型仅做数据交付，不播放、不连接 OBS、不推流。

诊断控制消息只在 Python 诊断进程之间使用，不是生成的 Protobuf 或 Rust 生产 IPC，不构成共享句柄 ACL/对端认证证据。源样本位置是计划值，不是设备已播放时钟；没有输出窗口、安全帧、P0 停止、实际音画同步或长稳验证。旧 `FrameSlot` 协议未接入新架构。M0 和相关生产验收继续 pending。
