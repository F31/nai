## 二、扩域量出的第二件事：判据自己有个缺陷

我原本只打算「扩域 + 修 3 处」。扩完之后判据报回来的第一版是 **7 条**，多出来的 4 条长这样：

```
openspec/specs/engineering-foundation/spec.md:858: the link target "adr/0016-…md" …
openspec/specs/engineering-foundation/spec.md:865: the link target "0051-*.md" is a glob …
```

看原文才发现，这两行是**规格在举例子**：

```
- **WHEN** `docs/reports/<某报告>.md` 里写着 `[ADR 0016](adr/0016-…md)`，而报告住在 …
- **WHEN** 某条链接写成 `[ADR 0051](0051-*.md)`
```

链接形状整个包在反引号里——它是**被引用的文本**，不是这份文件承诺要走到的位置。判它，等于
要求作者不能举例。而 `docs/` 里这种形状是 **0** 条，所以 W151 那一轮看不见它：**域就是结论的边界**。

全仓实测：链接形状活在代码段里的共 **4** 条（`openspec/` 两份规格各 2 条，归档 delta 与主规格
同一段文字），`docs/` / 根目录 / 其他域都是 0。

⇒ 本轮从「扩域」变成「扩域 + 修一条判据缺陷」，两件事在同一个提交里，因为**只有扩域能让这条缺陷显形**。

## 四、处置：3 处全部走第一类（就地订正 URL）

目标是**可复原**的（文件都在 `docs/adr/`，只是层级错），按 ADR 0125 的二分走「就地订正 URL」，
**差分只含 URL 字符串，正文一字未动**。这也是 `A dead pointer is either corrected in place or
demoted, never guessed` 那条 Requirement 的第一次实际适用：没有一处需要降级，也没有一处需要猜编号。

## 五、判据改造与零样本

| 改动 | 内容 |
| --- | --- |
| `maskCode` | 围栏块 + 行内代码遮蔽；**只把字符换成空格、保留换行** ⇒ 行号不变 |
| `documentPathsOf` | 文档域的唯一定义；调用方 MUST 用它构造文档集 |
| 域 | `docs/` → 全仓已跟踪 `*.md`（`DOCS_ROOT` 删除） |
| 守卫 | 三条空集守卫的措辞随域改写（「in this repository」） |

遮蔽为什么不写成「跳过含反引号的行」：**链接与反引号可以同处一行**，按行跳过会因为一个反引号
丢掉同一行里的真指针。所以是遮蔽而不是跳过，且用判别性样本钉住（见下）。

**用例**：9 → **11**（新增 2 条）。原有八条合成样本全保留。

| 注入 | 改法 | 结果 |
| --- | --- | --- |
| I1 | 关掉代码段豁免 | 红 **2** 条：`#1`（真实语料 4 条）+ `#5` |
| I2 | 域缩回 `docs/` | 红 **1** 条：`#1`，且红在「域必须越过 docs/」这条断言上 |
| I3 | 只遮蔽围栏、放过行内 | 红 **3** 条：`#1` `#5` `#6` |
| I4 | 只遮蔽行内、放过围栏 | 红 **2** 条：`#5` `#6`，**不**红 `#1` |

每次注入后 `cp` 还原并用 `sha256sum -c` 核对基线字节（`ba59fae0…8b84` / `2f4cc5a6…b5e1`），
四次都 OK。

**I4 是本轮最诚实的一条结果**：围栏豁免在真实语料里**没有样本**，它只被合成样本支撑。
这与「注入不变红 ≠ 判据退化」是两回事——这里是「红在合成样本、不红在真实语料」，
如实登记进 ADR 0126 的残余第 1 条，MUST NOT 记作「已被真实语料验证」。

**另一处零样本**：I2 之所以能抓住缩域，靠的是 `#1` 里那句
「域必须越过 docs/」的域断言，而不靠错误集——缩域后错误集**恰好空**（`docs/` 本来就是 0 错），
只断言「零错误」的用例会全绿。这正是「一致性样本 ≠ 判别性样本」的一个真实例子。

**仍然零样本的两类**（扩域后全仓实测，比 W151 时域大 3 倍）：

1. 锚点（`#fragment`）：**0** 条。
2. 引用式链接定义行（`[x]: url`）：**0** 条。

**一处踩坑（值得记）**：归档后第一次跑门控，`spec-merge` 判据报了两条互相矛盾的错——
「W151 那条 Requirement 主规格里没有」与「主规格里这条没出处」。两条其实是同一件事的两个方向：
判据的域来自 `.git/index`，而归档目录当时**还没 `git add`** ⇒ 重放集里只有 W151 的 `ADDED`、
没有我这份 `REMOVED`+`ADDED`，于是「旧的不见了」与「新的没来路」同时成立。
这正是 W135 那条「未跟踪 ≠ 未登记」在**归档 delta** 上的复现；处置是 `git add` 后重跑，判据随即全绿。
教训是：**归档后立刻 `git add`**，否则自家判据会对着一个它看不见的世界下结论。
