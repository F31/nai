# 公共输出设备时钟的接纳条件

## 结果

宿主不再因为状态里出现设备时钟就直接拒绝。一条观测要同时满足这些条件才通过：输出实例和准备身份与当前状态相同，会话编号符合文本格式，代次至少为 1，流代次和设备频率都不是 0，采样率是 24 kHz，已播放样本不超过提交样本，也不超过片段长度。已播放样本大于 0 时，设备位置也必须大于 0。没有回执的状态仍然拒绝这个字段。缺省的空观测也被拒绝。

按暂停那次的数字做了定向检查：提交 27840 时，已播放 27312、0 和 27840 都通过，27841 被拒绝。输出实例不符、流代次为 0、频率为 0、采样率 48000、代次为 0、会话为空、以及已播放大于 0 但设备位置为 0，也都拒绝。没有时钟字段的原状态仍然通过。

宿主库测试 10 项通过。`openspec validate v49-realistic-avatar --strict` 通过。1.3.10 没有勾选。

## 没有改变的路径

公共播放仍使用 CPAL 的提交游标。那条路径不读 `IAudioClock`，状态里继续不填设备时钟。研究桥上的 WASAPI 已播放样本也没有送进这个宿主。因此这次只是接纳规则，不是同流硬件接线，不是公共窗口改按已播放样本选帧，也不是研究帧进入公共输出。

164 项 ACC、OBS 和真实公共音画都不因此改变。
