# FP8整图算子诊断

## 结论

本轮完成同一实例、同一真实PCM单块的BF16/FP8采证。FP8实际执行240次scaled_mm，去噪实际kernel累计从584.80ms降至430.95ms（约26.3%下降），但去噪流范围由786.36ms升至835.84ms。实际计算变快未转为整段加速，下一优先级应转向主机提交、编译图边界和流等待分析，不继续盲目降低精度。这里只确定非kernel残差增加，尚未证明其中每一项的因果或时长；不能直接称全部为CPU开销。

## 装配与验证

扩展显式profile工具，允许作用域FP8候选与operator trace联用；维护预热后分别采BF16与FP8，新输出路径拒绝覆盖，不与像素留存混用。各路线另留一次无profiler热运行，退出恢复原BF16。按实际kernel事件统计，CPU归因与CUDA范围分开；增加pid/tid匹配，防止另一主机线程被错误归属到重叠阶段。

OpenSpec严格校验通过；算子统计4项、候选生命周期4项CPU测试通过；Windows本机GPU整链诊断退出0。一次模型装载、0次API，无新增素材或生产设置修改。

## 数据

输入取既有source.pcm前30720样本，24kHz单声道，1.28秒/32帧；768×768，四步，全部30层FFN候选，静态缓存预算1GiB。无像素文件IO。维护与编译阶段不算稳态。

| 指标 | BF16 | FP8 |
|---|---:|---:|
| 未插桩热运行墙钟 | 1531ms | 1563ms |
| 未插桩compute | 1359ms | 1359ms |
| profiler去噪实际kernel累计 | 584.80ms | 430.95ms |
| profiler去噪GPU范围（含间隙） | 786.36ms | 835.84ms |
| 范围减kernel累计残差 | 201.56ms | 404.89ms |
| profiler解码kernel累计 | 482.64ms | 442.79ms |

恢复BF16墙钟1703ms/compute1500ms，32帧hash与初始BF16完全一致。单次顺序有漂移，不足以授端到端性能改善或回退结论；所有profiler时间均非实时基准。

FP8实际e4m3矩阵核240次累计122.07ms。两个主要BF16矩阵核在参考累计402.17ms，FP8后剩余一个主要BF16核126.75ms；不能把两组差值直接称FFN纯加速，因为不同矩阵可能共用kernel名字。量化/GELU已出现融合内核，不能仅凭动态量化存在就断言它吃掉全部收益。注意力约101.67/98.04ms，解码仍是独立大项。
