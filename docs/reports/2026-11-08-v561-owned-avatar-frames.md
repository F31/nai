# Rust拥有真实形象帧及设备时钟预演

状态：常驻worker协议2、真实帧消费、短句有界预准备音画及播放中停止工程验证通过。正式常驻公共输出装配、映射ACL/句柄broker、持续实时、人工音画同步精度和长稳未通过；34项ACC/M0不升级。

## 本轮实现

worker不再自行启动独立诊断receiver，配置移除receiver字段，不做旧格式兼容。升级私有协议2：签名事件绑定任务/epoch、PCM摘要/样本、形象摘要、映射名及FrameRef；Release也走签名控制。Rust启动配置中的只读helper，按偏移/长度取得独立像素并核对摘要、严格序号、三槽代次、源范围和几何后交给回调，消费后回执；原始像素不经JSON/protobuf。只有一个未确认帧，控制/读取结果队列有界，读取1秒上限并检查父取消；helper和映射随任务释放。签名不等于Windows映射ACL或句柄broker认证，本轮仍用具名映射及已有只读C++ helper，不能提升0.30状态。

新增nai-v561-avatar-preview：整句最多6秒/PCM288000字节、像素总量256MiB，先完成形象准备再创建预演窗口。复用协议2流式音频执行器播放既有PCM（模型API调用0），使用原始设备epoch和经验证的样本时钟选择帧。结束、取消、时钟失效时清空画面；关闭/Esc撤销父Operation。自动停止测试触发依据设备实际样本，不用墙钟推进或伪造播放进度。

本轮未新增模型依赖，产物/缓存均在E盘；没有更新当前桌面安装组合。现有三种avatar相关probe已按新协议构建；旧JSON不能直接传给新worker，不自动迁移。

## 真实模型和窗口

素材：已有授权docs/jjf.jpg，768×768、49帧块、Lite四步及既有1.92秒技术语音PCM（历史音频文件，不启动或恢复旧Qwen服务）。未调用LLM/TTS、录音、OBS或推流；没有新人工画质评价。

工件根：target-windows/v561-owned-avatar-frames。

| 场景 | 结果 |
| --- | --- |
| real-01 同一worker两任务 | 48/48帧各自由Rust取回并释放；预热33641ms，任务12953/4094ms |
| real-01 取消和恢复 | 第3任务取消并清理，第4任务48/48帧；模型始终加载1次 |
| preview-01 正常预演 | 源46080样本全部播放，127条时钟观察，48帧独立取回；33个不同帧实际提交窗口，结束安全画面提交成功 |
| preview-01 准备成本 | 预热30297ms，随后形象准备13746ms，像素113246208字节 |
| preview-stop-01 启动阶段停止 | 原按启动墙钟500ms触发，当时设备样本0；仅算启动阶段取消，不算播放中停止 |
| preview-stop-02 实际播放中停止 | 设备观察12435样本（约518ms），38条时钟、窗口提交9帧；停止后17ms提交安全画面；completed=false，无自动恢复 |

停止17ms是逻辑撤销到安全窗口提交的耗时，不是硬件静音完成证明。正常预演的33个窗口帧不等于48帧全显示，不能称满帧率。首段生成仍远慢于音频时长；全句预准备也不属于流式低延迟或持续实时通过。
