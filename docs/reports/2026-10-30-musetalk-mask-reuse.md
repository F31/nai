# 真人视频驱动：逐帧融合掩码复用研究

## 实现与验证

在隔离研究脚本加入可选 `--precompute-masks`：从当前已授权研究视频的每帧和对应人脸定位框产生掩码，仅在本进程内按帧序复用；最多 120 帧、掩码总量不超过 64 MiB。默认仍用原逐帧方式。该机制不是持久形象资产、许可绑定或生产缓存，不能跨视频/会话使用。上游预计算函数的模糊核为 0.1，而当前 `get_image` 为 0.05；此次按现有逐帧路径独立计算，避免静默改变融合效果。

以用户授权视频的真实 120 帧、真实 FaceParsing 模型以及逐帧定位结果，使用人工构造的反色人脸输入，对原路径和预计算路径逐像素比较，120 帧全部完全一致。这验证相同输入下的融合等价，不是生成视频的主观画质或口型验证。

单次隔离测量：掩码准备 13.563 秒、缓存 11,767,188 字节；120 帧重用掩码的融合 1.995 秒，原方案分割加融合 12.533 秒。两者在同一进程交错测量，原方案含 CUDA 同步，受系统负载及探针影响；仅说明当前样本重用阶段节省了分割计算，首次准备加一次播放并无总耗时优势。测量不含 UNet、TTS、真实播放和编码，不能推断端到端实时性能。

定向单测 2 项（含边缘裁剪和数量约束）通过，OpenSpec strict 通过。CodeGraph MCP 本轮不可用（transport closed），已直接核查上游源码。模型、视频和数据均留在本地，未调用模型 API 或推流。

## 未闭环与失败

完整样片链路连续两次在 UNet 加载到 GPU 时 CUDA OOM（分别报告仍有约 21.64/21.87 GiB 显存可用）；均发生于掩码准备前，无法归因于本次掩码实现。未修改系统分页配置，尚未定位根因。隔离分割验证不能替代真实端到端生成和听感对照，因此 1.3.4 不勾选。持续缓存仍需绑定视频、模型与预处理版本、授权和撤销，测试损坏及资源回收后才能考虑生产使用。

下一步优先定位模型加载时系统提交量与 GPU 分配关系，完成完整样片复测；之后再评估多次输出重用的端到端收益、实时流和许可绑定。
