# Windows 音频设备时钟与视频帧映射验证

## 现有边界

项目已有 `DeviceClockCursor` 验证 WASAPI `IAudioClock` 的设备频率、流身份、单调性和已提交上界；`VideoCursor` 把经过验证的播放样本位置映射为视频帧并拒绝回退/越界。`apps/output-keeper` 的本地播放路径已使用这些组件，但新工作台的 `apps/public-output-keeper/src/preload.rs` 当前用音频回调的 `submitted_samples` 推进画面；提交进度不等于硬件已播放位置。写实模型与上述硬件时钟尚未装配。

## 本轮验证

扩展既有 Windows 显式静音 WASAPI 测试：取得默认输出设备的 `IAudioClock`，实际写入静音、采集设备位置，经现有设备游标转换为 48 kHz 样本位置，再使用视频游标计算 25 FPS 帧；逐次核对公式、帧序单调以及硬件位置不超过提交量。停止流后验证硬件时钟冻结及相同位置选帧不变化。测试不输出声音、不打开麦克风、不推流，不产生 PlaybackAck。

本机实测成功：设备时钟频率 384000，采样到 24019 播放帧，48 次观测，12 次视频帧变化，停止位置 199680；1 项真实 Windows 设备测试通过。`nai-media-core` 时钟相关定向测试 10 项通过，OpenSpec strict 通过。硬件设备时钟到视频索引的映射得到工程证据，但没有显示真实生成画面、进行音画同步感知或接入公共输出；不能据此声称完整实时直播通过。

验证过程中初次命令因 shell PATH 未含 cargo 而未执行；随后使用已安装的 Rust 1.96 与 MSVC 环境、E 盘项目缓存完成编译。CodeGraph MCP transport closed，已直接检查现有源码与设备测试。未变更用户数据、模型、Key 或安装版。
