# 新任务链独立音频执行

## 实现

新增 `nai-v561-audio-output` Windows子进程，由新task-control入口的可信启动参数 `--audio-output <绝对exe路径>` 显式启用，默认仍只合成、不播放。该内部入口需要Protobuf宿主，不是桌面工作台启动器；未修改开始菜单或现有安装。

Qwen原始24kHz单声道PCM16走独立spawn继承stdin，严格长度、SHA256和20秒上限；控制元数据走本机命名管道，first_instance、reject_remote_clients、随机管道名、单次spawn密钥、非零epoch与严格递增序号。密钥通过清空环境后的子进程环境交付（仅保留必要Windows环境），命令与回执均以HMAC-SHA256绑定全部字段，不在管道中传送原始密钥。拒绝伪造MAC、错误epoch、旧序号和不符来源元数据。两个协议均从schemas先生成，未复用旧审批、预算或媒体ABI。

设备在未开门的静音准备阶段初始化，收到有效续租才消费源PCM；每次租期最多500ms，父端100ms续租，子端音频回调直接检查原子短租约，不等待模型/数据库/控制面锁。父任务取消后停止续租并回收子进程；即使父进程失联，子端租约和管道关闭仍能独立关门。完成回执需父端确认后再关闭管道；先撤权，再至多等250ms确认。设备观察先读线程完成、再读最终样本，避免旧样本与新完成状态拼接。

Task控制面的合成与播放共用同一任务Operation，直到音频执行完成才收尾任务。新完成码`AUDIO_PLAYBACK_COMPLETED`和`played_samples`只表示同一WASAPI流的设备时钟观察，停止码仍明确为逻辑停止；真人接管仍明确`HUMAN_OWNER_NO_MIC`。

## 验证与失败记录

- 最终Windows原生测试18项通过：独立输出端9项（准备无续租、坏hash、坏MAC、静音播放完成、丢续租、重放、错epoch、控制EOF、显式停止）；任务入口9项（含独立输出完成/接管与原7项协议回归）。无真实模型调用的测试均用静音PCM。
- AudioLease 3项通过，时钟转换1项通过、2项既有显式设备测试未运行（ignored）；此次真实设备证据来自上述原生进程测试，不能把ignored项算通过。
- 修复前播放失败多次，针对10ms短句复现10/10失败；阶段日志显示首续租后下一续租被拒绝，设备初始化占用了短租期。改成静音预初始化后同样10轮通过；最终HMAC组合又通过上述18项测试。未放宽500ms租期。早期完整播放失败及首次clippy私有方法命名提示保留；私有from_reading改名为observe_reading并运行对应测试。
- 构建及定向clippy（-D warnings）通过；增量缓存硬链接退回复制提示保留，缓存全在E盘。
- schema --check生成无漂移、OpenSpec严格校验及18包依赖边界（含normal/build/dev/target声明）检查通过；本轮涉及的已跟踪文件diff空白检查通过。
- 真实本地Qwen调用1次，无重试，短句“你好，数字人语音播放链路已接通。”；返回并设备观察播放84480/84480个24kHz样本（3.52秒），任务总耗时23718ms，停止后EXIT=0。无付费供应商、无开麦、无推流。没有人工听感确认，也没有首音独立计时，不能称23.7秒为首响时间。
- 实测账本：`target-windows/v561-task-control-acceptance/real-qwen-audio-1793976580877290200.json`。
