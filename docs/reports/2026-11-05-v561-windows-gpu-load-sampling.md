# Windows 真实生成期间 GPU 采样

512×512 人脸构图、Windows FlashHead Lite、无编译、已有 Qwen 语音，独立诊断完成 10 块、240 帧；不含窗口播放或 OBS。首块之后 9 块平均 5.636 秒，范围 5.626–5.646 秒，每块音频 0.96 秒。

与生成块完成时间重叠的 43 个逐秒 GPU 读数：核心频率 172–180 MHz、利用率 96–100%、功率 26.15–29.22 W、温度 41–42°C。采样在最后块完成前约 7.9 秒结束，不能代表最后片段。设备另一次状态查询显示当前 ceiling 34.75 W、默认 95 W；与采样不是同一字段或完整时间序列，不作为全过程上限。

采样驱动对 `power.limit` 返回不可用；因此该轮采样的旧版 `status=ok` 仅表示查询成功，并不代表所有字段完整。已修改采样脚本：缺任何数值字段时完整性为 `partial`，列出缺失字段并返回非零；3 个真实采样确认缺失 `power_limit_w` 被报告。不能据本次证明功率策略、供电或模型中的单一根因。未修改电源策略、CUDA 或 Qwen。

原始记录：`target-windows/flashhead-acceptance/windows-eager-powered-20261105.jsonl`、`windows-eager-power-20261105.jsonl`、`windows-power-completeness-20261105.jsonl`。下一步核实实际供电/性能模式，正常供电后补全覆盖首尾的对时采样，并做同条件编译范围对照。M0、口型质量与 OBS 不受本次局部诊断升级。

## 接电状态确认后的复测

用户确认已接电源且使用性能模式；Windows `powercfg` 当时显示“平衡”，与厂商性能模式不必然冲突。随后一次空闲查询显示设备 ceiling 约 109 W，未修改系统设置。相同图像、语音、尺寸与块大小下：

- 不编译：10 块完成，除首块外平均 1.147 秒／块（1.016–1.301 秒）。10 个与生成完成区间重叠的 GPU 采样：73.51–115.97 W、1155–2692 MHz、51–55°C。
- 模型和 VAE 均编译（热缓存）：10 块完成，首块 56.495 秒，除首块外平均 0.609 秒／块（0.557–0.660 秒），低于每块 0.96 秒的音频长度。实际模型与 VAE 编译包装均已核对，但不能排除局部图回退。
- 编译版仅 4 个采样与生成完成区间重叠，功率 97.00–113.19 W、频率 1335–1957 MHz、温度 55–57°C；采样在最后块结束前约 1.9 秒结束。两轮采样器均因驱动不给 `power_limit_w` 标记 partial。功率限制可能动态变化，两个测试并未交错且负载未完全控制，因此不能将差异全部归因于编译或电源。

日志：`windows-eager-ac-inference.jsonl` / `windows-eager-ac-power.jsonl`，以及 `windows-compiled-ac-inference.jsonl` / `windows-compiled-ac-power.jsonl`。这支持继续编译版真实播放验证，但不证明播放、OBS、长稳或画质通过。热缓存首块仍需约 56 秒，必须在开播前预热；冷编译成本另见先前报告。
