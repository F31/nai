# RF05 TTS有界传输与取消前置

2026-10-23。内部执行层已实现/Windows与WSL定向实测，完整TTS任务与试听尚未实现。没有调用真实供应商、读取用户Key或播放设备；不更新运行中的工作台，也不将本轮计入ACC通过。

## 实现

- `nai-runtime-core::tts`提供短文本与字符计价策略：最多256个Unicode字符/1024字节，拒绝空白与异常控制字符；按配置的分/百万字符使用整数向上取整。未知价格拒绝估算，确认零价可以为零；这只是估算，不是供应商usage或账单。
- 复用既有静态HTTP适配器的HTTPS/URL与依赖，在`nai-llm-openai::tts`增加内部Rust请求/结果接缝。独立TTS凭据保存逻辑不变；请求持有Zeroizing Key，不实现旧Provider兼容或自动降级。没有新依赖或常驻进程。
- `POST /audio/speech`显式WAV、24kHz、非流式供应商输出，网络接收仍按有界块读取。禁止重试/跳转，连接上限3秒，总请求期限最多15秒，取消每20ms检查；响应最多1MiB，音频最多20秒。成功返回owned PCM16；音频不经过JSON/Base64控制总线。
- 独立核验RIFF声明长度、chunk边界、唯一fmt/data、PCM编码、单声道/24kHz/16位、字节率与块对齐；拒绝空、截断、重复格式、压缩/错误通道/错误采样率等内容。当前只接受16字节基础PCM fmt，真实供应商其他WAV变体需明确扩展后验收。
- 取消、超时、HTTP错误、无效音频不返回部分数据。结果只保留有限WorkbenchError与HTTP状态码，不返回供应商错误正文；发起send尝试即保守标request_started。取消不证明免费，未声明usage或结算完成，不自动播放。

协议参数参考[SiliconFlow官方语音API](https://docs.siliconflow.cn/docs/api/audio-speech-post)。官方支持WAV与采样率选项不等于本模型/账户实际成功；真实返回兼容与音质仍待授权验收。

## 验证

WSL与Windows分别通过：纯策略1项、适配器集成5项。本地HTTP断言路径/鉴权/显式格式/采样率及一次请求，覆盖正常PCM、错误/截断/超长/重复WAV、401/302错误、取消前不发送、派发后取消且丢弃迟到音频、静默服务期限与无效配置拒绝。相关all-targets clippy通过。首次clippy提示`is_multiple_of`已修正后复核通过；没有全仓测试。

本轮仅新增进程内Rust模块，没有跨语言、持久化、HTTP对外服务或媒体协议变更，因此无需改写生成契约。未来接线须先增加/生成正式任务与媒体引用契约，不能把内部音频Vec塞进控制消息。
