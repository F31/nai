# 定位缓存命中后的完整样片与内存诊断

## 内存诊断

上轮两次完整链路在 UNet GPU 装载时报告 CUDA OOM，而 `nvidia-smi` 此次快照为 24463 MiB 总量、4500 MiB 已用；独立诊断在不加载视频帧的条件下，从同一本地音频依次运行 Whisper、VAE、UNet，模型全部实际加载成功。通过 Windows `GlobalMemoryStatusEx` 在诊断进程记录：启动时可用物理内存约 6220 MiB、可用提交量约 6817 MiB；UNet CPU 映射及装配后可用提交量约 2124 MiB；转 GPU 半精度后约 3938 MiB。此数字表明系统内存提交余量是需要进一步观察的因素，但不能由成功或快照单独证明此前 OOM 根因；诊断与完整程序负载不同。

## 实际缓存命中与样片

随后在未修改系统电源、分页文件、代理或其他程序的情况下，以同一用户授权视频、已有 Qwen 音频和同一研究脚本再次运行，输出 `location_cache hit`，不加载定位模型、不重新计算 120 帧坐标；完成 120 帧输出和 4 秒音视频封装，FFmpeg 全文件解码通过，结果在 `target-windows/realistic-avatar-research/video-inspection/musetalk-sample-1793360776799697000/sample.mp4`。真实定位缓存命中链路至此已有单次完整工程证据，未调用 TTS、未上传、未推流。

本轮 main 合计 66.453 秒：视频解码和缓存核验 1.266 秒、定位与定位模型加载均 0 秒、Whisper 及特征 7.766 秒、渲染模型加载 5.844 秒、120 帧渲染/融合/编码 51.187 秒、封装检查 0.344 秒。逐帧 CUDA 同步探针拆分为 VAE 编码 12.377 秒、UNet 13.371 秒、VAE 解码 10.956 秒、融合和写入 14.062 秒。逐帧同步本身会增加耗时，不能用该数据宣称无探针实时吞吐。

前一轮未使用逐帧同步探针的未命中样片 main 合计 81.313 秒、定位与定位模型加载共 29.453 秒；两次测量方式不同、系统负载不同，不能将总耗时差额当作精确提速。只能确认本轮命中成功省去逐帧定位，整个研究链路依然远未实时。当前 Python 进程 RSS 200ms 采样峰值约 4813.1 MiB，PyTorch GPU 峰值 allocated 2025.7 MiB/reserved 2192.0 MiB，不含子进程、驱动或其他程序，不能当作整机峰值。

与上轮用户评价“声音正常、口型可接受”的样片逐帧解码对照，均为 120 帧，完整画面每通道绝对像素差均值 0.015184（0–255），最大 16；两次编码及推理存在差异，数字不能替代用户对口型、听感或闪烁的主观复核。对照脚本首次在两个流结束后错误访问空帧而报错，修正统计变量后重跑得到上述数据，失败如实保留。

## 剩余工作

本轮没有实现正式模型宿主、预处理长期资产管理或授权撤销；研究缓存只含坐标且不是输出授权。需实现有界、版本化的形象素材预处理，进一步细分和优化 VAE、UNet 和分割融合（例如可控预计算及批处理），在真实设备下比较质量/首音/吞吐，并完成流式时序、停止接管、OBS 与长稳。许可闭包、NativeOnnx 路线及 v49 全项验收仍未完成，现行注册表状态不变。
