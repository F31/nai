# V5.6.1 性能路线复审与执行方案

## 结论与证据

当前 768／四步／49 帧组合未达到持续实时，继续零散更换编译选项的收益依据不足。保留现行基线，停止扩大当前 TensorRT 154 子图路线；任何模型、空间合成策略或默认画质变更须另立 OpenSpec／ADR。

1. 官方配置默认 512×512、33 帧、25 fps；本机用户认可的是 768，空间像素量增至 2.25 倍。注意力的实际成本还受 token 数与具体核实现影响，不能把像素比例直接当作耗时比例。官方 RTX 4090 的 96 FPS 不是当前笔记本 768、显示及 Qwen／OBS 并发承诺。
2. 本机查询 RTX 5090 Laptop、24463 MiB、驱动 610.62，默认功率限制 95 W、最大报告值 175 W。它们不等于运行时有效上限，175 W 也不代表可安全或持续设定。此前运行频率／功耗变化与速度相关，尚未证明电源、温控或特定驱动是根因。
3. 59.2 秒运行的稳定块约 1.59–1.73 秒／1.6 秒语音，没有工程余量，也未覆盖实时 Qwen 并发。预缓冲、增加块长和丢迟到帧不能解决长期生产慢于消费。
4. GPU 忙碌样本常达 95% 以上；CUDA Graph 主要解决提交开销，不能凭参数保证计算密集任务加速。原路径已有 PyTorch 编译。需要真实时间线证据才能判断计算、带宽、复制、同步、CPU 或 WSL 争用。
5. TensorRT dry-run 的 95.04% 是算子数覆盖，154 子图可能增加切换；单 FFN 低优化等级和少量固定顺序计时不能证明所有 TensorRT 无效。两条编译路径最大误差均为 0.5，不能据此独断 TensorRT 失真；视频质量必须独立验收。
6. 衣物模糊与 VAE 连续往返存在实验证据关联，但没有证明全部因果。用户不认可较低分辨率和两步采样，性能优化不能隐性牺牲该质量标准。

## 执行顺序及止损

| 顺序 | 任务及交付 | 判定与后续 |
| --- | --- | --- |
| P0 | 固定素材／种子／热缓存／电源场景，分别测 512 官方设置、768 现设置；用 Nsight Systems 或可用 profiler 采集短段时间线，分出 GPU 核、复制、同步、VAE、注意力；再比较 Qwen 停止／运行及实际合成时的争用 | 两种配置都慢则优先环境／实现；512 快而 768 慢则优先画质计算预算。分析只需短段，不先重复十分钟或全量测试 |
| P1 | 仅对占比最大的 1–2 类瓶颈做融合／预计算／设备驻留实验，保持四步和输出标准；交错 A/B 顺序，分别记录冷启动和预热后 P50/P95／显存 | 全链实际收益至少 15% 才扩大；无收益立即关闭候选，不继续堆开关 |
| P2 | 在独立规格中做 512 或 640 的动态头部区域生成＋授权高分辨率动态视频合成的样片；以区域缩小而非全画面降清晰度减少计算 | 仅为待证假设，FlashHead 非原生局部修补模型；需姿态匹配、跟踪、遮挡、颜色和边界一致性。拒绝静态衣物覆盖、接缝、口型变差，不承诺成功 |
| P3 | 对可预知讲解提前缓存完整真实音画；自由问答仍走有界在线生成，等待时显示自然待机并给出真实状态；新回答准备足够前不启动该段音频 | 缓存闭环可以先交付，但不能宣称自由问答已实时。接管／取消须使旧队列失效；无无限缓冲 |
| P4 | 若本机 768 仍不足，优先借用桌面 GPU 在同一配置测一次，再决定外部 GPU worker 或硬件投入；若坚持全本地，再选择至多一个有授权和实测可能性的高效模型做纵向对照 | 先测后采购；不擅自复活已退役模型、建立双引擎主线或改变本地产品承诺 |

建议项目性能目标：1.6 秒块预热后 P95 ≤1.2 秒（25% 时间余量），端到端统计包含实际必要复制与调度，不只是模型函数；首响、插问／接管另定义用户可接受门槛。先 60 秒通过且无持续缓冲下降、无空画面，再升级 10 分钟实时 Qwen／OBS 联合负载，然后 30 分钟。画质继续由用户认可的 768 四步样片对照。目标是工程门槛，不是现有实现已达成的指标。

## 业界方法和适用边界

- [FlashHead 官方](https://github.com/Soul-AILab/SoulX-FlashHead)及[默认配置](https://raw.githubusercontent.com/Soul-AILab/SoulX-FlashHead/main/flash_head/configs/infer_params.yaml)：蒸馏生成加流式推理，仍需匹配分辨率、硬件及完整链路。
- [NVIDIA CUDA Graph 性能排障](https://docs.nvidia.com/dl-cuda-graph/latest/troubleshooting/performance-issues.html)和[Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/)：先区分计算密集与提交开销，再对真正空隙优化。
- [MuseTalk 官方](https://github.com/TMElyralab/MuseTalk)：面部区域处理和离线准备体现了限制在线工作量的思路；只借鉴方法，不恢复本项目已退役实现，不将其分辨率或平台速度套用于本机。
- [ER-NeRF 官方](https://github.com/Fictionarry/ER-NeRF)：通过人物专属训练降低在线生成任务复杂度，但增加素材、训练和维护要求，不能当作即装即用的 Windows 替换件。

潜在创新为计算分区、可预测讲解的提前生成和测得的单 worker 资源调度，而非无依据承诺 TensorRT、换语言、插帧或量化必然提高质量和实时性。上述 P2/P4 尚未立项实施，不能当作已验证解决方案。
