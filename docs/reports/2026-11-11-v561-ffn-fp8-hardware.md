# FFN混合精度：规格、硬件探测与量化融合候选

## 结论

当前PyTorch2.7.1+cu128/CUDA12.8、RTX5090 Laptop（capability12.0）实际支持本候选FP8 e4m3fn scaled_mm和BF16输出，不需要安装新运行时。eager激活量化会吞掉收益；融合量化探针出现进一步评估线索，但仍仅合成矩阵，未接入形象模型，当前BF16默认不变。

本次编译量化后两组矩阵中位数速度比为1.17x/1.69x（包含动态激活量化，权重预处理单列）。只有3次交错采样，时间波动明显，不能称稳定收益或数字人整体加速。FP8相对BF16的合成输出相对L2约3.75%，不能推断实际FFN误差、口型/身份/衣物或连续场景质量通过。

## 规格与门槛

新增v561-ffn-mixed-precision。意向仅覆盖FFN两层Linear，保留GELU/归一化/注意力/VAE和768/四步；静态权重量化、动态激活、FP32缩放/累加、BF16输出，use_fast_accum=False。正式模型适配器尚未实现。

准入顺序为硬件支持→实际FFN输入/输出→完整图像/口型/身份/衣物及跨块主观验收→原三句性能→取消/期限/单GPU/OBS长稳→正式配置/维护激活。矩阵误差、PSNR或编译计数均不能替代主观质量。新精度非像素等价时没有自动质量通过。

## 工程与资源

probe_ffn_fp8显式读取当前avatar/model配置推导形状：M/K/N为3456/1536/8960和3456/8960/1536。仅随机合成矩阵，模型加载0、API0。输入配置最多64KiB，输出拒绝覆盖，重复次数2–6，调用传入张量预算1GiB。检查几何、对齐、预算后才分配GPU张量。2项CPU准入测试通过，关联维护6项/编译器4项共12项通过。

普通硬件探测受原45秒硬期限；显式编译量化模式受原240秒维护硬期限，各层正式采样仍45秒。编译/驱动/临时缓存沿E盘avatar temp目录，编译器通过已验证MSVC/SDK发现机制配置本进程，无系统环境/依赖修改。主机权重预处理时间使用高分辨率perf_counter，GPU阶段使用CUDA事件；均不能解释为纯kernel占用。没有静默BF16回退。

## 三次有明确目的的探测

产物位于target-windows/v561-ffn-mixed-precision，均未加载人像模型或调用任何API。

1. hardware-01：确认API可执行、输出有限，但包含量化的速度比仅0.57x/0.52x，不称加速。
2. hardware-stages-02：分离量化与核心GEMM。第二组核心FP8约0.54–0.62ms，BF16约1.40–1.55ms，但eager量化约1.81ms，确认不能忽略量化开销。
3. hardware-compiled-03：仅编译激活量化函数，两个形状各新增1个实际图和3个内核；其他模型执行器未更改。第一组编译量化与eager逐位相同，第二组不逐位相同；该差异明确保留。

| 形状M/K/N | BF16三次ms | FP8含融合量化三次ms | 中位数速度比 |
| --- | --- | --- | ---: |
| 3456/1536/8960 | 0.979 / 1.074 / 1.064 | 2.549 / 0.912 / 0.904 | 1.17x |
| 3456/8960/1536 | 1.424 / 1.506 / 1.461 | 0.647 / 0.864 / 0.970 | 1.69x |

不比较不同轮随机功耗/顺序形成固定加速比；第一组离群值、第二组量化阶段波动均在原始报告保留。FP8误差相对L2分别0.03749/0.03757，绝对最大差0.205/0.207，均为随机矩阵输出值而非像素值。实际层可能出现不同分布/尾值和误差累计，须进入F03验证。
