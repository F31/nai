# Windows 共享内存依赖审查

V5.6.1 需要在 Windows 上把 Python 产生的真实帧交付 Rust，项目工作区禁止 unsafe。检查 `shared_memory` 的公开 API，其映射视图访问要求调用方使用 unsafe；未纳入。

下载 `winmmf` 0.6.2 源码到 `target-windows/v561-dependency-review`，没有安装或加入项目依赖。该库使用四字节锁头，不兼容当前 Python 诊断的无头共享段；其 `open_read` 内部仍申请全部映射访问权限，且审查发现 `read_to_buf` 的扩容及设置长度逻辑不能保证请求长度对应已初始化有效数据。故不能仅因该 API 标记为 safe 就用于生产媒体读取。其许可为 MPL-2.0，若将来使用也需单独评估。

这些发现不意味着 Windows 共享内存不可行；需要可靠的进程间同步、句柄及权限管理，以及经审查的窄平台封装。尚未接入新依赖或实现真实 Rust 共享帧读取，不得以本次审查声称播放链路完成。模型帧 16 kHz 与播放时钟 24 kHz 的换算已在帧调度器修正并定向验证。
