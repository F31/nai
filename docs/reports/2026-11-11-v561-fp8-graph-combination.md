# FP8 FFN与单步图重放组合

## 实现范围

显式组合原FP8 FFN与单步CUDA Graph，仅诊断工具，不改默认配置或Rust协议。先BF16参考→FP8维护/参考→图维护/热运行→释放图后FP8回归→释放FFN后BF16回归。两个ExitStack逆序回收：图引用和静态buffer先同步清理，才恢复FFN/编译模块；异常同顺序。FP8静态预算1GiB，图预算4GiB分别执行，均非硬件内存配额。

可选1–3对交错热测在同图/同权重存活期间切换图重放与原FP8调用，不重新捕获；旁路同样校验输入身份与取消，下一次重放重新复制所有输入。输出独立clone，防止跨步/跨块覆盖。

OpenSpec规格先扩展并严格校验通过。生命周期测试新增组合异常回收顺序和旁路复用：graph reset时FFN仍是候选、原forward已恢复；形状变化拒绝且不新增图。候选9项及原FFN4项关联CPU测试通过。CPU替身仅验证控制/生命周期，不授GPU算子通过。

## 第一轮真实GPU

Windows RTX5090 Laptop，单模型、既有真实3.84秒PCM、768×768/四步、固定seed42、无profiler或像素文件IO。维护与热运行分开。

| 模式 | 墙钟 | compute |
|---|---:|---:|
| BF16参考 | 4735ms | 4595ms |
| FP8热参考 | 4562ms | 4250ms |
| 图热运行 | 4312ms | 3922ms |
| 图热运行重复 | 3938ms | 3656ms |
| 释放图后FP8恢复 | 4266ms | 3937ms |
| BF16最终恢复 | 4406ms | 4110ms |

一次捕获、36次重放。图维护和热运行96帧全部与同实例FP8参考hash一致，图释放后的FP8亦一致；最终BF1696帧与BF16参考一致。不同精度间不要求hash一致，也不据同精度等价授新精度整体验收。

图静态输入/输出10,211,332字节，allocated增量18,732,544字节，reserved增量0；FP8静态权重825,753,840字节。reserved为0不等于图零成本，不代替峰值测量。最快墙钟仍大于3840ms源音频，且存在顺序漂移，不能只选最快一轮授实时通过。

## 证据

target-windows/v561-fp8-graph/combo-01.json与combo-02.json及各自stdout/stderr/维护状态保留。两轮均退出0、分别模型装载1次、合计API0次；第二轮是有界交错采证，不是失败重试。

## 第二轮交错热测

同一模型/同一张图，保持全部FP8参数及原始权重，图捕获一次；图重放72次、原调用旁路36次。取消/元数据检查两条路线均执行。每对顺序第一/三对原调用→图，第二对图→原调用；无重复捕获开销。

| 对数 | FP8原调用墙钟/compute | FP8+图墙钟/compute |
|---|---:|---:|
| 1 | 4453/4173ms | 3860/3626ms |
| 2（顺序倒置） | 4437/4110ms | 3937/3610ms |
| 3 | 4454/4188ms | 3781/3500ms |
| 中位数 | 4453/4173ms | 3860/3610ms |

相对同精度原调用，组合墙钟中位数下降13.32%，compute下降13.49%。这支持当前机器/该片段下图重放与FP8可获得叠加后的实际净收益，不将单块或profiler结果外推为整场直播。

三轮图墙钟范围3781–3937ms，中位数3860ms比3840ms源音频略高；仅一轮低于源时长，样本少且计时有量化，不满足稳定实时余量。第二轮初始BF16墙钟4375ms、最终4344ms；这里没有足够BF16交错样本，不能把上述13.32%说成相对BF16的已证明稳定增益。

全部图维护/热运行/交错帧与同实例FP8参考96帧hash一致；所有旁路与释放图后的FP8确认亦一致；最终BF16与初始BF16一致。无需重新要求主观审看相同像素，但FP8总体质量仍只保留既有短片接受范围，未升级真人连续体验或OBS证据。

本轮最终9项图生命周期/旁路/组合异常及4项FFN生命周期测试、OpenSpec严格校验通过。未运行无关全量回归。
