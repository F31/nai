# 公共执行栅栏与同流 WASAPI 隔离整合

在 Windows 测试中组合现有 `PublicExecutionGate` / `ExecutionFence` 和默认关闭的实验同流音频后端；使用隔离构造的 bundle、receipt 与静音 PCM，不使用或修改用户业务资料。设备初始化后执行挑战、接收匹配租约、开始设备提交；通过新挑战及递增序号续租并观察同一流继续推进；重放旧租约触发执行栅栏终止，音频线程停止提交。真实默认输出设备测试 1 项通过，OpenSpec strict 与 31 包依赖边界通过。测试自行构造租约，并未执行实际 root 权威签发或认证跨进程通信，不是生产播放许可或声音播放证据。

测试仅在本机静音情况下完成，且实验内层一次性栅栏最长 500ms，不能支持直播连续运行。生产 public-output-keeper 仍使用原 CPAL 路径，设备时钟字段仍被宿主拒绝；同流后端尚未接线到生产许可/设备身份、未实现可信连续续租、独立进程故障回收、设备断连处理、真实语音、唇形、OBS 与长稳。不能将本轮标记为整个任务闭环。

下一主线应一次性交付：以现有 root 签发的 `PublicExecutionGate` 替代实验双重栅栏，绑定设备流身份与帧时钟；定义独立进程的受限 IPC/失联清权；以真实音频和 OBS 测试停止、重放、失联、连续输出与性能，全部通过后才更新工作台。
