# FlashHead 推理与帧传输重叠诊断

新增显式 `--overlap-transfer` 诊断选项：一个独立发送线程串行拥有 Rust 传输器，最多等待一块帧，下一块推理可与当前块发送并行；队列满时有界等待并反压，完成时先排空，失败先停止进程、等待发送线程退出后再释放共享段。此选项只支持 Rust 诊断接收器；默认保持原同步发送。报告字段 `transport_s` 在重叠模式仅表示 GPU 到 CPU 转换及入队等待，不是实际全部发送耗时；累计发送时间另记 `overlap_send_seconds`。

对相同肖像、先前 Qwen 语音前 6.72 秒、48 帧预缓冲和 7 块分别执行单轮：同步默认后端窗口提交 163/168 帧、最长安全画面 63 ms；重叠默认后端提交 168/168、未记录安全画面、最大设备时钟相对帧迟到约 40 ms；重叠 cuDNN 也为 168/168、未记录安全画面、最大约 40 ms。每种只有一轮，系统负载和温度未严格控制，不能将变化全部归因于代码，更不能由短样本推断长稳。

从各轮 JSONL 排除首块计算平均：同步默认每块约 1.122 秒，重叠默认约 1.045 秒，重叠 cuDNN 约 1.101 秒；每块对应 0.96 秒音频。cuDNN 首块约 4.54 秒，重叠默认约 2.34 秒。首块及稳态本轮未显示 cuDNN 优势，保留默认后端。重叠默认累计发送约 0.578 秒；由于与推理并行，不可再把它直接加到模型计时上。

三项纯逻辑测试覆盖顺序、错误传播和有发送任务时先停止再释放；另用 12 个合成帧验证真实 Windows 共享槽到 Rust 的重叠链路。两轮真实模型完成 168 帧接收与提交，无付费调用、推流或录制。日志 `target-windows/flashhead-acceptance/rust-av-overlap48-6720ms.jsonl`、`rust-av-overlap-cudnn48-6720ms.jsonl`；窗口输出统计来自本次进程控制台。

当前结果仍是隔离程序短测；稳态算力尚不足以保证不耗尽预缓冲。生产级媒体权限、持续语音流、OBS 实录、工作台装配及 10 分钟 M0 仍未完成。后续应继续测量并降低视觉模型计算或建立经过质量验证的降载配置，再进行更长真实音画与 OBS 验收，不能靠继续扩大缓冲冒称实时。
