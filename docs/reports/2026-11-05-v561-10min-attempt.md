# V5.6.1 有界长音画与十分钟尝试

隔离诊断的音频源扩展到显式有界上限 600 秒，原有旧音频接口的 20 秒限制不变；读取前校验文件大小，生成块数与 PCM 时长不符时拒绝。减少窗口重复转换及提交同一帧，仍在无变化时处理窗口事件；首次窗口仍提交安全画面。

两次 60.48 秒真实模型、已有 Qwen 语音循环、384×384、本机窗口及设备测试：原窗口循环接收 1512 帧、提交 1479 帧，无记录安全画面；优化后接收及提交均 1512 帧，无记录安全画面。两轮并非严格控制负载对照，不能将全部变化归因于窗口优化。第一轮 GPU 采样正常，播放阶段 61 个样本中最高温度 71°C、最高占用 9853 MiB，瞬时最大功耗约 170.79 W；这些值是采样观察，不是精确峰值或长期结论。模型时段去掉首块平均约 0.8297 秒／块，最高 0.9976 秒。

随后执行 600 秒隔离尝试：Qwen 1.7B 健康检查通过，隔离 OBS 录制目标窗口及进程音频，播放的是已有合成语音循环，不是持续新生成 TTS。模型第 597 个块（序号 596）入队后，接收器确认等待超时，进程退出码 1；没有完成 625 块或十分钟音画，M0 不通过。第 2 至 597 块模型计算平均约 1.0031 秒／块，431 块超过 0.96 秒；第 2 至 597 块完成间隔约 608.38 秒，明显大于同一区间约 571.2 秒音频跨度，预缓冲最终不足。根因推测是音频先结束而帧仍未送完、消费队列不再推进；现有日志不足以证明这一推测是唯一原因。

已对诊断播放终止状态增加明确检查：音频停止或播放结束而输入未完成时立即失败，不再等待发送端确认超时；针对提前结束、未完成、正常完成的状态测试，以及超长 PCM 在打开设备前拒绝的测试通过。该改动尚未进行第二次十分钟故障复验，不宣称持续播放已修好。

追加 Windows 跨进程故障复现：使用 1.92 秒静音和 10 帧合成画面，保持生产者连接不关闭，音频结束后诊断进程在 4 秒内返回明确 `audio completed before all frames were received`，没有等 15 秒接收超时；同批共享槽正常及接收器退出测试共 3 项通过。这验证了故障处置，不证明十分钟轮次的唯一根因。

另外做一轮显式 320×320 短对照，168 帧均提交且无记录安全画面，但除首块以外平均 1.0513 秒／块，慢于先前 384×384 的单次 0.9395 秒／块；两次未控制运行环境，不能证明尺寸与性能的确定性关系。未改变默认尺寸，320 样帧保存在 `target-windows/flashhead-acceptance/rust-av-overlap320-sample.png`。

资源采样器 600 秒结束，共 228 个样本，最大间隔约 2.80 秒；最高 GPU 温度 85°C、最高整机显存占用 9869 MiB、系统内存占用最高约 23432 MiB。采样中 `-ProcessName` 通过 `pwsh -File` 传递数组的方式不正确，进程项为 null；模型 JSONL 中仍有 Python RSS。Qwen 健康与 OBS 状态只在采样开始时核对，未证明全程活跃生成。

证据位于 `target-windows/flashhead-acceptance/rust-av-overlap384-600s.jsonl`、同名前后缀 stdout/stderr 日志及 `baseline-384-10min/`。这是失败轮次，不得改变验收表为通过。下一步应降低稳态计算耗时或使用经过用户画质验证的降载配置，补可观测的帧、音频队列和耗尽原因，再重跑真实 Qwen 活动生成及 OBS 长时验收；生产装配和访问认证仍未完成。
