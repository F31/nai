# SageAttention 2.2 与 49 帧块隔离测试

之前的 SageAttention 2.1 社区 wheel 标注 PyTorch 2.7.0；本轮从 [Windows 构建发布](https://github.com/woct0rdho/SageAttention/releases/tag/v2.2.0-windows) 获取文件名标注 Python 3.10、PyTorch 2.7.1、CUDA 12.8 的 2.2 wheel，发布方 SHA-256 `68015b797baef5c3b4db4f645052299d6f0174476f1b9f12973a86f7341569fa` 与下载一致。哈希只确认文件一致，不证明发布链、二进制安全或正式 ABI 兼容。安装仅在项目 E 盘隔离目录，不覆盖 Qwen、原 PyTorch 或工作台。

RTX 5090 bf16 基础注意力单测为 `[1,12,512,128]`；与 PyTorch SDPA 比较输出有限、最大绝对差 0.02930、平均绝对差 0.002116。量化误差不能推广为整个人脸/音画质量通过。

768 原图参考、四步、49 帧（净输出 40 帧/1.6 秒）、相同种子与音频的隔离无编译生成：Sage 2.2 产出四块，后 3 块为 1.734、1.713、1.724 秒，平均约 1.724 秒；此前默认后端另一轮平均约 1.998 秒。两轮未交错、GPU 状态未严格对齐，不能声称稳定加速比；候选本轮仍慢于 1.6 秒音频。导入状态显示 Sage 可用，上游普通注意力分支选择优先级支持该路径；这不证明每个子算子均使用 Sage。

对照视频 `target-windows/flashhead-acceptance/mouth-768-block49-default-vs-sage220.mp4` 左默认、右 Sage，固定尺寸/音频/种子并完整解码。用户反馈右侧嘴部清晰度和口型可接受，并询问衣服是否被模糊；未压缩帧显示两种后端衣服均逐块变软，见下文。音画长稳、交互延迟、Qwen 并发及 OBS 均未验证；正式默认不变。

编译版后续实测：同 768／四步／49 帧，FlashHead 模型与 VAE 均包装编译，`sage_available=true`、不引入 Flash2/Flash3；准备 94.8 秒，首块 92.1 秒，后 3 块 1.750、1.667、1.753 秒（均值约 1.723 秒）／1.6 秒音频，尚无持续实时余量。导入标记及上游分支优先级不代表所有注意力调用都已计数；两轮运行状态和负载未严格控制，不能将差异归因编译。日志 `windows-768-block49-sage220-compiled-20261106.jsonl`；使用已有语音，未进行 Qwen 并发或窗口播放。候选没有进入正式默认。

## 衣物变软反馈

用户指出头部以下衣物模糊。原始 RGB 帧第 12、50、100、145 帧的左右对照 `target-windows/flashhead-acceptance/block49-garment-frame-inspection.png` 可见两侧随时间逐渐变软，并非仅压缩后的 MP4 现象；诊断代码与视频组合命令没有添加衣物模糊滤镜。固定衣物矩形 `[160:608,570:730]` 每 5 帧抽样 8 帧的灰度拉普拉斯方差：参考图约 353；默认后端四段均值 239、173、113、89；Sage 四段 234、174、107、87。画面姿态、光线与区域组成会影响该边缘代理，不能把它当独立质量分数或证明唯一原因。

FlashHead 每块末尾将生成画面重新编码为下块运动条件；逐块往返可能导致细节累积损失，这是依据时序代码作出的假设，尚未通过对照证明。下一步应对静态参考、VAE 往返和连续生成作受控时序实验，并验证减少漂移的方案对衣物、身份、口型、运动连续性和实时开销的影响；不得以静态衣物覆盖冒充真实动态修复。
