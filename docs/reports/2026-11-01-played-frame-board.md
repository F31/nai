# 已播放源样本选择当前帧

## 结果

媒体核心新增 `PlayedFrameBoard`。调用方交出代次、源样本序号、不透明帧编号、截止时间和同一单调时钟上的现在。选帧只看设备已经播放的源样本。提交游标不是输入。

截止时间前到达、并且当时还没被播到的帧进入队列。队列容量由调用方指定，范围是 1 到 16。播到该序号时呈现队列里不大于该位置的最新一帧，被跳过的更早帧直接丢掉。已经播过才送到的帧，以及晚于截止时间送到的帧，都拒绝，画面停在已经接受的那一帧。没有任何可显示帧时返回安全待机。

另一代次、已播放位置回退，或显式撤销，都会清空队列并回到安全待机。之后旧帧不能再进入。

`cargo test -p nai-media-core --lib played_frame` 通过 11 项。`cargo clippy -p nai-media-core --lib -- -D warnings` 通过。`openspec validate v49-realistic-avatar --strict` 返回 “Change 'v49-realistic-avatar' is valid”。1.3.10 和 1.3.11 没有勾选。

## 没有改变的路径

公共窗口仍按提交样本选图，没有调用这个选帧器。没有把 MuseTalk 或 960×540 研究帧放进 keeper，也没有把 Python 放进正式安装包。没有新协议字段，没有像素缓冲，没有播放许可。没有跑声卡、GPU、Qwen 或 OBS。解码与下一批推理的重叠、分块语音特征，以及和 Qwen 同时运行的 60 秒播放，都还没有做。

随后 Windows 公共执行把该选帧器接到已播放源样本，见 [公共窗口按已播放样本选帧](2026-11-01-public-played-frame.md)。
