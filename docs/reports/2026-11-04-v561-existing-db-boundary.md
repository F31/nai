# V5.6.1 已有数据库保护

新数据根原先在识别已有 `nai.db` 前就打开可写连接并设置版本，可能修改旧数据库。现在先用 SQLite 只读连接核对版本、用户表、列顺序和 settings 中的结构版本；存在旧 `foundation.sqlite`，或已有 `nai.db` 未通过检查时返回不兼容，不执行迁移、建表或创建配置和资源目录。当前结构的库可正常重开，新建数据库才初始化当前结构。

Windows 定向测试 `cargo test -p nai-foundation-sqlite v561 --offline -- --skip rejects_symlink_escape_when_parent_exists`：13 项通过，覆盖旧库原字节、旧根拒绝、未知或不完整结构拒绝及当前库重复打开。跳过的符号链接测试此前因 Windows 创建符号链接权限不足失败，并非已通过。

识别规则用于区分已知结构，不是数据库内容或来源的安全认证；只读检查与后续打开之间的并发替换尚未消除。SQLite WAL 只读访问可能涉及辅助文件，不能保证操作系统层面绝无新文件。初始化过程尚不是完整崩溃恢复事务。

`scripts/v561-start.ps1` 仍启动 `nai-foundation-engine`，当前装配仍使用旧 `Store`。本次只保护新数据根，不代表工作台已经切换到新库，也不代表旧工作区、审批和预算链路已移除。应完成新引擎装配和协议消费后，按实际依赖移除旧实现；M0 模型、许可和真实目标机验收仍待完成。
