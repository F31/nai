# Flow参考对齐实现与真实计数验证

## 本轮交付

实现显式Flow参考条件对齐，并完成同模型/同音色的原配置两次、对齐两次真实合成。候选实际把参考87token/174mel帧变为75token/150mel帧，padding13→0，首块门槛41→28，输入decoder实测28，均完成有效PCM。未改变hop、lookahead、精度、LLM参考文本/语音token或声纹embedding，原用户音频文件未修改。

这是TTS-01首块路径的工程/计数证据。性能及人工音质未闭环，默认未激活，34ACC pending/M0 No-Go不变。

## 实现和验证范围

scripts/cosyvoice_flow_alignment.py读取模型token_hop_len、flow.token_mel_ratio/input_frame_rate/output_size，配置显式最小秒数与字节上限。复制条件字典，仅四个Flow token/长度、特征/长度字段创建owned张量；完整LLM条件和embedding不替换。检查类型、batch/特征维度、长度值及2倍对应、最小上下文和资源；未知结构或不满足门槛拒绝。安装在现有条件缓存之后，缓存原内容不修改；可恢复原wrapper。

scripts/prepare-cosyvoice-flow-alignment.py在已核对cache边界增加CLI：--flow-reference-min-seconds缺省None即不安装，max-bytes有界。未知/重复源结构拒绝，原server.py不覆盖。当前候选明确3秒最小参考、1MiB Flow条件预算，模型声明25token/s、25hop、2mel/token、80维。

5项核心测试覆盖四字段同步、原Flow/LLM别名和缓存不污染、反复调用、最小上下文/预算/错误长度、未知闭包及纯变换前后取消回调；2项入口测试覆盖默认关闭和未知边界拒绝。服务安装不接管原request gate取消机制，仍按既有取消交付/非可抢占后台drain工作；本轮未实际测试服务断连或GPU硬取消。

## 追加一次真实负载遥测：环境不满足性能定论

为核实数倍跨轮波动，恢复原服务后追加一次原配置短句（没有失败重试），并以250ms采NVIDIA GPU全局状态。该次首PCM13.641秒、总14.734秒、音频2.72秒、RTF5.417，完成。共55个采样点，其中GPU利用率≥50%的3点SM频率787–900MHz、功耗28.87–36.23W、温度39℃；全程也出现最高2175MHz，不能称固定锁900MHz或已证明具体功率上限。小样本全局遥测不等于模型kernel归因，也不证明所有性能问题来自电源。

同时Win32_Battery.BatteryStatus=1（放电）、剩余65%，活动电源方案“平衡”；Microsoft文档确认该状态含义：[Win32_Battery](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-battery)。测试后可用物理内存860852224字节（约0.80GiB）、可用提交约13.71GiB、Pages/sec=309。电源及资源状态与接电性能模式验收条件不一致，足以阻止据本轮数据评价稳定算法性能；不是证明电源或换页的单一因果。

已要求操作者接原装电源、核对厂商性能模式并释放闲置资源；未自动更改电源计划、关闭程序或重启WSL。收到回复并只读复核后再进行依赖该条件的验证，不连续重复当前慢速测试。
