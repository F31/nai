# 原生任务控制入口

## 交付

新增独立 `nai-v561-task-control` 可执行文件，调用新的 Tasks 编排模块和现有 Qwen Adapter，不启动历史 foundation engine，不打开用户数据库。参数可配置 endpoint/model/voice/language/deadline；默认沿当前 Qwen Config，限本机回环 API。

先新增 `schemas/v561/task_control.proto` 并用固定生成器生成 Rust/TS/C++/Python，再实现消费者。私有继承 stdio 使用4字节小端长度前缀、16KiB上限、版本1和严格递增序号。支持讲解文本合成、回答文本合成、真人所有权接管、显式结束真人任务、状态和停止。回答命令只消费已给出的文本，不包含LLM生成能力。

最多一个模型调用在途，无待执行模型队列；忙时拒绝新合成，但接管/停止/查询继续处理。旧请求取消后有界收尾，不释放新真人所有者。输入通道容量2，输出通道8，输出反压失败则撤权退出；stdout写线程不阻塞控制面收尾，最多等250ms刷新。EOF、超大/截断/损坏帧停止进程。命令不携带Key，事件只有固定安全状态码及合成样本元数据；PCM不经过控制协议。控制入口不监听端口，不能作为通用未认证HTTP服务暴露。

## 实测

- Windows原生子进程+生成Python Protobuf+本机假Qwen服务7项通过：合成完成、接管/忙拒绝/旧完成/显式恢复、停止不等待服务端、重放/版本/未知命令、超大帧、截断帧、父进程EOF。
- 实际Qwen调用1次，短句“你好，这是任务控制验证。”，无重试；返回55680个24kHz样本（2.32秒），从发命令到完成4484ms，停止回执后EXIT=0。未播放、未调用付费供应商。该耗时是本轮单句观测，不是首音或实时吞吐保证。
- 实测账本：`target-windows/v561-task-control-acceptance/real-qwen-1793974730324006300.json`。
- 新程序构建、定向clippy（-D warnings）、schema --check无漂移及OpenSpec严格校验通过。生成包含288个消息/14个proto源；C++生成不等于C++编译或三语言全套验收。
- 沙箱内protoc首次启动报Windows DLL重定位错误，正常本机环境重跑生成及检查通过；没有修改系统DLL或工具链。硬链接退回复制提示保留，缓存仍在E盘。
