# V5.6.1 帧与播放时钟契约

本轮为 M0 准备新增独立 Protobuf：共享帧引用、指定槽位代次的释放消息、音频设备时钟观察。控制消息不传递帧或 PCM；允许首帧、首槽及零采样位置，并区分缺失字段。池标识和摘要不构成授权，释放不代表播放，计划采样位置也不代表设备播放。

生成器新增仅针对 V5.6.1 的 Python 产物，构建暂存和描述符使用 `CARGO_TARGET_DIR`，未设置时位于 `target-windows/schema`。Rust 提供独立结构检查，校验配置化尺寸上限、序号存在性、槽位和代次、负载长度，以及时钟状态与采样位置的一致性；调用方仍须核验来源、当前 epoch 和真实池权限。Python 使用生成模块时应禁止在生成目录创建字节码缓存，例如使用 `python -B`。

验证：Windows Rust 定向 4 项通过，包括 Python protobuf 编码向量与 Rust 解码/重编码、零值存在性、代次与尺寸拒绝、时钟缺项拒绝；`cargo xtask schema --check` 无漂移。首次沙箱内 protoc 因系统 DLL 重定位失败，授权环境执行通过。未调用模型、未操作现有数据。

描述符定向测试 5 项与 OpenSpec 严格校验通过。V5.6.1 验收表检查器本轮因本机 Node 依赖 `yaml` 缺失未能运行；未修改验收表，也未据此认定验收通过。

局限：这不是 Rust 跨进程共享内存消费者，未接实际音频设备时钟、窗口或 OBS，也没有测得端到端实时性；M0 未完成，验收注册表状态不变。下一步应实现可信的有界槽交付与 Rust 实际读取/释放，并与真实播放设备时钟对齐后再测实时帧链路。
