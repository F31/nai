# W72：冻结基线与注册表的对账门控

- 日期：2026-10-12
- 变更：`openspec/changes/w72-baseline-reconciliation-gate/`（归档后为 `openspec/changes/archive/2026-10-12-w72-baseline-reconciliation-gate/`）
- 裁决：[ADR 0050](adr/0050-baseline-registry-reconciliation.md)（对账门控；缺口①的括号语义裁定；四情形规格订正）
- 基线：**`docs/直播数字人 + 智能体系统技术方案 V3.10.md` 零改动**（本轮是**加断言**，不是升基线）
- 登记：`tests/registry.yaml` **88** 条不变、**归属不变**、**一条 `status` 未动**（H18 与 B07 仍 `pending`）
- 承接：W71 报告「未做与遗留」里如实登记的**两处门控缺口**（缺口②为主线，缺口①需先裁定括号语义）。**本轮关闭两者。**

## 一、判断：缺口②要抓的不是「有人改了东西」，而是「改完之后没人说」

W68 把 B07 加进 `tests/registry.yaml` 是**正确**的动作。错的是：**没有任何机器可读的地方**注意到
§48.5 的家族索引还写着 `B | B01–B06`、§57.3 的计数行还写着 `= 87`。
这两处最后是被**人逐行读**出来的，跨了 **W68 → W71 两轮**。

所以断言不能写成「基线与注册表必须相等」：

> 基线被 ADR 批准后**不可变**（`AGENTS.md`），实现轮次**没有权限**改 §57.3。

写死相等会有两种结局，两种都不可接受：**跳过门控**（门控失去意义），或**为一条验收项开一次升基线轮次**
（把「加一条验收项」的成本抬到一次 ADR）。**这不是严格，是死锁。**

## 二、方法：先核实两侧声明，再决定断言写在哪一层

| 步骤 | 实测 |
|---|---|
| 注册表实测分布 | **88** 条：`slice_0` 10 / `r1` 37 / `r2` 9 / `r3` 1 / `experimental` 2 / `capability_pack` 29；九族 `S12 R11 A14 B7 O5 P1 M18 H18 X2` |
| §57.3 发布线正本 | **6** 线，逐 id 与注册表**完全一致**（W71 收录的结果） |
| §48.5 家族索引 | **9** 族，展开后与注册表家族集合**完全一致** |
| 待收录偏差 | **零**——故台账初始为空；**台账为空本身就是「W71 已全部收录」这条断言** |

核实还确认了一件**必须写进断言的反例**：**§16 的验收注册表没有 B07 是设计，不是遗漏**
（V3.10 §58.3：给 §16 增行会位移其后全部行号、破坏 `§NNN` 引用契约）。
⇒ 新断言 MUST NOT 要求 §16 增行；判据只能取自 §48.5 与 §57.3。

## 三、关键：断言的形状，与三条被否决的写法

| 候选 | 否决理由 |
|---|---|
| `§57.3 == 注册表`（硬相等） | 见第一节：**死锁**。基线不可变，实现轮次无权限 |
| 只比对**条数** | 条数不符有一百种原因，**id 才是可执行的线索**；且「把 B07 换成 B08」这类改动条数不变 |
| 只比对 §57.3（不读 §48.5） | 覆盖不到**家族完整性**，而缺口①正在那里；且 §57.3 是**发布线**视角、§48.5 是**家族**视角 |

**采取**：`在册 == 基线声明 ∪ baseline_deviations`，其中台账**不是豁免**：

| 性质 | 落实 | 失败样例（均有用例） |
|---|---|---|
| **具名** | `id` + `registered`（登记轮次）+ 非空 `reason` | 非列表 / id 非法 / 缺轮次 / 缺理由 / 重复 |
| **相称** | MUST 对应一处**真实**差异 | 台账写 `S02` 而实际差异是 `B07` ⇒ **两条都失败** |
| **自清理** | 基线收录后不清空 ⇒ 不再对应差异 | **陈旧条目** |

⇒「**已登记但尚未收录进基线**」从 W68→W71 期间那种「在报告、`notes`、活文档里各写一遍」的**说法**，
变成**可判定**的状态。这与 ADR 0042 决策 4 是同一形式：「在册」≠「测得」⇒ 现在「已声明」≠「已收录」。

**基线文档的选取**：`docs/` 中**版本号最大**者（自维护，门控里不写死文件名），
且 MUST 与 `openspec/config.yaml` 声明的指针一致——这样一份废弃草稿不会让门控悄悄对着它跑。

## 四、缺口①的裁定：括号是**示例**，判据来源是 §48.5

需求原文：「SHALL 断言每个『基线已定义完整编号段』的家族**逐号在册**（当前为 M01–M18 与 H01–H18，各 18 条）」
——而 §48.5 声明**九**个连续编号段。裁定：

> 括号是**示例**；「基线已定义完整编号段」的取值 MUST 从 **§48.5 的家族索引逐行读出**（当前 **9** 族）。

`COMPLETE_FAMILIES`（M 18 / H 18）**保留**，两者挡的不是同一件事：

| 守卫 | 挡什么 | 判据来源 |
|---|---|---|
| `COMPLETE_FAMILIES` | **§48.5 自己被改小**（M 行改成 `M01–M12`） | 写死的 18 |
| §48.5 家族索引对账 | **注册表少了 §48.5 声明的某一项**（B07 未收录） | 基线正文，逐行读出 |

**只有后者覆盖 S/R/A/B/O/P/X 七族。** ⇒ 缺口①不需要单独的实现轮：它由缺口②的实现**顺带关闭**，
规格只需把判据来源写清楚（本轮 `admission-registry` 的 MODIFIED 需求 + 一个新场景）。

## 五、非空洞：门控最可能废掉的方式是**解析悄悄落空**

失败模式不是「漏改」，而是 §57.3/§48.5 的**章节号被改**（或被删）导致解析出**空集**——
空集会让「对账」产生两种相反的假象。本实现取「宁可吵」的一侧，并把两类错误**分开具名**：

| 措施 | 落实 |
|---|---|
| 定位按**章节号**（`^#+\s*57\.3\b`），不按标题文本 | 改**措辞**不影响解析（有用例）；改**号码**必然失败（有用例） |
| 解析失败 vs 设计漂移 | `§57.3 heading not found` 单独一行，不被读成「注册表多了 88 条」 |
| 两张「照抄基线」的表**逐项钉死** | `familiesInOrder`、`rowLabels`（§57.3 的「线」列写 `Slice-0`，而 `release_lines` 的键是 `slice_0`——这张映射改小就是静默失效） |
| §57.3 **表内自洽** | 计数行 == 表格展开；合计 == 各行之和；漏线 / 多出未知线各自具名 |
| 用例锚点 `replaceOnce`（**恰好命中一次**） | 见下 |

**`replaceOnce` 当场开火，并带出一个发现**：`` `r1` **37** `` 命中 **2** 处——§57.3 的计数行，
以及 **§58.5 逐字复述的同一条计数行**。后者说明：

> **W71 已经把这条断言用散文写在了 §58.5**（「正本仍是 §57.3……与 `tests/registry.yaml` 逐条一致」）。
> 本轮做的事就是把它**变成机器可读的**。散文形式的断言**不是断言**——它不会失败。

若不用 `replaceOnce`，这个用例会改到 §58.5 那一份、而 §57.3 没动，于是**假装通过**。

## 六、核实中发现的第三件事：W71 的 E5 订正没有传播到它自己的**规格**

核实「哪些地方已经声明过这件事」时发现：**被 W65 先例否证的规则进了活的主规范。**

| 位置 | 写的是 | 与什么冲突 |
|---|---|---|
| 基线 **§56.2 第 1 行**（权威） | 四情形，其中**情形②**「`§NNN` 的版本前缀 ⇒ 随基线更新」 | — |
| `specs/spec-driven-delivery/spec.md`（W71 **新增**） | 「版本归属引用（形如「V3.9 §51.3」）……**MUST NOT** 随基线号变更」，且场景要求「改写为 V3.10 §51.3 **MUST 被拒绝**」 | §56.2 情形②；且 W71 **自己落地**的 29 条能力包标记写的正是 `【V3.10 §51.3（V3.9 收缩：自 rN 降为能力包）；INV-33/34】` |
| `docs/adr/0048` 的勘误段、`docs/adr/0049` 的「后果」行 | 同源的措辞 | 同上 |

**处置按 §56.2 的载体分界**（不是新规则，是既有规则的应用）：
`openspec/specs/`（**活的主规范**，§56.2 的历史记录清单只列 `docs/reports/`、`docs/adr/`、
`openspec/changes/archive/`）⇒ **就地订正**；`docs/adr/` ⇒ **追加勘误段**（原文不改写）。

**为什么这条比措辞更重要**：规格是**下一个升基线轮次的行为依据**。留着它，会把 W65 已证伪的判据
再执行一遍——而订正的目的恰恰是消除不实陈述。**残余风险如实登记**：这类**语义**矛盾没有门控，
本轮发现的这一处是靠**人读**出来的（见第八节）。

## 八、未做与遗留

1. **不做「规格 vs 基线」的自动对账**（ADR 0050 遗留 1）。§56.2 的四情形是**语义**规则
   （「这句是在声明当前基线，还是在陈述某一版」只能读出来）。本轮只覆盖**可机读**的那一半（编号与计数）。
   **残余风险的证据就是本轮本身**：规格里的矛盾是靠人读发现的，不是靠门控。
2. **§56.2「立即订正」与「跨轮次收录」的张力**（ADR 0050 遗留 2）：§56 前言要求「如实登记」之后
   **紧接着**订正现行规范，而 A12/A13（W54/W55 登记、W65 收录）与 B07（W68 登记、W71 收录）都是
   **跨轮次**收录。本轮把「待收录」做成可判定状态，但**没有**裁定「多久算太久」——待决策项。
3. **门控现在依赖基线的章节号与两张表的写法**（已知代价）：章节被重编号或表格被改写成别的形态时，
   门控**报解析失败**而不是静默通过——这是有意的取舍，解析失败与设计漂移**分开具名**。
4. **§16 的验收注册表仍不含 B07**：按 V3.10 §58.3 的设计保留（增行会位移行号）。
5. H18、B07 **仍为 `pending`**；§57.5 与 §48.7 的待决策项、§56.2 对 doc-comment 前辍引用 ADR 0015 是否恰当：沿用 W71 的登记，未动。
6. **基线 §58.6 仍写「两处门控缺口（本版发现，只登记、不裁定）」——基线不改，且这是对的**：
   该句是**关于 V3.10 这一版的陈述**（§56.2 情形③：「本版只登记、不裁定」在 V3.10 是事实），
   且基线被 ADR 批准后不可变。关闭的事实记在**本轮报告与 ADR 0050**，不在基线里回填。
   顺带一提：**§58.6 自己预测得很准**——它写这两项「需**专门一轮**并各自配**非空洞注入守卫**」，
   本轮正是那一轮，注入守卫 **21 组**。**这也是「冻结基线里的待办不会自己消失」的又一例**：
   它需要后续轮次**读到**它才会被处理（本轮读到了）。

## 九、方法论教训

1. **「补断言」的第一步是问「断言能不能写死相等」**。若被断言的一方**不可变**，相等就是死锁；
   正确形状是「相等 + 一份具名、相称、自清理的偏差台账」。**豁免要看得见，不要看不见。**
2. **守不住的地方不是「漏改」，是「解析悄悄落空」**。任何读外部文本的守卫都必须回答：
   「取不到东西时它是通过还是失败？」——本轮把它做成**具名失败**，并把解析失败与设计漂移**分开报**。
3. **用例的锚点必须恰好命中一次**。否则用例会改到别处而**假装通过**。
   这个守卫本轮**立刻开火**，并带出一个发现：**§58.5 早已用散文写了同一条断言**——
   **散文形式的断言不是断言，它不会失败。**
4. **缺口之间会互相消解**：缺口①（括号语义）需要的不是独立实现，而是把**判据来源**写对；
   写对之后它被缺口②的实现顺带覆盖。**先看两个缺口是不是同一个问题的两面。**
5. **订正本身也要被检索**：W71 改了基线、ADR、设计与提案，却漏了**自己的规格差量**——
   而同一条错引在 W71 是**四处活文档**（C6 教训）。**「改完全仓检索」必须包括本轮自己产出的文件。**
6. **规格与历史记录不是一类**：规格是活的主规范（就地订正），ADR/报告/归档是历史记录（追加勘误段）。
   同一段错误措辞，处置方式由**载体**决定，不由内容决定。
7. **「已登记」不等于「已闭环」**：本轮之前，这两处缺口在报告里写得很清楚——
   但**报告里的待办不会告警**。把待办变成断言，是唯一能让它自己出声的方式。

## 十、勘误（W73，原文不改写）

本报告两处表述在 W73 核实后被订正，按 §56.2 的载体规则**保留原文 + 追加勘误段**：

1. **§八 遗留第 2 条把 A12/A13 描述为「跨轮次收录」，这不准确。**
   逐版读基线正文后的事实是：W54/W55 新增 A12/A13/A14 时，**活索引 §48.5 还不存在**
   （§48 是 V3.8 的新章）；当时存在的 `§39.5 验收总表索引` 是 **V3.7 的版本专属章节**（§56.2 情形③），
   它的落后是**设计**而非漂移。偏差是**在 W56 出现的**——ADR 0047 新建的 V3.8 里，那份活的跨版本索引
   **诞生时就落后于注册表**（A 行写 `A01–A08；A09–A11 补充`，而注册表此刻已有 A12–A14）——
   直到 W65（V3.9）被收录，中间**九轮**没有任何记录写着「这里不一致」。
   ⇒ 它属于**静默漂移**（W56 引入、W65 收录），而不是「已登记但收录得晚」。
   「静默」与「登记了但晚收录」是两种不同的失败，本报告把它们混为了一谈。
2. **§八 遗留第 2 条同时写着该张力「没有裁定多久算太久」——W73 已裁定。**
   「紧接着」被读作**不晚于下一次基线修订轮次**，可判定形式是台账条目的
   `since_baseline` MUST 等于当前基线版本（跨版只有**收录**或**显式结转**两种处置）。
   见 ADR 0051 决策 2、`docs/reports/2026-10-12-w73-registry-schema-and-ledger-lifetime.md`。

**未变的部分（防止误读）**：本报告 §七 的 CI 结论、§八 遗留 1/3/4/5、§九 的七条方法论教训均继续有效；
台账 `baseline_deviations` 在 W73 之后**仍为空**。
