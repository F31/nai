# 迟到帧恢复与 WSL 编译能力

V5.6.1 调度器在设备播放位置已知时，校验帧身份、序号、槽代次及摘要后，直接丢弃超出允许迟到时间的帧，不占用待播队列；丢弃仍推进防重放状态。诊断程序单独统计 `dropped_late`，不把它当成成功显示。

Windows 定向调度测试 7 项和播放终止测试 1 项通过。使用合成画面、真实音频设备及静音，先发送 8 帧、暂停生产 1.5 秒、再发送余帧：168 帧接收、23 帧因迟到被丢弃、127 帧提交，最长安全画面约 958 ms；由于提交数超过停顿前的 8 帧，可证后续恢复显示。该演练不代表真实模型在持续慢于音频时能自行追上，也不作为嘴部质量证据。

性能方向核查：当前 Windows 推理环境未发现 Triton 或 flash_attn，之前使用 PyTorch 回退；现有 WSL Qwen 环境只读检查为 PyTorch 2.14.1+cu130、CUDA 和 Triton 可用、flash_attn 不存在。在 RTX 5090 上运行小矩阵 `torch.compile`，结果有限且与 eager 最大绝对误差为 0；探针报告 `target-windows/flashhead-acceptance/wsl-compile-probe.json`，编译和临时缓存指定 E 盘。首次 shell here-document 行尾错误导致探针在成功计算后以 NameError 退出，修正为独立脚本重跑退出 0。

这只证明小矩阵能编译，不证明 FlashHead 能编译、性能提升、画质不变或长期稳定。WSL Qwen 环境缺 diffusers、xfuser、yunchang、mediapipe 和 cv2；项目 E 盘旧独立虚拟环境也没有所需包。本轮未安装软件或改动 Qwen 环境。若继续验证，应在 E 盘建立隔离依赖、核对版本和许可、测真实模型/音画与显存，再决定是否影响运行架构。

用户反馈嘴部仍模糊；本轮没有人脸修复模型或画质通过证据。正式工作台、共享内存权限、M0 及长时实时均未闭环。
