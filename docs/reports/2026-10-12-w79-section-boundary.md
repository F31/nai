# W79 · 节界（按章节号取表需要一个边界断言）

- 日期：2026-10-12
- 基线：V3.10（`docs/直播数字人 + 智能体系统技术方案 V3.10.md`）
- 裁定：[ADR 0057](../adr/0057-section-boundary.md)
- 变更：`openspec/changes/archive/2026-10-12-w79-section-boundary/`

## 一、判断与范围

上一轮（W78）报告 §八遗留第 2 条写的是：

> **§51.2 刻意未读**：§51.2 是散文、没有表格，而 `sectionTable` 取的是「标题之后第一张表」
> ⇒ 对 §51.2 调用它会**静默取到 §51.3 的表**。……这条限制写进 ADR 0056 遗留 2 与 AGENTS.md，
> **不靠记性绕开**。

「不靠记性绕开」——但它事实上**就是**靠记性：那是一条**写给人的告诫**，不是**一条判据**。
而 `sectionTable` 不是某个解析器的内部细节，它是**三个解析器（§48.5／§51.3／§57.3）共同的地基**：
地基上的错会**同时**污染三张表。本轮做的就是把这句告诫变成**结构 + 判据**。

**范围**：只改 `scripts/contracts/baseline.mjs` 与 `tests/registry.test.mjs`；
**不改基线正文、不改 `tests/registry.yaml`、不改任何 Rust、不新增依赖边**。

## 二、审实

### 2.1 现状：搜索域是无界的（实测）

```js
let index = start + 1;
while (index < lines.length && !isTableLine(lines[index])) index += 1;   // ← 会一直走到文件末尾
```

**探针（只用公开 API，不改被测文件）**：给一段「§57.3 标题在、本节内没有表、后面跟着 §57.9 的一张表」
的文本，`parseReleaseLines` 返回：

```
found = true
errors = []                                        ← 一条错都没有
lines  = [["slice_0",["S01","S02","S03","S04"]]]   ← 这四行来自 §57.9
```

⇒ 它把**邻节的表**当成了 §57.3 自己的表。**这不是「解析器还不会读一段散文」，
而是「解析器会读错一段散文并且读得很自信」**——成功与失败两种情形的返回值**形状完全相同**。

### 2.2 三态不该合并

| 状态 | 含义 | 现状 |
| --- | --- | --- |
| 该节标题不存在 | 章节号被改指 / 被重排 | 已具名（W73 立） |
| 章节在、**本节内没有表** | 表被删 / 被挪 / 被更浅的标题挡开 | **完全沉默**，回落到邻节的表 |
| 解析成功 | —— | —— |

把后两者合成「解析出的表是空的」会让**上层用错误的措辞定位**：§57.3 会去报「计数行为空」、
§51.3 会去报「declares 0 capability packs」。**错误的措辞不只是不够精确，它会把定位引向错误的方向。**

### 2.3 边界该按什么定

按**标题层级**：`[标题行, 下一个层级 ≤ 该标题的行)`。层级更深（`####`）**不**截断——
写成「遇到任何标题就停」会把子标题误当节界，于是本节里明明有表却报「本节内无表」，那是**假阳性**方向。

实测 V3.10 的标题层级直方图 **`h1 = 1 / h2 = 59 / h3 = 259`，无 `####`**
⇒ 这半条语义在当前正文上**不可观测**，故**必须由合成存根验证**，而不是靠「反正现在没有」蒙过去。

## 三、裁定

见 [ADR 0057](../adr/0057-section-boundary.md) 决策 1–5，要点：

1. 搜索域由标题层级封闭；更深标题不截断；
2. 三态分开具名，**MUST NOT 回落到邻节的表**、也 **MUST NOT** 用空表代替；
3. `sectionTable` **导出**，使「§51.2 本节内无表」从**记性**变成**会被检查的前提**（§57.5 为第二个样本）；
4. 边界若被收得过紧，由**同一组判据自己抓住**（三张表同时报「本节内无表」）；
5. **不与 `pending-decisions.mjs` 的章节抽取合并**（那里按正则抽章节号、不取表；绑一起会互相牵动）。

| 注入 | 期望（实际均命中） |
| --- | --- |
| **F0** 基线（未注入） | 对账 `errors = []`、测试全绿 ⇒ **先证「本来就绿」**，免得把基线红读成注入生效 |
| **F1** §51.3 节内表格被删 | `§51.3 has no table inside its section`，且**不得**出现任何 `§51.3 declares …` ⇒ 证明**没有借 §52 的表** |
| **F2** §48.5 节内表格被删 | `§48.5 has no table inside its section` |
| **F3** §57.3 节内表格被删 | `§57.3 has no table inside its section`（**且计数行不再被冒充**） |
| **F4** 给 §51.2 插一张表 | 前提断言变红并具名（`§51.2 is prose`） |

| **F6** §51.3 与表之间插 `### 51.3.1`（层级写错） | `§51.3 has no table inside its section` ⇒ **同级标题确实截断** |
| **F7** §51.3 与表之间插 `#### 51.3.1`（层级正确） | **对账 `errors = []`、测试全绿** ⇒ **反向注入**：证边界**没有**被收得过紧 |

F7 是这一轮唯一「注入后必须仍然绿」的一项：**只验「会红」是不够的，还要验「不该红时不红」**——
否则把边界写成「遇标题即停」也能让 F1–F6 全绿。

**测试内**另用合成存根覆盖三处解析器自身的行为：本节无表 + 邻节有表（不得借用）、
`####` 不截断 / `###` 截断、以及 §51.2／§57.5 的前提。

> **一处方法论自纠**：第一版探针用 `pathlib.write_text` 还原，**它在本机会把 `\n` 变成 CRLF**
> ——文件从 226 578 字节涨到 229 291 字节，而**内容哈希（对解码后的文本算的）看不出这件事**。
> 靠 `git status` 才发现。⇒ **还原的核对基准必须是字节**；这与 W69「`copyFileSync` 连 mtime 一起复制」
> 是同一族教训：**验证脚本自己也要被验证**。已用 `git checkout --` 复原为 LF（字节哈希对上原值）。

## 八、遗留

1. **「第一张表」的语义未变**：本节内若有多张表（如 §48.5 有家族索引表 + H01–H18 逐条判据表），
   取的仍是第一张。删掉第一张而留下第二张时，本轮会报**内容层**的错（「unreadable family label」）
   而不是「无表」——**这是边界，不是缺陷**：节内定位从不是本轮的命题。
2. **层级语义在正文上不可观测**（V3.10 无 `####`）：由合成存根覆盖，已在 ADR 0057 决策 1 说明。
3. **不校验「章节号与层级的一致性」**（如 `#### 57.3.1` 挂在 `## 57` 之下）：属文档结构问题，
   不属取表边界。
4. **判据只覆盖被解析的那三节**：新增解析点 MUST 一并进 `tests/registry.test.mjs` 的 `PARSED_TABLES`
   ——那是「新增解析点要付出一次登记」的提醒（**不是**靠脚本自动发现的契约）。
5. **`CAPABILITY_PACK_IDS` 仍是手写数组**（W78 遗留 4 未变）：要真正生成 MUST 先解决
   `registry.mjs` ↔ `baseline.mjs` 的依赖方向。
6. **§56.2 的边界待明确**（W78 报告 §八第 8 条未变）：`openspec/changes/archive/` 里
   「上一轮发布的归档」与「本轮刚归档、尚未入库」是否同一处置，仍需一次基线修订写死。
7. harness 轨道 **H18 与 B07** 仍 `pending`；W76 台账的 5 条 `decidable_in_repo`
   （`PD-09/22/24/31/34`）仍只登记了推荐。
8. `cargo xtask schema --check` 本机仍跑不了（宿主对 node 派生任何子进程的 `EBUSY`）。
   本轮**未改任何 schema 与生成器输入** ⇒ 零漂移由结构性理由 + CI 独立步骤兜底，**未写成「已通过」**。

## 九、方法论教训

1. **「写进文档、不靠记性绕开」如果只有文档，那它就还是记性。** 一句告诫与一条判据的差别是：
   前者在**没人读**的时候失效，后者在**没人读**的时候报警。
2. **地基上的错会同时污染所有上层。** `sectionTable` 服务三个解析器——
   所以「本节内无表」这件事**不该只能通过三个上层的间接症状去观察**，它该是一个**导出**的、
   可被直接断言的性质。
3. **只验「会红」是不够的，还要验「不该红时不红」。** F1–F6 全绿也可能来自一个**过紧**的边界
   （「遇标题即停」）；F7 是唯一能区分二者的注入。**假阳性与假阴性不对称时，两侧都要有注入。**
4. **权威计数要选一个「不由人挑」的口径。** 目标数有两种数法（含不含 cargo 包装行）就会有两种结果；
   `^test result:` 的**行数**没有这个自由度——**先找一个不会歧义的口径，再用它校正常用的那个**。
5. **一个被订正过的错会回来。** W38/W71 明确修过同一处多算，W77/W78 又犯了一次，
   还给它配了一段**方向相反的归因**。⇒ 订正 MUST 落到**判据或口径**上，不能只落到一段说明文字上；
   否则下一次遇到同样的形状，人会**再一次**得出相反结论。
6. **验证脚本自己也要被验证**（W69 的第二次适用）：还原用的 `write_text` 把 `\n` 变成了 CRLF，
   而**内容哈希看不见**——因为它是拿解码后的文本算的。**核对基准要与被核对的量同型**（字节 vs 字节）。
