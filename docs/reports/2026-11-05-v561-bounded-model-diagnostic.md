# FlashHead 有界模型资源诊断

为 M0 准备新增 `scripts/flashhead-bounded-diagnostic.py`。测试使用官方 FlashHead 单进程和已授权肖像、此前 Qwen 实际生成的 2.08 秒语音循环；固定 8 秒音频缓存，每次只保留当前模型输出块，记录每块资源后释放，不写视频、不播放、不推流。只验证模型本身，不构成实时传输、音频时钟、OBS 或 M0 验收。进程内期限只在块之间检查，不能打断卡住的 GPU 调用。

Windows RTX 5090 Laptop；PyTorch 2.7.1+cu128，官方依赖版本，`TORCH_COMPILE_DISABLE=1`，无 FlashAttention。模型进入 eval；Wav2Vec2 的训练遮罩参数不在检查点，先前检查 eval 条件下不使用该参数。Qwen 服务在测试后健康，未发新合成请求。

记录文件：`target-windows/flashhead-acceptance/bounded-60s-20261105.jsonl`。模型准备至 ready 22.219 秒；63 块，处理音频跨度 60.48 秒，全部结束 86.859 秒；块平均 1.0144 秒、P95 1.063 秒、最慢 2.313 秒。每块对应 0.96 秒音频；从 ready 至完成约 64.64 秒，快于实时不能成立，可能产生累积延迟。数值含有限性检查与进程内诊断开销，不代表优化后极限，也不代表播放或 OBS 帧率。

按块采样进程 RSS 首块约 2189.1 MiB、末块 2195.0 MiB、最高约 2195.1 MiB；PyTorch 峰值分配约 5.0 GiB、保留约 5.54 GiB。每块模型输出为 float tensor，约 72 MiB；块间释放，未保存全段。RSS 不是系统总内存，GPU 统计不是整机显存峰值；60 秒有限性不能证明 10 分钟长稳。

验证：实机 63 块及完成记录，退出 0；`--help` 可在无模型加载下运行；OpenSpec 严格校验通过。真实逐帧共享内存、消费者背压、样本时钟、停止取消、真实实时语音、OBS 与 10 分钟 M0 均未实现或未验，不标记通过。下一步先优化测得的单位块耗时，明确视频时间戳/共享槽和音频输出，M0 未通过前不将它包装成生产就绪。
