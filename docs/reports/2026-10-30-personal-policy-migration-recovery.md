# 个人偏好迁移恢复判定

新增基于迁移日志契约的纯恢复判定：严格解析日志及重复字段，区分备份未核验、核验失败与核验通过；只允许合法阶段和数据库版本组合。已核验备份须先持久记录，再允许版本升级；数据库已提交而日志尚未完成时仅建议补写日志，绝不建议用旧备份覆盖已提交事实。数据库损坏、版本矛盾或备份校验失败均拒绝。备份状态必须由可信存储层对当前日志指定身份实际核验，领域层本身不做文件 I/O。

Windows 定向 `cargo test -p nai-runtime-core --lib personal_policy_migration --offline` 两项通过，覆盖阶段中断、版本矛盾、损坏/备份失败及伪造日志；`cargo xtask check-deps` 通过 31 包。首次未限制 `--lib` 的定向命令在链接无关 `public_media` 集成测试时发生 LNK1104（无法打开输出文件），原因未确认；随后仅针对变更库重新执行通过，不能声称该集成测试通过。构建缓存位于 E 盘 `target-windows/live-auto-build`。

本轮没有修改数据库或触发迁移。该模块只给出决策，尚无生产调用方；日志的持久写入、核验与激活的原子性、版本 3 数据库 schema、真正的进程中断恢复和原生集成验证仍未实现，验收注册表不变。
