# W05/W06 帧槽位所有权与Linux tmpfs-file演练报告

日期：2026-10-09。基线：V3.6 §26.3/31.2 W05/W06；验收来源 tests/registry.yaml（A01、R03）。
OpenSpec change：w05-w06-frame-slots；ADR 0017。环境：Linux/WSL，Rust1.96.0、Node22.23.1、pnpm8.15.0、OpenSpec1.14.1。
没有设备、GPU、SDK或Python，没有真实付费调用。

## 实现

- 新增 provisional Protobuf：FrameSlotTicket（元信息，不含数据）、FrameSlotCommit、FrameSlotEvent（write_started/committed/error）。提交分支按生成器配置boxed，避免oneof过大；线格式不变，未手改生成代码。
- nai-media-core 新增 `frame_slots`：单owner Free→Writing→Ready→Reading→Free 状态机；ticket 绑定 pool identity/session/epoch/双方身份/slot_generation/整份metadata；最多16槽、8MiB每槽、64MiB每池；reserve期限非延长≤250ms。
- commit/read 校验 RGBA8 精确长度、metadata 一致与 SHA256；release 前不可覆盖 Reading；ABA/重复/未知身份/作用域不符返回 StaleEpoch/PermissionDenied。
- 超时、断连、读取取消或完整性失败一律退休整池，不复用内存；新池 identity 不同。
- Linux `shared_ram`（tmpfs-file-drill）：私有 `/dev/shm` 目录（当前owner、0700）、unlink 的0600文件、继承FD、safe Rust 分块 `read_at/write_at`，有复制；非Linux返回 CapabilityNotReady。
- `nai-shared-frame-drill` 一次性子进程：需显式 `--shared-frame-drill <ticket-hex>`，stdin 为继承数据FD，stdout 仅有界 Protobuf 事件；`--stall-after-partial` 用于强杀演练。
- 端到端：W06 2D 真实合成像素写入槽位，reader 读回owned副本，元信息/完整性一致；buffer_ref 由owner产生，与渲染器本地引用不同。

## 状态与缺口

- A01保持implemented：新增帧数据面所有权与真实工程传输证据；但独立render-worker/keeper生产装配、protected handle broker、命名管道身份与Windows映射未实现，不能标完整tested。
- R03保持implemented：新增“producer强杀→整池退休→新identity”可移植证据；正式engine/bridge/worker与设备故障矩阵仍缺。
- tmpfs-file-drill 是 Linux 工程后端，有复制，不是mmap/零拷贝，不是正式buffer.channel/output.deliver支持，不产生播放ACK。
- 逻辑退休不保证恶意/卡死peer立即释放FD；supervisor须kill/wait。本轮测试已kill/wait。
- 无1080p性能/RSS测量、无设备/GPU、无Windows映射认证。
- 下一主线：独立render-worker与keeper装配、protected handle broker身份与命名管道验证，再接真实进程故障与待机切换。
