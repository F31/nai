# 真实 FlashHead 帧交付 Rust 的隔离诊断

新增 Python 有界共享槽发送器、独立 Windows 只读映射助手和 Rust 接收器。Python 与 Rust 控制消息采用 V5.6.1 Protobuf，映射助手与 Rust 间另用有界二进制媒体管道；每帧校验 epoch、序号、槽位代次、尺寸和 SHA-256，接收器确认后才复用槽。Rust 不直接使用 unsafe 映射操作；实际映射读取由独立 C++ 进程完成并有一次跨进程数据复制，不是零拷贝。

真实模型验证使用已授权肖像及此前本地 Qwen 语音，FlashHead Lite 生成两个块共 48 帧（512×512，25 fps），Rust 验证并确认 48 帧。记录 `target-windows/flashhead-acceptance/rust-shm-20261105.jsonl`；其中两个块传输耗时分别约 0.0872 和 0.0395 秒，未包含完整直播输出，不能据此推断长期帧率或延迟。首轮因官方模型源码要求工作目录为上游目录而未启动；修正目录后成功。

Windows 定向测试 2 项通过：真实共享段多次复用和接收进程退出后无确认；后者还修复了清理已断开管道时的异常。测试及真实模型未调用付费接口、未播放音频、未推流。

本次是受调用方约束的隔离诊断：映射名称由同机进程传入，未完成命名映射 ACL、对端身份认证和生产生命周期管理。Rust 目前只核验并丢弃帧，未把它们接入设备时钟、窗口或 OBS，不能说真实播放链路已打通；M0 仍未验收。下一步需将经过权限约束的帧接到时钟调度和常驻窗口，并与同一音频流作整链测试。
