# V5.2 设计增补：智能体与写实数字人一体化

2026-10-30；设计目标，非已实现或验收声明。本增补基于 V5.2、ADR 0190/0191、个人模式与写实数字人活动 OpenSpec，以及 [CreatorBox 静态研究](reports/2026-10-30-creatorbox-technical-review.md)。CreatorBox 核心模型与服务端受保护；其文档所述能力仅作为体验和接口设计参考，不推断具体模型、平台授权、实时指标或代码复用权。资料参考：[数字人生成器](https://xiesx123.github.io/CreatorBox/zh/component/dh)、[发布记录](https://github.com/xiesx123/CreatorBox/releases)。

## 产品目标和边界

用户选择自己的合法真人视频、声音和主题/资料后，可预览数字人，明确开始后由统一直播智能体持续讲解；可选择关闭公屏，或在真实获准平台接入后设置抽样比例，由智能体挑选相关问题、AI 生成回答、语音播出并返回讲解。真人随时接管、暂停、静音或停止。只填写主题也应支持生成内容，但无可核实依据时不得把模型猜测包装为资料事实；输出按现有守门及个人模式最终裁决执行。

用户选择/上传视频是优先的真人效果入口；照片作为可选独立能力，只有实测模型支持才显示可用。真人底版负责外观、镜头和素材自带动作；实时音频驱动口型，有限表情或动作由获准片段/已认证后端提供。视频底版不等于自由手势、实时全身生成或三维模型，明确展示可用动作。声音默认复用已配置 Qwen-TTS；主播麦克风直驱嘴型与真人音轨接管是不同能力，单独启用和验收。

## 首页与一键准备

首页依次提供形象卡（选择已有或导入视频、私有预览）、声音（已保存配置与试听）、主题/资料（可选人工内容）、互动（仅主题 / 主题加平台，平台可用时选择并设置比例）、画面与开始/暂停/静音/接管/结束。自动检测既有模型与输出，正常状态收起，失败提供明确原因及可点击修复；只在缺失时要求必要输入。工作区、模型、设备和高级参数放设置，原内容、历史和复盘仍可达。常见参数有安全默认，文件与设备优先选择器；不展示技术路径、协议或内部审批对象给普通使用者。

“准备画面”与“开始直播”分开：前者按需准备本地渲染、私有试听及公共输出，不发平台开播命令；后者在真实条件就绪后由用户明确触发。平台开播的执行方式依各实际授权和适配能力，不能将 OBS 连接当作平台已开播。一键准备为可取消有界状态机，分别观测引擎、模型、形象/许可、音频设备、画面、OBS 进程/控制连接/场景与源/音轨/实际信号及平台连接；没有证据显示未知，失败不自动重复外部副作用。公屏未授权时仍可仅主题讲解。

## 真人视频、实时音画与输出

合法视频导入以有限大小/时长/格式、稳定身份与版本、源哈希及授权记录管理；预处理在独立受限宿主执行，检测解码、人脸有效性、姿态、尺寸、时长及画面质量并提供人工预览、失败原因和可重试入口。所得素材/缓存绑定源、模型与参数版本；替换、撤权、删除或过期时取消相关任务并复检输出。权限声明不等于自动证明权属。未上传授权人物数据到外部服务；未来用户主动选择远程服务时另明确数据流及授权。

Qwen 音频产生后按实际输出样本时钟驱动口型及字幕，分句和预取有界，缓存身份包括音频内容、模型/配置、视频版本和有效期。允许预计算但须记录首音及额外等待；对真正流式 TTS 单独声明和测量，不能用整段预计算冒充低首包时延。画面帧附会话、epoch、形象及模型版本、帧序和 PTS，控制面与 PCM/帧数据面分离。预览消费同一经验证生产时间线且独立有界、可丢旧帧，不反压公共输出。

实时调度优先 P0/撤权/真人接管，其后按受限计划处理当前句、用户点播与选中互动；普通插问可在句边界暂停并在有效上下文下按真实完成回执归位。中断、清空队列、停止与恢复各自明确语义；已提交或未知结果不得自动重播。输出进程独立执行租约与安全停止，不因外部渲染器、LLM 或数据库阻塞失效。虚拟摄像头是可选独立输出能力，音频须单独路由；不改变既有窗口捕获路径，未经认证不宣布可用。

## 后端与 CreatorBox 对照

统一渲染能力契约描述输入素材、音频格式、版本、支持动作、时间戳、健康、可取消操作和实际输出回执；内核不依赖具体 SDK，组合根按能力装配并保护媒体数据通道。V5.2/ADR 0190 的 NativeOnnx 保持正式默认目标；MuseTalk 仍是首选验证候选，模型/前后处理/运行工件需逐项核验。研究 Python 推理和外部 Qwen 不冒充 NativeOnnx。

CreatorBox 仅为可选独立本地服务候选：先确认使用和集成许可、确切版本及其模型权利，再基于公开接口验证启动、状态、音频提交、完成、打断、停止、失联、音画出口与回执。外部服务是否满足身份绑定、可取消、媒体传输和独立停播须实测；不能由 Socket.IO 命令成功或虚拟摄像头存在推定。若外部服务自行持有未经 keeper 约束的直接播出通道，不能用于受控公共输出；仅可按实际许可和安全范围进行隔离预览。若未来认可为独立 Python 服务 profile，必须通过单独 ADR 和适用规则裁决，披露依赖、权限、资源、故障和部署条件，不静默变更正式 Windows 无 Python 推理的既有约束。现阶段不安装、不嵌入、不分发其代码/权重。

## 执行顺序和完成条件

1. **写实样片优先**：冻结候选模型/资产/依赖及来源，使用合法真人视频和本地 Qwen，完成第一段可播放的对口型视频，记录画质、首帧、同步、性能、失败；并行核实可选外部服务许可和固定版本。单张照片仍可作模型诊断，不代替视频主体验证。
2. **连续公共音画**：完善实时帧/音频及预览契约，接入有界渲染宿主和公共输出，完成连续待机、讲解、停止/撤权、音画回执及 OBS 实录；先以不推流的本机验收闭环。
3. **智能体讲解与插问**：复用可信内容、任务上下文、问题池、分句预取、已播回执；实现无公屏主动讲解、已获准公屏筛选、问答、归位、真人接管恢复；无授权渠道明确不可用。
4. **个人首页和一键准备**：按新流程提供实际可执行入口及失败修复；个人模式的工作区策略、预算与授权须先完成 ADR 0191 与现行主规格差异裁决、迁移和恢复，不通过隐藏控件绕过原有守门。用户真实体验和回退要单列结果。
5. **验收与发布**：选定同一台机器、同一合法视频和 Qwen 音频进行候选后端对照；记录版本、首帧、首音、帧率/丢帧、AV 差、停止/接管、资源峰值和释放、听感/画质、OBS 音轨及 30 分钟→2h→8h→候选 24h 分级结果。实时/跨平台/长稳各自以实测为准。日常只测变更闭包；发布组合执行适用完整门槛。CreatorBox 可选对照失败不阻塞原创后端继续验证，但不得因此宣称 CreatorBox 或 nai 已认证。

以上均是设计和任务，不变更 `tests/registry.yaml` 的现行 164 项状态，不把源文件、模型下载、单次 GPU 算子、模型生成或模拟测试当作完整直播通过。
