# V5.6.1 性能预算与工作筛选规则

日期：2026-11-11。决策依据：ADR 0203、[ADR0204](adr/0204-personal-live-experience-budget.md)（用户采纳的个人直播体验预算修订）。适用范围：V5.6.1 单引擎基线的所有性能与优化工作。

## 北极星

2026-11-17用户明确选择完全本机、允许新回答等待数秒（[ADR0205](adr/0205-local-waiting-reply-experience.md)）。下表3秒新回答目标保留历史与优化参考，不再是个人本机新回答准入硬门；新的数值体验上限尚未约定，不能将45秒取消deadline称为合格等待。缓存播放、句间、取消及内容完整性要求不变，机器预算文件不改写历史。自动AI问答/归位仍须真实验证。

M0（`tests/v561/registry.yaml` 已定义的 5 项：SETUP-01/02/03、TTS-01、HEAD-01）是当前唯一北极星。
任何不移动 M0 的工作排在其后；每轮结束必须回答「本轮让哪项 M0 证据前进了什么」，
回答不了的工作不下轮继续。

首声预算及TTS首块性质已按用户指示修订，其余门不变，不追改历史报告中的旧门。机器预算为 `tests/v561/experience-budget.json`，由Schema和体验检查器验证。实测取自 `docs/reports/2026-11-10-v561-generation-progress.md`、
`2026-11-11-v561-fp8-graph-combination.md`、`2026-11-11-v561-avatar-compute-profile.md`。

冷启动的模型加载/准备单独报告，不计入“已就绪后”的首声；不得通过预先调用未知内容或假音频隐藏延迟。输入已备文本的运行明确不包含LLM，TTS首PCM不等于端到端首声。连续讲解以设备逐句首尾重算gap、累计静默和增长趋势，`ready_count`只作诊断。单TTS常驻、一个未来句槽、条件缓存及任务内PCM/帧复用；跨任务整句缓存未接入时不得声称命中。缓存不补偿持续吞吐赤字，30分钟未执行则保持pending。

2026-11-11动态质量反馈：用户认为本轮512/3说话视频太模糊，因此512/3保留为性能实验，不能凭抽帧“≈4步”授予动态质量通过；新独立体验组合恢复此前接受过的768/4质量参数，用户随后确认该768/4组合“清晰度可以接受”（仅本轮清晰度）。768/4的实时吞吐/3秒首声仍独立验收，不因画质退路而改绿。

## 工作筛选规则（先算上限，再动手）

1. 任何优化轮开始前必须写出该杠杆的 Amdahl 理论上限：它作用在占总耗时多少比例的阶段上、
   极限能省多少。上限小于缺口则本轮不做。按 2026-11-11 数据：去噪占视频 53%、VAE 解码 35%、
   动作编码 8%；只优化去噪内 GEMM（去噪的 69%）的极限是总视频 −37%，仍不够把 RTF 1.4 压到 0.8。
2. 单次测量差异 <5% 在当前环境噪声下按零处理（环境含共享 GPU、主机内存压力、计时量化），
   不作为激活或拒绝候选的证据。
3. 每轮必须带机器状态前导：GPU 占用进程、可用物理/虚拟内存、温度/功耗、后台合成进程清单。

## 结构性杠杆优先级（数学上能闭合缺口的方向）

1. 去噪步数 4→2：上游对 2 步有一等时间表（`flash_head_pipeline.py`），理论去噪时间减半。
   质量门：同分辨率黄金帧像素指标 + 操作者人工审看。
2. 渲染分辨率 768→512：上游默认即 512（`infer_params.yaml`），VAE 解码与变换器 token 数
   近平方下降。质量门：缩放到同尺寸对比 + 人工审看。
3. 编译/量化做透一次（TensorRT 或带校准的 FP8 + 图重放嵌套），限时封顶，不做第二轮微调。

三者叠加的理论区间 RTF 0.3–0.6。若全部做完稳态 RTF 仍 >0.9，触发决策门（见 ADR 0203）：
直播路径改用 2D/audio2blendshape（仓库已有 avatar-2d 与基线内置二维形象），FlashHead
转为离线预渲染片段（V5.6.1 基线已授权的预录片段路线）。

## 测量协议

- 固定输入：`target-windows/v561-32frame-first-packet/source.pcm`（92160 样本 / 3.84 秒）、
  固定种子 42、同进程热态、编译边界与正式候选一致（块级编译 + eager SDPA）。
- 每配置至少 2 个独立进程样本；报告中位数与范围，不报单点。
- 采集帧（capture）运行与计时运行分开；采集运行的墙钟标注含 IO，不作计时证据。
- 后台 GPU/内存消耗者（如并行合成服务）必须先停止或如实记录为噪声来源。

## 流程双轨

- ACC 轨：移动 registry 验收的切片，走完整 OpenSpec（proposal/design/tasks/specs）。
- 实验轨：profiling、探针、候选测量，只产出 `docs/reports/` 实验报告与保留产物，
  不建 ADR、不动 registry、不升级任何 ACC。实验轨结论要进入主路径时，再开 ACC 轨变更。
