## 1 目标、范围与发布线

### 1.1 目标

做一个「数字人 + 智能体」系统：数字人负责形象、声音与表演，智能体负责感知、决策、行动、记忆与评估。核心问题是：该不该说、说什么、有没有依据、是否获准、何时说、怎么演，并且全程可审计、可接管、可回放。

### 1.2 固定约束

- LLM 与 TTS 使用 API，首版不部署本地 LLM/TTS。
- 本地知识库与 RAG，兼容第三方知识 API，统一契约。
- 写实形象运行端为 Rust + ONNX Runtime，正式安装包不依赖 Python。
- Windows 桌面首发；本地优先，Local 部署不需要自建云主机。
- Lite / Standard / Pro 是同一内核的能力预设，不是三套代码。

### 1.3 非目标

本地 LLM/TTS；手机本地写实克隆（作为单独认证的实验）；智能体改价、转账、上下架、封禁；观众连麦 ASR；非官方抓取；多智能体自治协作。

### 1.4 发布线与范围冻结

| 级别 | 内容 | 退出条件 |
| --- | --- | --- |
| Slice-0 演练闭环 | 内核骨架；手工事件 → 模板/LLM → 守门 → TTS API → 2D → 录制；决策日志；output-keeper；最小桌面控制台 | S01–S04、R01–R03、R07、A01、A04 |
| R1 = Lite | Slice-0 + 审批与接管 + 真人接管音轨 + 手机监控包（可选）+ R0/R1 知识 + 声明式技能与官方只读技能 + 市场客户端 + 合规门禁 + 演示包 + 基础复盘 | R1 范围内全部 S/R 项、A01–A07、B01、B03、B05、B06、O01–O05、M01–M07、M13–M16、M18、H01–H12、H15、H17、H18 |
| R2 = Standard | R1 + 写实形象（过 Gate）+ 混合检索 + 节目编排 + 抖音正式接入 + 聚类与预合成 + 影子模式 | B02、B04、R06、R11、A08–A10、P01、H13、H14、H16 |

| 实验 | 手机本地运行、手机出画、私有化 Provider、wasm 宿主 | 不阻塞主线 |

契约冻结规则：

- 契约状态：Draft → Frozen(v1) → Deprecated。只有被某个切片验收用例覆盖的契约才能 Frozen，其余保持 Draft，不生成消费者代码。
- 宿主实现顺序：先 inproc 与 subprocess；wasm、remote 宿主以及 Postgres、NATS 适配器只保留契约，首个真实插件需要时再实现。
- 偏离设计必须写 ADR；不得为赶进度跳过安全不变量与模型 Gate。

## 3 总体架构

### 3.1 分层

- L5 体验层：桌面控制台、手机监控包、团队控制台。只发命令、看状态，不持有媒体时钟与密钥。
- L4 智能体层：决策、守门、记忆、技能、节目编排。以插件形式存在。
- L3 能力层：LLM、TTS、知识与 RAG、数字人渲染。以插件或远程服务形式存在。
- L2 媒体与输出层：output-keeper、render-worker、输出适配。
- L1 接入层：手工与回放连接器、平台连接器。
- L0 稳定内核：只含八项机制，不含业务策略。

上层只依赖下层的能力契约；跨层调用经内核做权限检查并记入决策日志。

### 3.2 内核的八项机制

能力登记与绑定解析；生命周期与健康检查；会话与 epoch；调度原语（有界队列、截止期、令牌）；权限与租约执行；配置与凭据访问；控制通信与媒体通道协商；审计与观测接口。

策略不在内核：内容策略、风险分级表、知识排序、LLM 选择、节目脚本、\*\*播报调度策略（公平、预算比例、聚类规则）\*\*都是可替换模块或配置。内核只提供队列与令牌原语。安全不变量（第 2 章）不能被任何可编辑策略撤销。

### 3.3 进程拓扑

| 进程 | 职责 | 崩溃影响 | 恢复 |
| --- | --- | --- | --- |
| engine | 内核、会话、调度、智能体、知识、Provider 调用、决策日志（官方插件以 inproc 运行） | 停止新生成；keeper 在租约到期后静音并待机 | supervisor 重启，只恢复待机，不恢复旧审批与自动权限 |
| output-keeper | 画面窗口、音频设备与播放、租约校验、待机画面、虚拟人标识叠加、本地静音与热键、真人音轨混音 | 出画中断（逻辑最简，故障概率最低） | supervisor 重启；OBS/伴侣预置待机场景作为最后手段 |
| render-worker | 2D 渲染或 ort 推理，经共享内存向 keeper 送帧 | keeper 切待机画面，静音通道不受影响 | 重启后需新授权；写实失败不自动当作 2D 通过验收 |
| platform-bridge（C++） | 官方 SDK 桥接，事件转发 | 平台事件中断，自动互动撤权；手工与回放仍可用 | 重连后不恢复旧自动权限 |
| control-server（可选） | 手机中继与集中管理 | 手机失联；本地实时链路不受影响 | 无状态重启 |
| supervisor / update-helper | 监督重启、升级替换 | 无自动重启能力 | 极小体量，独立于被替换程序 |

keeper 与 worker 的拆分是相对 V3.5 的关键变化：keeper 不加载模型和 Provider，只负责出画、出声与静音，因此 CUDA 崩溃或模型 OOM 不会带走静音通道与待机画面。

### 3.4 控制与媒体分离

- 控制消息有界（初值 64KiB），紧急命令使用独立队列与连接，不与业务共享容量。
- PCM 用有界环形缓冲；视频帧在 render-worker 与 keeper 之间走共享内存，不经 JSON 或 Base64。
- 内核只协商通道、租约与失效，不逐帧解析像素。
- 事件投递至少一次并幂等处理；音频跨故障不宣称恰好一次，状态不明的旧句不重播。

### 3.5 宿主与信任域

| 宿主 | 加载方式 | 崩溃隔离 | 适用 |
| --- | --- | --- | --- |
| inproc | 编译期静态链接，由 Cargo feature 与配置选择；不支持运行时加载动态库 | 无（OOM、abort、忙循环、FFI 无法隔离） | 官方审查的规则、调度、基础检索 |
| subprocess | 运行时启动，命名管道 | 进程级，但不是权限沙箱 | 平台 SDK、GPU/模型、复杂解析 |
| remote | TLS 上的 RPC | 远程 | 第三方知识、网关、云渲染 |
| wasm | 运行时加载组件，限内存与执行预算 | 沙箱（认证后） | 规则、只读变换 |

信任域（official / enterprise / community / dev）由内核按签名验证与信任库派生，清单中的自报字段一律忽略。inproc 仅允许 official 与 enterprise。

## 4 契约与插件体系

### 4.1 能力注册表（唯一事实源）

`schemas/catalog/capabilities.yaml` 是能力目录的唯一来源，文档表格由它生成。每项包含：id 与主版本、类别（内核原语 / 宿主原语 / 插件契约）、必需性、状态（Draft / Frozen / Deprecated）、首次出现的切片、缺失时的降级行为。

当前插件契约：platform.events、agent.decide、guard.check、knowledge.retrieve、memory.access、skill.invoke、show.plan、llm.generate、tts.synthesize、avatar.render、output.deliver、control.manage、storage.persist、runtime.observe。宿主原语：audio.timeline、channel.open、media.clock、avatar.profile。开放平台相关契约（Draft，自 R1 起逐步冻结）：skill.invoke、data.query、data.subscribe、device.sense、device.control、market.catalog（客户端）、asr.transcribe（预留）。

V3.5 的旧名兼容表删除。系统尚未发布，不需要兼容适配。

### 4.2 必需性与绑定解析

- required：缺失则会话不可就绪。conditional：缺失只阻止对应模式或场景（如知识回答需要检索）。optional：缺失则按降级表运行。
- Prepare 时：读档位与部署配置 → 场景要求 → 依赖闭包 → 签名与版本检查 → 启动必要宿主 → 健康检查 → 主备解析，生成 CapabilityView 与 BindingSnapshot。
- 降级表是数据，不写在插件代码里；智能体读取 CapabilityView 调整行为，界面用同一视图显示已降级项。
- 明确的降级前提：缺 guard 则拒绝所有外发；缺 avatar.profile 则拒绝激活该形象。

### 4.3 清单、生命周期与热替换

- 清单包含：插件 ID 与版本、内核版本范围、契约、supported\_hosts、依赖能力、资源认证 profile、权限、模型与素材哈希、许可、配置与数据 Schema、迁移钩子、健康检查、回滚兼容范围。
- 生命周期：Absent → Installed → Validated → Ready → Active → Idle → Suspended；失败进入 Failed，升级进入 Draining。
- 直播中允许：预算收紧、权限撤销、知识失效、Provider 在句边界切换。程序、模型、形象包更新只暂存，不在活动会话中替换。

### 4.4 签名、信任与撤销

签名只证明来源与完整性。准入由内核信任库、审核记录与撤销列表决定。升级包、插件、模型都要校验哈希与签名并检查撤销列表。

### 4.5 第三方扩展策略

首发只有官方构建、remote 服务、声明式技能与接入器（无自有代码），以及通过认证的 wasm。第三方原生 subprocess 在 AppContainer 或等价受限环境的认证完成前不开放。Job Object 只约束资源与生命周期，不是权限沙箱。

### 4.6 一致性测试与依赖纪律

- 每个 Frozen 契约配一致性套件：契约合法性、流式语义（正常结束、错误、超时、取消）、迟到数据按 epoch 丢弃、背压、错误码、幂等。
- 声明多个宿主的实现，在每个声明的宿主下通过同一套件。
- 同一主版本内只增可选字段；内核同时支持 N 与 N-1 次版本。
- CI 依赖检查：contracts 不依赖业务包；kernel 不依赖 plugins、native、Tauri；plugins 之间零直接依赖；UI 不访问数据库与凭据；media 不直接调用 LLM/TTS 公网接口。

## 5 智能体运行时

### 5.1 决策循环

观察 → 决策 → 授权执行 → 行动 → 写决策日志。

- Observation 包含：模式与能力视图、触发事件、当前产品与节目段、最近实际播完的句子、媒体状态、待播秒数、截止时间、预算、获准的观众上下文。平台未提供的字段标 unknown，不编造。
- Decision 动作：speak、stay\_silent、ask\_human、request\_skill、request\_scene\_change、defer。**沉默是合法动作。**
- Decision 只是请求，最终授权由运行时执行；模型不能直接触发播放，也不能写业务数据。

### 5.2 分级路由

| 路由 | 适用 | 调用策略 |
| --- | --- | --- |
| 固定模板 | 欢迎、礼物合并感谢、已批准节目句 | 不调 LLM，可复用有效语音缓存 |
| 直接回答 | 一般互动、非敏感闲聊 | 一次短上下文 LLM，不先做独立分类 |
| 知识回答 | 产品规格、活动、售后政策 | 检索证据后一次 LLM；事实核验失败转人工 |
| 人工处理 | 缺证据、争议、个体承诺、越权要求 | 给操作员候选，不自动外发 |

多步工具规划不进入实时自动路径。未入选的事件不触发任何付费调用。

### 5.3 播报容量与调度

- 回答 20–40 个汉字，上限约 60；按 3 字/秒估算，30 字约 10 秒，最终以实际 TTS 时长为准。
- 语音债务 = 当前剩余时长 + 待播时长。初值：一条播放中、最多两条短待播、总待播不超过 20 秒；超出则拒绝生成或合并。
- 优先级：P0 静音与授权撤销 > P1 人工点播 > P2 已批准关键节目句 > P3 相关产品问题 > P4 合并感谢 > P5 寒暄。TTL 初值：问答 15 秒、欢迎 5 秒、感谢 20 秒，过期不补播。
- 预算比例（问答约 65%、欢迎与感谢约 20%、节目约 15%）是场景策略初值，不是固定标准。
- **聚类合并**：TTL 内语义相近的问题合并成一次回答并点名多位观众。涉及价格、库存、优惠、承诺的回答不参与合并复用，每个提问仍单独校验事实。
- **节目感知预合成**：节目计划已知的后续段落与高频问答，在空闲时预合成并缓存。缓存键包含最终文本、事实版本、Provider 与模型、音色、发音规则、音频参数，事实变化立即失效。
- **价值/秒排序**：同级候选按「相关度 × 紧迫度 ÷ 预计占用秒数」排序，为规则化初值，不引入在线学习。每位观众设冷却与占比上限，防止被刷屏者垄断。
- 调度策略是可替换模块，内核只提供队列与令牌原语。

### 5.4 守门

| 阶段 | 检查 |
| --- | --- |
| input | 注入、隐私、越权、场景是否允许回答 |
| evidence | 权限、来源、版本、冲突、有效期 |
| output | 内容、金额与单位、引用是否来自本次检索、承诺限制 |
| preplay | 审批、事实、epoch、授权、租约的最后核验 |

- 结果：pass、rewrite、block、escalate，附原因、规则版本与风险。
- 重写后重跑相关阶段，最多重写 1 次，不无限递归调用 LLM。
- 风险等级由受控规则与事实决定，模型自报的低风险不作数。
- 守门分 basic、standard，可叠加审核 API。自动受监督模式的策略前置条件要求 standard 及以上。基础守门不能因缺少收费审核 API 而被绕过。

### 5.5 记忆

- 工作记忆：有界保留最近播完的内容，未播内容不写成事实。
- 场次记忆：已讲主题、已回答问题、已批准承诺、恢复点，优先确定性提取，必要时才用 API 摘要。
- 语义记忆：就是知识库，不混入未经批准的评论。
- 观众长期记忆：**默认关闭**。开启需记录平台与应用作用域 ID、用途、少量允许字段、授权、保留期和删除入口；不跨平台关联身份，不用昵称作唯一标识，不从情绪推断敏感画像。

### 5.6 技能与风险分级

| 级别 | 示例 | 处置 |
| --- | --- | --- |
| risk\_0 | 普通回答、只读事实查询 | 自动，经守门 |
| risk\_1 | 有事实依据的产品解释；向运营发通知 | 自动，限频并审计 |
| risk\_2 | 切商品卡、弹出优惠、触发互动 | 人工批准，且平台能力已授权 |
| risk\_3 | 改价、转账、上下架、封禁、改配置 | 不暴露给模型 |

技能描述包含参数与结果 Schema、权限、副作用分类、风险、期限、并发与幂等。URL、SQL、文件路径不能由模型任意输入，只能选择受控资源 ID。工具返回也是不可信数据，不执行其中的「下一步指令」。名义上只读的远端接口也要逐个审核副作用。

### 5.7 节目编排与表演

- ShowPlan 包含场景、版本、段落、目标时长、主题与脚本引用、打断策略、检查点与证据绑定。检查点保存段落与已完成句，不保存未播出的生成文本；恢复前重新校验产品、价格、活动、素材与授权，重启默认待机。
- PerformanceCue 包含：cue\_id、session\_id、utterance\_id、epoch、display\_text、speech\_text、risk、evidence\_refs、fact\_versions、voice、performance（emotion、gesture、gaze、intensity）、policy\_version、过期时间、approval\_ref。不支持的动作映射到已认证的基础动作或省略，降级只影响表演，不改变已批准事实。
- **表演存在感层**：待机微动作（眨眼、呼吸、点头）和「读弹幕时视线转向」，由渲染层按 cue 与状态驱动，不改变已批准内容。2D 在没有音素信息时是音量驱动嘴型，界面如实标注，不宣传精确音素口型。

### 5.8 决策日志

- 只追加，哈希链（每条包含前一条的哈希）。记录链：事件 → Observation 摘要 → Decision → 守门结果 → Cue → 审批 → 合成与缓冲 → 本地播放 ACK → 取消或过期原因 → 用量。
- 统一用途：审计与申诉材料、回放平台、影子评估、黄金集回归、崩溃恢复（状态表是日志的投影，可重建）、成本对账。
- 回放需要记录 Provider 的返回。默认记录并脱敏，场景可关闭；关闭后回放只验证决策与守门。观众原文与昵称按保留期脱敏。
- 日志写入不得阻塞 P0 路径。写入失败进入有界缓冲并告警；授权、事实、审批等关键提交仍须先持久化。

### 5.9 评估与运营闭环

- 黄金集随场景版本，覆盖正常回答、事实更新、注入、冲突、越权、无答案、取消、工具返回攻击。修改提示词、人设、规则、模型或知识后，必须通过相关回归才生效。
- 模式爬坡：演练 → 影子（候选只记录，不合成）→ 人工辅助 → 受监督自动。
- 人工修改回流：被改写或驳回的候选进入坏案例池，经人工确认后扩充黄金集。
- 场次复盘报告：互动量与入选率、回答覆盖率、人工批准/修改/拒答比例与原因、延迟分位、故障与降级事件、成本与预算、守门命中分类。

## 6 知识与 RAG

| 层 | 内容 | 存储与检索 |
| --- | --- | --- |
| KB0 权威事实 | SKU、规格、价格、库存口径、活动条件 | SQLite 结构化表，精确 ID 与别名查询；有版本、有效期、发布人 |
| KB1 文档与 FAQ | 说明书、售后政策、已批准问答 | 中文分词 + FTS5/BM25 |
| KB2 语义检索 | 自然表达问题、较大知识集 | Embedding API + 本地向量索引，与词法结果融合 |
| KB3 第三方知识 | 外部知识服务 | 同一接口，保留返回能力与信任标记 |

- 价格、承诺、活动规则只信 KB0，不由向量相似度推导。文档与结构化事实冲突时按明确的权威来源处理并提示冲突。
- SQLite FTS5 默认的 unicode61 不是中文分词器。必须使用可验证的中文分词预处理或自定义 tokenizer，并测试一、二字短词。
- 流水线：产品与场景过滤 → 精确事实 → 词法检索（必要时加向量）→ RRF 等融合 → 取 3–5 条证据 → 生成 → 重要实体逐项校验。检索前后都做权限过滤，返回后再校验版本与有效期。无证据、有冲突或已过期时澄清或转人工。
- 切块 300–600 字、重叠 50–100 字、候选各 10–20 条，是调试起点。
- 发布：导入 → 解析预览 → 产品与权限标注 → 小样评估 → 人工发布新快照。直播中不做全量索引。事实变更立即取消依赖旧版本的候选、审批与语音；权限撤销或删除先阻断检索与缓存，再异步清除向量与副本。Embedding 模型变更需独立重建索引。
- 数据外发：每个 Provider 的上传范围在界面展示；标记 local\_only 的文档只走本地词法检索或人工。
- 第三方知识区分检索 API、RAG 问答 API、仅答案 API。后两者不冒充可核验证据。
- **冷启动**：从商品表格或页面一键生成 KB0 事实与 FAQ 草稿（LLM 辅助），必须人工审核后发布。
- 质量门槛（设计值）：至少 100 个贴近真实直播的问题；有证据问题 Recall@5 ≥90%；高风险事实不允许自动播报错误；无答案问题正确澄清或转人工；热索引检索 P95 ≤300ms。检索延迟、证据正确率、最终答案正确率分别报告。

## 7 Provider 与成本

- LLM：支持中文与结构化输出、数据政策明确、并发配额足够。先验证单供应商完整链路，再接第二家做替换测试。主备分别通过提示词与安全回归。
- TTS：中文流式。记录首包、首段可播、最终时长、格式、重采样、取消与计费口径；不假定有音素时间戳。换供应商可能改变音色：只在句边界由操作员确认，或改用已批准缓存，不在一句内拼接两家音频。
- Provider 配置记录：地区、模型版本、输出格式、流式方式、速率限制、超时、重试、价格单位、数据留存政策。
- 预算：每日与每场的软硬预算，80% 提示，100% 停止新付费生成并转批准缓存或人工。用 usage 做实时账，账单异步对账，没有余额 API 时不显示虚构余额。
- 成本公式与示例见 25.5。示例单价是假设，必须用实际报价替换。
- 可选 AI 网关：云端托管密钥、统一预算与路由，不启用时不启动。直连回退仅在本机有合法凭据且数据政策允许时可用。

## 8 数字人与媒体

### 8.1 形象档位

- **2D（Lite 默认）**：授权的简单分层纹理、嘴部开合、少量循环动作。集成显卡可渲染，不承诺零 GPU。素材、引擎、音色、肖像分别核对许可，Live2D 等 SDK 有发布许可条件。
- **写实（Standard）**：Rust ort + ONNX Runtime，Windows NVIDIA CUDA 首发。TensorRT、DirectML 单独认证。
- 3D 与远程渲染：契约预留，单独认证。

### 8.2 写实模型准入 Gate

| Gate | 证据 |
| --- | --- |
| G0 来源与授权 | 权重、代码、训练素材、肖像、声音的使用权利成立，完整流程可取得 |
| G1 正确性 | 原实现与 Rust 流程在固定输入下逐段对齐：预处理、音频特征、生成、后处理 |
| G2 实时性 | 目标机上与直播工具同时运行，实测帧率、延迟、显存、CPU、温度 |
| G3 稳定性 | 静音、取消、句边界、长播、OOM、进程重启、形象切换与输出恢复 |

- 完整链路包含音频编码器、预处理与后处理，不得把缺失组件留在未声明的 Python 服务里。
- 锁定 Rust crate、ORT、CUDA、cuDNN 与驱动兼容矩阵；音频特征窗口所需的未来音频计入开口延迟。
- Gate 失败：更换模型或标记插件不可用。**自动回退 2D 不等于写实验收通过。**

### 8.3 媒体管线

- 以音频样本计数为主时钟，视频按 PTS 对齐；缓冲从 200–500ms 测起。
- keeper 只有在取得有效租约和已批准的 utterance 集合后才消费音频；迟到数据按 epoch 丢弃。
- 取消顺序：接管 → keeper 先静音并清缓冲 → epoch 递增并持久记录 → 取消 LLM、TTS、知识、模型任务 → 丢弃迟到结果 → 审批失效 → 未完成任务标记 Cancelled。取消令牌是协作机制，已提交的 GPU 计算无法强制终止，完成后丢弃结果。
- 视频持续落后于音频时，停止当前数字人发声并切待机，不允许有声无口型地继续。

### 8.4 待机与降级

keeper 常驻待机画面。render-worker 故障时切待机并保持静音通道；重启后须重新授权。写实切 2D 需运营预先授权，在句间切换并写日志。

### 8.5 真人接管音轨

- 接管 = 暂停自动 + 数字人静音 + 清队列 + 可选真人音轨接入。
- 真人麦克风由 keeper 混音输出，独立于 TTS 音轨；接管时 TTS 轨静音。设备使用稳定标识，监控默认设备变化。
- 只允许一条有效收音路径，避免 OBS 与伴侣重复收音造成回声；接管前做回声测试。
- 恢复自动互动必须明确操作，并复核授权、事实版本与值守租约，不因真人讲话结束而自动恢复。

## 9 平台接入与输出

### 9.1 输出

默认：keeper 固定出画窗口 + 独立音频输出路径，由 OBS 或直播伴侣采集。先实测目标版本对窗口的捕获（最小化、缩放、透明）与音频设备。不开发虚拟摄像头驱动，不堆叠多套输出。录制与推流分别验证接收、声道与音画同步。

### 9.2 抖音

以下据官方互动工具文档，使用前按实际版本复核：

- 插件有 exe 与小程序两种产物类型。exe 只在直播伴侣内运行，可推送音视频素材上屏；小程序类型在抖音 App 与伴侣均可运行，形态是玩法面板加画布卡片。审核通过或上线后产物配置不能变更，申请前必须定案。
- 事件类型：点赞、评论、礼物、关注、粉丝团，均需申请权限；**未列出进场事件**，欢迎默认用「首次发言欢迎」。
- 文档没有说明小程序类型能承载全屏数字人音视频；也没有找到手机端把第三方画面接入开播的官方途径，不据此假定可用。
- 桥接由伴侣启动并连接常驻引擎；伴侣退出时桥接退出，引擎转待机；重连不恢复旧自动权限。需处理多次启动、端口占用、SDK 失联、消息重复、旧房间事件、时间漂移、权限撤销。
- 平台能力快照取值 granted、denied、unknown，取最严格交集。缺失能力只关闭对应功能，不自行合成事件。

### 9.3 接入节奏

正式接入后置，风险发现前置。M0 用官方调试版伴侣和 C++ 示例做桥接 PoC：启动参数、素材通道、推一路测试音视频、接收模拟互动、退出与重连、分辨率与通道约束。调试成功不等于上线授权。平台准入确认（数字人用途、产物类型、权限与费用）从第一天起发出。

### 9.4 其他平台

快手、视频号放入同一平台插件目录。在核实官方接口前保留显式 Unavailable 实现，不宣称可上线。

## 10 控制面与手机

### 10.1 桌面控制台

四个入口：直播台、知识、形象与 Provider、运行记录；插件按能力状态动态注册导航。直播台同屏展示：真实画面与音频电平、事件来源、模式、当前播报与待播秒数、待审批候选（最终文本、证据、失效时间）、API 与预算与设备状态。固定可见「暂停自动、立即静音、人工接管」。

### 10.2 手机监控包（可选加装，所有档位）

- 功能：状态看板、审批、接管、紧急静音、快捷话术插播、告警、知识速补（进入审核发布流程）。**它不是手机开播。**
- 连接路线（M0b PoC 后定案）：
  - A 中继 + PWA：需要有效 HTTPS 域名与证书。PWA 的 Service Worker 需要安全上下文，局域网明文 HTTP 或自签名证书不满足。
  - B 原生壳 + 局域网直连 + 证书固定：需要应用分发；Tauri 2 移动端成熟度待验证。
- 最小形态：看板、审批、接管、紧急静音；预览与推送可后置。
- 预览按需开启，用真正编码的低码率流；关闭立即释放编码器与带宽，不得挤占正式出画。
- 中继终止 TLS 时可读取业务内容，不宣称端到端加密；需要时使用经审核的端到端协议。

### 10.3 实验形态

- 手机本地运行（Lite-Mobile）：单进程、全部插件 inproc，需要原生壳（内核不能运行在 PWA 中），仅前台演练与录制，iOS 后台基本不可用。准入门槛在 M0b 前写定，未达则搁置。
- 云渲染与手机出画取决于平台入口，作为单独认证项。

## 11 安全设计

### 11.1 V3.5 已有设计与 V3.6 的补充

依据对 V3.5 全文的审阅，已具备的安全设计：

- 授权与模式：平台能力 granted/denied/unknown 取最严格交集；演练、人工辅助、受监督自动三种模式；自动模式需值守租约。
- 审批与取消：审批绑定候选哈希、会话、epoch、角色与 TTL；epoch 使旧审批与旧音频失效；媒体独立静音。
- 内容安全：四阶段守门；评论、知识、工具返回作为不可信数据；LLM 不拿 R3 权限。
- 隔离与信任：四类宿主；签名不等于安全；信任库与撤销列表；IPC 的 ACL、握手、帧长度检查、路径规范化。
- 数据与密钥：系统凭据库与 credential\_ref；观众画像默认关闭；Provider 上传范围展示；手机命令防重放与实际 ACK；升级验签与 journal。

### 11.2 资产与信任边界

**需要保护的资产**：平台账号与直播权限；直播画面与声音（对外可见）；API 密钥与设备令牌；权威事实与已发布知识；观众数据；模型、形象、音色与肖像授权；审批与决策日志；升级包与插件包。

**信任边界**：

- 观众输入（评论、昵称、礼物留言）：不可信。
- 知识文档与第三方知识返回：半可信，可能含注入或过期内容。
- LLM 与 TTS 输出：不可信，必须经守门与授权。
- 外部 Provider：数据出境与留存按其政策，单独展示。
- 插件：按信任域区分，签名只证明来源。
- 手机与远程设备：凭设备身份与角色，不因在同一网络而可信。
- 云中继：半可信，可读业务内容（TLS 终止）。
- 平台 SDK 桥接：受限边界，只转换事件。

### 11.4 角色与权限

| 角色 | 可以 | 不可以 |
| --- | --- | --- |
| 观察者 | 看板、脱敏弹幕 | 任何命令 |
| 场控 | 审批与驳回、快捷话术插播、暂停自动、紧急静音、接管 | 切换到自动模式、结束会话、改配置 |
| 主播/管理员 | 场控全部 + 切换模式（二次确认）、开始或结束会话、切场景或商品卡（risk\_2） | 改密钥、导入模型 |
| 仅本机管理员 | 密钥、模型与形象导入、信任库、外发策略、插件安装 | — |

紧急静音对场控以上无门槛。risk\_2 动作可配置为双人确认。待审批数量设上限，超限时合并或拒绝，避免审批疲劳。

### 11.5 密钥与数据保护

- 密钥只存系统凭据库，配置只存 credential\_ref；前端不持有密钥。密钥分用途、最小权限，有轮换流程。日志、诊断包、崩溃转储不含明文密钥，CI 做密钥扫描。
- 静态数据：数据库、录制、备份、缓存位于用户数据目录并受操作系统访问控制。备份与录制提供可选加密，密钥由系统密钥保护机制封装（具体机制待选型验证）。
- 传输：所有网络通信用 TLS。云中继终止 TLS，不宣称端到端加密。
- 日志：默认脱敏、轮转；审批、事实、授权记录单独保留，不因采样丢失。
- 删除：撤销先阻断检索、缓存与播报，再异步清除向量与副本；备份保留与清除期限明确列出。

### 11.6 插件与供应链

- 构建：Cargo.lock 与工具链锁定；CI 做依赖漏洞与许可审计；每次发布附 SBOM。
- 加载：原生库与模型只从已验签目录加载；路径规范化，拒绝路径穿越与重解析点逃逸；第三方原生进程不共享引擎用户令牌。
- 模型与素材：BOM 记录来源、哈希、许可，以及肖像与声音授权。
- 撤销：撤销列表在安装与每次启动时检查，被撤销的插件或模型立即禁用。
- 升级包：验签、哈希、撤销检查通过后才可进入待激活。

### 11.7 AI 专项安全

- 系统策略与观众文本、检索片段、工具返回分段标注；输出走结构化 Schema。
- LLM 只产出 Decision 与候选，授权由运行时执行。
- 数字、单位、优惠条件与证据逐项校验。
- 知识库投毒防护：导入 → 解析预览 → 人工发布；保留来源；外部知识标注信任等级。
- 观众昵称与评论经过滤后才用于朗读，不直接朗读原文。
- 提示词、人设、规则、模型、Provider 的变更都按安全相关变更处理，必须通过注入与越权回归。

### 11.8 紧急开关分级

| 级别 | 动作 | 触发者 | 效果 |
| --- | --- | --- | --- |
| L1 | 本地静音或热键 | 任一值守者 | 立即停声并清缓冲 |
| L2 | 暂停自动互动 | 场控以上 | 停新自动回复，转人工辅助 |
| L3 | 撤销值守租约 | 系统或管理员 | 撤销自动权限，不自动恢复 |
| L4 | 吊销设备与会话令牌 | 管理员 | 远程控制立即失效 |
| L5 | 撤销或轮换 Provider 凭据 | 管理员 | 阻断对应外发 |
| L6 | 撤销插件或模型 | 管理员或发布方 | 立即禁用并回退到认证组合 |
| L7 | 事故模式 | 管理员 | 停止直播输出、保全日志、导出审计包 |

### 11.9 安全测试与事件响应

- 测试：每条发布线前做威胁建模评审；IPC 帧与握手模糊测试；依赖与许可审计；密钥扫描；注入与越权红队集；涉及中继时做远程控制面渗透测试；备份恢复演练。
- 事件分类：内容事故、数据泄露、账号与平台风险、供应链事件。
- 响应流程：止损（L1–L7）→ 保全（导出决策日志审计包）→ 定位 → 通报（平台与用户，视合规要求）→ 复盘 → 把案例补入回归集。

## 12 可靠性设计

### 12.1 故障域与处置

| 故障 | 检测 | 自动处置 | 恢复后状态 |
| --- | --- | --- | --- |
| engine 崩溃或卡死 | 租约续期失败、supervisor 心跳 | keeper 到期静音并待机；supervisor 重启 engine | 待机；旧审批与自动权限作废 |
| keeper 崩溃 | supervisor 心跳 | 重启 keeper；OBS 预置待机场景作为最后手段 | 待机；重新取得租约 |
| render-worker 崩溃或 OOM | 进程退出、帧超时 | keeper 切待机并保持静音通道；记录原因 | 重启后重新授权；写实失败不自动当作 2D 验收通过 |
| platform-bridge 失联 | 管道断开、事件心跳 | 撤销自动互动，转手工或回放 | 重连不恢复旧自动权限 |
| LLM 超时或限流 | deadline、429 | 尚未播放时用批准模板或转人工；有限重试且受期限约束 | 不拼接两个模型的回复 |
| TTS 超时 | 首包超时 | 用已批准缓存或转人工；避免重复合成造成重复播报 | 状态不明的句子取消 |
| 知识检索失败或第三方超时 | 超时、错误码 | 停止依赖知识的自动回答，转澄清或人工 | 不绕过证据要求 |
| 网络断开 | 连接监测 | 本地实时链路与本地静音不受影响；远程能力按其门控停用 | 手机与中继重连后不补执行过期审批 |
| 磁盘不足 | 余量检查 | 停止新录制与后台索引，保护审计与权威数据；直播不停 | 提示归档，不自动删除受保护证据 |
| GPU 驱动重置或显存不足 | 设备事件、分配失败 | 降载档位（认证的）或停用写实并告警 | 需重新体检 |
| 数据库写失败或损坏 | 事务错误、完整性检查 | 停止新授权提交，转待机；从一致性备份恢复 | 恢复演练覆盖，不使用过期审批 |
| 平台权限撤销或房间结束 | 平台事件、能力快照变化 | 立即撤销对应功能，epoch 递增 | 重新核对授权后才可恢复 |
| 升级中断或断电 | 升级 journal | 恢复到完整的旧组合或新组合 | 不混合 Schema |
| 整机或断电 | 无软件手段 | 靠备用设备与运营流程；云端心跳看门狗可告警 | 不承诺软件层不中断 |

### 12.2 降级原则

- 降级顺序：模板 → 已批准缓存 → 人工 → 静音待机。
- 任何降级都不得绕过授权、守门、事实核验与审批。
- 降级表是数据，随档位与场景提供；智能体读取 CapabilityView 调整行为，界面用同一视图显示已降级项并给出可行动说明。
- 支持包导出默认脱敏，不含密钥、原始观众身份、未经同意的文档或录音。

### 12.3 资源治理与过载

- 所有状态以 session\_id 隔离，Lite 默认一个活动会话。Pro 多会话时，每会话独立 epoch、授权、队列、预算、知识绑定、审批与输出 ID；共享只限不可变模型、只读知识快照与受控连接池。
- GPU 吞吐、显存、音频时序、API 配额分别准入。新会话容量不足时拒绝或等待，不能让已开播会话 OOM。复用模型权重不代表中间张量可共享，需测峰值。
- OOM 分类处置：GPU 显存、系统内存、磁盘、API 配额各有对应降载路径。
- 事件突发（如 1000 条）先去重、合并、过期，只对入选候选调用付费接口；关键状态事件（连接、权限、房间结束）使用单独槽位或合并最后状态；溢出有指标与原因，不宣称零丢失。
- 后台任务（索引、日志压缩、备份、上传）在直播中限速，不抢实时资源。

### 12.4 数据可靠性

- SQLite 单写 owner、小事务、短读事务、非直播高峰 checkpoint；WAL 要求同机，不放网络盘；多节点写入用关系数据库适配器。
- 授权、事实、审批、配置等关键提交使用最强同步级别（synchronous=FULL，对性能的影响待实测）；遥测使用独立缓冲，允许丢失。
- 备份使用一致性在线备份，不只复制主库文件而遗漏 WAL。权威事实与批准记录有备份与恢复演练；索引可重建。
- 决策日志做哈希链完整性校验。

### 12.5 可靠性指标（设计值，待实测）

| 指标 | 目标 |
| --- | --- |
| 本地紧急静音 | P95 ≤250ms |
| engine 失联后静音 | ≤租约截止（初值 600ms）+ 已知音频设备缓冲 |
| engine 崩溃后回到待机 | ≤30s |
| keeper 崩溃后恢复出画 | ≤10s |
| 模板任务开口 | P95 ≤1.5s |
| 普通 API 任务开口 | P95 ≤3s，超限转模板或人工 |
| 负载下控制响应 | P95 ≤50ms |
| 写实出帧与音画偏差 | 稳定 25fps；P95 ≤80ms（指定档位） |
| 长播稳定 | 2 小时、8 小时、24 小时无持续资源增长 |
| 备份恢复 | 演练成功率 100% |

每次报告附版本、硬件、模型、网络、冷热状态、样本数与并发。整条路径实测分位数，不把各阶段 P95 相加。

### 12.6 故障演练清单

分别强杀 engine、keeper、render-worker、bridge；断网；Provider 返回 429 与超时；磁盘写满；升级各步骤断电；GPU OOM；事件风暴；时钟漂移；音频设备热插拔；审批过期；知识撤销；数据库恢复。每个发布候选做一次全量演练，其中可自动化的部分进入日常 CI。

## 13 合规与隐私

### 13.1 平台合规门禁

公开报道称，抖音在 2023 年发布过数字人直播的行业倡议，涉及真人驱动与实时互动、实名注册与虚拟人标识、避免录播与重复话术。**该规则的现行有效性与具体条款待向平台核对。** 无论具体条款如何，开播体检必须包含以下核对项：

- 账号已完成平台要求的实名与类目确认。
- 直播画面叠加虚拟人标识（由 keeper 强制，场景与插件不可关闭，INV-20）。
- 现场有可接管的操作员；自动互动的权限状态为 granted，unknown 与 denied 一律按未授权处理。
- 话术与回复有多样性，不长时间重复固定内容。
- 互动与审批记录可导出，用于申诉与审计。

不通过合规核对时，系统只允许演练模式。

### 13.2 数据与隐私

- 观众数据最小化：事件原文与昵称按保留期脱敏；长期画像默认关闭；不跨平台关联身份。
- 每个 Provider 展示其获得的数据范围、留存政策与出境情况；local\_only 数据不上传。
- 诊断包与日志默认脱敏。平台与法规对观众数据的具体要求待核对，保留期与删除流程据此配置。

### 13.3 素材与许可

形象、音色、肖像、模型、引擎、素材分别登记授权证明、范围与期限；授权失效时先阻止新播放，再清理与通知。

## 14 部署、档位与升级

### 14.1 档位预设

| 能力域 | Lite | Standard | Pro |
| --- | --- | --- | --- |
| 平台 | 手工与回放，可装一个已批准连接器 | 抖音连接器与事件治理 | 多平台连接器与独立能力快照 |
| 知识 | KB0、KB1，可配置基础语义检索 | 混合检索、快照、质量评估 | 多知识空间、集中发布 |
| 智能体 | 规则、模板、短回复、审批 | 节目编排、只读技能、影子评估、聚类与预合成 | 扩展技能、跨会话运营 |
| 记忆 | 工作记忆与场次摘要 | 场次记忆与检索 | 可选长期记忆，观众画像默认关闭 |
| 形象 | 授权 2D | 2D + 通过 Gate 的写实 | 多形象，可选远程渲染 |
| 输出 | 窗口与音频采集、录制 | 更多认证输出适配器 | 多会话独立输出 |
| 管理 | 桌面，手机包可选 | 桌面 + 手机包 | 团队、角色、设备管理 |
| 会话 | 单活动会话 | 单活动会话 | 多会话，受硬件、API、平台限额 |

矩阵是默认预设，不是禁止加装。组合偏离预设时标为「Lite + 自定义能力」，仍沿用同一升级路径。授权与商业权益只影响安装与启用，不改变契约与数据格式；许可证服务不可达不得切断已有合法运行的会话。

### 14.2 部署配置

| 配置 | 形态 | 必需自建云资源 |
| --- | --- | --- |
| Local | 内核、知识、媒体、连接器都在工作站；LLM 与 TTS 直连 API | 0 台（API 费用另计） |
| Hybrid | 实时链路在本地；轻量控制与中继、共享配置可选 | 一个轻量服务；不承载模型权重与视频转码，资源为待测预算 |
| Distributed | 会话、知识、渲染按能力远程化 | 按真实负载规划，不承诺一个小实例覆盖全部 |

部署配置与档位正交。默认不依赖 Redis、NATS、Kubernetes、对象存储集群；有真实需求时作为可选依赖。平台桥接与媒体输出的操作系统要求保留在对应边缘节点，不假定 Linux 云机能运行 Windows SDK 或虚拟音频设备。

### 14.3 升级与回滚

- **两条路径**：插件包安装是日常主路径；内核升级少见。Lite → Standard → Pro 使用同一迁移图，不要求先装中间档。硬件不足时可完成安装并标记「不可运行」，不显示「写实已启用」。
- **事务式流程**：解析依赖闭包 → 预检（系统、GPU、驱动、双份磁盘空间、凭据）→ 暂存下载并验签、验哈希、查撤销 → 等待无活动会话 → 一致性备份 → 迁移到新数据目录 → 隔离自检 → 写 journal（prepared、migrated、checked、committed、rolled\_back）→ 原子替换当前版本清单 → 展示实际能力状态。
- 开播中只暂存，不替换。Windows 文件锁由独立 update-helper 在应用停止后处理。
- **首版迁移只做向前**。升级前整库备份；回滚等于恢复旧程序与备份，并导出升级后的新写入。不可逆迁移前单独告知，不承诺无限期一键回滚。
- 降档：先排空多余会话，停用依赖能力，数据保留，不静默删除。
- 部署迁移（Local → Hybrid → Distributed）：一致导出导入、权限映射、哈希验证；SQLite 不挂多节点写；实时链路留在原部署，在维护窗口切换。

### 14.4 成本口径

月成本 = LLM + TTS + Embedding 与知识 API + 云资源 + 网络与中继 + 存储与备份 + 本地电力与设备 + 授权与平台费 + 维护人工。公式与示例见 25.5。三档在同一负载下的成本差异来自启用的能力，而不是档位名称。未启用的能力不占用进程、端口、显存或云请求。

## 15 易用性与运营

- **可用性目标**（设计值，待验证）：安装后约 10 分钟内听到第一句演练语音；约 30 分钟内完成一次真实输出验证。
- **开播流程**：选择场景 → 检查形象与事实版本 → 测试音频与画面 → 连接真实事件或明确标注手工来源 → 合规核对 → 确认模式与值守 → 开始。自动权限与上一场的审批不跨场继承。
- **开播体检**：平台授权、API 连通与计费口径、形象与模型校验、GPU 与显存、音频路由与回声、输出连通、手机监督端、预算、CapabilityView 中的降级项、合规门禁。
- **演示包**：授权的演示形象、示例知识、示例场景，加 Provider 预设、一键连通测试与成本预估。
- **场景包**：角色口吻、产品集合、禁答范围、批准模板、节目节奏、音色与形象、知识来源、预算与黄金集。
- **术语隔离**：界面不出现 capability、epoch、lease、binding 等词；错误说明可行动，例如「知识接口超时，本问题未播报，可人工回答」。高级视图才展示插件绑定与协议日志。
- **决策可解释**：点击任一句，查看触发事件、路由、证据、守门结果、模型与提示词版本、延迟分解。
- **复盘报告**：见 5.9。
- 关闭管理端与结束直播是两个操作；关闭界面时明确提示剩余运行状态，无有效值守则退出自动权限。

## 17 工程组织与实施路线

### 17.2 仓库结构要点

### 17.5 根 AGENTS.md（精简）

- 本文是主规范；先改 schemas 并生成契约，再改消费者。kernel 不依赖具体插件、Tauri 或平台 SDK；plugins 之间禁止直接依赖。

- 不提交密钥、许可不明的权重或素材、生产观众数据。
- 按切片推进；偏离设计写 ADR；每项交付说明修改、实际测试、未测环境与外部阻塞。

本部分把 V3.5 第 19–32 章中仍然有效的协议、状态机、数据、知识、Provider、媒体、API、配置、构建与测试细则整合为独立规范，并按第一部分的决定做了修订。

- **使用方式**：编码代理每个任务只读第 2 章不变量、1.4 发布线、当前任务卡（第 31 章）和任务相关章节。契约以 `schemas/` 为准，本部分是其说明。
- 时间一律 UTC 毫秒。跨进程传递剩余期限（remaining\_budget\_ms），接收方转换为本地单调截止时刻，不比较两台机器的单调时钟。
- 所有 ID（消息、平台、房间、观众、64 位计数）一律用字符串，JS 端不得用 number 承载。
- 金额使用最小货币单位或十进制，不用浮点。
- 未知配置字段在生产模式报错，不静默忽略；未知事件类型保留脱敏诊断，不触发说话。
- 示例中的 ID、时间、授权值只是 Schema 示意，不能硬编码成可运行授权。
- 没有真实 SDK、模型、凭据时，返回显式 Unavailable 并报告 Blocked，不用 mock 冒充真实接入。

## 20 契约、协议与错误

### 20.1 契约源

`schemas/core/*.proto` 与 `schemas/domain/*.proto`（Protobuf）定义跨进程与跨语言消息，生成 Rust、TypeScript、C++ 桩。JSON Schema 描述配置、插件与模型清单、声明式界面；OpenAPI 描述 HTTP 端点。先改 Schema 再生成，禁止三种语言各手写相似对象；CI 重新生成必须无 diff。

进程内 SDK 用类型化 Rust 接口，跨进程映射为同一语义；不导出不稳定的 Rust trait ABI 给外部动态库。清单声明协议与 Schema 主版本，握手选择兼容版本。

### 20.2 控制消息信封

- 必需字段：protocol\_major、protocol\_minor、message\_type、message\_id、request\_id、trace\_id、session\_id（会话命令必需）、generation\_epoch、sent\_at\_utc\_ms、payload、remaining\_budget\_ms。
- 控制载荷上限初值 64KiB；普通请求有期限；紧急命令使用独立的有界队列与连接。
- 无法确认期限的有风险操作一律拒绝。

### 20.3 IPC 帧与握手

- 帧：4 字节小端长度 + Protobuf 正文。先检查最大长度再分配内存；处理 partial read、多个帧合并、EOF、过大帧、未知消息类型、取消与恶意长度。
- 握手：携带插件 ID 与版本、协议范围、nonce、运行会话与身份材料。ACL 与对端进程身份验证先于能力授权。
- 本地管道用 ACL 限定账户与进程范围。「同一 Windows 用户启动子进程」不足以保证密钥不可访问。
- 模型文件与原生库只从已验签目录加载，路径规范化后必须位于允许根目录；拒绝路径穿越、符号链接与重解析点逃逸。
- 第三方原生进程只拿其获准凭据，不共享引擎用户令牌。Job Object 约束资源与生命周期，不是权限沙箱。无法满足受限执行环境时，拒绝加载或改用 wasm 或远端实现。

### 20.4 错误模型

统一结构：request\_id + error{code, category, retryable, message, details}。

核心码：INVALID\_ARGUMENT、UNAUTHENTICATED、PERMISSION\_DENIED、CAPABILITY\_ABSENT、CAPABILITY\_NOT\_READY、VERSION\_INCOMPATIBLE、RESOURCE\_EXHAUSTED、DEADLINE\_EXCEEDED、STALE\_EPOCH、EVIDENCE\_EXPIRED、APPROVAL\_EXPIRED、BUDGET\_EXCEEDED、PROVIDER\_UNAVAILABLE，以及 UNVERIFIED\_EXTERNAL\_DEPENDENCY（缺少官方 SDK 或接口文档时）。面向用户的 message 必须是可行动的说明。

### 20.5 插件 SDK 语义

- Plugin：describe、validate\_config、start、health、suspend、resume、stop。
- CapabilityClient：invoke、stream、cancel。PluginContext 提供有权限的日志、配置、凭据引用、时钟、预算与能力客户端。
- 所有调用带请求上下文与取消令牌。流以 data、complete、error 明确结束，**EOF 不等于正常完成**。
- 契约规格优先于某个 Rust 语法模板：带泛型的 async 方法不能未经编译就装成 dyn 对象，可用 BoxFuture 等方式实现。

### 20.6 Slice-0 要冻结的契约

| 契约 | 核心操作 | 关键约束 |
| --- | --- | --- |
| platform.events@1 | subscribe(session) 返回事件流；capabilities() 返回能力快照；status() | 手工与回放实现同一接口；不明能力为 unknown |

## 21 状态机与会话

### 21.1 三个状态维度

- **生命周期**：Created → Preparing → Ready 或 ReadyDegraded → Running → Draining → Stopped。严重错误进入 Faulted，恢复需重新 Prepare，不自动沿用授权。
- **行为模式**：Rehearsal、Assisted、AutoSupervised，由策略、平台能力与值守决定，不与网络状态混用。
- **媒体状态**：Standby、Buffering、Playing、Muted、DeviceLost、Failed。同一 Running 会话可以处于 Muted。

RoomStarted 只是输入事实，不会自动把 Ready 切到 Auto。「开始」必须通过 preflight，ReadyDegraded 要列出缺失能力。

### 21.2 Prepare 与绑定快照

Prepare 流程见 4.2，产出 CapabilityView 与 BindingSnapshot（带版本，限定 session）。必需能力缺失为 NotReady；条件必需缺失只阻止对应模式；可选缺失为 ReadyDegraded。

运行中某能力不健康时按降级表（29.3）处理，不得跨知识域任意切换「备份」知识。缺 guard 拒绝所有外发；缺 avatar.profile 拒绝激活该形象；纯音频或字幕模式只在场景明确允许并预授权时可选。

### 21.3 播报任务状态机

Selected → Retrieving 或 Generating → Guarded → AwaitingApproval 或 Approved → Synthesizing → Buffering → Committed → Playing → Completed。任一步可进入 Cancelled、Expired、Blocked、Failed。

- 模板可以跳过 Retrieving 与 Generating，但不能跳过 Guarded 与当前授权。
- **Completed 以本地播放完成 ACK 为准**。LLM 结束、TTS 下载完成、播放器接收都不算完成。
- 日志区分生成、批准、提交、本地播完；平台传输状态记为未知。

### 21.4 租约、值守与幂等

- **播放租约**绑定 session、epoch、允许的 utterance 集合、模式与审批、有效期；keeper 验证租约后才消费音频。初值：200ms 续租，600ms 失联截止。
- **值守租约**（自动模式）由操作员主动确认，期限由场景设定。网络心跳不能续期；到期后停止启动新的自动回复，并在短期限内撤销输出授权。桌面仍有人值守时，手机断线不应误判为无人。
- **命令幂等**：session + command\_id 唯一，重复提交返回已执行结果。紧急命令高优先且幂等，重复静音不会重开音轨。去重 TTL 不短于允许的重试窗口。
- **重启恢复**：只恢复待机和状态，不恢复旧审批、旧自动权限与已撤销设备。

## 22 调度与队列

### 22.1 数据结构

每个会话有独立且有界的 EventIngress、CandidateQueue、UtteranceQueue 与媒体水位。输入突发先去重、合并、过期，再选可播候选；未入选的事件不启动付费生成。

预算维度：请求次数、Token、字符或秒数、待播秒数、GPU 并发、工具步数、各 Provider 配额。

### 22.2 事件处理

- 去重键：platform、app、room、type、provider event ID。没有可靠 ID 时用有界窗口的启发式哈希，并标记可能误合并。
- 支持的事件：comment、gift、like、follow、unfollow、fansclub、房间生命周期、权限变化。enter 只在平台真实提供时才有。
- 礼物保留数量语义（delta、cumulative、unknown）与连击 ID（若提供），未知数量不累加推算。点赞可按窗口聚合。
- 首次评论欢迎不能说「刚进直播间」。
- 重连只重新评估尚未过期的事件；审计补录不补播旧感谢。

### 22.3 过载与背压

- 优先级：P0 静音与授权撤销（独立通道，不等数据库 checkpoint、模型锁或普通网络请求）> P1 人工点播 > P2 场景关键任务 > P3 相关问题 > P4 感谢 > P5 寒暄。
- 满载时先丢可无损聚合的点赞与重复的模板触发；连接、权限、房间结束等状态事件使用单独槽位，或合并为最后状态。
- 新任务同时受截止期与语音债务限制。溢出有指标与原因，不宣称零丢失。

### 22.4 公平性

每位观众设冷却，同主题合并，单观众占比设上限，并记录欠服务计数。礼物价值不能永久排斥普通问题。TTL 与预算比例的初值见 5.3。

### 22.5 预算执行

- 入选时预留预计成本与资源令牌；Provider 返回 usage 后结算；取消仍可能计费，也要入账。
- 全局额度与会话额度都通过才准入。多会话不得各自消耗同一份共享余额而超限。
- 未知 usage 保留估算状态，由账单对账纠正，不清零也不重复扣。

### 22.6 ShowPlan 契约

ShowPlan 含 scene\_id、version、segment\_id、target\_duration、topic\_refs、script\_refs、interrupt\_policy、checkpoint、evidence\_binding。段落：开场、讲解、问答、互动、行动提示、收尾。

允许的动作来自场景白名单。切商品卡需要真实的平台能力与 risk\_2 批准，节目脚本不能绕过。重启默认待机，不自动补播上一场节目。

## 23 数据与存储

### 23.1 数据目录与单写 owner

- 数据根使用系统用户数据目录（由 Tauri 或操作系统路径 API 解析），安装目录只读。数据根下分：config、db、knowledge、indexes、assets、models、cache、recordings、logs、backups、upgrade-staging。
- 密钥在系统凭据库，配置只存 credential\_ref。
- 存储端口由 engine 的单写 owner 提供事务，插件不得跨线程或进程直接写库。只读知识索引可用独立快照减少争用。
- 分布式 profile 通过存储端口切换到关系数据库，**禁止多个节点挂载同一个 SQLite 文件写入**。
- 每条领域记录带 workspace 与 session 作用域，主键从 Lite 起保留作用域，避免升级到 Pro 时重编号。

### 23.2 表目录（按归属分层）

| 归属 | 表 | 要点 |
| --- | --- | --- |
| 内核迁移 | workspaces、runtime\_profiles、plugin\_installations、capability\_bindings | 当前能力组合不等于授权状态；会话冻结的绑定快照另存 |
| 内核迁移 | sessions、session\_snapshots | epoch 单调递增；历史状态不自动续权；快照是安全恢复材料 |
| 内核迁移 | approvals | 单次授权，带唯一约束；禁止裸 approved 布尔 |
| 内核迁移 | decision\_log | 只追加、哈希链，见 5.8 |
| 内核迁移 | upgrade\_journal、schema\_migrations | 崩溃恢复幂等；版本、校验和、兼容范围 |
| 知识插件 | documents、document\_revisions、chunks | 已发布版本不可原地覆盖；原文可追溯到段落、页、表格位置 |
| 知识插件 | facts | 带类型的值、单位、权威来源、有效范围；货币用最小单位或 decimal |
| 知识插件 | knowledge\_snapshots、vector\_index\_manifests、knowledge\_sources | 原子发布的引用集合；不同 embedding 模型空间隔离；local、remote、hybrid 路由 |
| Provider 与媒体插件 | provider\_profiles、usage\_ledger | 密钥只存引用；估算、已结算、待对账分开 |
| Provider 与媒体插件 | tts\_cache、voice\_assets、avatar\_assets | 缓存有效性与 LRU 配额；声线与形象授权 |
| 场景与记忆 | scenes、show\_plans、memory\_records | 场景与节目有版本；观众记忆默认无数据 |
| 手机与团队包 | devices、roles | 配对、吊销、角色；Local 保留逻辑 Schema，不启动额外服务 |
| 短期 | event\_inbox | 去重键与 TTL，不永久存全部弹幕 |
| 投影（可由 decision\_log 重建） | utterances、evidence\_links、用量汇总、审计视图 | 不以生成结束标记 completed；用于播放前复检与事实失效反查 |

插件表在插件首次启用时按其迁移创建，未安装的插件没有对应的表。Provider 原生 usage 保留可扩展字段与计量单位，不强行把所有 TTS 转成 Token。

### 23.3 约束

- 启用外键；关键提交用事务；事实发布与失效标记在同一事务内完成。
- approvals 约束：UNIQUE(session\_id, generation\_epoch, candidate\_hash, action\_scope)，并为 (session\_id, generation\_epoch, candidate\_hash, expires\_at\_ms) 建活跃查询索引。字段包括 approval\_id、session\_id、generation\_epoch、candidate\_hash、actor\_id、action\_scope、expires\_at\_ms、revoked\_at\_ms。
- 迁移编号与命名一致。SQLite 与 PostgreSQL 的映射由存储适配器实现，不能依赖「方言相似」自动迁库。content hash 使用规范化前后明确的算法与版本。

### 23.4 备份与恢复

- 使用 SQLite 备份 API 或经验证的一致快照。录制可排除；原文、事实、素材授权、模型清单必须纳入。备份记录哈希、Schema、活动版本组合、创建时间与敏感数据范围；云备份可选加密并限定上传内容。
- 恢复先验完整性与兼容性，隔离预检，再替换非活动状态。
- **恢复不恢复播放租约、旧审批与已撤销的设备身份**。旧候选全部过期，新会话 epoch 不与旧任务冲突。
- 验收：干净机器恢复知识与配置后，能重新准备会话，而不只是文件能解压。

### 23.5 保留与配额（起点，可配置）

| 资源 | 起点 | 要点 |
| --- | --- | --- |
| 原始事件 | 有界队列；可选审计保留，默认脱敏 | 高频事件不无限落盘；重连不重播旧句 |
| 运行日志 | 7 天、单机总量 512MB | 审批与事实变更记录单独保留（30–90 天或按业务与法规），不因采样丢失 |
| 录制 | 总量 20GB，且低于磁盘安全余量即停止新录制 | 停止录制不停直播；不自动删除受保护证据，提示归档 |
| TTS 缓存 | LRU 与 TTL，起点 1GB | 事实撤销即时失效 |
| 向量与知识 | 配额、增量索引、冷快照归档 | 旧索引在升级回滚期内保留 |

配额必须同时检查剩余磁盘，不能固定 20GB 导致小磁盘被写满。SQLite 用小事务、短读事务、非直播高峰 checkpoint，避免 WAL 无限增长。

## 24 知识实施细则

### 24.1 文档导入

- 格式：TXT、Markdown、CSV、JSON，PDF 与 DOCX 按已安装的解析器。扫描 PDF 的 OCR 是独立可选能力，未安装时标「需 OCR」，不能把空文本当作已入库。
- 限制：文件大小、页数、解析期限、解压比。复杂解析在限资源的子进程执行；拒绝压缩炸弹与外链自动抓取。
- 状态：Uploaded → Parsed → Reviewed → Chunked → Indexed → Evaluated → Published，任一阶段可进入 Failed 或 Cancelled。
- 发布前显示抽取文本、表格与页码、所属产品、有效期、上传政策。向量生成可后台调用 API，但未经允许不上传受限文档。

### 24.2 本地检索

- 先按服务端 ACL、workspace、产品、场景、时间过滤；随后依次是精确事实、中文词法、向量候选。融合用排名（RRF 等），不直接比较不同供应商的分数。
- 每条证据含 source span、revision、有效期、权威级别、permission revision。Rerank 可选；超时只保留已完成的合法证据，不返回「什么都没有」来误导生成。
- 索引身份 = embedding 维度 + 度量 + 归一化 + 模型快照 + 切块版本。
- 本地语义索引须在目标环境用 Rust 跑通，不需要 Python sidecar。小库先用精确检索验证正确性；规模上去后再用 HNSW 等成熟实现，不用未经测量的线性扫描承诺百万级低延迟。

### 24.3 第三方知识接口

- 必需：capabilities、health、search。可选：answer、sync、delete。
- 能力标志：retrieval\_with\_evidence、answer\_with\_evidence、answer\_only。带证据的答案经守门后可直接作为候选，不默认再调 LLM 改写；answer\_only 只作人工参考，不能支撑敏感的自动回复。
- 请求字段：request\_id、session\_id、kb\_ids、query、filters、top\_k、remaining\_budget\_ms。
- 响应字段：status、provider\_id、evidence\[\]（evidence\_id、document\_id、revision、chunk\_id、text、source\_ref、rank、valid\_until）、answer\_draft、usage。
- status 取值：complete、partial、empty、timeout、unavailable、unauthorized。**empty 与 timeout 不得混用。**
- 客户端 filters 不是授权依据，适配器按会话允许的知识空间重新映射。证据 ID 保证来源作用域内唯一。远端版本缺失时标未知，用短 TTL 或人工策略，不伪造本地版本。

### 24.4 路由与删除

- local、remote、hybrid 由场景配置。remote 只在明确存在同知识域镜像时才回退到 local；hybrid 合并已完成的合法证据并显示缺失的来源。权威事实按字段策略优先，不是一律本地胜出。
- 删除先发布 tombstone，使所有待播内容失效，再清缓存、索引与远端可删除的副本。无法删除的第三方留存要在使用前明确政策，不宣称已完全擦除。

## 25 Provider 实施细则

### 25.1 LLM 协议

- 内部请求含：模型 profile、提示词版本、获准上下文、证据列表、输出 Schema、最大输出、deadline、预算。响应支持完整结构化结果与有序流，错误与结束都明确。
- SSE 解析要处理多行 data、分片 UTF-8、工具调用增量与服务端异常，不按每个 TCP chunk 解析 JSON。
- 供应商特有参数放在各自的 adapter。「OpenAI 兼容」只表示候选，不保证工具、JSON、推理参数一致。不支持 Schema 时，用严格解析、校验与有限纠正，仍失败则 ask\_human。

### 25.2 TTS 与发音词典

- TtsRequest 含：speech\_text、display\_text\_ref、voice 与 revision、语言、语速与情绪（能力允许时）、发音词典版本、格式要求、过期时间、批准句段哈希。
- 词典覆盖术语、型号、英文缩写、数字、单位、百分比、公式，按场景匹配，不盲目替换普通词。规范化前后重要事实必须相等，例如「1,299元」与「一千二百九十九元」。
- 支持 SSML 或音素的 Provider 用其合法协议；不支持则用试听验证过的文本替代；不把同一 SSML 传给所有厂商。展示文本与朗读文本都绑定审批版本。
- 链路：获准文本 → 规范化与复检 → TTS 编码流 → 解码 PCM → 输出采样率分支 + 模型采样率分支 → 时间轴与嘴型。解码不得阻塞优先静音。
- 复刻声线的许可、地域、用途、期限与删除流程分别登记。

### 25.3 重试、取消与熔断

- 401 与 403 不自动重试；429 遵循 Retry-After 但不超过任务期限；5xx 与连接错误用有限指数退避加抖动，初值最多一次额外尝试。
- 已提交播放的句段不因 TTS 重试而重播。取消后迟到的字节丢弃，服务端仍计费则入账。
- 熔断按 Provider 与故障类别，不让一个 Embedding 索引失败关闭整场 LLM。前台请求优先于后台批量，共享限额。

### 25.4 缓存键

键包含：最终朗读文本、Provider 与模型、voice 与版本、语言、词典、语速与情绪、格式与采样率、fact/knowledge/policy revision、权限作用域、有效期。

文件哈希校验并限制路径；事实撤销立即禁用，LRU 删除磁盘副本；不同 workspace 不复用受限内容的缓存；语义缓存默认只用于明确的非敏感内容，不以相似句复用价格音频。

### 25.5 成本模型

- 月成本 = LLM + TTS + Embedding 与知识 API + 自建云 CPU/内存/GPU + 网络与中继 + 存储与备份 + 本地电力与设备摊销 + 授权与平台费 + 维护人工。运营值守单独列示，不假设无人化节省。
- LLM = 输入百万 Token × 输入单价 + 输出百万 Token × 输出单价，含分类、总结、重试与缓存计费差异。TTS 按供应商计费文本或输出秒数；预生成语音也产生费用，只在多次有效复用时摊薄。
- 示例（仅用于预算模型，单价为假设，须用实际报价替换）：每天 8 小时、每月 26 天，讲话占 30%、平均 3 字/秒，40% 播报来自有效缓存；每天 400 次 LLM 调用，平均输入 1500 与输出 100 Token；输入输出价按 2 与 6 元每百万 Token。
  - 总播报文本 673,920 字符，需新合成 404,352 字符。
  - LLM 输入 15.6 百万 Token 约 31.2 元，输出 1.04 百万 Token 约 6.24 元。
  - TTS 按 1 元与 3.5 元每万字符，约 40.4 元与 141.5 元。
  - LLM + TTS 约 77.9–179.0 元；预留 15% 额外调用后约 89.6–205.8 元。
- 敏感项：讲话比例升高；LLM 输入变长；每条评论先分类；取消后无限重试；连续手机预览（1Mbps 约 93.6GB/月/观看端）；功耗（150–350W、208 小时约 31–73kWh）；云 GPU 在线小时。
- 400 次调用不等于都播报：先排队准入再调模型。按 30 字回答估算，平均互动容量约 864 条/天，节目与人工讲话也占用该容量。
- 预算控制：每日与每场的软硬预算，80% 提示，100% 停止新付费请求；用 usage 估算做实时账，账单异步对账；没有余额 API 时不显示虚构余额。

## 26 媒体、模型包与形象实施

### 26.1 媒体数据

- 音频块字段：session\_id、utterance\_id、epoch、seq、sample\_rate、channels、sample\_format、sample\_start、sample\_count、end\_of\_stream。
- 视频帧字段：上述标识 + frame\_seq、pts、time\_base、duration、width、height、pixel\_format、buffer\_ref、base\_clip\_index。
- 音频时长按样本数计，视频按有理数 time base；审计用的 UTC 不当媒体时钟。PCM 块的到达时间不等于内容时间。
- 16k 模型分支与 48k 输出分支的 sample\_start 不直接比较，重采样前后保持确定的样本映射。跨机渲染使用独立时钟与抖动缓冲，不比较两台机器的单调时钟。

### 26.2 水位与起播

- 起播缓冲 200–500ms（含模型前瞻），按实测调整。25fps 下 300ms 约 8 帧，1 秒上限约 25 帧。model\_batch\_size、max\_inflight\_batches、max\_ready\_frames 分开设置，不用无限队列掩盖推理落后。
- 已批准的首段音频与对应的首批视频都达到水位才 commit。少量迟帧重复最近帧；持续迟到则取消当前句，静音并待机或经授权降级；不长时间有声无嘴动。
- 末块 padding 只用于模型输入，不延长实际语音或持续动嘴。录制 PTS 单调，句间补静音或待机，保持媒体时钟连续。

### 26.3 数据面所有权

- 本地共享内存槽位明确 producer 与 consumer 状态、长度、seq、epoch 与释放；覆盖前确认 consumer 不再使用；断连时释放相关会话资源并拒绝过期句柄。
- 1080p RGB 25fps 的原始数据约 155.5MB/s，优先避免多次复制与控制总线序列化。跨进程 GPU 纹理共享依赖具体系统与设备，未经测试不写「零拷贝」。

### 26.4 模型包与形象包

- **模型包清单**：所有 graph 与外部权重；预处理与后处理版本；输入输出名称、shape、dtype、opset；采样率、窗口、步长、前瞻、padding、归一化；输出帧映射；执行后端与精度认证；运行库与驱动矩阵；哈希；BOM；golden 参考。缺任一必需项为 NotReady，不用默认值猜测。
- **形象包**：asset 与 avatar ID、素材版本与哈希、授权、绑定的模型与个性化 checkpoint、裁剪 ROI、掩码与关键点、底版 fps 与时长、姿态与自然切换点、循环片段、支持的动作与情绪、音色绑定。模型原生 ROI 与最终 1080p 合成画质分别评估；淡入淡出不能保证任意姿态切换自然。
- **avatar.profile** 返回：支持的输入音频、认证的模型与资源 profile、动作与情绪与视线与强度范围、声音时间信息要求、原生与合成分辨率、帧率范围、未来上下文、可切换点、降级路径。缺必要字段拒绝激活，不猜默认值。

### 26.5 GPU 与执行后端

- 先用 FP32 与原流程逐段对齐，再认证 FP16；INT8 必须有量化与校准及质量报告。
- 记录实际的节点放置、CPU 回落、GPU 复制与全部子图耗时，不以「CUDA EP 注册成功」宣称全 GPU。CPU 档未达实时，不自动顶替写实直播。
- TensorRT 记录 shape profile、engine 与 timing cache、GPU 与运行时版本、图哈希；DirectML 有不同的 Session 约束，按官方文档独立设置。缓存兼容性变化即重建，不从别的 GPU 机器直接复制。
- 离线导出工具可以用 Python，但必须生成完整基准，并在无 Python 的安装环境中验证。

### 26.6 资源压力处理

- GPU OOM：关闭预览或减小已认证的缓存档位 → 取消当前句并静音 → 释放并重启渲染宿主 → 预热与自检 → 人工或明确政策恢复。OOM 时不再加载第二个模型。
- 系统内存或 CPU 压力：暂停解析、重建索引等可选后台任务。
- 网络或配额压力：暂停后台 Embedding 调用。
- 分类处置，不把「暂停云 Embedding」当作释放本地显存。

### 26.7 2D 实现要点

- 可用 wgpu 与 winit 做原生窗口，使用已授权的分层纹理。音频 RMS、平滑与噪声门限驱动有限的嘴部开合；帧位置按对应音频的时间，而不是当前网络包的音量。
- 音频播放选择经 Windows 设备验证的库或后端。固定设备 ID、缓冲与 WASAPI 路由必须实测，不因通用库支持 Windows 就宣称伴侣收音已通过。
- 3D 与 VRM 是独立插件，骨骼、blendshape、材质与引擎授权逐项登记。若 TTS 没有音素时间，需明确独立音素估计的成本与延迟，不把 2D 音量开合宣传成精确口型。

## 27 平台桥接、网关与多会话

### 27.1 SDK 桥接

- 桥接只做：SDK 初始化、官方事件与权限转换、与引擎的认证 IPC、退出。需处理伴侣多次启动、SDK 回调线程、exe 被结束、引擎独立重启、账号或房间变化。
- SDK 回调快速入队，不同步等待 LLM 或磁盘大事务；平台要求的 ACK 按官方协议处理。
- 握手检查路径、签名、nonce 与有效令牌；官方 SDK 库不能从任意路径加载。
- 没有官方接口文档或 SDK 时返回 UNVERIFIED\_EXTERNAL\_DEPENDENCY；演练走 manual 与 replay，不用 fake connector 冒充真实能力。

### 27.2 公网回调网关（仅所选官方接入模式需要时）

- 流程：原始 body 按官方算法验签 → 限制载荷、时间、房间、application → 写持久 inbox → 尽快按协议 ACK → 异步推送。
- 内部 ACK 目标可设 P95 <100ms，但须服从具体平台时限；不得在回调请求中生成或配音。
- 桌面主动出站 TLS/WSS 接收，不开放工作站公网端口。使用游标与序号，但不承诺所有平台消息可恢复、严格有序或零丢失；至少一次投递加幂等。
- 网关断开使相关自动互动失效。

### 27.3 多平台与多会话

- Pro 按连接器实例与会话隔离。同一账号能否同时多会话，由平台条件决定。
- 共享的输出 GPU 池分配 session 到 output 的映射，不向所有房间广播音频。
- 连接器支持能力快照查询与变化事件；unknown 不当 granted。连接恢复后进入 Prepare 与权限复核，不自动恢复旧的 Auto 状态。

### 27.4 轻云控制服务部署

- 单进程服务，提供 Dockerfile、健康检查、非 root 用户、只读根文件系统与持久卷路径；可用 Docker Compose 或系统服务部署。
- 数据库明确为 SQLite 单副本持久卷或关系服务，不把临时容器盘当长期状态。TLS 可由已有反向代理提供；自带则需证书自动续期与失败告警。
- 多副本需要共享关系存储、命令路由与 ownership，不允许两个实例同时授予同一会话的输出租约。Kubernetes 与 Helm 是可选部署包，不是 Local 或轻云的前置条件。

## 28 控制 API、角色与界面

### 28.1 端口边界

同机 Tauri 优先使用受保护的 IPC；HTTP 只用于已启用的手机、轻云与测试适配，Local 默认不开放 HTTP 端口。REST 与 WSS 使用 /api/v1，由 OpenAPI 生成客户端。无公网匿名管理 API；回环地址也需短期令牌与来源检查，不允许任意网页通过 CORS 访问。

### 28.2 写命令语义

- 写命令带 command\_id 与 expected\_state\_revision，会话控制再带 epoch。
- 冲突返回 409，权限不足 403，依赖未就绪返回 409 并带 CAPABILITY\_NOT\_READY。
- 重放返回原执行结果。长任务返回 202 与 job ID，界面订阅实际完成状态。**HTTP 202 不等于已静音。**

### 28.3 接口分组

| 分组 | 代表接口 | 注册者 |
| --- | --- | --- |
| 运行与能力 | GET /health、/runtime/status、/capabilities、/plugins | 核心 |
| 会话 | POST /sessions、/sessions/{id}/prepare、start、stop、mute、takeover、mode；GET events、queue；POST manual-events | 核心 |
| 审批 | GET /approvals；POST /approvals/{id}/approve、reject | 核心 |
| 升级与备份 | POST /upgrades/plan、execute、{id}/rollback；POST /backups、/restore/preflight | 核心 |
| 观测 | GET /usage、/diagnostics；GET /ws（状态订阅与命令结果） | 核心 |
| 设备 | POST /devices/pair、/devices/{id}/revoke | 手机包 |
| 知识 | 导入、jobs、snapshots 发布、search、evaluate、DELETE documents | 知识插件 |
| Provider | GET 与 PUT /providers/{id}、POST test | Provider 插件 |
| 形象 | GET /avatars、POST validate | 形象插件 |
| 场景 | GET 与 PUT /scenes/{id}、POST validate | 场景模块 |

核心命令组是稳定面，其余端点由对应插件注册，未安装的插件不出现。

- Provider 写凭据走安全后端入口，不把返回值带回前端。
- approval 端点重新验证事实、内容哈希、epoch 与 TTL，不因界面显示了候选就信任它。
- DELETE 区分立即撤销与异步物理删除的完成状态。

### 28.4 角色与权限

| 角色标识 | 对应 11.4 | 权限（示例） |
| --- | --- | --- |
| viewer | 观察者 | runtime.read、session.read |
| operator | 场控（含审批） | viewer 全部 + approval.read、approval.write、media.mute、session.takeover、event.manual.write |
| admin | 主播或管理员 | operator 全部 + session.manage、session.mode.change、scene.configure、knowledge.edit、knowledge.publish、device.manage、runtime.observe |
| 本机管理员 | 仅本机 | provider.configure（经安全入口）、模型与形象导入、信任库、外发策略、插件安装、runtime.upgrade、storage.backup、storage.restore |

工作站角色与平台账号权限分开。团队 OIDC 是 Pro 可选的身份适配器，不强制 Local 登录云。

### 28.5 设备配对与撤销

首次配对需本机确认一次性短期 code；持久设备凭据存在安全存储并可轮换。撤销立即断开令牌与连接，并取消该设备相关的未执行审批。

### 28.6 界面覆盖与安全

- 导航按已启用的能力动态注册：直播台、场景与节目、智能体策略、技能、知识、记忆、形象、音色、Provider、平台、插件、评估与回放、设备与手机、团队权限、部署与升级、诊断。
- 直播台固定显示静音、接管、停止自动；待审批显示最终 speech 与 display 文本、依据与版本、失效倒计时、当前模式；队列显示秒数而不是条数。手机保留这些核心控制，并显示实际 ACK、断线与设备权限。
- 知识导入显示解析、索引与发布状态；模型中心区分已安装、未认证、资源不足、Ready；升级页列出影响、外部条件、资源与费用增量、维护窗口、日志与恢复入口。
- 确认规则：误点静音无需确认；恢复自动、删除、回滚按实际风险明确确认并复核条件，不设无意义的层层弹窗。
- Tauri 的 capabilities 与 CSP 只开放必要的命令与资源；前端没有任意 shell、文件系统、SQL 权限；外部 URL 只由受控逻辑打开；模型输出或知识片段不能当 HTML 插入执行；UI 升级不得改变后台权限行为。

## 29 配置、仓库与构建

### 29.1 配置分层与生效

- 优先级：只读发行默认 → 部署 profile → workspace → 场景 → 会话覆盖。不可绕过的安全条件不随优先级覆盖。每层有 Schema、revision 与审计，Provider 密钥只存引用。
- 生效时机四类：immediate\_restrict（收紧立即生效）、sentence\_boundary、next\_session、maintenance\_window，界面提前展示影响。
- edition manifest 只指定默认插件与能力，不固化资源参数。resource profile 是已认证的模型、硬件与负载组合，无认证显示 candidate。edition、资源认证、平台能力快照、商业权益四者相互独立。

### 29.3 绑定与降级表

| 故障或缺失 | 处理 | 禁止 |
| --- | --- | --- |
| 主 LLM 不可用 | 句边界切到已认证的备份，或用批准模板、人工 | 未核策略直接换未知模型 |
| TTS 不可用 | 有效缓存或人工；授权的文字模式可选 | 偷偷部署本地 TTS；一句中拼接声线 |
| Embedding 或 Rerank 不可用 | 合法词法检索、不重排并标状态 | 把错误当无答案；跨模型混向量 |
| 必需的权威知识缺失 | 澄清或人工，停止相关自动内容 | 无证据编造价格或库存 |
| Guard 不可用 | 拒绝所有外发，待机或真人音轨 | 模板与缓存免审播报 |
| 写实 GPU 不可用 | 停句静音；认证恢复或预授权切 2D | 未认证的 CPU 回落；OOM 时加载备用大模型 |
| 平台断开或权限撤销 | 关闭相关真实自动互动，重连后复核 | 用缓存事件继续假装真实反馈 |
| 手机或云控制断开 | 本地控制保留，按值守租约评估 | 用网络心跳充当有人监督 |
| 输出设备变化 | 静音并重测设备与路由 | 自动切换默认设备造成回声或泄音 |
| 预算耗尽 | 停止新付费调用；合法缓存或人工 | 无限重试；篡改 usage 清零 |

降级规则使用受限枚举与版本化配置，不允许配置任意 shell 脚本。不符合场景安全条件的 fallback，即使表中列出也不执行。

### 29.4 仓库与依赖方向

- **技术栈**：Rust + Tokio + serde + tracing；按需 axum 与 reqwest；Tauri 2 + React + TypeScript + Vite；独立的薄 C++ 桥接；SQLite + FTS5 + 嵌入式向量；ort。版本经兼容测试后锁入 Cargo.lock 与工具链文件，不写「永远 latest」。
- **应用**：apps/engine、output-keeper、render-worker、update-helper、control-server、desktop、remote-web。
- **核心 crate**：dh-contracts、dh-kernel、dh-plugin-sdk、dh-plugin-hosts、dh-runtime、dh-storage、dh-security、dh-media-core、dh-knowledge-core、dh-provider-core、dh-control-api、dh-upgrade-core、dh-conformance。
- **其他目录**：plugins/\*（按切片创建）、native/douyin-bridge、packages/{contracts-ts, plugin-ui-sdk, ui-components, api-client}、schemas/{core, domain, config, plugin, openapi, catalog}、profiles/{editions, deployments, resources}、migrations/{sqlite, postgres}、tests、xtask、tools/{model-export, avatar-authoring}、docs/adr。

### 29.5 构建、产物与发布

- Rust workspace 统一依赖版本。default-members 包含可移植的内核、契约与逻辑测试；Windows 音频、桌面、GPU、SDK 包由对应 runner 构建。禁止「全 features 一起开」导致互斥的执行后端混用，xtask 按 profile 选择包与 features。
- inproc 插件只包含编译链接的实现，未编入的插件不能靠改配置出现。内核源码与公共二进制兼容线一致，不复制 LiteKernel 与 ProKernel 之类的类型。
- Tauri sidecar 按目标三元组命名并打包。默认的 UI 父子生命周期要显式处理：需要在 UI 关闭后继续运行的引擎与 keeper 由独立 supervisor 或托盘管理，不依赖 WebView 保活，也不开放任意 shell。
- **产物**：core-runtime（engine、可信插件、supervisor、update-helper）；desktop-shell；media-base（keeper、render-worker、2D、窗口输出）；plugin-pack（manifest + 二进制 + 配置 Schema + 哈希与签名 + BOM）；model-pack 与 avatar-pack 分离；profile-pack。
- 发布目录含 catalog、兼容矩阵、哈希、签名、SBOM 与许可、安装器、可选离线包、Schema、操作与恢复文档、测试报告。安装器不含凭据；未认证的模型可作为 candidate 单独提供，但界面标注不可用于正式播报。
- **签名**：发布签名、Windows 代码签名、模型哈希与企业信任策略各自负责，不用一个自签名替代平台或商用许可；私钥不进仓库与诊断；撤销列表与离线可信缓存有期限。
- **原生依赖**：ORT、CUDA、cuDNN、媒体编解码记录版本、许可与下载方式，不假设所有 CUDA 组件可随包分发；FFmpeg 记录构建选项与许可，不盲目打包未知的 GPL 构建；应用加载受控的 DLL 路径，不依赖开发机 PATH。
- **CI**：Schema 生成无 diff、fmt 与 clippy、依赖边界、纯逻辑测试、契约套件、Windows 安装与媒体测试、UI 类型检查与关键流程、升级故障注入、供应链与密钥扫描。GPU 与真实 SDK 验收在受控机器上单独执行，报告硬件、版本、授权；无法执行就标 Blocked，不写成 CI Passed。

## 33 开放平台总览（第三部分）

### 33.1 判断：V3.6 有扩展骨架，但还不是开放平台

V3.6 已有微内核、能力契约、插件包、信任域、风险分级、场景包，这些是开放平台的地基。但整体仍是「一个产品加插件」，缺少让第三方持续贡献的完整机制：

- 扩展只分「插件」一类，没有区分接入器、技能、资产包、界面面板，各自的风险与分发方式不同。
- skill.invoke 仍是 Draft，没有技能清单、有效风险重算、技能路由与上下文预算。
- 没有统一的数据契约：数据来源、时效、权威级别、敏感分类没有标准字段，守门与外发策略无从依据。
- 没有设备与硬件接入的抽象，也没有物理安全联锁。
- 没有分发体系：目录、审核、权限展示、更新授权、撤销与下架、信任等级与计费。
- 没有开发者体验：脚手架、本地模拟宿主、技能测试台、自检套件。
- 非直播场景（导览、前台、门店）的输入来源与合规要求没有设计。

### 33.2 开放平台模型：一个内核、五类扩展、一个分发体系

| 扩展类型 | 作用 | 典型实现形态 |
| --- | --- | --- |
| Connector（接入器） | 把数据源、业务系统、设备、平台接进来或把动作送出去 | 声明式 HTTP/Webhook、通用协议适配器、SDK 桥接、远端服务 |
| Skill（技能） | 智能体可请求调用的能力单元：查询、计算、动作 | 声明式、wasm 沙箱、远端、官方原生 |
| Pack（资产包） | 场景包、知识包、形象与音色包、规则包（守门与合规词库）、评测包 | 数据文件加清单，无可执行代码 |
| Provider（模型服务适配） | LLM、TTS、Embedding、Rerank、ASR、审核 | 适配器加远端服务 |
| Panel（界面面板） | 声明式的控制台面板与手机卡片 | 声明式配置，R3 才开放 |

五类扩展共用同一套清单、签名、信任域、权限、生命周期与撤销机制（见 4.3、4.4），不为市场另建一套。

### 33.3 开放不等于放权

平台对所有扩展都保证以下不变量，它们优先于任何扩展声明：

- INV-22：扩展（技能、接入器、资产包）不得绕过守门、授权、审批、租约与决策日志，不得直接发声。
- INV-23：扩展的实际权限不得超出清单声明与用户授权；出站网络、数据范围、凭据、设备能力由宿主强制执行，不靠自觉。
- INV-24：技能与数据源的返回一律是数据，必须带来源与时效；过期、来源不明、敏感分类受限的数据不得用于播报或外发。
- INV-25：被撤销的扩展立即禁用并取消进行中的调用；更新引入新增权限或更高风险时必须重新授权。

## 34 数据源、系统与设备接入

### 34.1 接入分类

| 类别 | 示例 | 方向 | 常见接口 | 默认风险 |
| --- | --- | --- | --- | --- |
| 直播与互动平台 | 抖音、快手、视频号、自建 H5 | 入：事件；出：画面与声音 | 官方 SDK、回调 | 见第 9 章 |
| 业务系统 | 商品库、ERP、订单、CRM、工单、库存、会员 | 入：查询与订阅 | REST、Webhook、数据库只读视图 | 读 risk\_0；写 risk\_2 以上 |
| 内容与知识源 | 文档库、Wiki、表格、网页、FAQ 系统、第三方 RAG | 入 | 文件、API | 同第 6 章 |
| 外部信息 | 天气、新闻、行情、赛事、交通 | 入 | API、RSS | 只读，来源白名单，带 TTL |
| 直播设备 | 摄像头与云台、麦克风阵列、声卡、灯光、导播台（OBS、vMix）、提词器、大屏 | 入出 | OBS WebSocket、灯光协议、厂商 SDK | 输出影响画面，按 risk\_2 |
| 现场感知设备 | 触摸屏、传感器、人流计数、扫码、RFID | 入 | MQTT、串口、SDK | 涉及隐私，需评估 |
| 现场执行设备 | 机械、门禁、打印、发券机 | 出 | SDK、PLC 网关 | 物理动作，默认 risk\_3 禁止 |
| 办公与通知 | 企业微信、飞书、邮件、Webhook | 出 | API | risk\_1，限频 |

### 34.2 统一数据契约

- **data.query@1**（按需拉取）：请求含 source\_ref、受控查询参数（不接受自由 SQL 或自由 URL）、deadline、数据范围令牌；响应含 records，以及每条的来源信息：source\_id、fetched\_at、valid\_until、authority（system\_of\_record、derived、external、unverified）、classification（public、internal、personal、restricted）、revision。
- **data.subscribe@1**（推送订阅）：Webhook、MQTT 或长连接事件流；声明去重键、顺序语义、重连语义与背压。进入调度后按普通事件处理，不绕过 EventIngress。
- **device.sense@1 与 device.control@1**：声明动作枚举、取值范围、速率限制与安全联锁。control 默认 risk\_2；物理执行类默认 risk\_3，需要本地确认与独立开关。
- **asr.transcribe@1**（预留）：语音输入，用于连麦、导览、前台等场景，R3 才实现。

数据进入系统有三条路径：

- 技能按需拉取（query）。
- 事实同步：把价格、库存等权威数据写入 KB0 的新修订，沿用第 6 章的发布与失效规则。
- 事件订阅：作为新的领域事件进入调度。

关键规则：

1. 实时业务数据用于播报时必须带来源信息；过期即丢弃；不进语义缓存，TTS 缓存必须绑定数据修订。
2. classification 决定外发：personal 与 restricted 数据不进云 LLM 上下文，除非场景明确允许且 Provider 的数据政策满足；否则只走本地规则或脱敏。
3. 多个数据源冲突时，按字段的权威级别处理；无法判定则转人工。

### 34.3 接入器实现形态

- **声明式 HTTP/Webhook 接入器**（无代码）：配置域名白名单、认证引用、请求与响应映射、分页、限频。这是最适合第三方贡献的形态。
- **官方通用协议适配器**：HTTP/Webhook、MQTT、OBS WebSocket、数据库只读视图（参数化查询）。
- **SDK 桥接**：平台与厂商 SDK，在 subprocess 宿主运行（见第 27 章）。
- **远端连接器服务**：企业自有系统通过 remote 宿主接入。
- **MCP 适配**：见 35.2。

接入器清单必须声明：数据分类、方向、速率、入站与出站网络白名单、凭据引用、离线行为、健康检查、沙箱要求，以及含异常（超时、乱序、重复）的测试夹具。

### 34.4 硬件接入原则

- 设备驱动与 SDK 放在 subprocess 或边缘节点，不进内核进程。
- 设备能力声明、安全联锁与本地手动覆盖是必需项；设备事件写入决策日志。
- 设备热插拔、断线、重复与超时要有明确处置；测试使用模拟设备。
- 摄像头视觉感知（识别观众动作、表情）涉及隐私与法规，默认关闭，R3 之后单独评估，不作为首版能力。
- 物理执行类设备默认禁用，启用需管理员本机确认。

## 35 技能（Skill）规范

### 35.1 定义

技能是智能体可请求调用的能力单元：输入 Schema → 受控执行 → 输出 Schema。技能**不直接说话、不改变授权、不产生表演指令**，只返回数据，由决策器和守门决定能否使用。

### 35.2 实现形态

| 形态 | 说明 | 可上架 | 信任要求 |
| --- | --- | --- | --- |
| 声明式 HTTP 技能 | 配置映射调用已授权的 REST 或 Webhook，无自有代码 | 是，首选 | community 即可 |
| wasm 沙箱技能 | 纯计算与受控宿主调用（成熟度待验证） | 沙箱认证后 | community 即可 |
| subprocess 或 remote 技能 | 原生或远端服务 | 仅 official、enterprise、verified | 第三方原生在沙箱认证前不开放 |
| MCP 工具适配 | 把 MCP 服务的工具映射为技能描述 | 视同 remote，逐工具审核 | 工具描述与返回都不可信；不信任服务端自报的只读或低风险；协议版本与认证方式待验证 |

### 35.3 技能清单字段

- 标识与来源：id、version、publisher、license、BOM、signature。
- 描述：给人看的名称与说明；给模型看的 model\_description（长度受限、经审核、不得含指令性内容）。
- 接口：params\_schema（拒绝额外字段）、result\_schema、timeout\_ms、rate\_limit、max\_cost、idempotency、locale。
- 影响：side\_effect（none、read、write\_internal、visible\_to\_audience、physical）、declared\_risk。
- 权限：data\_scopes、network\_allowlist、credential\_refs、device\_caps。
- 数据外发声明：会把哪些数据发往哪里。
- 运行：runtime host、requires（能力与内核版本范围）、test\_fixtures。

**有效风险 = max(声明风险, 由 side\_effect 与权限推导的风险)**。声明低于推导的，上架审核与加载时都拒绝。

### 35.4 调用链

模型请求 → Schema 校验 → 计算有效风险 → 策略判定（允许、需审批、拒绝）→ 权限与外发检查（classification × 目的地）→ 预算准入 → 受限宿主执行（deadline、取消、出站白名单）→ 结果 Schema 校验与大小上限，并标记不可信 → 若用于播报，绑定证据后进入守门 → 写决策日志（技能 ID 与版本、参数哈希、结果摘要、成本）。

### 35.5 技能路由与上下文预算

场景只启用白名单内的技能。每次决策前由路由器（规则优先，必要时用小模型）挑选相关技能，初值不超过 5 个，只把它们的描述放进提示词。技能数量增加，不线性增加提示成本，也不扩大注入面。

### 35.6 并发、幂等与副作用

- 读技能可缓存，缓存带 TTL 与数据修订。
- 写技能必须带幂等键；失败不重试写操作，除非可证明幂等。
- 同一决策周期内技能调用步数设上限（初值 2）。多步工具规划只在人工批准路径，不进实时自动路径。

### 35.7 官方首批技能建议

- R1：商品事实查询、活动与优惠规则查询、FAQ 检索、库存与价格状态（只读）、时间与日历、通知运营（risk\_1）、转人工工单（risk\_1）。
- R2：订单与物流状态（只读，需用户授权）、天气（只读）、切换商品卡（risk\_2，需平台能力）。
- 默认禁用：发放优惠券、改价、下单、退款等 risk\_3 动作。

## 36 技能市场与分发

### 36.1 形态

- 官方市场：独立项目，通过开放接口对接（见第 38 章）；本项目只提供客户端与适配层。
- 企业私有市场：任何实现了同一开放接口的目录服务，含自建镜像。
- 本地侧载：开发模式，信任域为 dev，界面显著标注。

Local 部署不依赖在线市场；支持离线包与镜像目录。

### 36.2 可上架内容

Skill、Connector、Pack（场景、知识、规则、评测）、形象与音色包（需肖像与声线授权证明）、Provider 适配器、Panel。统一使用 plugin-pack 分发格式，增加 skill、connector、pack 等类型字段。

### 36.3 目录元数据

每条目录项包含：id、版本、发布者、类型、信任等级、权限摘要、风险标签、兼容范围、变更日志、哈希与签名、下载大小、许可与价格；评分可选。目录本身可自托管，并带签名。

### 36.4 发布流水线（由市场项目负责）

开发 → 本地测试台 → 一致性与安全自检 → 提交 → **自动审核**（签名、Schema、依赖与许可、权限与风险一致性、恶意模式、隐私声明）→ **人工审核**（高风险权限、官方认证标签）→ 发布（签名与版本）→ 灰度、评分与举报 → 撤销与下架。

### 36.5 安装与运行时

- 安装前展示权限清单（网络域名、数据范围、凭据、设备、成本）与风险标签，由用户或管理员授权。
- 更新时若权限增加或风险升级，必须重新授权；自动更新默认关闭，开播中只暂存。
- **安装不等于启用**：技能需要单独勾选启用到某个场景。
- 运行时监控调用量、错误率、延迟、出站流量与成本；异常时自动降级或停用并告警。
- 撤销列表即时生效，进行中的调用取消。

### 36.6 信任等级与默认策略

| 等级 | 来源 | 默认允许形态 | 自动模式可用 |
| --- | --- | --- | --- |
| official | 官方构建 | 全部 | 是 |
| verified | 通过身份与代码审核的发布者 | 声明式、wasm、remote | 需企业管理员批准 |
| community | 开放提交 | 仅声明式与 wasm（认证后） | 默认否，仅演练与辅助 |
| dev | 本地侧载 | 全部，仅限开发 | 否 |

策略包可以收紧这些默认值，不能放宽第 2 章与 33.3 的不变量。

### 36.7 许可与计费

- 支持免费、付费、订阅、按量等方式。授权校验失败不得切断已有合法运行的会话（沿用 14.1）。
- 技能运行产生的 API 与第三方费用计入预算账本，并按技能归因。
- 分成与结算属于商务模型，本文不设计。

### 36.8 肖像、声线与品牌素材

需提供授权证明与期限，过期自动停用；不允许上架没有授权证据的真人数字分身。

### 36.9 仿冒与滥用防护

发布者身份校验；名称防仿冒；签名绑定发布者；版本回滚保护，防止降级攻击；举报与应急下架。

## 38 市场开放接口与客户端适配

本章取代第三部分中「市场由本项目自建」的隐含假设：公开官方市场从一开始就做，但作为**独立项目**开发，通过开放接口与本项目对接。本项目只提供客户端、接口适配与使用方式。

### 38.1 边界与职责划分

| 能力 | 市场项目（独立） | 本项目（客户端与适配层） |
| --- | --- | --- |
| 开发者账号与发布者身份校验 | 负责 | 只校验签名链与信任等级 |
| 提交、自动与人工审核、风险标签 | 负责 | 本地重新计算有效风险，市场标签仅作参考 |
| 目录、搜索、评分、举报 | 负责 | 浏览与展示，调用接口 |
| 包存储与分发 | 负责 | 下载、断点续传、哈希与签名校验 |
| 签名与根密钥管理 | 签发 | 持有信任根并校验，处理轮换 |
| 撤销与应急下架 | 发布撤销列表 | 订阅并在本地强制执行 |
| 授权、订阅、计费、结算 | 负责 | 校验授权令牌，展示费用，把成本归因入账 |
| 安装、启用、权限授权、运行时监控、卸载 | 不涉及 | 负责 |
| 信任等级默认值与自动模式限制 | 提供标签 | 本地策略包决定 |
| 遥测 | 接收 | 默认关闭，脱敏 |

原则：市场是信息与分发服务，**不是信任的唯一权威**。本地策略与第 2 章、33.3 的不变量优先。新增不变量：

- INV-26：市场不可用或被攻破，不得影响正在进行的直播与本地安全不变量；未通过本地校验的包一律不安装、不激活。

### 38.2 开放接口（Market Open API v1）

用 OpenAPI 描述并版本化，任何实现了该接口的服务都可以作为市场源，包括企业私有目录。

| 接口组 | 作用 |
| --- | --- |
| GET /v1/discovery | 市场标识、API 版本范围、支持的特性、签名根指纹、遥测与计费能力声明 |
| GET /v1/catalog、/v1/catalog/search | 分页与过滤（类型、场景、信任等级、兼容范围、语言），返回目录项摘要 |
| GET /v1/extensions/{id}、/versions/{ver} | 详情、权限摘要、市场标注的风险标签、变更日志、依赖、兼容范围、清单哈希 |
| GET /v1/packages/{id}/{ver} | 下载，支持 Range，附哈希与签名元数据 |
| GET /v1/metadata/{root、timestamp、snapshot、targets} | 签名元数据，借鉴 TUF 的分层思想以防回滚与冻结攻击；具体方案待选型验证 |
| GET /v1/revocations?since= | 带签名的增量撤销列表，含序号与过期时间 |
| 授权令牌接口 | 付费扩展的授权令牌签发与校验；令牌短期、可离线验证，绑定 workspace 与随机安装 ID |
| POST /v1/reports | 举报，可选，需用户同意 |
| POST /v1/telemetry | 可选，默认关闭，只收聚合统计，不含观众内容 |

- 认证：目录匿名可读；付费包下载需授权令牌；账号登录（OIDC）只用于购买与举报，不用于运行。
- 所有响应带 request\_id；限速与退避；版本协商；错误码风格沿用 20.4。
- 客户端不得因市场响应执行任意代码或脚本。目录字段未知时忽略；安全元数据字段未知时拒绝。

### 38.3 信任模型与校验

- **信任根**：客户端内置官方市场的根公钥，支持多根与轮换（交叉签名或多方签名更新，具体方案待定）。企业或第三方市场必须由管理员显式导入其根。不同市场的根相互隔离，来源不混用信任。
- **校验流水线**：TLS → 元数据签名与新鲜度（时间戳未过期、版本单调，防回滚与冻结）→ 清单哈希 → 包哈希与签名 → 发布者签名链 → 撤销检查 → 兼容性（内核与契约版本范围）→ 本地有效风险重算 → 权限清单展示 → 用户或管理员授权 → 暂存 → 无活动会话时激活。
- **本地为准**：市场给的风险标签只作参考；本地按 35.3 重算，不一致取较高者并提示。
- **市场被攻破时的最坏情况**：伪造的包因没有有效签名链被拒；签名有效但恶意的包仍受权限、沙箱与审批限制；撤销可能被延迟，处理见 38.4。

### 38.4 撤销与失效保护

- 客户端联网时按间隔拉取撤销列表（初值每小时一次），开播前体检强制刷新一次；失败则使用本地缓存。
- 撤销条目含：扩展 ID、版本范围、原因分类、生效时间、严重级别。严重级别 critical 立即禁用并取消调用；high 在下一个句边界停用；normal 在下个会话生效。
- 缓存超过设定期限（初值 72 小时）：阻止新的安装与更新；对已启用且风险为 risk\_2 及以上的扩展，在自动模式下降级为需审批。**不立即停用普通的已运行扩展**，避免市场不可用造成直播被动中断。
- 离线包自带元数据快照与撤销快照，超期时提示。

### 38.5 多源与镜像

- 源配置：官方市场（默认）、企业私有目录或镜像、本地目录（离线包）、dev 侧载。每个源有独立的信任根，以及独立的信任等级上限（例如企业源可授予 enterprise）。
- 同名扩展跨源冲突时不自动合并，需要用户选择并标注来源。扩展 ID 带发布者命名空间，依赖只在声明的源内解析，防止依赖混淆。
- 企业镜像支持两种模式：保持官方签名链不变地同步；或经企业审批后用企业根重签，并标记为 enterprise 等级。

### 38.6 客户端行为与体验

- **扩展中心**：多源搜索；按场景、类型、信任、兼容范围过滤；详情页显示权限清单、有效风险、数据外发声明、变更、评分、举报入口、许可与价格；安装、启用、更新、卸载；更新只通知，不自动安装。
- **开播保护**：开播中禁止安装与更新激活；市场调用使用独立的低优先级、限速、有界队列，不占用实时资源；市场整体故障时扩展中心显示离线，不影响直播。
- 缓存：目录与图标缓存有 TTL；价格与授权状态以实时为准。
- **隐私**：请求不携带观众、会话或知识内容；设备标识使用可重置的随机安装 ID；遥测默认关闭，开启需明确同意并显示上报字段。
- **付费**：授权令牌离线验证；离线宽限期初值 7 天，可配置；到期后阻止新会话启用该扩展，不切断正在运行的会话（沿用 14.1）。

### 38.7 参考实现与测试

- 本项目随仓库提供参考模拟市场（mock market），仅用于测试与演示：实现 Open API v1 的最小子集，含签名元数据生成与撤销，不是正式市场。
- 契约测试：市场项目与本项目共用 OpenAPI 与测试向量（签名元数据样本、回滚攻击样本、冻结攻击样本、撤销样本），双方 CI 都运行。
- 版本演进：Open API 主版本内向后兼容；客户端同时支持 N 与 N-1，通过 discovery 协商。

### 38.8 需要与市场项目约定的事项

- 根密钥的保管、轮换与泄露应急流程。
- 审核标准与响应时限；撤销的响应时限（critical 级别应为小时级，具体数值待定）。
- 授权令牌的格式与有效期。
- 发布者身份校验方式；名称防仿冒；知识产权与未成年人相关投诉处理。
- 区域合规与内容审核要求（具体法规待核对）。
- 可用性目标与灾备。

- 技术路线：手机监控采用中继加 PWA 还是原生壳加局域网直连；wasm 组件模型的异步与流式能力；MCP 适配的协议版本与认证；Tauri 2 移动端成熟度；静态数据加密所用的系统密钥保护机制。
- 写实形象：合法完整的模型来源与授权；Gate G0–G3 结论。
- 商务：技能的定价、分成与结算方式（不在本方案范围内）。

## 40 智能体 Harness 总览（第四部分）

第四部分把智能体从「决策循环加路由表」补成**工程化**的运行时，并把开放接口从一行适配说明补成**可判定的互操作边界**。

### 40.1 判断：V3.7 有智能体，但智能体还不是工程化的

行业内把这件事的划分写作 `Agent = Model + Harness`：模型负责推理与生成，**Harness** 负责模型之外那套让智能体在长链路、可执行、低容错场景里持续正确的东西——上下文管理、工具接口、编排、状态与记忆、验证闭环、约束与恢复。V3.7 §5 给了「观察 → 决策 → 授权执行 → 行动 → 写决策日志」的循环与一张分级路由表，§35–§38 给了技能与扩展骨架；这些是必要的地基，但按上面的划分，V3.7 里 harness 只有零散零件：

| 缺口 | V3.7 的现状（实测命中） | 后果 |
| --- | --- | --- |
| 上下文装配 | §5.1 只列 Observation 的**字段**，没有定义「给模型看什么、按什么顺序、各占多少预算、怎么裁剪」 | 约束容易被证据与工具日志挤掉；同一次调用无法重建 |
| 记忆读写 | §5.5 是四类记忆的**叙述**，没有写入门槛、读取过滤与遗忘的接口语义 | 「把工具返回写成事实」「跨作用域读取」无判据 |
| 意图识别 | 全文命中数 **0**；§5.2 反而写明「一次短上下文 LLM，**不先做独立分类**」 | 该取舍只对**实时**路径成立，却被写成全局结论；非实时路径（人工辅助、影子、入站外部请求）没有意图语义 |
| 工具调用 | 命中 **1 处**，且是 §987 的 SSE 解析措辞（「工具调用增量」），**不是能力定义**；§35.6 只有一句「步数上限初值 2」 | 循环的终止、并行、部分失败、与守门的分工无定义 |
| 语义缓存 | 命中 **3 处**：§1008 一句纪律、§1480（§34.2 规则 1）、§1646（M04） | 无键、无命中判据、无误命中度量；「命中不等于复用授权」未成文 |
| 开放接口 | MCP 命中 **4 处**（§1490「见 35.2」、§1515 表格一行、§1658「MCP 适配调研」、§1873 待确认）；**A2A 命中数 0** | MCP 只被当作「技能的一种实现形态」，其 resources / prompts / sampling 与远端服务端的信任未处置；智能体与智能体的互操作完全缺失 |
| harness 自身的可观测与门控 | 无 | 「harness 有没有按设计工作」无法判真伪 |

⇒ 第四部分逐项补成**可判定的边界**，并**不推翻** V3.7 已裁定的实时路径取舍（不做多步工具规划、不做独立分类器、并发与缓存的既有纪律），只在其上加「装配、预算、循环、门控」。

**本轮定位**：只定义边界、不变量、验收与工作项；**不实现**任何 harness 代码。§33.1 那句「有扩展骨架，但还不是开放平台」同样适用于 harness：V3.8 给出骨架与判据，落地随 §47.6 的工作项推进。

### 40.4 Harness 的五条纪律

1. **装配优先于累积**：模型可见的一切都必须经 §41 的装配产生。
2. **建议与授权分离**：意图、相似度、模型自报都是建议（INV-29、INV-30）；授权只来自 §4.2、§5.4、§5.6、§21.4 的既有机制。
3. **不可信一律标注**：外部来源进上下文即在结构上标记（§41.3）。
4. **有界**：循环步数、并行度、结果大小、缓存条目、委派深度全部有界，越界具名终止、不静默截断。
5. **默认可关闭**：harness 新机制默认只在演练、影子与人工辅助下启用；进入实时自动路径必须过回归（§47.3）。

## 41 上下文装配与预算（L1 信息边界层）

### 41.1 装配步骤与固定顺序

每次调用付费模型前，上下文 MUST 由下列步骤按**固定顺序**生成。顺序固定只有一个目的：让**约束不被挤掉**。预算不足时从后往前裁剪，前段不可裁。

| 序 | 片段 | 来源 | 裁剪 |
| --- | --- | --- | --- |
| 1 | 系统策略与安全约束 | 配置（§29.1；按 §11.7 作安全相关变更管理） | 不可裁 |
| 2 | 人设、场景口吻与禁答范围 | 场景包（§15） | 不可裁 |
| 3 | 任务与输出契约（Decision 动作枚举、输出 Schema） | 契约（§20.6、§5.1） | 不可裁 |
| 4 | 当前事件与 Observation 摘要 | §5.1、§22.2 | 可裁至摘要 |
| 5 | 已批准事实与检索证据 | KB0/KB1（§6）、§24 | 最多 3–5 条（§6 初值） |
| 6 | 记忆片段 | §42 | 独立配额，见 §42.3 |
| 7 | 可用技能与工具描述 | §35.5（最多 5 个）、§46 | 可裁 |
| 8 | 最近实际播完的句子 | §5.5 工作记忆 | 可裁 |
| 9 | 工具结果与外部返回 | §44、§46 | 可裁；一律标不可信 |

**不可裁剪段（1–3）缺失时 MUST 拒绝调用**，MUST NOT 用「少几条策略继续生成」顶上。

### 41.2 分段预算

- 预算按**段**分配，不是一个总上限：策略与人设段取固定下限；证据段、记忆段、技能描述段、工具结果段各有独立配额。
- Token 与字符同时记录；`remaining_budget_ms` 与 Token 预算是**两个**维度，互不替代（沿用 §20.2、§22.1）。
- 裁剪 MUST 记录**被裁了什么与原因**，作为 §47.1 的观测项。
- 初值只作起点，MUST 用 §47.2 的黄金集回放调参并记录 ADR。

### 41.3 片段标注与不可信边界

每个片段 MUST 携带：来源类型（系统策略 / 场景 / 事件 / 知识证据 / 记忆 / 工具结果 / 外部智能体）、来源标识、作用域、时效（如适用），以及**数据或指令**的标注。观众文本、检索片段、工具返回、外部智能体返回一律标为**数据**；其中出现的「忽略规则」「已批准」等措辞没有指令权（沿用 INV-09、§11.7）。

### 41.4 压缩、重置与利用率

- 上下文变长时，优先**丢弃已失效片段**（事实失效、权限撤销、过期证据），其次用**结构化摘要**替换已播内容。摘要 MUST 引用来源，MUST NOT 用无来源的自由摘要替代事实（与 §24.4 的 tombstone 纪律一致）。
- 上下文利用率 MUST 作为观测项登记（§47.1），但**本轮不设告警阈值**：外部公开的「用到若干比例后质量下降」来自特定模型与任务，MUST NOT 直接外推为本系统门限；阈值待本场景回放实测后另行裁决。

### 41.5 可判定性

装配 MUST 落决策日志：进入的片段标识、各段预算占用、裁剪项与原因、本次调用的模型与提示词版本。装配记录 MUST NOT 含明文凭据（INV-11）。验收 H01、H02。

## 42 记忆子系统（L4 记忆与状态层）

### 42.1 四类记忆

沿用 §5.5 的分类，本节把它升级为**有接口语义的读写面**。

| 记忆 | 内容 | 写入 | 读取 | 生命周期 |
| --- | --- | --- | --- | --- |
| 工作记忆 | 最近实际播完的内容 | 播放完成 ACK 后（§21.3） | 每次装配 | 有界，随会话 |
| 场次记忆 | 已讲主题、已回答问题、已批准承诺、恢复点 | 已批准且已播完的候选 | 每次装配，带配额 | 按保留期（§23.5） |
| 语义记忆 | 已发布知识（KB0–KB3） | 只经 §6 的发布流程 | 经 §6 检索 | 随知识快照 |
| 观众长期记忆 | 允许字段的长期画像 | **默认关闭**（INV-17） | 需授权并记录用途 | 按保留期与删除入口 |

### 42.2 写入规则

- 只有**已批准且已播完**的内容可写为场次记忆；未播出的生成文本 MUST NOT 写成事实（沿用 §5.7 的检查点纪律）。
- 工具返回、外部智能体返回、评论原文、模型草稿 MUST NOT 直接写成事实或承诺（INV-09、INV-24、INV-31）。要成为事实，必须走 §6 的导入与发布。
- 每次写入 MUST 带：作用域（workspace/session）、来源标识、时间，以及「叙述还是权威事实」的标注。

### 42.3 读取规则

- 读取 MUST 先按作用域过滤（workspace、session、场景），再按时效过滤。过期、被撤销或权限不足的条目 MUST NOT 进入上下文，且 MUST NOT 用「近似条目」顶替（沿用 §21.2「不得跨知识域任意切换备份知识」）。
- 观众长期记忆的读取 MUST 有授权引用并记录用途；未授权时按「无记忆」继续，MUST NOT 以推断补齐。
- 记忆段有独立配额；超配额按「场次记忆 > 工作记忆 > 观众长期记忆」的固定优先级裁剪。

### 42.4 遗忘与删除

- TTL 到期、事实失效、权限撤销、用户请求删除四类触发共用 §24.4 的删除链：**先阻断检索与读取，再异步清除副本**。
- 删除 MUST 可验证：读取侧先失效，清理侧给出完成状态；第三方留存不可清除时 MUST 在使用前明示政策（沿用 §24.4），MUST NOT 宣称已完全擦除。

### 42.5 跨会话边界

会话结束不清空场次记忆（按保留期），但**授权、审批、租约、设备身份与自动权限一律不跨场继承**（沿用 §21.4、§8.5、§9.2）。跨会话能力只在 Pro 档位按 §14.1 的「跨会话运营」启用。

### 42.6 契约

§20.6 曾把 `memory.access@1` 列入「保持 Draft」的契约；**仓库的能力目录已把它标为 `frozen`**（`schemas/catalog/capabilities.json`，实测）。因此本节的增量不是「冻不冻结」，而是**冻结后的语义是否补齐**：`write(scope, record)`、`read(query, scope, budget)`、`forget(target, reason)`、`scopes()` 四项操作的语义要求见 §42.2–§42.4，并 MUST 落进 §4.6 的一致性套件（作用域越权的拒绝、过期与撤销的拒绝、删除的可验证性）。**§20.6 的 Draft 清单与仓库目录在这个契约上已不一致**——此处以目录为准并如实登记，不修改 §20.6 原文。验收 H03、H04。

## 43 意图识别与路由衔接（L3 执行编排层）

### 43.1 分路径：把「不做独立分类」限定回它成立的路径

§5.2「一次短上下文 LLM，不先做独立分类」是**实时自动路径**的延迟取舍，应当保留；但它被写成了全局结论，于是非实时路径没有意图语义。第四部分的处置是**按路径分开**：

| 路径 | 意图识别 | 理由 |
| --- | --- | --- |
| 实时自动（受监督自动） | **不做独立分类器**；仍靠 §5.2 路由表与规则、模板命中 | 延迟预算最紧，多一次分类调用换不来足够收益（§5.2 的取舍继续有效） |
| 人工辅助、影子评估 | 可做显式意图识别，结果只作展示与建议 | 有人复核，延迟不敏感 |
| 节目编排与预合成 | 可做显式意图识别，用于选题与缓存归类 | 离线，可重跑 |
| 入站外部请求与数据订阅 | **必须先判意图类别**，再决定是否进人工队列 | 外部来源不得直接驱动外发（INV-31） |

### 43.2 意图的最小表示

意图 MUST 表示为「**封闭枚举 + 置信度 + 依据引用**」：MUST NOT 是自由文本，也 MUST NOT 只给枚举而无依据。`unknown` 是一等取值，不是错误。

枚举初值（调整须记录 ADR）：`ask_fact` 事实性提问、`ask_policy` 政策与售后、`chitchat` 闲聊、`request_action` 要求执行动作、`risk_or_complaint` 投诉与风险、`test_or_probe` 试探与注入、`unknown`。

- 依据引用 MUST 指向本次装配的片段（§41），MUST NOT 是「模型说它是」。
- 置信度 MUST 与依据一起记录；只有枚举或只有分数都算未定义。

### 43.3 与风险分级、授权的边界

- 意图 MUST NOT 决定风险。风险仍由 §5.6 的 `max(声明风险, 由 side_effect 与权限推导的风险)` 决定；`request_action` 不因「用户很想」而降级为可自动执行。
- 意图 MUST NOT 构成授权，MUST NOT 改变守门阶段数或强度（INV-29、INV-04）。

### 43.4 拒识与降级

- 置信度低于阈值 ⇒ MUST 落 `unknown` ⇒ 澄清或转人工；MUST NOT「按最可能的猜一个」外发。阈值待 §47.2 实测，MUST NOT 直接采用外部观察值。
- `request_action` ⇒ 走 §5.6 的 risk_2 人工批准路径与平台能力门控；`risk_or_complaint` ⇒ 直接 escalate；`test_or_probe` ⇒ 提高守门关注并记录。
- 意图识别自身失败（超时、模型不可用）MUST 按 INV-32 具名降级：退到规则命中或人工，**不是**退到无意图的分类默认值。

### 43.5 与守门的衔接

意图是守门 **input 阶段的一个输入**，不替代任何阶段（守门仍四阶段，缺失即拒绝外发）。意图与守门结论不一致时，**以守门为准**并记录冲突，用于 §47.2 的回归。验收 H05、H06。

## 44 工具调用与技能编排（L2 工具系统层）

### 44.1 与 §35 的关系

§35 定义技能是什么、清单字段、有效风险、调用链与上架规则；本节只定义**循环**的运行时语义（何时多步、怎么终止、怎么失败、怎么与守门衔接）。两者冲突时以 §35 的清单与风险规则为准。

### 44.2 单步与多步

- 实时自动路径**保持** §5.2 与 §35.6 的取舍：不做多步工具规划，单次决策周期内技能调用步数上限初值 2。
- 多步工具循环只在**不进实时自动外发**的路径启用：人工辅助、影子评估、离线预合成、入站外部请求的处理队列。
- 「多步」的判据是**调用次数**，不是耗时：一次调用内部服务端做多少步不计入，但必须在清单里声明。远端服务的内部行为不可见 ⇒ **只信其声明与产出，不信其自述**。

### 44.3 循环的终止条件（全部有界，越界具名终止）

| 维度 | 初值 | 越界行为 |
| --- | --- | --- |
| 步数 | 2（§35.6） | 终止并报 `RESOURCE_EXHAUSTED`，附已完成步骤与结果 |
| 总 deadline | 随调用（§20.2） | `DEADLINE_EXCEEDED`；已完成步骤按 §44.6 标注 |
| 预算 | §22.5 的预算池 | `BUDGET_EXCEEDED`；不落库半成品为事实 |
| 并行度 | 见 §44.5 | 拒绝超额并行，降为串行 |
| 结果总大小 | 清单声明上限 | 截断并**显式标注截断**，不得静默丢尾 |

**静默截断 MUST NOT 存在**：任何边界命中都必须产生具名结果与原因，写决策日志。

### 44.4 单步语义

沿用 §35.4 的调用链：Schema 校验（拒绝额外字段）→ 计算有效风险 → 策略判定（允许 / 需审批 / 拒绝）→ 权限与外发检查（classification × 目的地）→ 预算准入 → 受限宿主执行（deadline、取消、出站白名单）→ 结果 Schema 校验与大小上限并**标注不可信**。

### 44.5 并行与依赖

- 并行只在**无相互依赖**且 `side_effect ∈ {none, read}` 时允许；`write_internal`、`visible_to_audience`、`physical` MUST NOT 并行。
- 同一轮的并行调用 MUST 共享同一 deadline 与预算池，MUST NOT 各拿一份预算。
- 并行结果 MUST 按声明的顺序合并；冲突按 §34.2 的权威级别处理，无法判定转人工。

### 44.6 失败、重试与部分失败

- 读类可重试，受 deadline 与预算约束（沿用 §25.3）；写类 MUST NOT 重试，除非可证明幂等且带幂等键（§35.6）。
- **部分失败 MUST 显式标注缺失**：结果必须能区分「查到了、值为空」与「没查到」。MUST NOT 用空结果冒充无数据（与 §6「不返回『什么都没有』来误导生成」一致，与 §24.3「empty 与 timeout 不得混用」同一纪律）。
- 工具全失败时按 INV-32 降级：转模板、转人工或静默，MUST NOT 让模型「凭印象」补一个答案。

### 44.7 与守门的交互

工具结果进上下文即标为不可信数据（§41.3）；用于播报 MUST 先绑定证据再进 §5.4 守门。**「工具调用成功」不是「内容可信」，也不是「已获准外发」**——这两步都不省略。验收 H09、H10。

## 45 语义缓存（性能层）

### 45.1 两类缓存必须分开

§25.4 只给了一条纪律。实践中最容易混淆的是两类缓存共用一套判据，第四部分强制分开：

| 缓存 | 复用对象 | 命中判据 | 键的必需项 |
| --- | --- | --- | --- |
| TTS 精确缓存（已有，§25.4） | **音频** | 逐字相同 | 最终朗读文本、Provider 与模型、voice 与版本、语言、词典、语速与情绪、格式与采样率、事实/知识/策略修订、权限作用域、有效期 |
| 语义缓存（本节新增） | **回答文本或候选**，**不含音频** | 语义相似超阈值 **且** 证据复核通过 | 上述键 + embedding 模型与修订、意图类别、场景与知识空间 |

**语义缓存 MUST NOT 复用音频**：相似句复用音频会把「事实绑定」这条链断掉。

### 45.2 命中不等于可用

- 命中只复用**文本或候选**，**不复制授权、审批、事实版本**（INV-30）；复用后的候选仍 MUST 走 §5.4 守门与 §5.6 的有效风险判定。
- 命中后 MUST 重跑证据复核：相似不等于同一事实。证据不可得时 MUST 放弃复用（转生成或人工），MUST NOT 沿用旧引用。
- **语义相似度不构成证据**：价格、规格等只信 KB0（沿用 §6）。

### 45.3 禁用域（硬约束）

下列内容 MUST NOT 进入语义缓存，只允许逐字精确复用且绑定同一事实修订：价格、库存、优惠与活动条件、承诺与售后政策、以及任何个体化承诺。该禁用域与 §5.3「涉及价格、库存、优惠、承诺的回答不参与合并复用」一致，并**推广到缓存层**。M04 的判据（价格类数据不进语义缓存）在此获得缓存侧的对应实现要求。

### 45.4 失效

事实、权限、策略任一 revision 变化 ⇒ 相关作用域条目**立即失效**（沿用 §25.4）；撤销（§24.4）先阻断读取再清理副本；不同 workspace MUST NOT 复用受限内容的缓存（沿用 §25.4）。

### 45.5 度量

命中率与**误命中率** MUST 一起报，不得只报命中率；误命中用 §47.2 的黄金集回放度量（同 §6「检索延迟、证据正确率、最终答案正确率分别报告」的纪律）。缓存压测 MUST NOT 以「命中率上升」单独作为结论。验收 H07、H08。

## 46 开放互操作：MCP、A2A 与连接器注册

### 46.1 三类外部接入的位置

| 形态 | 方向 | 是否承载自有代码 | 章节 |
| --- | --- | --- | --- |
| Connector（连接器） | 数据入、动作出 | 声明式无代码 / 远端服务 / SDK 桥接 | §34（既有），§46.4 |
| Skill（技能） | 模型可请求调用的能力 | 声明式 / wasm / subprocess / remote | §35（既有） |
| Peer Agent（对端智能体，A2A） | 委派进来、委派出去 | 对端是**不可信的推理主体** | **§46.3（新增）** |

三者共用同一套清单、签名、信任域、权限、生命周期与撤销（§33.2、§4.3、§4.4），**不为互操作另建一套**。

### 46.2 MCP

MCP 的定位是**给模型接工具与资源**，因此在结构上映射进已有的两套面，而不是新造一层：

| MCP 概念 | 本项目映射 | 强制要求 |
| --- | --- | --- |
| tools | 技能（§35） | **逐工具审核**，生成清单条目与有效风险；不信任服务端自报的只读或低风险（§35.2） |
| resources | 数据源（§34.2 的 `data.query`） | 一律带来源、时效、权威级别与敏感分类；MUST NOT 直接当证据，MUST NOT 绕过 §6 |
| prompts | **不得**直接作为系统提示 | 提示是配置产物，其变更按 §11.7 的「安全相关变更」处理（回归 + 记录） |
| sampling（服务端反向调用模型） | **默认禁用** | 启用需本机管理员授权、计入预算、逐次记决策日志 |

**清单快照与描述漂移**：接入时 MUST 生成工具清单快照（名称、描述、参数 Schema、来源、版本）。工具描述是**注入面的一部分**，其变更 MUST 触发重新审核——§35.3 要求 `model_description`「不得含指令性内容」，而远端可以改描述，所以必须重审。

**信任**：MCP 服务端视同 **remote 宿主**（§35.2）；协议版本与认证方式**待验证**（§35.2 已如实标注），本方案不臆造具体协议版本。

### 46.3 A2A（智能体与智能体互操作）

本项目在该协议下**既是服务端也是客户端**，两侧边界不同。

**入站（外部智能体请求本智能体）**

- MUST 走独立入口，不复用平台事件或控制面通道；入口的请求一律按**外部请求**处理：**不构成用户指令、不构成授权、不构成值守**（INV-31）。
- 默认只在**人工辅助**模式下响应；在受监督自动模式下响应入站请求 MUST 由场景显式启用并预授权。
- MUST 有对端身份、作用域、速率限制与体积上限；对端身份由**本地信任配置**派生，MUST NOT 取自请求自报。入站请求 MUST 先过 §43 的意图判定，再进人工队列。

**出站（本智能体委派给外部智能体）**

- MUST 声明目标、目的、数据范围与超时；数据外发按 §34.2 的 classification 决定，**MUST NOT** 把观众原文、知识原文或凭据发出去。
- 返回一律按**外部数据**进上下文并标不可信；用于播报 MUST 绑定证据并进守门。
- **委派边界**：MUST NOT 委派 risk_2 及以上的动作（§5.6）；MUST NOT 委派需要凭据的动作；委派链深度上限初值 **1**（不得再委派）。

**与 MCP 的区别（必须写清，否则会被混用）**：MCP 是「给模型接工具与资源」，调用方仍是本智能体，产出是数据；A2A 是「把任务交给另一个智能体」，对端会自行推理与行动，产出是**另一个主体的结论**。故 A2A 的输出 MUST 更保守：绑定证据、标不可信、绝不因「对端说已批准」而跳过守门。

### 46.4 连接器注册

新增连接器 MUST 在清单里声明：数据分类（classification）、方向、速率、入站与出站网络白名单、凭据引用、离线行为、健康检查、沙箱要求，以及含异常（超时、乱序、重复）的测试夹具（沿用 §34.3）。

**知识库连接器是一等形态**，对接 §24.3 的第三方知识接口：必需 `capabilities`/`health`/`search`，可选 `answer`/`sync`/`delete`；带证据与仅答案的区别、`empty` 与 `timeout` 不得混用等纪律沿用 §24.3。

### 46.5 契约：本轮不新增契约名

| 契约 | 状态 | 说明 |
| --- | --- | --- |
| `skill.invoke@1` | 已 frozen（既有） | MCP 的 `tools` **映射为技能**，复用此契约（§46.2） |
| `data.query@1` | 已 Draft（既有） | MCP 的 `resources` 走此数据面（§46.2）；不另立新契约 |
| `memory.access@1` | 已 frozen（**与 §20.6 不一致**） | 见 §42.6：以目录为准并如实登记 |

**不新增 `mcp.tool@1` / `a2a.*` 之类的契约名**，这是一处与 §37.4 的有意差别，理由三条：

1. MCP 的四面都能映射到**已有**契约或既有机制（tools → 技能；resources → 数据面；prompts 与 sampling → 配置与授权），不需要新契约；
2. A2A 的**协议版本与认证方式待验证**（§35.2）。在一个还没有请求/响应形状的协议上先占契约名，只会产生**半声明的 draft**，而 §4.1 与 W52 起的能力目录纪律明确禁止半声明 draft——它会让 `stage` 字段失去意义，等于把「已冻结」与「未冻结」混为一谈，把「未验证」伪装成「已登记」；
3. 因此 A2A 的契约**待协议验证后**随对应工作项（W62）加入目录；本轮只登记边界与验收（H13、H14），它们在注册表里 `contract` **留空**（沿用 M10/M12 的先例），而不是引用一个目录里不存在的名字。

**基线-目录不一致（如实登记）**：§20.6 把 `memory.access@1` 列为保持 Draft，能力目录已标 `frozen`；第四部分以目录为准，不改 §20.6 原文。

### 46.6 新增风险与验收

新增威胁见 §48.4（T-23、T-24）。验收 H11–H14。

## 47 Harness 的观测、评估与门控

### 47.1 观测

harness 每层 MUST 产出可回放记录，进入 §5.8 的决策日志链（只追加、哈希链）：

| 层 | 记录项 |
| --- | --- |
| L1 装配 | 片段标识与来源、各段预算占用、裁剪项与原因、模型与提示词版本 |
| L3 意图 | 枚举、置信度、依据引用、阈值命中与否、与守门的冲突 |
| L4 记忆 | 读写的键、作用域、来源、命中/未命中、删除的完成状态 |
| L2 工具 | 每步的技能 ID 与版本、参数哈希、结果摘要与大小、终止原因、成本 |
| 缓存 | 命中/未命中、失效原因、复用的条目版本 |

所有记录 MUST NOT 含明文凭据（INV-11）；观众原文与昵称按保留期脱敏（§5.8）。

### 47.2 评估

harness 自身的属性 MUST 进 §5.9 的黄金集，至少覆盖六类：装配回归（顺序与预算）、意图拒识（低置信落 `unknown`）、工具失败恢复（部分失败与全失败）、缓存误命中（禁用域与事实变更）、MCP 工具描述漂移、A2A 越权委派。修改 harness 的提示词、装配顺序、阈值、路由或技能清单后，MUST 通过相关回归才生效（沿用 §5.9）。

### 47.3 模式爬坡

沿用 §5.9：演练 → 影子 → 人工辅助 → 受监督自动。**harness 新机制默认只在演练、影子与人工辅助下启用**；进入受监督自动 MUST 先通过 §47.2 的回归，并在决策日志留下启用记录。

### 47.4 恢复与降级

| 失败层 | 具名降级 |
| --- | --- |
| 装配（不可裁剪段缺失） | 拒绝调用，退模板（§12.2 降级顺序第 1 级） |
| 记忆读失败 | 按「无记忆」继续并在界面标注降级项；不得以推断补齐 |
| 意图不可用或低置信 | 澄清或转人工；不得用分类默认值 |
| 工具失败 | 显式标注缺失；退模板或人工；不得让模型凭印象补 |
| 缓存不可用或失效 | 重新生成或转人工；不得沿用旧引用 |
| MCP/A2A 对端不可用 | 关闭相关能力；已有会话不受影响（沿用 §38.4 的失效保护精神） |

任何一层降级 MUST 在 CapabilityView 与界面可见并给出可行动说明（沿用 §12.2、§15）。

### 47.5 门控

第四部分**本轮不新增静态门控**：harness 尚无实现，门控须随实现轮次建立，且必须**非空洞**（沿用 W54/W55 的做法：零新增依赖、进既有 `cargo xtask check --profile full`、带注入样本的守卫）。本轮机器可判定部分只有**一处**，且落在既有门控内：`tests/registry` 的 **H 家族在册断言**（§48.5）——它同时把规格早已要求、却一直未实现的 **M 家族断言补齐**（逐号比号、缺号即失败并指名缺哪个，并以「人为删号」的注册表验证该断言确实会失败）。本轮**不新增契约**（§46.5），故能力目录侧没有新的可判定面。
