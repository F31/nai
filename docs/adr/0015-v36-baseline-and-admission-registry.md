# ADR 0015：V3.6 升基线、勘误裁决与验收体系切换

- 日期：2026-10-08
- 状态：Accepted
- 旧基线：V3.5（docs/digital-host-agent-design-V3.5-OpenCode.md）
- 新基线：V3.6（docs/直播数字人 + 智能体系统技术方案 V3.6.md）

## 决策 1：V3.6 升为唯一实现基线

V3.6 已完整审阅并整合 V3.5 全部有效细则，修正已知缺陷（媒体进程拆分、决策日志统一、平台合规、威胁模型、切片发布线、统一验收注册表）。
V3.5 降为历史参考，不再作为实现基线；历史版本仅供追溯，不自行拼接旧条款覆盖 V3.6。

- docs/design.md 指向 V3.6 并同步导航章节。
- AGENTS.md / openspec/config.yaml 的基线条款同步更新。
- V3.6 中「dh-*」命名不采纳（见决策 3），全文按 nai-* 项目名解读。
- 依赖 `docs/digital-host-agent-design-V3.5-OpenCode.md` 的既有归档/规格（D01–D14）保持原状，其内容由 V3.6 主规格按勘误清单兼容继承。

## 决策 2：勘误与裁决清单（V3.6 内部矛盾）

V3.6 内部存在多处编号/口径/切片矛盾，作为新基线前必须裁决。以下裁决写入验收注册表实施规则，并在 registry.yaml 中落实：

| 项 | V3.6 原文问题 | 裁决 |
|---|---|---|
| R 编号二义 | R01–R11 是验收编号，R1/R2/R3 又是发布线名，§16「线」列混用 | registry.yaml 用独立 `release_line` 字段（如 `R1`）区分验收编号与发布线，不照抄 §16 文本 |
| R1 退出条件口径 | §1.4（56 行）与 §17.3（698 行）验收集合不一致 | 以 §16 验收注册表为准；§17.3 的 R1 行按注册表口径修正 |
| W03/W15 线号 | W03 任务卡把 R04 列 Slice-0、W15 列 R09/R10，与 §16 的 R1 冲突 | 以 §16 为准：R04/R05/R08–R10 属 R1；W03 卡勘误为 R07（Slice-0）+ R04（R1） |
| 冻结规则循环 | K2 规定「被切片验收覆盖才可 Frozen」，但 W01 要求 Slice-0 即冻结 9 个契约 | 引入 `provisional`（预冻结）中间态：Slice-0 使用的契约标记 provisional，被 S01–S04/R01–R03/R07/A01/A04 覆盖后正式 Frozen |
| 值守租约短期限 | §21.4「到期后短期限内撤销授权」无初值（播放租约有 200/600ms） | 初值：值守租约失效后 600ms 内撤销输出授权（与播放租约失联截止一致），实现时按实测记录 ADR |
| X01 门槛时间点 | §16 写「M0 前写定」、§10.3 写「M0b 前写定」 | 统一为 M0b 前写定（实验项不阻塞主线） |
| 决策日志缓冲取舍 | 「写入失败进有界缓冲并告警」与「关键提交先持久化」满时取舍未说明 | 决策日志有界缓冲满时丢弃遥测段并告警；授权、事实、审批、配置等关键提交仍先持久化，不允许丢弃 |
| 回填规则 | V3.6 未说明旧实现如何进入注册表 | 已实测项（D01–D14 归档测试）以「实测」状态回填并引用归档报告；未实测目标能力标「未执行」，不冒充认证 |

## 决策 3：命名保持 nai-*，不重命名

V3.6 使用 dh-* 命名，但系统尚未发布且 ADR 0001 已确立 nai-* 工程标识，14 份归档与生成契约均绑定 nai-*。
重命名零收益且污染归档与生成产物。裁决：V3.6 的 dh-* 仅为方案文档建议名，仓库、crates、packages、二进制、契约前缀一律保持 nai-*；V3.6 文档的架构/流程/验收内容按 nai-* 解读采纳。

## 后果与实施

- 后续开发按 V3.6 切片发布线（Slice-0 / R1 / R2 / R3）与验收注册表（S/A/R/O/X + release_line）推进，不再新增 T/E/U 编号；V3.6 §30.4 保留旧编号追溯，不提供 D→新编号映射（需自建，见 registry.yaml 的 mapping 段）。
- 新变更先改能力注册表与验收注册表，再冻结契约与消费者代码。
- V3.6 的 K13 规范金字塔：编码代理每次只加载 L0（不变量+发布线）、当前 L1 契约与 L2 任务卡，不整篇载入。
- 本 ADR 的三项决策作为流程切换 OpenSpec 变更（d15-admission-registry）的依据，变更归档时本 ADR 随附勘误清单生效。
