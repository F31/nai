# ADR 0040：黄金集评估执行体的边界

- 状态：接受
- 日期：2026-10-11
- 相关：[ADR 0032](0032-knowledge-quality-gate-boundary.md)、[ADR 0033](0033-golden-set-payload-boundary.md)、[docs/golden-set.md](../golden-set.md)、[tests/rag-golden/README.md](../../tests/rag-golden/README.md)

## 背景

B01 的验收是规格 §655「100 题集**达到**第 6 章门槛」＝实测达标。W30 交付了判定机制
（`nai-kernel::golden`），W31 交付了载荷载体（`xtask check --golden` 与题集格式）。逐条核对后，
距达标还缺四段，性质完全不同：

| # | 缺什么 | 性质 | 谁做 |
| --- | --- | --- | --- |
| ① | 100 题题集内容 | 数据 | 场景包产出方（外部） |
| ② | 参考答案判据 | 口径 | 本仓库 |
| ③ | 评估执行体 | 编排代码 | 本仓库 |
| ④ | 真实知识库内容 | 数据 | 场景包产出方（外部） |

② 容易被忽略：题集 schema 原本不含参考答案，而 `Submission.answer` 由调用方注入——即使 100 题到位，
`answer_accuracy` 仍是外部判定后填进去的，**达标链条上有一段没有可复现的执行体**。

③ 是核对后确认的真缺口：全仓库没有任何代码把「题集 → 检索 → 生成 → 逐题判定 → 报告」串起来。
两个接缝其实都已具备（`nai-provider-core::TextGenerator`、`nai-storage` 的 `retrieve_local`），
缺的只是**组织者**。

ADR 0033 的后果段把「真实题集内容、真实模型评估与真实检索质量」一并划给外部。对 ①④ 这是对的
（数据必须人工投入，代造即臆造真值）；对 ③ 它把**编排代码**也说成外部的，代价是真实模型已经可用
（W36），却没有任何一次运行能产生 B01 的结论。

## 决策

### 1. 参考答案是题集的一部分，修订升到 2

每题必须声明 `expected`：`{ kind: "reference", must_include: [...], must_exclude: [...] }`。
`must_include` 至少一条——一个没有任何要求的参考答案，会让判定在「自动正确」与「永远未判定」之间二选一，
两者都等于把判定关掉。

修订号语义是「本构建认识的**唯一**修订」：**不做双读**。同时接受 1 与 2，会让一份漏写 `expected` 的旧题集
读成「没有参考答案要求」而不是结构不合规——静默改变用例含义，与 ADR 0033 决策 2 拒绝未知字段是同一条理由。
因此夹具 `tests/fixtures/rag-golden/example-min.json` 同步升到修订 2。

### 2. 判定是口径，落在 kernel 且是纯函数

`judge_answer(&ExpectedAnswer, &str) -> AnswerVerdict`：归一化（小写折叠 + 空白折叠）后比较；
任一 `must_exclude` 命中即为 `Incorrect`（否定式优先，否则「既说对又说错」会通过）；`must_include`
全部命中才为 `Correct`。

取**子串**而非相似度阈值：阈值需要一个数字，而那个数字本身就成了判据，且不可复现。

判定的产物是**既有的** `AnswerVerdict`，因此 `Submission`/`evaluate`/`QualityReport` 一个字段都没改，
`Unknown` 从正确率分母排除的语义原样继承。判定放 kernel 而不是放执行体，是因为它是**口径**不是编排：
放在执行体里会失去 portable 门控的覆盖。

### 3. 执行体落在 xtask 的 example

`xtask/examples/golden_eval.rs`，对照既有先例 `crates/nai-provider-core/examples/live_provider_smoke.rs`
——真实链路（需要凭据/网络）在仓库里一律放 `examples/`，不进测试、不进工程门控。

理由：

- **解析器只有一个真相**。读取在 `xtask/src/golden.rs`，执行体用同 crate 的 `read_case_set` / `case_set_files`
  （两者与审计共用同一个 `parse_case_set`），不为「跑评估」再造第二个解析器。
- **不进 lib ⇒ portable 门控的覆盖与耗时不变**。真实接线要 `nai-provider-core` 与 tokio，都是
  `[dev-dependencies]`，只在构建 example 时编译。
- **零新增包**（仍 18 个）。tool 层无依赖限制（ADR 0033 决策 1），不必再造一个 app 层包。

### 4. 执行体只驱动生成侧，未驱动的一律具名，不得填零

本执行体驱动的是「问题进、答案出」这一段：真实 `TextGenerator` + kernel 的 `answer_verdict`。
它**不**驱动行为侧——检索证据、守门判定、副作用通道、取消通道——因此**不对这些判据报结论**，
而是把三项未驱动字段连同原因打印出来，且明确写出「这不是 B01 达标」。

否决「用答案文本猜 outcome 再喂 `evaluate`」：那样会得到一个字段齐全的报告，其中
`no_answer_*`、`side_effect_executed` 之类的 token 会**假失败**（把「执行体没驱动」读成「系统差」），
而 `MustNotAct` 会**假通过**（本路径没有副作用通道，恒为空）——两种误导都比缺字段严重。
部分提交喂给 `evaluate` 本就会被拒（`every golden case needs exactly one submission`），
这正是它该有的行为。

### 5. 缺前置拒绝桩替代，退出码分明

| 情况 | 行为 |
| --- | --- |
| 目录内无 `*.json` | `CAPABILITY_NOT_READY`，退出 1，不发起调用 |
| 结构不合规 | 逐条报出缺陷，退出 1，**不发起任何调用** |
| 缺少环境变量 | `CAPABILITY_NOT_READY` + 变量**名**，退出 1 |
| 真实调用失败 | 退出 2 |

凭据只从环境读取，绝不打印、绝不写进证据记录。一个让评估变绿的演练桩，正是 §30.1 禁止的东西。

### 6. 与 ADR 0033 的关系是补足，不是推翻

0033 的七条决策全部保持：载荷落点在 xtask、格式为 JSON、「未提供」以文件数为唯一判据、确认人前移到载荷边界、
B01 回调为 `blocked`、不代造题内容、不并入 portable。本 ADR 只补两件 0033 未覆盖的事
（参考答案判据、执行体），并让修订号前进一步。

### 7. B01 仍为 `blocked`

① 与 ④ 未达，§655 的「达标」仍不可能达成。registry 记明缺口从四段降到两段，**状态不变**——
「执行体就位」不是达标（`live-provider-evidence` 规格对此已有明条：一次连通冒烟不得用来把 B01 标为达标）。

## 否决方案

| 方案 | 否决理由 |
| --- | --- |
| 判定放执行体（不进 portable） | 判据是口径不是编排；会失去工程门控覆盖 |
| schema 1 与 2 双读 | 会静默改变旧题集含义（同 ADR 0033 决策 2） |
| `must_include` 允许为空 | 「没有要求」会自动判正确或永远未判定，等于关掉判定 |
| 用 LLM-as-judge 判正确率 | 用待评模型评自己，效力需另一套论证；本轮取确定性规则，不引入新凭据 |
| 参考答案用相似度阈值 | 阈值本身成为判据且不可复现 |
| 新建 `apps/golden-eval` | 第 19 个包，且解析器会成为第二真相 |
| 执行体并入 `check --profile portable` | 业务题集未建不应让工程基础门控变红（同 ADR 0033 决策 7） |
| 用答案文本推断 outcome 喂 `evaluate` | 造出字段齐全但含义失真的报告：行为类假失败、注入类假通过 |
| 在评测里临时构造知识库充当「真实检索」 | 那是夹具，会让人把演练读成质量水平 |
| 造 100 题夹具当样例 | 臆造真值 |

## 后果

- B01 的达标链条上，**仓库内可控的两段（判据、执行体）已齐**；剩下两段是纯外部投入
  （100 题内容、真实知识库），到位后**零代码改动**即可出完整结论。
- 「100 题从哪里来」仍只有一个答案（`tests/rag-golden/*.json`），且现在多了一条「参考答案也是题集的一部分」。
- 工程门控不受影响：`check-deps` 仍 18 包方向不变，portable 的覆盖范围与耗时不变。
- 遗留：行为侧执行（守门/副作用/取消的观测接入）与真实检索接入未做；执行体目前只在生成侧产出结论。

## 勘误（2026-10-11 复核）

「后果」首条所写「（100 题内容、真实知识库）到位后**零代码改动**即可出完整结论」**对检索侧不成立**。保留原文并订正：

- 100 题内容到位 ⇒ 门禁放行 + 生成侧 `answer_accuracy`，零代码改动即可；
- 真实知识库到位 ⇒ **本身不会**让执行体驱动检索：未驱动项是常量（`xtask/examples/golden_eval.rs` 的 `UNDRIVEN`，无条件打印），
  故 Recall@5、检索 P95 与行为类判据要出数仍需**扩展执行体或另接采样器**——这与本 ADR 末条「遗留：行为侧执行与真实检索接入未做」
  本来就是同一件事，只是原措辞把它写成了「零代码改动」。

本条订正的是**充分性声明的措辞**，不改动本 ADR 的任何决策，也不改变 B01 的 `blocked` 判定。
