# ADR 0123：归档记录的结构判据 —— 判全部归档、归一化只到大小写、例外进自清理台账

- 状态：已接受（W149，2026-10-18）
- 基线：`docs/直播数字人 + 智能体系统技术方案 V3.11.md`
- 相关：ADR 0117（`validateChange()` 是 non-blocking，Why 段长度没有门控）、
  `scripts/contracts/archived-proposal.mjs`、`tests/contracts/archived-proposal.test.mjs`、
  `scripts/contracts/test-reachability.mjs`（站点登记）、`xtask/src/lib.rs`（门控接线）

## 背景

W143 §八第 1 条登记了 5 轮：**2 份归档 proposal 结构性缺段**。它一直没被接手，因为两种处置
都有代价——「修」是改已发布的历史记录，「不修」则让任何未来的「全量 proposal 可解析」判据
都必须先给它们开例外。

本轮先把它量成数字（`openspec/changes/archive/` 实测）：

| 事实 | 值 |
| --- | --- |
| 归档变更目录 | **145**（每个目录都有 `proposal.md`） |
| 有 `## Why` + `## What Changes` | **143** |
| 缺 `## What Changes`（写 `## What`） | **1**：`2026-10-09-engine-assembly` |
| 两段都缺（全中文标题） | **1**：`2026-10-10-w31-golden-set-payload` |
| 段存在但正文为空 | **0** |
| `openspec validate --archived` | **145 / 0**——上面两份都是 ✓ |

最后一行的意义是：**这条缺口对现有门控零信号**。`--archived` 判的是「归档过的东西能不能解析」，
不是「它有没有把话说完」。而 `archive.js` 的 `validateChange()` 是 non-blocking（ADR 0117）：
新归档缺 Why 只会在归档那一刻打一行警告，之后没有任何判据会再问——缺口被「归档」这个动作
永久地固化了。

## 决定

### 一、判**全部**归档记录，不按时间划界

「2026-10-18 之后归档的才算」是一条按日期开的豁免：它不具名、不自清理，而且允许被回溯性绕过
（把目录名改早一天即可）。例外一律进台账，台账自带三条纪律（见决定四）。

### 二、标题归一化只到大小写与 `Changes` 的 `s` 可选

`## what changes` 与 `## What Changes` 等价；`## What` 与 `## 为什么` **不**等价。

理由是判据的读者：归档记录只会在「若干个月后有人问这次为什么做」时被打开，那时唯一能依赖的
是一份稳定的结构。把近义词并进必需段，等于用宽容替代一致；而这两份恰好是台账存在的理由，
不是归一化该放行的样本。**归一化的边界两侧都钉了断言**（`what changes` 接受、`What` 拒绝）。

### 三、空段等于缺段，但措辞不同

今天没有空段（实测 0 份），判据仍要判它：一个留着 `## Why` 却下面什么都没有的文档，比没有这个
标题更糟——它看起来像答过了。这与「必填字段存在 ≠ 这个态付了账」是同一条纪律。

### 四、例外进台账，台账三项纪律

台账条目 `{change, missing, sinceBaseline, reason}`：

1. **具名**：`change` 是归档目录名，MUST 真的存在（否则「例外无主体」）；
2. **相称**：`missing` MUST 等于这份文档**实际**缺的段集合。声明不符 ⇒ 报错并同时给出两边
   ——「盖住的不是这份文档」和「文档缺段了」是两件事，混在一起就判不出前者；
3. **自清理**：文档补齐后条目 MUST 被删掉，否则判据红。一条比理由活得久的例外，就是一条豁免。

例外**抑制**它盖住的那几条报错——这是「例外」的定义；不抑制的话，它只是把红字旁边加了一行注释。

### 五、域从 `.git/index` 派生，且**任意**已跟踪文件都算

只认 `proposal.md` 会让「某次归档整个漏掉 proposal」落在域外——那恰恰是本判据该报的东西。
因此域是「归档目录下的任意已跟踪文件 → 变更名」，`proposal.md` 缺失是一等公民的失败。
代价：未跟踪的归档目录不在域内（与 W135 的 `pending-registration` 同一条边界，两者不互相替代）。

## 后果

- 门控多一步纯静态 Node 测试（读 `.git/index` 与归档文本，不需要 protoc、不编译）；
  站点登记在 `TEST_REGISTRATION_SITES`，`tier: portable`（它跑在 `engineering_checks` 里）。
- **历史记录零改动**：2 份例外留在台账里，判据不要求改已发布的 proposal。
- **进程语义零改动**：不加 `archive.js` 的阻塞路径（外部工具的语义不在本仓库），判据落在
  本机门控与 CI 里——这与 W147 学到的「`--archived` MUST 在推送前绿」是同一种处置：
  把「归档之后没人问」变成「提交时有人问」。
- **不做的事**：不判 proposal 的其余段（`Impact` / `Non-Goals` 是否必填属另一条判据）、
  不判重复标题、不判段内长度（Why 的 1000 字符上限仍按 ADR 0117 保持无门控）。

## 残余（具名，本轮不做）

1. **归档 proposal 之外的归档记录**（`tasks.md` / `specs/`）结构未判：`--archived` 会报未勾任务，
   但 `tasks.md` 的段结构、specs 的 Requirement 形态都没有独立判据。
2. **`openspec/` 之外的变更文档**不在域内（本仓库的变更只在 `openspec/` 下，故暂无影响）。
3. **台账的 `sinceBaseline` 只校验非空**，不由本判据校验「是否等于当前基线」——那需要一条
   「基线版本从哪读」的唯一出处，属独立一轮。
