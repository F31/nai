# ADR 0032：知识质量门槛的边界——题级召回、三份分报、逐题门禁

- 日期：2026-10-10
- 状态：Accepted
- 基线：V3.6 §6（知识与 RAG 的质量门槛）、§5.9（评估与运营闭环）、§5.6（技能与风险分级）；承接 ADR 0026（升级核心）、ADR 0029（多会话隔离）、ADR 0030（真人接管）、ADR 0031（运营度量）
- 变更：`openspec/changes/w30-knowledge-quality-gate/`
- 判据：`tests/registry.yaml` B01「知识质量：100 题集达到第 6 章门槛」

## 背景

B01 的**真值**（100 道贴近真实直播的问题、真实模型在这些题上的表现）需要外部场景包与真实模型评估，本轮不假装有。但 §6 与 §5.9 里至少有四件事是**判据口径**，此前没有落点：

1. **「Recall@5 ≥90%」没说分母是什么。** 题级命中还是文档级命中？同一 run 上两者可以差十几个百分点。若没有任何有证据用例，`0/0` 会被算成 0% 或 100%。
2. **「检索延迟、证据正确率、最终答案正确率分别报告」是一句禁止令。** 它禁止把三者压成一个「质量分」。一个分数会把「检索坏了但答案侥幸对」与「检索好了但生成坏了」变成同一件事。
3. **「必须通过相关回归才生效」是一道门禁，不是一次比较。** 平均分不降而单题翻转是最典型的静默退化；只在平均值上判定的门禁会放行它。
4. **「经人工确认后扩充」是一条授权边界。** 若坏案例能直接写进黄金集，回归门禁就失去意义。

九项决策必须先回答：落**哪个 crate**；召回**什么口径**；三份正确率**怎么组织**；缺测**怎么表达**；未判定答案**算不算错**；门禁**比什么**；基线不绿**能不能放行**；跨版本**能不能比**；审计**怎么才不成为死代码**。

## 决策

### D1 放进 `crates/nai-kernel`（`golden.rs`）

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 放进 `nai-knowledge-core`（shared） | 与检索管线同住 | **否决**：§6 的检索 P95 用的是 W29 已落在 kernel 的分位实现。shared 层要么反向依赖 kernel，要么复制一份分位——后者会在两次口径调整后产生两个不同的 P95。 |
| B. 新增 `nai-quality-core` | 独立成包 | **否决**：改动 workspace 组成（18 包）与依赖方向，而本模块只依赖 `ErrorCode` 与 `std`。 |
| C. 放进 `crates/nai-kernel` | 与 `metrics.rs`/`review.rs` 同 crate | **采纳**：复用 `LatencySamples`（分位）与 `Ratio`（比例），一个真相；依赖方向不变。 |

### D2 召回以**题级**判定，文档级仅作对照

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 只报文档粒度召回 | 命中文档数 / 应命中文档数 | **否决**：对「一题 5 个证据」与「一题 1 个证据」等权，一题全丢与五题各丢一个得到同一个数字，掩盖整题失败。 |
| B. 只报题级召回 | 全部所需证据进前 5 才算命中 | **否决**（单独）：看不到「命中了一半」这种部分进展。 |
| C. 两者都报，分开呈现 | 题级为主、文档级为对照 | **采纳**：口径不再含糊，且谁也不能替代谁。 |

### D3 三份正确率各自独立，不合成

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 一个加权「知识质量分」 | `w1·recall + w2·accuracy + …` | **否决**：把「检索坏了但答案侥幸对」与「检索好了但生成坏了」压成同一件事，两者修法完全不同；且 §6 的原话就是「分别报告」。 |
| B. 三个独立字段 | `evidence_recall_at_5` / `answer_accuracy` / `retrieval_p95_ms` | **采纳**：没有任何合成方法，结构上就禁止了总分。 |

### D4 缺测一律 `None` + 具名，门槛计为未达标

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 用 0 或 1 填补 | 缺测当 0%（或乐观当 100%） | **否决**：「没测过」与「测到 0」是两回事（同 W26 `Unmeasured`、W15 `Unknown`、W29 `unmeasured`）。填补会让「没有检索样本」读成「P95 = 0ms，达标」。 |
| B. `None` + `unmeasured` 具名，门槛报未测量 | `retrieval_meets_target() -> Option<bool>`，未测门槛计为未达标 | **采纳**。 |

### D5 `AnswerVerdict::Unknown` 从分母排除

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 未判定计为错误 | 计入分母且计为错 | **否决**：未判定既不是对也不是错；计入错误会让人工尚未复核读成质量下降。 |
| B. 未判定从分母排除 | 只计 `Correct` / `Incorrect` | **采纳**：全部未判定时正确率为「未测量」而非 0%。 |

### D6 回归门禁**逐题**比较

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 只比较集级指标 | 召回不降即放行 | **否决**：平均分不降而单题翻转是最典型的静默退化。测试里 1000‰ → 989‰ 也必须被拒。 |
| B. 逐用例比较 + 指标比较 | 任一题由通过变失败即拒 | **采纳**。 |

### D7 门禁不看基线是否达标

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 「不比基线差」就放行 | 相对判定 | **否决**：基线本身没达标时，相对判定会把历史缺陷一起放行。 |
| B. 候选任一门槛失败即拒 | `candidate_gate_failed` | **采纳**：绝对门槛优先于相对比较。 |

### D8 跨版本硬拒，不标注后继续比较

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 标注版本不同后继续比较 | 报里加一个「版本不同」标记 | **否决**：§5.9 说黄金集**随场景版本**；跨版本没有共同基准，标注后继续比较会产生看似有效却无意义的结论。 |
| B. `VERSION_INCOMPATIBLE` 直接 `Err` | 拒绝比较 | **采纳**。 |

### D9 审计是对上报值的纯函数，且期望与类别的相容性在运行前查

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 只依赖 `evaluate` 的构造保证，不做审计 | 省一套规则 | **否决**：报告字段公开，审计规则否则永远不被执行，成为死代码。 |
| B. 期望与类别不相容在**运行时**计为系统失败 | 当成系统错了 | **否决**：会污染召回与门槛，让人去修系统而不是修题。 |
| C. 运行前报用例缺陷 + 审计对上报值做纯函数 | 两类问题分开报 | **采纳**。 |

## 后果

- 正向：§6 的五条门槛与 §5.9 的三条生命周期语句都有了可执行落点；三份正确率在结构上无法被合成；退化的最小形态（单题翻转）被门禁拦住；坏案例的入集是一次具名授权。
- 代价：黄金集报告与场次复盘报告各有一份 `unmeasured` 约定与一套审计标记，读者需要知道「在线复盘」与「离线门禁」是两条线。二者共用分位实现，但语义不同，这是有意的。
- 风险：`MINIMUM_CASES = 100` 与 `RETRIEVAL_P95_LIMIT_MS = 300`、`RECALL_AT_5_TARGET_PERMILLE = 900` 都是 §6 的**设计值**。若基线版本更新这些数字，需要同步改常量与文档；测试断言了这三者的取值，因此改动不会是静默的。

## 否决方案汇总

文档粒度单报 · 加权质量分 · 缺测填 0 · 未判定计错 · 只比集级指标 · 不比基线就放行 · 跨版本标注后继续比较 · 运行时才查用例缺陷 · 只靠 `evaluate` 不做审计。
