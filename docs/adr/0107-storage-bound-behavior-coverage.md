# ADR 0107：存储上限名册的行为覆盖——R08 升 `tested`

- 状态：Accepted｜日期：2026-10-16｜归属：W129（R08 收口）
- 关联：ADR 0103（W125 名册与口径）、ADR 0100（`tested` 的证据可核验）、ADR 0099（有界预算）、
  ADR 0077（判据引用常量而非复制字面量）、`local-persistence` / `knowledge-pipeline` /
  `scheduling-and-budgets` spec、`admission-registry` spec §Honest backfill、R08

## 背景
W125（ADR 0103）冻结了 R08 的名册：按 `crates/nai-storage` 的**具名拒绝**（或具名丢弃计数）普查，
约束「单次写入或单份快照/备份可占用资源」的上限共 **19 项**，并把其中 8 项接上载体，
**剩余 11 项零覆盖**（W125 的 registry notes 逐字具名列出）。W126 审计（`docs/reports/2026-10-16-state-of-implementation-audit.md`）
把 R08 归入「缺口③ 仓库内的未竟之工」，并写下推进条件：「剩 11 项是"照方抓药"，
且**全部覆盖完毕后 R08 才谈升 `tested`**」。

「零覆盖」的实测判据：全仓搜该 11 条拒绝名，只有**定义处**一处命中（`grep` 计数 = 1 × 11）
⇒ 这些闸门可以被删掉、改成恒真、或把边界挪一格，而没有任何一条测试会红。
W125 的**幅度判据**管的是「上限是不是它自称的那个数」，它**不**管「闸门还在不在、边界在哪一侧」。

## 决策
1. **补齐的是「行为」那一半，与幅度判据分工并存**：新增 8 条判据，每条上限一对夹具——
   **恰在界上必须过、越界必须具名拒绝**。夹具**从常量派生** ⇒ 抬高常量**不会**让这 8 条变红
   （那是幅度判据的职责）。分工刻意保留：只有幅度钉，则「声明之后从不读取」的上限会全绿；
   只有行为钉，则「上限从 4096 悄悄变成 40960」也全绿。
2. **12 个具名常量，不是一个 `65536`**：三条同名数值（配置文本 / 事实编码 / 候选编码）是**不同的对象**
   ⇒ 三个常量。共用一个会让「改动其中一条上限」不知不觉地改动另外两条。判据一律**引用**常量，
   MUST NOT 复制字面量（ADR 0077 对 `Operation::CEILING` 的同一条规矩）。
3. **拆一处合并拒绝**：候选路径原先 `dependencies.len() > 32 || cue.encode_to_vec().len() > 65536`
   配一个拒绝名 ⇒ 拆成 `candidate dependency limit` / `candidate payload limit`。
   理由与 W125 对 `publication` 的完全相同：一个 `if` 里的多个条件 MUST 各自举证，
   否则「绊到依赖条数」的夹具会替候选编码的上限背书。这是本轮**唯一**的语义变化（`ErrorCode` 不变）。
4. **两处 SQL 读窗口从上限派生**（`LIMIT 上限 + 1`）：撤销批次与快照 artifact 原先写死 `4097` / `513`。
   那个 `+1` 是**检测机制**本身——多读出来的那一行就是「后面还有」的证据；写死它等于让
   「上限悄悄变大」时检测静默失效。
5. **名册闭世界**：新增一条判据把「有没有上限**不在这张名册上**」也钉住（按清单扫的盲区恰是清单的补集）。
   闭世界分三层：文件层（`lib.rs` 的每个 `mod` 都有被扫源文件）、元素层（每个顶格常量**恰好**归入
   三类之一，三分是划分）、反方向（三张清单上的名字都真的扫得到）。谓词按「顶格」而**不是**按可见性筛
   ——按可见性筛是**弱类别**，私有上限（如 `MAX_DIMENSION`）会从后门溜走。
6. **一处弱化具名登记，不顺手改**：`MAX_LEDGER_ENTRY_BYTES`（⑨）**从被认可的路径走不到**
   ——`nai-budget-core` 把字符串字段限在 256 字符、`units` 限在 32 键 × 64 字符，
   故最大合法条目只有几 KB。设计不上手改（那是另一件事），但「它今天走不到」既被**说清楚**，
   又被一条**会过期**的断言钉住（`maximal.encode_to_vec().len() < cap / 4`）。⑨ 的闸门仍两侧都在，
   但**如实标明是接缝级**（直接问 `budget::encode`），不是路径级。
7. **R08 升 `tested`**：依据 ADR 0100 §6 的门槛与 `admission-registry` 的 Honest backfill 要求
   ——「`tested` 仅可用于已有归档实测证据的项目」，且「未完成或外部阻塞的目标 MUST 保留 implemented/blocked」。
   现测：名册 19 项**全部**有幅度钉 + 行为钉（12 个条件 + 7 个既有载体），闭世界成立；
   D03 验收原文的「数量/大小/路径受限」即由本名册承载，WAL/事务/备份/路径穿越由 D03 的 12 项存储测试承载。
   **没有剩下的缺口**（这与 W128 的 R10 相反：R10 剩余缺口是外部真值 ⇒ 按 ADR 0100 不升）。

## 后果
- 正向：R08 的「有界」从「19 项里 8 项有载体」变成「19/19 有幅度 + 行为 + 闭世界」；
  「声明之后从不读取」这条退化路径首次被**结构性**堵住（闭世界判据）。
- **R08 升 `tested`**（`implemented → tested`）。语义上不改 met/unmet 归类
  （`MET_STATUSES` 含二者），对账类守卫不受影响——这也是「只升认证强度」风险可控的原因。
- 生产代码：12 个常量提取 + 一处拒绝拆名 + 两处读窗口派生；**无取值改动、无 `ErrorCode` 改动**。
- 测试：`nai-storage` 63 → 72（+8 行为边界 +1 闭世界）。
- **注入验证**：8 组 / 17 条注入真跑，逐条确认「对应判据变红且可归因」，随后**逐字节还原**
  （`sha256sum -c` 全 OK）。对照：R1 只动比较符/窗口、不动常量值 ⇒ 名册幅度判据**留绿**，
  证明幅度钉与行为钉分工成立。
- 如实披露：⑨ 的上限**今天从被认可的路径走不到**（见决策 6）；本名册的普查域**限于 `crates/nai-storage`**，
  域外（`nai-budget-core` 的输入形状校验等）按 W125 口径**不收**并具名在册（`SHAPE_LIMITS`）。
