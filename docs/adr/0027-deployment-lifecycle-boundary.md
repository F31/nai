# ADR 0027：部署生命周期的边界——声明式驻留、TTL 释放、单一迁移图、离线即编译期性质

- 日期：2026-10-10
- 状态：Accepted
- 基线：V3.6 §14.1（档位预设）、§14.2（部署配置）、§14.3（升级与回滚中的降档与部署迁移）、§14.4（成本口径末句）；§31.4 工作项 W25；承接 ADR 0026（升级器分层）
- 变更：`openspec/changes/w25-tier-idle-migration/`
- 判据：`tests/registry.yaml` A08「档位升级不重装内核」、A09「空闲回收」、R11「离线升级与部署迁移」

## 背景

W15（ADR 0026）回答了「一个升级包能不能装」，并顺带把 A08 的注记从「升级器未实现」推进到「只差 W25」。
剩下的是升级器的另一半，同属 §14，也正是 W25 的三项验收：

- **A08**：档位升级靠加装插件包与配置迁移完成，不重装内核；**未启用插件无后台进程、端口、显存或云请求**。
- **A09**：未安装的模块没有后台进程、端口、显存与云请求；**结束场次后按 TTL 卸载模型、结束临时 worker、关闭未用预览**。
- **R11**：离线包可安装；Local → Hybrid → Distributed 迁移后**权限与证据版本一致**，**输出切换不重复播报**。

四个问题必须先回答：这段逻辑**放哪个 crate**；「不用的东西不占资源」靠**什么**成立；空闲释放是
**立即还是按 TTL**；离线是**一个开关还是一种结构性质**。

## 决策

### D1 放进 `crates/nai-upgrade-core`，不新开 crate

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 新增 `nai-lifecycle-core` | 驻留、回收、迁移、延迟、演练各建一个 crate | **否决**：A08/A09/R11 与 W15 共享同一条不变量——§14.4「未启用的能力不占用进程、端口、显存或云请求」。判据同源却分居两个 crate，同一条不变量就有了两个真相，且 `offline.rs` 还要跨 crate 复用 `verify_package`。 |
| B. 放进 `nai-storage` | 迁移本来就是搬数据 | **否决**：驻留账本与档位迁移图与 SQLite 无关；storage 的职责是「可靠地存」。且 `distributed + SQLite 多写者` 在本 capability 是**拒绝条件**，不是 storage 要去实现的能力。 |
| C. 放进 `nai-runtime` | 装配根掌握真实进程与资源 | **否决**：runtime 层无法被 `xtask` 在 portable 下单独测试；且装配根只会看见**它自己**启的那些资源，看见的越少越容易漏报。 |
| D. 扩展 `nai-upgrade-core`（shared） | 复用既有校验、撤销、`Operation` 与零新增依赖 | **采用**：与 `xtask/src/deps.rs` 的既有分层一致，**18 个包与依赖方向不变**，全部判据在 portable 下可测。 |

### D2 驻留足迹是**声明式**的，且只在 `enable` 时物化

`ResourceClaim { kind, name, amount }`，`kind` 是**封闭四族** `Process | Port | Vram | CloudRequest`——
正好是 A08/A09 原文列的四样。账本里每个能力有两份足迹：`declared`（安装时登记）与 `held`（启用时物化）。

于是「未安装/未启用 ⇒ 零占用」是账本的**结构性质**，不是约定。**否决**的两个替代方案：

- **写成文档表格**：那份表格不会被任何测试读到，忘记关闭的预览轮询进程照样存在——判据必须是可执行值。
- **完全由宿主上报**（「你告诉我现在占了什么」）：那样断言退化成对宿主的信任，宿主漏报就永远看不见。
  真实显存配额确实只能由宿主测量，但那是 **preflight/成本**的**输入**（已按可注入探针处理），不是驻留账本的真相来源。

### D3 排他性**只对进程名与端口成立**

`Process` 与 `Port` 在操作系统层面天然排他（同名进程只有一个、端口二次绑定必然失败），`enable` 时冲突即
`CONFLICT` 拒绝。`Vram` 与 `CloudRequest` **不排他**：两个能力可以各自加载同一模型、可以各自轮询同一 API。

四族一律排他会凭空造出「同一模型不能被两个能力使用」这种不存在的限制；一律不排他则会让「端口已被占用」
在启用时静默通过、在运行期炸掉。

### D4 空闲释放按 **TTL**，且分族——「立即释放」被否决

`IdlePolicy` 默认：临时 worker 30s、未用预览的云请求 60s、端口随其进程 30s、模型显存 300s。方向由
**重载代价**决定：worker 重启很便宜，先走；模型重载最贵，留到最后。端口与其进程同 TTL，因为「进程还在、
端口先放手」不是一个可达状态。

**否决**「场次一结束就全部释放」：看起来更干净，代价是下一句要付一次完整模型重载。规格写的是 TTL。

`reclaim(now)` 因此只释放 **TTL 已到期**的声明，并把仍保留的计入 `held_back` **如实报告**——运维问
「模型为什么还驻留」时应该拿到一个数字，而不是「已清理」的错觉。

审计做成对**公开快照值**（`CapabilityResidency`）的**纯函数** `audit_residency`，而不是只读自己的私有
字段。理由有二：宿主可以拿它审计**自己**的视图；而且每条规则都能被手工构造的状态真实触发——
一个只有误用才可达的检查，既没法测，也没法证明它活着。

### D5 档位迁移图是**两段差集的并**——「档位即内核配置」被否决

`tier_plan(from, to)`：`install` = 沿途档位增量的并，`remove` = 反向的并，`from == to` ⇒ 双空。集合是
`&'static str` 常量。因此：

- 「Lite → Pro 不要求先装中间档」不是特例分支，而是并集运算的必然结果；
- 「不重装内核」是**数据的性质**（集合里不可能出现内核），不是一条需要有人记住的规则。

**否决**把档位差异做成「安装内核的不同编译配置」——那正是 A08 明文禁止的「重装内核」。

### D6 离线是**编译期性质**，缺件是**显式拒绝**——`allow_fetch` 开关被否决

`nai-upgrade-core` 没有 HTTP 客户端（`check-deps` 也禁止 `media` 层之外的 http 依赖且 shared 层只依赖
contracts/storage/security 与纯算法库）。所以「离线安装不会偷偷下载」不是靠一个恒为 `false` 的
`offline: bool` 维持的伪保证——真要抓取得先加依赖，那是个显眼的、需要评审的动作。

`install_offline` 唯一的前置是「每个声明文件都在本地」；缺件以 `CAPABILITY_NOT_READY` 拒绝，并另有
`missing_artifacts` 给出**是哪个文件**。之所以与在线路径分开断言：`verify_package` 对缺件报的是
「missing package content」——对在线路径准确（字节还没到），对离线路径则不是运维需要的那句话
（「这个包不可能离线装，因为还差一个文件」）。两种拒绝都正确，**拒绝的原因不同**。

### D7 迁移的**三种拒绝先于任何搬动**，**三项复验不合并**

`plan_migration` 在产生计划前拒绝：有活动会话（§14.3「实时链路留在原部署，在维护窗口切换」）；
分布式目标 + SQLite 写者 > 1（§14.3「SQLite 不挂多节点写」）；**权限在目标形态无映射**——静默丢弃权限
是安全缺陷，不是便利。

`verify_migration` 复验三项且**错误码可区分**：权限集合（映射后期望值，顺序无关）、证据版本
（`VERSION_INCOMPATIBLE`）、数据哈希（`INVALID_ARGUMENT`）。**否决**「只比哈希」：哈希一致证明字节没被改，
但证明不了**权限被正确映射**——把 `admin.team` 悄悄降成 `viewer` 之后哈希照样一致。

`OutputSwitch` 以调用方给的 key 幂等（典型是 `session/epoch`）：同键第二次 `Duplicate`，即「输出切换不
重复播报」。key 由调用方给，因为「同一次切换」的身份只有调用方知道。

## 后果

**正面**
- A08/A09/R11 三项都有可执行判据，且全部在 portable 下可测；`nai-upgrade-core` 仍然零新增依赖、18 包不变。
- 「未启用即零占用」由**物化时机**保证，「按 TTL 释放」由**参数化时间**保证，二者都不依赖任何真实设备。
- 迁移的三种拒绝与三项复验各自对应一条明文规格句子，报告可直接逐句映射。

**代价 / 边界**
- `Vram` 是**声明式索赔**，不是真实显存配额；真实 GPU 探测仍需宿主注入（与 `preflight` 探针一致）。
- 审计的四条规则里有三条在正确使用下不可达，它们是**改错时的守卫**，靠 `audit_residency` 对快照的纯函数
  测试覆盖，而不是靠误用触发。
- R06（2h/8h/24h 长播）、B04（整链路延迟分位）需真实设备与长时运行，本轮**不做**；A08/A09 的
  `automation: manual` 与 R11 的真实轻云实例同理，registry 只补证据并**不标 `tested`**。
- A10（云断连不伤本地链路）与 A11（Pro 多会话隔离）是独立主线，本轮**不做**。
- 真实 Windows 安装器、update-helper 与代码签名链（W15 遗留）仍不在范围内。
