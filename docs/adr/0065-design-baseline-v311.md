## 背景

[ADR 0049](0049-design-baseline-v310.md)（2026-10-12，**W71**）把唯一实现基线从 V3.9 升为 **V3.10**，
处理的是**已登记但未收录的偏差**（B07 的基线文本与计数、H18 的默认启用集合）。本轮（**W87**）面对的是
**同一族问题的第三类**：不是「基线缺能力」，不是「范围过宽」，也不是「注册表与基线不一致」，而是
**一条一般规则自身的边界未写死**。

**登记处的原文**（W78 §八第 8 条，另在 W79–W86 的 §八逐轮复述，**连续八轮未收录**）：

> **一条待明确的判据边界**：§56.2 把 `openspec/changes/archive/` 列为「保留原文 + 追加勘误段」，
> 但**未区分「上一轮发布的归档」与「本轮刚归档、尚未入库」**。本轮撞上了后者，按「保护已发布原文」
> 的立意作了**就地订正**。**这个边界值得下一次基线修订时写死**，否则每一轮都要重新判一次。

**本轮核实后发现的第二处**：§56.2 的情形③ 把「**§56**」整体列为**保留原文**的版本专属章节，而
**V3.10 §58.2 的 E5 自己就就地订正过 §56.2**，[ADR 0049](0049-design-baseline-v310.md) 决策 4 的
「不改」清单亦**不含 §56**（只列 §39、§48.1/§48.2、§57.1/§57.2/§57.4/§57.5）。该行**自相矛盾**：
若「§56」整体冻结，则「随版本累积订正」这条**一般规则无法被订正**，E5 与 E2 都无从发生。

两项都不属于「可纯追加」的情形：§56.2 明写**纯追加 MUST NOT 被用来让矛盾长期存续**；边界不定，
则**每一轮作者都要重新判一次**同一件事。故本版即 §56 规则的**第二次跨轮次适用**（第一次是 V3.10）。

## 证据（本轮实测，先读后判）

**规模**（`wc -l` / `wc -c`）：`V3.10.md` = **2713 行 / 226,578 字节**；`V3.11.md` = **2766 行 / 233,290 字节**。
总差 **+53 行 / +6,712 字节** = **§59 追加块（53 行）** + **5 行 1:1 替换的净增（含在字节差内）**。

**契约证据**（`diff`，非 `-u`）：整文件共 **5 个 hunk** = **4 个 `c` 型**（`1c1`、`3c3`、`29c29`、
**`2573,2574c2573,2574`**——**2 行对 2 行**、列数相等）+ **1 个 `a` 型**（`2713a2714,2766`，即 §59 追加在**末行之后**），
`d` 型为 **0**。把范围限定在**前 2713 行**（既有正文）时只剩那 4 个 `c` 型 hunk、**零 `a`·`d`**
⇒ **无任何既有行被插入或删除，行号一一对应，全部既有 `§NNN` 引用继续有效**。
变更行号恰为 `[1, 3, 29, 2573, 2574]`（共 **5 行对 5 行**）：

## 决策

### 决策 1：V3.11 升为唯一实现基线

V3.11 保留 V3.10 的全部条款（**无删除**）：§1–§58 **除上述 4 个 hunk 所涉 5 行外逐字保留**，
并**追加 §59（V3.11 版本说明与订正索引）**。

- `docs/design.md` 指向 V3.11；`README.md`、`AGENTS.md`、`docs/development-plan.md`、`docs/engineering.md`、
  `openspec/config.yaml` 同步；
- V3.10 降为**历史参考**（与 V3.9/V3.8/V3.7/V3.6/V3.5 同等处置）：仅追溯，不自行拼接旧条款覆盖 V3.11。

### 决策 2：ADR 0049 的决策 1 被替代，决策 2–5 继续有效

ADR 0049 有五项实质决策，**只有决策 1（V3.10 升基线）**由本 ADR 替代：

- **决策 2（ADR 0048 的决策 2–5 继续有效）继续有效**；
- **决策 3（就地订正／追加勘误的边界，含 1:1 硬约束）继续有效，并由本轮 E1／E2 补明两处**：
  ① **历史记录的保护对象是「已发布的原文」**，判据 = 是否已进入提交（E1）；
  ② **情形③ 的「该版专属的版本章节」清单写精确**为「§56.1／§56.3／§56.4」（§56.2 是一般规则）（E2）。
- **决策 4（`capability_pack` 发布线与三条用户约束的对应）继续有效**：本轮**不改任何归属**——
  能力包集合仍**恰为** M01–M18 与 H05–H14、H16（**29** 条），与首版门槛互不相交；
- **决策 5（明确不改什么）继续有效**。

ADR 0049 **保留原文不改写**，仅在末尾追加「勘误（ADR 0065）」段（历史记录追加勘误，不就地改写）。

### 决策 3：本版类型 — 沿用 ADR 0049 决策 3 的判据，仍为**订正版**

**范围版** = 变更了 `tests/registry.yaml` 的**条目集合**或**任一条目的 `release_line`**；**订正版** = 两者皆未变。
V3.11 属后者——**88** 条不变、归属不变、**无一条 `status` 被改**。§49.2 的四栏评审对订正版**无对象**，
但本版 MUST 逐条列出**订正了什么**（§59.2 的 E1–E2）。

### 决策 4：本 ADR 明确不改什么

- **不改任何 acceptance 的 `status`**：88 条原样（H18 与 B07 仍 `pending`）；
- **不新增契约名、不改能力目录**：`schemas/catalog/capabilities.json` 与全部生成物**零漂移**；
- **不实现任何代码**：Rust 行为零改动；随版本号同步的只有**字符串常量**——`xtask/src/registry.rs` 的输出串、
  `schemas/tests/registry.schema.json` 的描述串、`scripts/contracts/registry.mjs` 的 `baseline` 串与两处错误消息、
  `tests/registry.test.mjs` 的注释与一条断言串、`tests/pending-decisions.yaml` 的 `baseline`、界面文案；
  **判定逻辑一行未改**；
- **不给 §16 的验收注册表增行**：插入行会使其后全部行号位移、破坏 `§NNN` 引用契约；
- **不重排 W 编号**：本版为 **W87**（V3.10 计划止于 W86）。

## 后果与实施

- 活文档的**当前基线指针**统一为 V3.11；**版本归属引用不变**（情形③）。
- 后续开发按 V3.11 的六条发布线与 `tests/registry.yaml` 推进；§57.3 仍为发布线**正本**，计数为 **88**。
- **已知代价（如实登记）**：本版生成了一份与 V3.10 有 **99.5%** 相同内容的版本文件，代价是文件重复
  （与 ADR 0049 相同的取舍）。交换的是**每个被 ADR 批准的基线产物保持不可变**——ADR 0049 的
  「15 hunk / 14 行 1:1 / 2713 行 / 226,578 字节」证据继续指向**同一个** `V3.10.md`，可独立复查。
- **本轮关闭的登记项**：
  1. W78 §八第 8 条的**归档边界**（另被 W79–W86 复述，连续八轮）⇒ 由 **E1** 收录；
  2. W87 核实中发现的 §56.2 **自相矛盾**（情形③ 的「§56」）⇒ 由 **E2** 收录。
- **遗留（不在本 ADR 范围）**：
  1. **W76 台账的 5 条 `decidable_in_repo` 仍只登记了推荐**（PD-09／PD-22／PD-24／PD-31／PD-34）：
     每条都值得单独一轮，本版不裁定（与 W76 §八第 3 条一致）；
  2. **H18 与 B07 仍 `pending`**：判定面已交付，接线与真实证据是 runtime／外部工作；
  3. **§56.2 情形③ 的清单是否还有其它不精确**：本版只订正「§56」一处，其余各项与 ADR 0049 决策 4
     逐项一致，未发现矛盾；
  4. §57.5 的待决策项与 §48.7 的全部事项继续有效。

无。本 ADR 撰写于订正当日，尚无被后续证据推翻的陈述。
