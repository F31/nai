# ADR 0141：引擎有限人工辅助节目生产者

状态：Accepted（2026-10-21）。承接 ADR 0140，依据 V3.11 §5.7/§53；不改变 B07 验收状态。

引擎新增 GET/POST `/api/v1/sessions/{id}/program`，分别使用 session.read / event.manual.write 权限。命令复用共享幂等账本、设备绑定、seq、epoch、状态修订 CAS、TTL 和载荷上限。start 绑定实际已发布快照，携带恰好四条提示，位置固定为卖点、规格、场景、售后。start 不访问 Provider，next 才经原有检索、四阶段守门、持久化调用预算、真实 API 适配器与候选存储生成。

复用 PitchRunner 的顺序与进入规则；本轮本地人工辅助策略初值为最小切换 100ms、同段冷却 1000ms，不作为测得的直播容量或认证标准。只执行一轮，最多四次生成尝试；开始派发后即消费该次尝试，队列准入或生成失败终止节目，不能以同 epoch 重新 start 清空上限。节目总期限 15 分钟，生成 deadline 再与命令 TTL、事实有效期取最小值，候选和播放继续受现有期限约束。金额、币种与单位预算仍由现有 DurableGateway 持久账本执行，四次上限不冒充金额预算、余额或成本预估。

节目生成要求所有检索证据具有当前有效的明确时间边界；未知期限在模型派发前拒绝。它不证明自由文本中价格、活动或承诺已经结构化分类，仍保留原守门和人工审批。普通手工问答保持兼容旧事实。

confirm 是操作员听完确认，仅当当前请求的精确候选仍有有效审批且已提交本机设备时允许前进；离线预览不算设备提交。它不写 PlaybackAck，也不向 PitchRunner 注入 completed_sentence_ids。真实完成生产者仍未实现。

P0 不获取节目锁。静音、接管、热发布的 epoch/知识切换令旧节目不可继续；没有自动恢复接口，也不把五面缺失写成 Fresh。活跃节目期间，普通手工问题拒绝并要求先显式静音/接管；静音后允许独立插问。当前不提供插问后自动归位。

进度、确认计数和四条提示仅驻留引擎内存，不增 DB 表、不承诺审计恢复或崩溃续播；重启沿既有会话恢复撤权流程处理。桌面现有人工辅助面板本轮不切换到新 API，下一步需处理固定四段编辑、引擎进度读取、审批播放关联和明确错误提示，再补真人麦克风与 OBS 验收。没有发布安装包或真实付费调用。
