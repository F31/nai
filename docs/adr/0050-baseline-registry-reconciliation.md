# ADR 0050：冻结基线与注册表的对账门控

- 日期：2026-10-12（W72）
- 状态：已接受
- 相关：ADR 0049（V3.10 订正版）、ADR 0048（就地订正/追加勘误的边界）、ADR 0042 决策 4（「在册」≠「测得」）
- 依据章节：V3.10 §48.5、§56.2、§57.3

## 背景

W71 的报告在「未做与遗留」里如实登记了两处门控缺口：

1. **缺口②**：**没有任何断言能发现「基线文本 vs 注册表」的漂移**。W68 在注册表新增 B07 之后，
   §48.5 仍写 `B \| B01–B06`、§57.3 仍写 `= 87`；**两轮之后才被人逐行读出来**，由 W71 收录。
2. **缺口①**：`admission-registry` 的「逐号在册」需求写「每个『基线已定义完整编号段』的家族」，
   括号里写「（当前为 M01–M18 与 H01–H18）」，而 §48.5 声明**九个**连续编号段——
   括号是「当前清单」还是「示例」没有裁定。

核实本轮还发现**第三件事**（不在原计划内）：**W71 自己的 E5 订正没有传播到它自己的规格差量。**
基线 §56.2 第 1 行把「就地订正的对象」写成四情形，其中情形②明确「`§NNN` 的版本前缀随基线更新」；
而 W71 新增的 `spec-driven-delivery` 需求写着「版本归属引用（形如「V3.9 §51.3」）MUST NOT 随基线号变更」，
其场景明确要求「改写成 V3.10 §51.3 MUST 被拒绝」——与 §56.2 情形②、也与 W71 **自己的落地**
（29 条能力包标记已写成 `【V3.10 §51.3（V3.9 收缩：自 rN 降为能力包）；INV-33/34】`）**直接相反**。

## 决策 1：断言写成「对账」，不是「相等」

**理由**：基线一旦被 ADR 批准即**不可变**（`AGENTS.md`）。若断言写成 `§57.3 == 注册表`，
则 W68 那样的合法新增会立刻让门控变红，而实现轮次**没有权限**改 §57.3——它只能跳过门控或开一次升基线轮次。
前者让门控失效，后者把「加一条验收项」的成本抬到一次 ADR。**这不是严格，是死锁。**

写成：

```
在册 == 基线声明 ∪ baseline_deviations
```

**基线文档的选取**：`docs/` 中**版本号最大**者（自维护，无需在门控里写死文件名），
且 MUST 与 `openspec/config.yaml` 声明的指针一致（这样一份废弃草稿不会让门控悄悄对着它跑）。

## 决策 2：`baseline_deviations` 不是豁免，它有三条性质

| 性质 | 落实 | 反例（MUST 失败） |
|---|---|---|
| **具名** | 每条给 `id` + `registered`（登记轮次）+ 非空 `reason` | 非列表 / id 非法 / 缺轮次 / 缺理由 / 重复登记 |
| **相称** | 每条 MUST 对应一处**真实**差异 | 台账写 `S02` 而实际差异是 `B07` ⇒ 真实差异与条目**两条都失败** |
| **自清理** | 基线收录后不清空 ⇒ 不再对应差异 | 陈旧条目 |

⇒「**已登记但尚未收录进基线**」从一个**说法**（W68→W71 期间它同时写在报告、`notes` 与活文档里）
变成一个**可判定**的状态。这与 ADR 0042 决策 4 的教训同形——「在册」与「测得」是两个不同的陈述，
现在「已声明」与「已收录」也是。

## 决策 3：家族完整性的判据来源是 §48.5，缺口①的括号是**示例**

`COMPLETE_FAMILIES`（M 18 / H 18）**保留**，因为它与新判据挡的不是同一件事：

| 守卫 | 挡什么 | 判据来源 |
|---|---|---|
| `COMPLETE_FAMILIES` | **§48.5 自己被改小**（M 行改成 `M01–M12`） | 写死的 18 |
| §48.5 家族索引对账 | **注册表少了 §48.5 声明的某一项**（B07 未收录） | 基线正文，逐行读出 |

**只有后者覆盖 S/R/A/B/O/P/X 七族。** 故缺口①的裁定是：

> 需求里「（当前为 M01–M18 与 H01–H18）」是**示例**，不是枚举；
> 「基线已定义完整编号段」的取值 MUST 从 §48.5 的家族索引**逐行读出**（当前 9 族，全部是连续段）。

⇒ 缺口①**不需要单独的实现轮**：它由决策 1 的实现顺带关闭，规格只需把判据来源写清楚。

## 决策 4：被先例否证的规则按载体分别处置

| 载体 | 处置 | 依据 |
|---|---|---|
| `openspec/specs/…`（**活的主规范**） | **就地订正**为四情形 | §56.2 第 1 行；历史记录清单只列 `docs/reports/`、`docs/adr/`、`openspec/changes/archive/`，**不含** `openspec/specs/` |
| `docs/adr/0048-*.md` 的勘误段、`docs/adr/0049-*.md` 的「后果」行 | **追加**勘误段（原文不改写） | §56.2 第 2 行 |

这一分界**不是**本轮新创的规则，它就是 §56.2 的应用。规格里保留被否证的规则**后果更重**：
规格是下一个升基线轮次的行为依据，留着它等于把 W65 已证伪的判据再执行一遍。

## 决策 5：本轮明确不改什么

- **不改基线正文**：`docs/直播数字人 + 智能体系统技术方案 V3.10.md` **零改动**——本轮是加断言，不是升基线。
- **不改 `tests/registry.yaml` 的任何 `acceptance` 条目**：88 条、六条发布线、全部 `status` 原样（H18 与 B07 仍 `pending`）。
- **不改 Rust 行为**：新代码全在 `scripts/` 与 `tests/`；`xtask/src/registry.rs` 与其输出串一字未改。
- **不改 `schemas/`**：能力目录与全部生成物零漂移。
- **不删 `COMPLETE_FAMILIES`**（决策 3）。
- **不给 §16 增行**（V3.10 §58.3 已裁定）。
- **不做「规格 vs 基线」的自动对账**：见「遗留」。

## 后果与实施

- 新增 `scripts/contracts/baseline.mjs`，由 `tests/registry.test.mjs` 驱动 ⇒ 自动进入
  `check --profile portable` 与 `full`（`engineering_checks` 已含 `registry::check`），**不需要新的 xtask 步骤**。
- `tests/registry.yaml` 新增 `baseline_deviations`（**当前为空**——W71 已收录两处偏差，台账为空本身就是该断言）。
- Node 用例 **4 → 11**；注入验证 **21 组**（19 组期望报错、2 组期望通过）。
- **已知代价（如实登记）**：门控现在依赖基线文档的**章节号**（§48.5、§57.3）与两张表的**写法**。
  章节被重编号或表格被改写成别的形态时，门控会**报解析失败**（而不是静默通过）——这是有意的取舍：
  宁可吵，不可假绿。解析失败与设计漂移在错误列表里**分开具名**。

## 遗留（如实登记，本轮不处理）

1. **语义类漂移仍只能靠人读**：四情形判据是**语义**规则（「这句是在声明当前基线，还是在陈述某一版」
   只能读出来）。本轮只覆盖**可机读**的那一半（编号与计数）。
   残余风险的证据就是本轮本身——**规格里的矛盾是靠人读发现的**，不是靠门控。
2. **§56.2「立即订正」与「跨轮次收录」的张力**：§56 前言要求「如实登记」之后**紧接着**订正现行规范，
   而 A12/A13（W54/W55 登记、W65 收录）与 B07（W68 登记、W71 收录）都是**跨轮次**收录。
   本轮把「待收录」做成可判定状态，但**没有**裁定「多久算太久」——这是一个待决策项。
3. **§57.5 与 §48.7 的待决策项**、**§56.2 对 doc-comment 前辍引用 ADR 0015 是否恰当**：沿用 W71 的登记，未动。
