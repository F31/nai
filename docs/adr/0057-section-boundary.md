# ADR 0057：节界——按章节号取表 MUST 在自己的边界内

- 状态：已接受
- 日期：2026-10-12
- 依据：ADR 0050（基线 ↔ 在册对账）、ADR 0051（重叠允许、漂移不行）、
  ADR 0056（§51.3 的判据；**遗留 2 登记的正是本轮的缺口**）、
  W73（「该节找不到」与「设计漂移」分开具名）、W78（本轮的前身）
- 影响：`scripts/contracts/baseline.mjs`、`tests/registry.test.mjs`；
  **不改基线正文、不改 `tests/registry.yaml`、不改任何 Rust、不新增依赖边**

## 背景

W78 的 `parseCapabilityPacks` **刻意不读 §51.2**，理由写在 ADR 0056 遗留 2：

> §51.2 是散文、没有表格，而 `sectionTable` 取的是「标题之后第一张表」
> ——对 §51.2 调用它会**静默取到 §51.3 的表**。

这条限制**只靠文档与记性维持**。而 `sectionTable` 是三个解析器（§48.5／§51.3／§57.3）
**共同的地基**——地基上的错会同时污染三张表。

`sectionTable` 的搜索域原本是无界的：

```js
let index = start + 1;
while (index < lines.length && !isTableLine(lines[index])) index += 1;   // ← 走到文件末尾
```

**实测（W79 探针，只用公开 API）**：给一段「§57.3 标题在、本节内没有表、后面跟着 §57.9 的一张表」
的文本，`parseReleaseLines` 返回——

```
found = true
errors = []                                        ← 一条错都没有
lines  = [["slice_0",["S01","S02","S03","S04"]]]   ← 这四行来自 §57.9
```

⇒ 它把**邻节的表**当成了 §57.3 自己的表，**并且没有任何一条错误**。这不是「解析器还不会读一段
散文」，而是「解析器会读错一段散文**并且读得很自信**」。成功与失败两种情形的返回值
**形状完全相同**，上层无法区分。

## 决策

### 决策 1：搜索域由标题层级封闭

域 = `[标题行, 下一个层级 ≤ 该标题的行)`。

- **层级 ≤ 本节**（`##`/`###`）⇒ 本节结束。这是 Markdown 的结构语义，也是
  「§57.3 是 §57 的一个子节」这句话的形式化。
- **层级更深**（`####`）⇒ **不截断**。写成「遇到任何标题就停」会把子标题误当节界，
  于是本节里明明有表却报「本节内无表」——那是**假阳性**方向（ADR 0052 的同一取舍：
  方向不安全的一侧不能选）。

当前 V3.10 的标题层级直方图是 `h1 = 1 / h2 = 59 / h3 = 259`，**没有 `####`**
⇒ 这半条语义在当前正文上**不可观测**，因此**必须由合成存根验证**（`####` 不截断 / `###` 截断），
而不是靠「反正现在没有」蒙过去。

### 决策 2：三种情形分开具名，且 MUST NOT 用空表代替

| 状态 | 含义 | 修法 |
| --- | --- | --- |
| `found: false` | 该节标题不存在 | 章节号被改指 / 被重排 |
| `found: true, hasTable: false` | 章节在，**本节内没有表** | 表被删 / 被挪 / 被更浅的标题挡开 |
| `found: true, hasTable: true` | 解析成功 | —— |

把后两者合成一个（「解析出的表是空的」）会让**上层用错误的措辞定位**：§57.3 会去报
「计数行为空」，§51.3 会去报「declares 0 capability packs」。**错误的措辞不只是不够精确，
它会把定位引向错误的方向**（W73 已把「该节找不到」与「设计漂移」分开，本条是同一原则的延伸）。

### 决策 3：把「刻意不读 §51.2」从记性变成**会被检查的前提**

`sectionTable` 因此**导出**，使「§51.2 本节内无表」可以被**断言**——它不是一句写给人的告诫，
而是一条会红的判据。若某次基线修订给 §51.2 加了表，这条断言会红：**那正是应该回去重读
ADR 0056 遗留 2 的时刻**。

同一条也用在 §57.5 上：它的下一节 `## 58` 恰好带着两张表（`E1–E5` 订正清单与变化表），
是「邻节有表」这种最容易借错的形状。

### 决策 4：边界若收得过紧，MUST 由同一组判据自己抓住

「三张被解析的表都落在各自节界内」这条断言（B-A）同时是**非空洞性**的来源：
若边界被收得过紧（例如把标题行本身当成节界），三条会**同时**报「本节内无表」。

### 决策 5：不与 `pending-decisions.mjs` 的章节抽取合并

那里的 `baselineSections` 按**正则**抽章节号、**不取表**（W76 立）。把两者绑在一起会让
任一方调整排除集或模式时牵动另一方——「**不合并不同维度**」（W66–W69 的既有取舍）。

## 后果

- **零行为变化**：三张表的名字、位置、断言一字未改；变的只是「表在不在本节内」。
- 新增 4 种具名失败：§48.5／§51.3／§57.3 「has no table inside its section」，
  以及「某散文节被加上了表」（前提断言）。
- `sectionTable` 成为**导出**符号：它是三张表的共同地基，「本节内有无表」是它的属性，
  不该只能通过三个上层解析器的间接症状去观察。
- 依赖边：**无新增**（只用 `node:fs`／`node:path` 与既有 import）。

## 遗留

1. **「第一张表」的语义未变**：本节内若有**多张**表（如 §48.5 有家族索引表 + H01–H18 逐条判据表），
   取的仍是第一张。若有人把家族索引表删掉而留下第二张，本轮会报**内容层**的错
   （「unreadable family label」）而不是「无表」——**这是边界，不是缺陷**：节内定位从不是本轮命题。
2. **层级语义在正文上不可观测**（无 `####`）：由合成存根覆盖，已在决策 1 说明。
3. **不校验「章节号与层级的一致性」**：例如 `#### 57.3.1` 写在 `## 57` 之下而非 `### 57.3` 之下，
   本轮不会报。它属于「文档结构」而非「取表边界」。
4. 判据仍只覆盖**被解析的那三节**；新增解析点 MUST 一并进 `PARSED_TABLES`（在 `tests/registry.test.mjs`
   里显式列举，作为「新解析点要付出一次登记」的提醒）。
