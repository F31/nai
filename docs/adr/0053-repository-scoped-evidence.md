# ADR 0053：仓库受限的消费证据——判据的输入必须等于它断言的对象

- 日期：2026-10-12（W75）
- 状态：已接受
- 相关：ADR 0052（消费守卫的边界；其 §八遗留 1 提出的方向被本 ADR 实现，其「必须派生 git 子进程」的陈述被本 ADR 订正）、ADR 0051 决策 3
- 依据章节：V3.10 §56.2（活文档 vs 历史记录）

## 背景：复核 W74 §八遗留 1，一条陈述被证伪

W74 留下的最重的一条遗留是：

> 未跟踪文件若落进「非 dot、非具名排除」的目录仍可能造出消费者……彻底消除需要「仓库文件集」
> 这个输入，而**取它需要派生 `git` 子进程（宿主禁止）**。

**第一步核实就把这条陈述拆成两半**：

- 「**node 派生 `git` 子进程会 `EBUSY`**」——**成立**（W74 实测 `git` 裸名与绝对路径、
  `process.execPath`、`cmd.exe`、`sh` 一律 `EBUSY`）。这是宿主约束，本轮不动。
- 「**因此取仓库文件集不可行**」——**不成立**。`.git/index` 是 Git 的 DIRC 格式，
  **纯 JS 可读**：实测 `magic=DIRC version=2 entries=922`，探针**完整解析 922/922** 条路径。

⇒ F2（W74 自己认定最严重的缺陷）不必停在「结构性收敛 + 登记残余风险」——缺口本身可以关掉。

### 实测：工作区扫描集与索引的关系

```
工作区扫描集（W74 裁定：跳 dot 段 + 4 条具名排除）  = 282
.git/index 全部路径                                  = 922
.git/index 里代码扩展名                              = 283
【A】工作区扫描到、但不在索引（即未跟踪）            = 0      ← 当前仓库干净
【B】在索引（代码）但不在扫描集                      = 1      ← .github/workflows/foundation.yml（dot 目录）
【C】工作区 ∩ 索引                                   = 282 = 扫描集
```

### F6（本轮新发现）：扫描集的路径格式不统一

`codeFiles()` 用 `dir.replace(/^\.\//, '')` 构造路径，而初始调用 `dir === '.'` 时该替换
**不生效**（`'.'` 不匹配 `^\.\/`）⇒ **根目录下的文件路径带 `./` 前缀**，子目录下的不带。
当前**无可观测影响**（`SELF` 恰在子目录、现有断言比较的都是子目录路径），但
**任何「与仓库路径集比较」的判据都会因此假阴性**——而本轮正是要做这个比较。
⇒ F6 不是「无害的历史遗留」，它是本轮判据的前置条件。

### 复核：W74 之后 F2 的**实际**可利用性（三条实测）

构造攻击（真孤儿 `schemas/config/w75-orphan.schema.json` + 未跟踪的 `.tmp-fake-consumer.rs`
内含 `include_str!` 指向它），在 W74 的守卫上实测：

| # | 条件 | 实测 |
|---|---|---|
| V1a | 原样 | **两条断言同时开火**：`exclusiveTo(RUST)` 的**钉死**断言（孤儿的加入让 Rust 的独有集合多一员）＋ 本 ADR 的 `repositoryErrors` |
| V1c | 把形状断言**放宽**为 `includes`（模拟「有人为了让自己的新消费者通过而顺手改松它」），保留 `repositoryErrors` | **`repositoryErrors` 独立兜住** ⇒ 新判据不是重复的 |
| V1b | 两条都停用 | **17/17 全绿** ⇒ 洗绿成立 |

**这一组实测的结论比「F2 还在不在」更重要**：

- W74 之后 F2 **难以洗绿**，但它挡住 F2 的是一条**形状**断言（`exclusiveTo` 的具名钉死），
  **不是**一条关于**来源**的断言。那是**副作用**，不是设计——**任何人合法地让一份新 schema
  只被 Rust 消费，都会让那条断言变红，而处置它最顺手的办法就是把钉死改松**（V1c 验的正是这个）。
- ⇒ **「碰巧挡住」不能算挡住。** 判据必须**直接**说出它要的东西：「读 schema 的文件 MUST 是仓库
  里的文件」。这就是决策 2。

## 决策 1：仓库文件集由 `.git/index` 纯 JS 取得

**取**：新增 `scripts/contracts/git-index.mjs`，`readTrackedPaths(root)` 读 `<root>/.git/index`；
`.git` 是**文件**时（worktree/submodule）跟随其 `gitdir:` 指针。解析 DIRC v2/v3/v4
（v4 的名字是「公共前缀长度 varint + 后缀」，条目不补齐），返回 `{ok:true, version, paths}` 或
`{ok:false, reason, detail}`。

**理由**：

- **零子进程**——读文件不受宿主约束，而 `git ls-files` 受；
- **自包含**——`node --test tests/contracts/schema.test.mjs` 单跑也能行使判据，不依赖别的步骤先跑；
- **格式稳定**——DIRC v2 是 Git 二十年默认（实测本仓库即 v2），且解析器自带字节流单测
  覆盖 v2/v3/v4 与每一类失败 ⇒ 脆弱性被约束在明处。

**否证过的备选**：

- *`git ls-files --cached --others --exclude-standard`*（`cargo xtask check --secrets` 已在用的写法）：
  **修不了 F2**。`--others` 恰恰把**未跟踪但未被忽略**的文件收进来——那个伪造的消费者也在集合里。
  它回答的是「git 会发布什么」，不是「仓库**已经承诺**了什么」。
- *由 xtask（Rust）导出清单文件供 node 读*：Rust 可以派生子进程，技术上可行，但引入**顺序耦合**
  （node 测试必须在 xtask 之后）与**陈旧产物**（单独跑 node 时读到上一轮的清单）。**判据的输入
  自包含，比复用一次 `git` 调用值钱**——「守卫读到陈旧输入」正是本轨道反复处理的失效形态。
- *不做*：W74 §八遗留 1 自己把它记为最严重缺陷的残余；既然存在纯 JS 的关掉路径，
  「继续登记」就不是唯一的负责任选项。
- *解析失败时降级为「通过并打印一行」*：会让保护在不知情时消失（ADR 0051 决策 3 的「假契约」同族）。
  **前提缺失必须可见**（见决策 4）。

## 决策 2：判据是「消费证据的来源 ⊆ 已跟踪路径集」

**取**：`consumptionOf(files)` 除 `consumed` 外再返回 `evidenceSources`（**提供了消费证据的文件**）；
新断言 `repositoryErrors([...evidenceSources], tracked)` 为空，并指名越界文件。
**非空洞**：`evidenceSources` MUST 非空（否则「来源 ⊆ 索引」对空集恒真）。

**为什么约束「证据来源」而不是「整个扫描集」**（这一条决定闭环是否被打断）：

- 若断言「扫描集 ⊆ 索引」，那么**任何**尚未 `git add` 的代码文件都会让门控红——而本程序的闭环
  顺序是「门控 → 勾 tasks → 归档 → 校验 → **提交时才 `git add`**」，新变更目录里的 `.yaml`
  会让门控**假红**，那会**改变工作流**。
- 约束「证据来源」只命中**真正读取 schema 的文件**（`xtask/src/*.rs`、`packages/.../*.rs`、
  `scripts/contracts/*.mjs` 等），它们**都是已跟踪的老文件** ⇒ 零假阳性。
- 而 F2 的攻击面**恰好就是证据来源**：伪造消费者之所以能洗绿，靠的是它**提供了证据**。
  **精确关掉那个入口，比扩大打击面更对。**

## 决策 3：扫描集的路径是 POSIX 相对路径（修 F6）

**取**：`codeFiles()` 的路径构造不再产生 `./` 前缀；断言「扫描集里 MUST NOT 有 `./` 开头的路径」
＋「至少有一个根目录文件可达」（后者让前者的非空洞性有个具体的锚）。

**理由**：F6 让扫描集与索引路径**不可比**。不修它，决策 2 的断言会对根目录文件
（如 `pnpm-workspace.yaml`）**静默假阴性**。F6 当前无可观测影响，正因为**还没有任何判据做过
这个比较**——这不能当作「不是缺陷」的证据（W37：实测钉住的差异也要问「该不该存在」）。

## 决策 4：索引不可解析 MUST 失败，且必须说得清是哪一类

**取**：四类失败各自有名——`missing`（`.git` 或 `index` 不可读）／`bad-magic`／
`unsupported-version`／`truncated`／`corrupt`（解出的「路径」含控制字符，例如按 SHA-1 的 20 字节
去读一个 SHA-256 索引）。守卫在前提缺失时**红**，消息含 `describeFailure()` 的一段话，
说清「没有索引就无法分辨仓库内容与工作区里的游离文件」。

**理由**：「判据的输入等于被断言的对象」是这条守卫的**前提**；前提缺失时静默退化，
正是 ADR 0051 决策 3 建立本守卫时要根除的形态（规格写着 SHALL 被校验，而零执行路径读它）。

## 决策 5：本轮明确不改什么

- **不改基线正文**：`docs/直播数字人 + 智能体系统技术方案 V3.9.md` **零改动**。
- **不改任何 schema 文件**（14 份原样）、**不改 `tests/registry.yaml` 的任何 `acceptance` 条目**。
- **不改 Rust**，**不新增 xtask 步骤**：新断言写在既有的 `tests/contracts/schema.test.mjs` 里

## 遗留（如实登记，本轮不处理）

1. **依赖 `.git` 内部格式**。缓解：DIRC v2 二十年稳定；解析器自带 v2/v3/v4 与四类失败的
   字节流单测；版本不支持时**明确失败**（不猜）。
2. **CI 上 `.git/index` 的可读性未在本机验证**。结构性理由：`.github/workflows/foundation.yml`
   用 `actions/checkout@v4`，无 `fetch-depth`/`index.version` 配置 ⇒ Git 默认 v2；**CI 观测时核对**。
   若 CI 实测失败，四类原因之一会直接出现在失败消息里。
3. **「已跟踪」是索引不是 HEAD**：已 `git add` 但未提交的文件算「仓库内容」。可接受——
   `git add` 是「意图提交」的显式声明。反之，**已提交但工作区被删**的文件不可能成为证据来源
   （它不在扫描集里，因为磁盘上没有）。
4. **`.github` 仍被结构性排除**（沿用 ADR 0052 决策 1）：将来若工作流成为某 schema 的唯一消费者，
   会被报成孤儿（假阳性，安全方向），处置是加一条具名例外，而不是恢复枚举式扫描。
5. **语义类漂移仍只能靠人读**（沿用 ADR 0050/0051/0052 的登记）。
6. **`§56.2` 自身两处张力、`§57.5`/`§48.7` 待决策项**：沿用 W71–W75 的登记，未动。
7. **`schema --check` 仍在本机跑不了**（宿主禁止 node 派生子进程）：取零漂移仍靠结构性理由 +
   CI 独立步骤；**不得把「跑不了」写成「已通过」**。
