# ADR0179：无损分句计划与两槽预取机制

日期：2026-10-26；状态：采纳。

V48-07采用基于已验证发布源的确定分句计划：最多32节目单元、128句、每句120个Unicode标量，计划原文总UTF-8不超过32768字节。优先自然句末，长句按空白/逗号或字符边界分割，不改字、不丢空白、不静默截断；小数及URL内部点不会被当成自然句末。此算法不声明语义分句或逐字时间对齐能力。

计划通过Protobuf的ReadLiveSpeechPlan/LiveSpeechPlan返回，携带原有AgentTaskContext与run/revision/epoch。读取按创建人、角色、事实来源、会话代次复检，不接受页面文本、不持久新对象、不预留费用或授予输出权。UI自动读取并折叠展示，仍按旧有单元准备流程执行。

runtime-core新增独立Prefetch机制：最多两槽，只准当前及下一句；ticket含代次、唯一attempt及期限。匹配且未过期才能回填，只消费当前Ready项，显式可信提交才前进。暂停禁止预留/取出；取消提升代次并清槽，取消已取出项标未知，继续不能隐式重播，须明确跳过且独立审计。该机制不持有Provider或媒体依赖，不代表生产预取已经接线。

自动衔接下一步须补充明确的批量批准范围（逐句文本哈希、源、模型/音色、输出目标、session/epoch、费用及期限），并在每句消费前复检。不能复制已有单句批准，也不能让页面自报提交。控制/媒体P0路径不变；插问归位和真人独立音轨在此后接线。
