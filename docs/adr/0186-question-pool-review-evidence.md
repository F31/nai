# ADR 0186：场次问题处理记录与复盘重点

日期：2026-10-27。状态：采纳。基线：V4.8；工程命名沿用 nai-*。

## 决策

问题入池时由可信存储核验工作区、当前场次、发布版本及实际会话 epoch/停止状态。新增类型化入池与读取契约；不同场次和不同 epoch 不去重。未关联场次的独立查询保持独立，不事后猜测历史归属。

复盘用途单独保存原始操作员提问、重复次数、候选身份/hash、处理结果和输出回执，每场、每操作员最多64条，仍由原 SQLite 单写者持有。它不保存候选回答正文，也不延长32条/120秒运行时问题池及子候选期限。原始提问用于人工复盘的读取权不授予旧候选执行权；发布撤销、证据删除、权限变化继续拒绝读取。

采纳/编辑采纳、忽略、取消、未命中与待核对独立于公共输出。可信输出回调只记录请求、软件音频提交结束或停止，不生成硬件/平台完成结论。浏览器不能伪造这些记录。

人工重点可带问题记录的对象版本/hash。一次问题最多关联一项重点，每场最多3项；保存、预览、应用及幂等读回复检来源。记录变化返回 QUESTION_CHANGED，重新核对前不创建下场草稿。原有 FAQ 三方对照、双草稿原子提交和不自动发布规则继续生效。

## 边界与影响

不增加数据库表、常驻服务或模型依赖；通过现有受保护的 publication 对象存储。无旧 ABI/协议兼容层，不删除历史资料。UI 自动选定并明确展示当前场次归属；没有当前场次时显示独立查询。

本切片完成问题记录到人工重点的工程链路，不代表自动总结、历史场次完整管理、第二场实际使用、长稳或渠道认证已完成。164项 ACC 仍 pending。
