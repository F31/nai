# ADR 0152：共享模型目录及凭据迁移边界

状态：Accepted（代码方向；不代表用户数据迁移或产品验收通过）。日期：2026-10-24。

## 决策

LLM/TTS配置归属root owner管理的共享目录，任务、预算、内容与权限继续归属业务工作区。单Store连接中增加shared_models/shared_model_versions及迁移journal/staging表，不创建隐藏业务工作区或第二个数据库写入者。SQL源为schemas/storage/shared-model-catalog.sql，基础v2表和根清单不变；这是显式启用的附加功能，不是旧ABI兼容层。

共享凭据AAD使用固定保留UUID，仅作为内部身份；实际Vault仍使用本数据根的原scope，LLM/TTS各自独立服务。迁移从源workspace/model/endpoint打开，再以共享scope及新modelID封装并回读，原密钥不删除。每个来源分配新的共享ID，禁止与任何旧对象ID冲突，不合并同名模型。旧配置和版本保留以支撑历史任务，新任务仅允许共享目录ID。

显式确认后持久化完整映射、预览hash、一致备份收据和逐项重加密状态。发布目录及committed同事务，发布前部分结果不可见。模型修改和新会话在迁移期间拒绝。恢复重用已完成条目；备份中断最多8次owned尝试，单条凭据最多3次尝试。用户可以显式放弃未提交迁移，保留原配置、备份和审计；已提交不可用放弃覆盖回滚。P0撤权先于所有目录查询。

## 后果和限制

共享目录当前每类最多8个活动模型；超限先拒绝，不截断。所有工作区共享修改效果，global写权限仅root owner；已授权工作区角色仍用于任务操作。密钥库写入和SQLite无法跨介质原子提交，seal后进程中断可能留下有界孤立目标条目，本轮不自动删除，也不宣称完整断电/生产回滚认证。现有运行程序更新仅在关闭后的维护窗口执行。
