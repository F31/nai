# ADR 0135：独立能力主备与派发后的路由边界

日期：2026-10-20。状态：采纳。基线V3.11与registry不变。

当前操作链路共用LLM/TTS模型，协议fixture未体现真实厂商分别选模型/音色的要求。本轮在场景中加入可选provider_routes，应用层装配独立能力路由；不新建内核、插件间依赖或服务。旧场景兼容，新配置缺少能力不回退旧共享配置。

每组1主4备上限，健康熔断和单次冷却试探，策略为主优先或已观测延迟优先。选择固定到本次请求，prompt装配记录、TTS音色与usage采用同一profile。派发权取自真实持久化账本；预算拒绝、取消与换代不作为供应商故障。已派发失败不跨供应商重发，下一次新显式请求再路由。无额外付费竞速或自动探测。

配置文件不含密钥；各Key只入本次engine环境，媒体子进程仍继承固定非机密白名单。新环境名限制NAI_PROVIDER_*，ID/环境名全局唯一，预算币种一致，拒绝带userinfo/查询的地址。运行中拒绝改配置，显式停止撤权后保存。壳复用锁定jsonschema，无新增常驻依赖。

真实收费生成、声音质量、厂商账单与平台认证仍是独立证据；本地协议测试和配置预检不提升registry状态。完整操作与局限见[配置指南](../provider-routing.md)。
