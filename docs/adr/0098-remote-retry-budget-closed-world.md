# ADR 0098：post_json 重试预算与 read_body 读取上限闭世界守卫

- 状态：Accepted
- 日期：2026-10-16
- 归属：W120（客户端内部**预算与边界**分支的判定面缺口勘定，延续 W113–W119 「先测后设计」判定面闭合节奏）
- 关联：ADR 0097（§出站请求构造）、ADR 0096（§parse_reply 的 RemoteStatus 映射）、ADR 0095（§top_k 截断）

## 背景
W119 闭合了出站请求构造。继续勘定客户端内部预算与边界分支：`post_json`（`remote.rs:195-241`）与
`read_body`（`remote.rs:133-135`）有三类分支**整段零判据**——既有 429 用例只用过 `Retry-After: 0`、且总在
预算耗尽前就成功，故这些分支一次都没被执行：

| 分支 | 位置 | 若被移除的后果 |
|---|---|---|
| `backoff >= op.remaining()` ⇒ `Unavailable` | `remote.rs:232-234` | 硬等到 `op` 到期 ⇒ 结果从 `Unavailable` 变 **`Timeout`**（语义错误） |
| `attempt >= max_retries` ⇒ `Unavailable` | `remote.rs:220-223` | 退避为 0 时**无限重试**直至 `op` 到期 |
| 5xx 走指数退避、**忽略** `Retry-After` | `remote.rs:225-231` | 5xx 用 `Retry-After: 100` 会立刻撞上一行 ⇒ **不再重试** |
| 响应体 > 8 MiB ⇒ `Invalid` | `remote.rs:133-135` | 响应体**无上限缓冲** |

## 决策
**判定面闭合，零生产代码改动**。只补可测判据，**每条分支都用判别性构造**，使断言在该分支被移除时**必然变红**
（而非仅记录现状）：

1. (a) 429 + `Retry-After: 100` + `op = 1s` ⇒ 断言 `Unavailable` **且耗时 <900ms**；若分支被移除则等到
   `op` 到期 ⇒ `RetrievalTimeout` 且耗时 ~1s ⇒ 断言变红。
2. (b) 持续 429 + `max_retries = 1`（退避 0）⇒ 断言 `Unavailable` **且尝试次数恰为 2**；若分支被移除则无限
   重试直至到期 ⇒ `Timeout` 而非 `Unavailable` ⇒ 断言变红。
3. (c) 503 **故意带** `Retry-After: 100` + `op = 30s` ⇒ 断言**仍重试并成功**（2 次尝试、`Complete`）；
   若误用 `Retry-After` 则 100s 撞上 (a) ⇒ `Unavailable` 且仅 1 次 ⇒ 断言变红。
4. (d) 回包 8 MiB + 1，经**合法字段** `evidence[0].text` 撑大（畸形 JSON 也返回 `Invalid`，会与「读到大包被拒」
   混淆，故必须用合法回包）⇒ 断言 `Err(RemoteError::Invalid)`；若上限被移除则正常解析 ⇒ 断言变红。

另把「尝试次数」显式清点（(b)(c) 断言精确值）：只断言最终状态会漏掉次数维度。

## 后果
- 正向：三条重试预算分支与一条读取上限从「从未执行」变为「被判别性断言钉住」，任一被改都会红；并把
  「放弃时是 `Unavailable` 而非 `Timeout`」这一**语义**显式固定（调用方据此区分「预算不足」与「超时」）。
- 零运行时变化、零契约字段改动、零迁移、零 schema 改动。
- 如实披露（非验收达标）：
  - 不断言真实网络下的退避时序（只钉「是否重试 / 何时放弃 / 放弃成什么」这类可判事实）。
  - 不断言 `Retry-After` 的语义正确性（远端语义属远端责任；本轮只钉**本客户端选用哪个退避来源**）。
  - (c) 依赖「5xx 与 429 退避来源不同」这一既有设计；若将来有意改为 5xx 也用 `Retry-After`，该判据会红，
    届时应**先改设计再改判据**，而不是反向。
  - registry：守卫不属 memory 子系统（H03/H04），无既有 H 条目需改。
