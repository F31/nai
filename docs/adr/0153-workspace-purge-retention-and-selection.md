# ADR 0153：工作区永久清理、财务保留与持久选择

日期：2026-10-24。状态：Accepted（工程实现，不等同用户数据已清理或产品认证通过）。

## 决策

回收区才允许永久清理；可信root owner必须读取完整影响计划，再以workspace revision、plan hash和明确ack确认。工作区持久选择、未排空会话/派发/费用预留、模型迁移准备态、尚未共享的模型配置均阻止清理。所有workspace_id关联表均需明确列入业务或保留清单，未知表失败关闭。

单SQLite事务将费用记录复制至独立保留账本，清除工作区业务行/角色，写workspace_delete永久墓碑、清理收据及文件hash队列。保留所有审计、历史幂等回执（可能含历史响应正文）、费用账本、共享目录、Keyring与已有备份，确认界面必须说明。不可把清除财务事实当作永久清理，也不承诺取证级磁盘安全擦除。

文件清理只处理本root精确owned路径，需标记和内容hash有效且无其他活跃对象引用。全root待清理队列上限4096条，每步32条；提交后清理/读取异常仍返回已删除与待清理状态，不误报业务事务回滚。待清理条目由专用队列恢复，通用GC跳过，坏文件或标记不再令整个工作台无法启动。旧备份只能恢复至新验证目录，不覆盖活动墓碑；不开放生产回滚或自动导入。

workspace_selection按可信principal保存最后选择；重启恢复有效项，回收/删除/失权时解释回退，不续会话、审批或播放。当前选择同时受界面和存储守门保护。

## 限制

当前不提供保留账本浏览和审计到期删除策略；不会删除系统密钥或备份副本。手动以OS权限替换活动数据库不属于本功能支持的恢复路径。物理文件故障需先修复环境再续办，不能通过忽略所有权/hash强行删除。新能力按维护窗口更新后由用户明确操作，不自动执行实际清理。
