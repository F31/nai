# ADR0184：真人设备打开等待期维持公共待机健康

2026-10-27，采纳，定向测试/Windows接管回归及600秒媒体稳态通过。录像尾部非运行段134ms时间戳间隔保留，见收尾报告。

真实语音接管后恢复已通过，但连续验收发现：重新打开WASAPI设备可能超过500ms；原桌面接管调用持有公共输出所有权并等待麦克风握手，普通公共监督也因业务命令进行中而跳过。即使数字人已静音，公共窗口的独立健康租约也会过期。这是实际装配缺陷，不能仅归为休眠中断，亦不能通过放宽租约解决。

在 `nai-workbench-host::human_mic` 增加共用 `start_with_standby` 入口：在原有有界握手等待中每10ms消费公共待机健康回执；若窗口terminal或仍有AI声音则拒绝。这里只轮询健康，不签发/续签任何AI执行许可。等待仍为设备阶段最多4秒、活跃控制250ms，媒体仍500ms；遇到超时、对端丢失或健康失败，通道标记失效，不把迟到回执复用到下一请求。真人开始仍以root先停AI、持久接管及新epoch为前提。

桌面壳和原生验收调用同一入口。600ms延迟回复下仍执行健康轮询、原期限保持，以及健康失败立即中止有定向测试。新的连续验收不重复调用模型；旧失败账本、休眠中断和3次真实Qwen任务保留。

OBS隔离配置严格匹配窗口标题，拒绝默认“标题丢失后退到同类窗口”，避免两种minifb窗口互相误抓。对应OBS33 `WINDOW_PRIORITY_TITLE=1`，见[官方源码](https://github.com/obsproject/obs-studio/blob/33.0.0/libobs/util/windows/window-helpers.h)。原用户OBS配置不改。

验收音轨对齐使用OBS实际Recording Start日志；NTFS文件创建时间可晚于该事件，不作为准确音频时钟。统计区间按真实阶段边界截断，不把随后真人阶段混入AI恢复区间。仍不从软件提交推断耳机/OBS硬件完成，不把10分钟混合运行算作全天连续讲品或全部ACC通过。
