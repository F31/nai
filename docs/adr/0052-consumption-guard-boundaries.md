# ADR 0052：消费守卫的边界——扫描集、语言闭包、来源自负其责与单一生成清单

- 日期：2026-10-12（W74）
- 状态：已接受
- 相关：ADR 0051（注册表形状契约接电与台账寿命，其决策 3 建立了本守卫、其遗留 2 提出了本 ADR 采用的修正方向）、ADR 0050 决策 2（台账的三条性质）、ADR 0042 决策 4
- 依据章节：V3.10 §56.2（活文档 vs 历史记录）、§30.1（证据目录）

## 背景：复核 W73 的消费守卫，四条缺陷与一条宿主约束

W73 建立了一条守卫：`schemas/**/*.schema.json` 的全集 MUST 等于「被消费的」∪「具名例外」。它在**结构**上是对的（派生而非清单、注释不算消费、例外必须付理由、五类注入覆盖）。本轮对它做**复核**，实测出四条缺陷；「先核实再裁定」在这里再次改写计划——**出发点写的「ADR 0051 遗留 2」，核实后发现问题更靠前、更深**。

### F1：非空洞断言自我满足

守卫写着「三条派生来源各自都被行使」，判据是：

```js
assert.ok(consumed.has('schemas/platform-matrix/platforms.schema.json') &&
  consumed.has('schemas/tests/registry.schema.json'),
  'the literal scan and the validator list must both contribute');
```

这两份 schema**都在 `AJV_SOURCES` 里**，所以这句话**只由 Ajv 清单独自满足**。实测：关掉路径字面量来源后仍是「消费 13 份 / `fail 0`」；把 `for (const pattern of [rust, literal])` 改成 `[rust]`（注入 V1）后守卫**照旧 13/13 绿**。⇒ 整条来源可以被删除而**没有任何断言变红**。

### F2：扫描的是工作区，不是仓库（最严重）

`/['"`]schemas\/([A-Za-z0-9_./-]+\.schema\.json)['"`]/g` 扫「工作区里所有匹配扩展名的文件」。实测：放一个**未跟踪**的 `.tmp-fake-consumer.mjs`（内含一句 schema 路径字面量），一个真孤儿立刻被洗绿 —— `# tests 13 / # pass 13 / # fail 0`。

「有一份 schema 没人读」是本守卫**唯一**要抓的东西，而一句临时脚本就能让它失效。这不只是「漏一次」，而是**判据的输入不等于仓库**。

### F3：两个缺陷互相掩盖

```js
const CODE_EXTENSIONS = ['.rs', '.mjs', '.ts', '.tsx', '.yml'];            // 缺 .yaml / .js
const text = stripCommentLines(await readFile(file, 'utf8'), file.endsWith('.yml'));  // 只对 .yml 用 # 注释
```

`.yml` 与 `.yaml` 是**同一种语言**，而注释语法按扩展名后缀判断 ⇒ 两者各错一半。更糟的是：**唯一暴露这个缺口的文件**（`tests/registry.yaml`，它正是 W73 写下「注释里的路径不算消费」那句注释的地方）**因为扩展名叫 `.yaml` 而根本不在扫描集内**——两个缺陷各自都躲在对方的盲区里。

实测（`dist/` 探针）：提到过 `.schema.json` 的 95 份文件里，`.md 79 / .rs 7 / .mjs 6 / .json 2 / .yaml 1`，那唯一一份 `.yaml` 就是 `tests/registry.yaml`。

### F4：`schemas/` 有第二处清单

- `scripts/contracts/validation.mjs` 的 `AJV_SOURCES`：**12** 条；
- `scripts/contracts/generate.mjs` 的 `jsonSources`：**10** 条（前者的子集）；
- 两份清单**无任何交叉断言**；生成物 `packages/contracts-ts/src/generated/config/*.ts` **已入库**。

⇒「生成面 ⊆ 校验面」这条**可以判定却无人判**。这正是 **ADR 0051 遗留 2** 触碰过的地方：它把风险写成「仅由模板消费的 schema 会被误报为孤儿」（安全的假阳性方向），但**真正的风险**是**两份清单可以无声漂移**——它当时的前提「今天不漏判」掩盖了这一点。

### 宿主约束：node 不能派生任何子进程

F2 的自然解法是「取仓库文件集」（`git ls-files`）。实测**不可行**：本机 node 对 `git`（裸名与绝对路径）、`process.execPath`、`cmd.exe`、`sh` **一律报 EBUSY** —— 这是**宿主**约束，不是「node 自旋 node」那么窄。

> **订正既有归因**：此前把 `cargo xtask schema --check` 本机跑不了的 EBUSY 解释为「node 自旋 node 的限制」。正确表述是「**宿主禁止 node 派生任何子进程**」，同一根因；处置与结论不变（仍靠结构性理由 + CI 独立步骤兜底）。

⇒ F2 只能靠**结构性收敛**处理（决策 1），残余风险如实登记（见遗留 1）。

## 决策 1：扫描集的形状是结构性的，且每条排除 MUST 付得起理由

**取**：扫描集 = 结构规则（从仓库根递归、**跳过所有以 `.` 开头的目录**）＋ **具名排除**（恰 4 条：`node_modules` / `target` / `graphify-out` / `dist`）。**每条具名排除 MUST 被 `.gitignore` 忽略。**

**理由**：「这条排除为什么无害」必须有个**可执行的**答案。`.gitignore` 恰好就是那个答案——一个目录被声明为「不是仓库的一部分」，把它排除掉就不可能藏起仓库内容。⇒ 排除从**豁免**变成**有证据的陈述**，且证据本身是活文档（改 `.gitignore` 会立刻反映到判据上）。

**否证过的备选**：

| 备选 | 为什么不用 |
|---|---|
| 枚举 `SKIP_DIRS` 字符串（W73 做法） | 那是**第二张会过期的清单**；W73 里的 `build`/`.venv` 既不在 `.gitignore` 也不在磁盘上，纯属抄来 |
| `git ls-files` | **不可行**（宿主禁止 node 派生子进程） |
| 把扫描收窄到几个「可信」目录 | 变成第三张会过期的清单，且「可信」无法判定 |

**无害性断言**（非空洞的形式）：**跳 dot 段与不跳 dot 段的消费集合 MUST 相同**。

实测：两侧文件数 281 / 282，唯一差异是 `.github/workflows/foundation.yml`，它的非注释行**不含任何 schema 路径** ⇒ 两侧消费集合相同。注入验证：在一个 dot 目录里放一份含 `include_str!(…schemas/…)` 的 `.rs` 文件 ⇒ 该断言**立刻红**，差异直指那份 schema ⇒ 它确实对输入敏感，且「跳 dot 当前无害」是被证明的，不是被假设的。

## 决策 2：语言闭包——可扫描扩展名由语言表派生

**取**：`CODE_LANGUAGES`（ext → `'slash'` | `'hash'`），`CODE_EXTENSIONS = [...CODE_LANGUAGES.keys()]`。

**理由**：F3 的形状是「扩展名清单与注释语言判断分居两处，各自漏一点，于是互相掩盖」。让**前者从后者派生**，这类缺陷在结构上就不可能出现——想扫新扩展名，就必须顺手声明它的注释语言。`.yml` 与 `.yaml` MUST 一起覆盖。

**为什么 `.yaml` 必须进来**：判据既然按扩展名解析注释语法，那么「不扫描的格式」与「误判注释语法的格式」就是同一类缺陷。实测把 `.yaml` 纳入扫描集后**消费集合不变**（`tests/registry.yaml` 里那两处提及不带引号、不够格当路径字面量；且字面量来源本轮已被移除）⇒ 这是一次**零行为变化的正确性修正**。

**非空洞断言**：扫描集 MUST 收录 `tests/registry.yaml`（具名）。注入：把 `.yaml` 换成不存在的扩展名 ⇒ 两处断言同时开火（主测试的收录断言 + 「`.yml`/`.yaml` 同语言」断言）。

## 决策 3：移除路径字面量来源；来源从「各自都被行使」改为「各有独有覆盖」

**取**：派生来源 = ① Ajv 校验器清单 ② Rust `include_str!`。判据是**独有覆盖**（某来源找到的、别的来源找不到的 schema 集合 MUST 非空）：

| 来源 | 独有找出的 schema（实测） | 条数 |
|---|---|---|
| Ajv 清单 | `config/binding-plan`、`catalog/catalog`、`plugin/ui`、`platform-matrix/platforms`、`tests/registry` | 5 |
| Rust `include_str!` | `config/upgrade-package` | 1 |

**为什么移除字面量来源**：它**零独有覆盖**（找到的每一份都也在 Ajv 清单里），且是**唯一**会读任意扩展名文件的来源 ⇒ 它是 F2 的**全部入口**。按「假阳性与假阴性不对称，永远选安全方向」：

- 保留它 ⇒ 换来**假阴性**（未跟踪文件洗绿）——危险方向；
- 移除它 ⇒ 换来**假阳性**（将来若有 schema 只被某个脚本加载，会被报成孤儿）——安全方向，加进 `AJV_SOURCES` 即可。

**否证过的备选**：*保留但要求它有独有覆盖* —— 当前无法满足，只能造一个假案例来满足，那是自欺；*保留它但只作「发现工具」不参与 pass/fail* —— 同一份扫描仍在读任意文件，入口没关，只是把结论藏起来。

**为什么把「各自都被行使」换成「独有覆盖」**：前者可被**单一来源**满足（F1 实测），后者不能——一条来源只要没有别人找不到的东西，就什么也没证明。

**注入验证**：抽掉 Ajv 来源 ⇒ 恰 5 份（上表左侧）同时变成孤儿，且该来源自己被指名为「零独有覆盖」；抽掉 Rust 来源 ⇒ `upgrade-package` 恰成孤儿。

## 决策 4：生成器与校验器读同一份 schema 清单

**取**：`validation.mjs` 导出 `TS_GENERATED_SOURCES`（10 条）；`generate.mjs` **删除**自己的 `jsonSources`，改为导入它。判据三件：**生成面 ⊆ 校验面**、**basename 互异**、**生成目录的 `.ts` 与清单双向相等**；外加一条防回退断言（`generate.mjs` 的源码 MUST 引用 `TS_GENERATED_SOURCES`）。

**理由**：两份清单不可能「都不出错」，只能**互相牵制**。`TS ⊆ AJV` 是**交叉**断言（F4 缺的正是这一条）；生成物已入库 ⇒「双向相等」把生成器**实际做了什么**与清单钉在一起，而不是核对一份自我声明的数组。`basename 互异` 对应一个真实风险：生成物按 basename 落盘，两条 schema 同名会**先写的被后写的覆盖**，而「生成成功」看起来一切正常。

这同时**闭合了 ADR 0051 遗留 2**：那里建议「若将来出现这种形态，正确做法是把该清单也做成一条派生来源，而不是给它加例外」——本 ADR 采用该方向，只是把它落在**单一来源 + 双向对齐**上（模板路径的具体取值仍抓不出来，用对齐取代它）。

## 决策 5：本轮明确不改什么

- **不改基线正文**：`docs/直播数字人 + 智能体系统方案 V3.10.md` **零改动**。
- **不改任何 schema 文件**（14 份原样）、**不改 `tests/registry.yaml` 的任何 `acceptance` 条目**（台账仍为空）。
- **不改 Rust 行为**，**不新增 xtask 步骤**：新断言写在既有的 `tests/contracts/schema.test.mjs` 里（已在 `engineering_checks` 上）⇒ 自动进入 `portable` 与 `full`。
- **不改生成物**：`packages/contracts-ts/src/generated/` 内容零漂移；本轮只把「谁生成它」的清单来源收成一份。
- **不删** `rag-golden/case-set.schema.json`（ADR 0051 决策 3 的具名例外，理由不变）。

## 后果与实施

- 交付：`scripts/contracts/validation.mjs`（导出 `TS_GENERATED_SOURCES`）、`scripts/contracts/generate.mjs`（改为导入）、`tests/contracts/schema.test.mjs`（扫描集结构化 + 语言表 + 两条来源 + 独有三组新断言）。
- 门控路径不变：`schema::node` ⇒ 新断言自动进入 `portable` 与 `full`。
- **已知代价（如实登记）**：判定覆盖从「三条来源」缩到「两条」，将来若有 schema 只被某个脚本加载，会被报成**假阳性孤儿**。这是**有意的取舍**（安全方向），处置是把它加进 `AJV_SOURCES`。

## 遗留（如实登记，本轮不处理）

1. **未跟踪文件若落进「非 dot、非具名排除」的目录仍可能造出消费者**（例如 `scripts/` 下的一份手放脚本）。缓解：**CI 从干净 checkout 跑**（`actions/checkout`）⇒ **CI 上「工作区 == 仓库」成立，该风险不存在**；它只存在于本机有人手工放置文件时。彻底消除需要「仓库文件集」这个输入，而取它需要派生 `git` 子进程（宿主禁止，见背景）。
2. **语义类漂移仍只能靠人读**（沿用 ADR 0050 遗留 1 / ADR 0051 遗留 1）：本轮修的全是「可机读的那一半」（集合、名字、来源）。
3. **`.github` 被结构性排除**是一次**有意**的取舍：代价是「工作流里的 schema 引用」不再算消费证据（实测损失为零，见决策 1）。若将来工作流确实成为某个 schema 的唯一消费者，正确做法是**为它加一条具名排除的反向声明**（把它变成「正在被考虑」），而不是恢复枚举式扫描。
4. **`§56.2` 自身两处张力**、**`§57.5`/`§48.7` 待决策项**：沿用 W71/W72/W73 的登记，未动。
5. **`schema --check` 仍在本机跑不了**（宿主禁止 node 派生子进程，见背景的订正）：取零漂移仍靠结构性理由 + CI 独立步骤；**不得把「跑不了」写成「已通过」**。
