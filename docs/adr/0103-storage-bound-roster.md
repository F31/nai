# ADR 0103：R08「存储维护有界」的口径与名册

- 状态：Accepted｜日期：2026-10-16｜归属：W125（R08 名册与覆盖）
- 关联：ADR 0102、ADR 0100、`local-persistence`/`knowledge-pipeline` spec、R08、D03、W77

## 背景
ADR 0102 把 R08 的缺口写成四项常量（`snapshot::MAX_BYTES`、`publication::{MAX_CHUNKS,MAX_BYTES}`、
`knowledge::MAX_CONTENT_BYTES`）。W125 按「具名拒绝（或具名丢弃计数）」普查 `crates/nai-storage`，
发现**约束单次写入或单份快照/备份可占用资源的上限共 19 项**，而本轮之前只有 2 项有载体。
⇒ 逐项点名既**不全**（漏 15 项），也**没给口径**（D03 的原始存储边界是「登记的不可变文件**数量/大小/路径受限**」）。
没有口径的名册，下一次普查会得出另一个数；没有名册，覆盖只能按感觉宣称。

## 决策
1. **口径（先定边界，再数成员）**：本项收**写路径**的资源上限——字节数或条目数，且以具名拒绝
   （或具名丢弃计数）表达。**不收**两类：
   (a) **读路径预算**——检索扫描上限以 `truncated` ⇒ `RetrievalPartial` **报告**而非拒绝，
   它约束一次查询的代价，不是可持久化资源的增长；
   (b) **输入形状校验**——标识符/token/`source_span` 长度、`MAX_TOKENS_PER_CHUNK`、`MAX_DIMENSION`、
   查询 token 与 `product_filters` 取值，约束「什么算合法输入」，不约束「一次写入能有多大」；
   `MAX_DIMENSION` 更是索引**身份**约束（同一 index 的向量必须同维度）。
2. **名册冻结为 19 项**（逐项位置与具名拒绝见 W125 报告 §一）。名册是**闭世界**：新增上限必须显式入册，
   否则本项的「有界」又开始无边界地漂移。
3. **覆盖是逐项的**，MUST NOT 由「同一族」推断：每项都要一条**可归因**的夹具（越界必须命中该上限自己的
   具名拒绝，而不是同族另一个上限的）。本轮覆盖 **8/19**。
4. **幅度判据与边界判据分工**：夹具从常量派生 ⇒ **抬高常量不会让边界判据变红**，只有名册**幅度判据**会；
   反过来，幅度判据发现不了「闸门被删掉」。两条都要有，缺一条就有一类漂移无人看守。
5. **同一常量在多个执行点复用**时不另立条目，但**两侧（写入/读回）的上限必须同值同界**，
   且必须有判据证明两侧都真的用了它（`snapshot::MAX_ARTIFACT` 的写入侧与读回侧）。
6. **合并的拒绝必须拆开**：`publication` 把「分块数」与「分块字节」并成一个理由时，一条计数夹具
   会替字节上限背书 ⇒ 拆成两条具名拒绝（`snapshot chunk count bound` / `snapshot chunk byte bound`）。
7. **夹具用稀疏逻辑长度**：`checked_file` 先比 `metadata().len()` 再读 ⇒ `set_len` 即可到达尺寸闸门
   （实测 0.39s / 逻辑长度 256MiB+1）。ADR 0102 以「256MiB 级夹具代价过高」推迟本项，**该理由作废**。

## 后果
- 正向：R08 从「一句话」变成「一份有口径、有成员、有覆盖状态的名册」；8 项有判别性载体（含注入验证）。
- 生产代码：6 处**可见性**变化 + 一处拒绝**拆名**；无行为语义改动（同一输入仍以同一 `ErrorCode` 拒绝）。
- 如实披露：名册 19 项**剩余 11 项零覆盖**（逐项具名在 registry 与报告中）⇒ R08 **维持 `implemented`**；
  MUST NOT 因「同族已有覆盖」或「守卫通过」而升级。
