# ADR 0134：批准候选到本机默认设备

日期：2026-10-20。状态：Accepted。

## 决策

在既有预览命令增加显式 `local_playback`，默认false；只允许人工辅助会话，本机默认设备、15%增益、≤5秒完整句段，超长拒绝而非截断。保留文件预览。两种动作分别幂等、分别标识预算请求，不把点击播放变成自动外播，也不在失败时重试付费请求。

root 仍是唯一 Store owner。审批时从已批准哈希对应cue记录事实版本；播放时读取实际审批proto并核对数据库actor/scope/expiry，重新检查当前授权、审批/知识有效性、事实、epoch和Preplay守门。旧空policy cue不能补填以绕过哈希，需生成新候选。桌面批准有效期改为30秒，并显示期限，候选自身过期仍优先。

keeper子进程使用清空后最小Windows环境，排除当前Provider凭据环境变量，不把根进程API密钥交给原生媒体依赖。状态先按封闭状态集、错误码字符和非硬件完成语义核验，再记录诊断。

root将已准入2D渲染器的真实RGBA顺序写入临时原始帧文件，与单声道s16 PCM分开。源Protobuf描述符包含数量、帧率、SHA256和候选/session/epoch；授权再绑定描述符SHA256，防止文件和描述符一起替换。最长5秒音频、64MiB帧数据，拒绝符号链接、越界尺寸、长度/哈希不符。原始数据不经JSON/Base64/控制通道，完成或取消清理临时目录。

同目录可信侧车 `nai-output-keeper` 经私有继承stdin/stdout启动。设备创建后ready，root再签发最长600ms租约，每100ms从真实存储复检并续期；每10ms检测停止/换代。读写各独立线程，队列容量2，初始化4秒/总调用12秒/回收250ms有界。keeper控制队列4、音频待消费队列1（另有活动块），每块≤200ms、每次完整Preplay，音频回调复用≤10ms门控分片并计入设备预计排队时间。Windows-only WASAPI/minifb，无新外部依赖（仅复用已有sha2），无新常驻服务。

keeper依据音频提交样本位置显示实际2D帧，P0/EOF/超时撤权清黑；root终止或不续期时，音频仍由输出侧短期限约束。UI静音不因合成/播放busy禁用，旧任务结果按连接代次丢弃。二进制状态帧显式flush，避免标准输出行缓冲阻断握手。

状态仅为running/submitted/cancelled/failed，不写PlaybackAck；缺失观测计数表示未知，不用0替代未知。完整submitted还须由root独立核对重采样后的预期样本数。设备提交不等于DAC实际完成或平台送达。

## 限制与成本

峰值媒体文件64MiB，keeper持有有界RGBA及像素缓冲，按需启动并回收；重采样48kHz与显示由本机承担。没有新进程常驻、云服务或Python推理依赖。当前没有设备选择/虚拟摄像头/直播SDK集成，也没有声学回环、音画延迟认证、签名/ACL对端认证或正式发布验收。原生窗口API与root同时卡住时的画面独立待机仍待认证，不能据此提高registry状态。
