## 背景

[ADR 0042](0042-design-baseline-v37.md)（2026-10-11）把唯一实现基线从 V3.6 升为 **V3.7**，理由是 V3.7 是 V3.6 的严格超集且已被 6 篇 ADR 当作基线引用。ADR 0042 同时留下一条**明确的后果**：V3.7 §1.4、§16、§33.1 前导都写「每条验收在 `tests/registry.yaml` 中登记」，而 **M01–M18 当时一条都没登记**，其决策 4 刻意「不追认 V3.7 第三部分已进入验收范围」，以免用基线切换掩盖一个独立的登记缺口。

该缺口后来被补齐（M01–M18 已按 `pending` 全数在册）。**本 ADR 面对与 ADR 0042 同构的一次变更，并直接应用那次留下的教训。**

本轮按用户指令，把「智能体 Harness 的工程化能力 + 开放互操作（MCP、A2A）」写进设计基线，产出 `docs/直播数字人 + 智能体系统技术方案 V3.8.md`。与 ADR 0042 的情境有一处**实质差异**，必须如实说明：V3.7 升基线时，文档**早已躺在仓库里**且**早已被当作基线使用**，ADR 0042 是对既成事实的追认与订正；V3.8 则是**本轮新建**的文档，升基线是**同一轮内的引入 + 裁决**，不是追认。

而 V3.8 已把智能体的工程化边界与开放互操作写成规范条款。本 ADR 处置这一不一致。

## 决策

### 决策 1：V3.8 升为唯一实现基线

V3.8 是 V3.7 的**严格超集**（证据：§1–§39 内容只增不改、无删除、无改写，仅 8 行 1:1 替换）。升基线**不损失任何既有条款**，
且使文档陈述与本轮新增的第四部分一致。

- `docs/design.md` 指向 V3.8；
- `README.md`、`AGENTS.md`、`docs/development-plan.md`、`docs/engineering.md`、`openspec/config.yaml` 同步；
- V3.7 降为**历史参考**（与 V3.6/V3.5 同等处置）：仅追溯，不自行拼接旧条款覆盖 V3.8。

### 决策 2：ADR 0042 的决策 2 与决策 3 继续有效，决策 1 被替代

ADR 0042 有三项实质决策，**只有决策 1（V3.7 升基线）**由本 ADR 替代：

- **决策 2（ADR 0015 的勘误与裁决清单继续有效）继续有效**——`release_line` 独立字段、`provisional` 中间态、
  值守租约 600ms 撤权初值、X01 门槛统一到 M0b、决策日志缓冲满时丢遥测不丢关键提交等，都是**内容层**裁决，
  与「基线是 V3.7 还是 V3.8」无关。
- **决策 3（`§NNN` 行号引用只改版本前辍、代码 doc-comment 不在订正范围）继续有效**，本 ADR 沿用其口径，不另立新规。

ADR 0042 **保留原文不改写**，仅在末尾追加「被 ADR 0047 替代决策 1」指针（历史记录追加勘误，不就地改写）。

### 决策 3：`§NNN` 引用只改版本前辍，活文档统一为 V3.8

因两版行号对齐（§1–§39 的 8 行改动全是 1:1），`§NNN` 的**数字不作变更**；只把**活文档**里的版本前辍从 `V3.7 §X` 订正为 `V3.8 §X`。

- **活文档**（承诺描述**当前状态**的）：`AGENTS.md`、`README.md`、`docs/{design,engineering,development-plan,cloud,deployment,mixing,multi-session,operations,upgrade,platform-matrix}.md`、
  `openspec/config.yaml`、`openspec/specs/{admission-registry,decision-log-integrity,duty-lease,platform-matrix}/spec.md`、
  `tests/registry.yaml` 的 `release_lines` 标签、`schemas/tests/registry.schema.json` 的描述、
  `xtask/src/registry.rs` 的成功输出串（**机器可见的当前状态断言**，必须随基线变）、`tests/registry.test.mjs` 的覆盖注释。
- **历史记录**（点时刻快照，原文不改写）：`docs/reports/`、`docs/adr/`、`openspec/changes/archive/` 中的 `V3.7` 一律保留。
- **代码 doc-comment 的版本前辍不在订正范围**（沿用 ADR 0042 决策 3 的两条理由：先例一致；它们记录的是该代码撰写时
  所依据的设计引用，属点时刻信息）。因行号对齐，这些引用在 V3.8 中**解析结果不变**，不构成错误引用。
- **`apps/desktop/src/main.tsx` 的页脚**是**界面可见的当前状态陈述**（不是引用性注释），故随基线一并订正。

### 决策 4：H 系列**就地登记**，不重复 ADR 0042 决策 4 留下的缺口

V3.8 §48.5 定义了新验收家族 **H01–H18**（Harness 与开放互操作），§47.6 定义了工作项 **W56–W64**。
ADR 0042 决策 4 曾**刻意不登记** M01–M18，其后果后来被判定为缺陷：「『尚未开始』应当以 `pending` 表达，
而不是省略条目——**在册与测得是两个不同的陈述**」，且省略会让「以注册表为准」这条规则把整部分从验收视野里抹掉。

本 ADR 直接应用该教训：

- H01–H18 **全数以 `pending` 登记**在 `tests/registry.yaml`（注册表 69 → **87** 条）；
- 注册表门控 `scripts/contracts/registry.mjs` 的编号正则扩展为 `(S|R|A|B|O|P|M|H|X)`，并**实现**规格早已要求
  但此前未实现的**家族在册断言**（M 家族 18 条、H 家族 18 条；缺号即失败并指名缺哪个）；
- `openspec/specs/admission-registry/spec.md` 的家族清单同步扩为含 `H`。

### 决策 5：本 ADR 明确不改什么

- **不改任何既有 acceptance 的 `status`**：V3.7 引入的 69 条状态原样，新增 18 条一律 `pending`。
- **不实现任何 harness 代码**：第四部分只定义边界、不变量与验收；§47.5 明确本轮**不新增静态门控**（无实现可门控）。
- **不重排工作项编号**：V3.7 §39.6 的计划止于 W40，**W41–W55 已被后续实际执行轮次占用**（见 `docs/development-plan.md`
  与 `docs/reports/`），故第四部分从 **W56** 起编号；既有编号一个不动。
- **不扩张观众长期记忆的字段集与保留期**（沿用 §5.5 既有约束）。

## 后果与实施

- 活文档的基线指针与 §-引用统一为 V3.8；除历史记录与代码 doc-comment 外，活文档不再出现 `V3.7` 作为**当前基线**的陈述。
- 后续开发按 V3.8 的切片发布线与 `tests/registry.yaml` 验收推进；H 系列与 M 系列同处 `pending` 起点。
- **已知代价（如实登记）**：本版遵守「§1–§39 内容零改写」，故 §1.4 的发布线表与 §16 的验收注册表**只在既有行内**
  增补 H 系列指针，**不新增行**；H01–H18 的完整判据以 §48.5 为准，登记状态以注册表为准。这是一处**已声明**的指针
  形状，换取的是「行号一一对应、既有 ADR 的 `§NNN` 引用全部继续有效」。
- **遗留（不在本 ADR 范围）**：
  1. V3.8 第四部分**零实现**：W56–W64 未开始，H01–H18 全部 `pending`；
  2. **平台与市场的老缺口仍在**（沿用 ADR 0042 的遗留 1–4）：V3.7 第三部分（第 33–38 章）零实现、W26–W40 未开始；
     `apps/` 仍缺 `platform-bridge`(C++)、`control-server`、`update-helper`、`remote-web`；`crates/conformance` 未建为独立 crate；
  3. **本轮不新增任何契约名**：MCP 四面映射到既有契约（`skill.invoke@1`／`data.query@1`），A2A 的协议版本与认证方式**待验证**（§35.2、§46.5、§48.7）⇒ 不为未验证协议占契约名（避免半声明 draft），H13/H14 的 `contract` 留空；
  5. `openspec/specs/spec-driven-delivery/spec.md` 的动机段仍写「以 V3.5 为统一设计基线」（**V3.7 升基线时亦未订正**，属遗留陈述，本轮不就地改写）；
  4. MCP 与 A2A 的**协议层事实未经实测**：本 ADR 只裁决设计与登记，不宣称任何互操作已可用。
