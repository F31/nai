# ADR 0127：指针的域收口 —— 域是「markdown 认为是链接的东西」，不是「看起来像链接的东西」

- 状态：已接受
- 日期：2026-10-19
- 轮次：W153
- 相关：[ADR 0125](0125-doc-link-reachability.md)（本条的判据与处置二分；其残余 1、残余 2 由本条结清）、
  [ADR 0126](0126-doc-domain-and-code-spans.md)（域扩到全仓、代码段豁免；其残余 2、残余 3 由本条结清）

## 背景

W151 立的判据、W152 扩的域，都在同一句话上留了口子：**「锚点与引用式链接在域外，理由是全仓 0 条样本」**。
ADR 0125 的残余 1（锚点）与残余 2（定义行）就是这两条。它们的形状比「还没写」更糟——
**判据对它们完全无感**：谁写下 `[x]: url`，那条指针不论指向哪里，既不绿也不红，直接不存在。

W153 先量（tracked **1460** / 文档 **996**，代码段内外分层）：

| 形状 | 外 | 内 |
| --- | --- | --- |
| 内联链接 | 962（相对 924） | 12 |
| 定义行 `[x]: url` | **0** | 0 |
| 引用式使用（label 命中定义） | **0** | 0 |
| 引用式使用 `[x][y]` 形态（不论有无定义） | **6** | 0 |
| 纯锚点 / `file.md#anchor` / `<a name=` | **0 / 0 / 0** | 0 / — / — |

**第二行与第四行要一起读**：定义行确实没有，但「用了引用式写法」的有 6 处。如果照着第二行的口径
去量第四行（`label 命中定义` 才算），这 6 处会被算成 0，于是「引用式链接没人用」这个**假结论**
会一直立着。这一轮的第一次量法就犯了这个错——量法错了，结论会反。

## 决策

1. **域 = 「markdown 认为是链接的东西」，不是「看起来像链接的东西」。**
   这是本轮唯一的新原则，下面每一条都是它的推论。判据的本职是「每条指针的落点都真的存在」；
   一个在 CommonMark 里根本不构成链接的字符序列，没有落点，也就没有「落点不存在」这回事。

2. **引用式定义行 `[label]: url` 进域。** URL 走与内联链接**同一套**判定（一个 `targetErrorOf`，
   两个调用点）：通配 / 越界或不可解码 / 索引里没有，三族缺陷一字不差。同一件事 MUST NOT 两处定义——
   定义行另写一套判据，迟早一处松。这才是本轮真正关掉的盲区。
   - 重复定义同一 label：**每一条都判**。渲染器取第一条，后面那几条也是人写下的死指针。
   - 定义指向站外：URL 不判（与内联链接同一条边界），但**label 照样算「有定义」**——
     否则 `[x][b]` 会被当成退化文本，而渲染器明明会把它化成一条外链。
   - 定义按**文档**生效（CommonMark）：`a.md` 的定义不给 `b.md` 的用法兜底。

3. **引用式使用：有定义是指针，无定义不是指针，只数不判。**
   有定义 ⇒ 它**是**链接，落点由定义那一侧判（不重判，同一个目标判两遍会让一处缺陷报两条）。
   无定义 ⇒ CommonMark 把它**降级成字面文本**，读者看到的正是原文写下的字 ⇒ **没有读者可见的缺陷**。
   **这一条推翻了我设计判据时的假设**：原设计写的是「label 无本文件定义 ⇒ 失败」，前提是
   「无定义的引用式使用 = 笔误」。实测把这 6 处全读了一遍，6 处都是**引注写法与引用式语法撞车**：
   标签活在同一份文档的资料清单里，清单写成 `- [S2] …`（V2.3 是 `- **[S1] …**`），不是 `[S2]: url`；
   V3.2 第 1032 行自己就写 `（[S1]、[S4]–[S16]）`。把 6 处判红，等于要求三份已发布的设计文档
   改排版——**判据错怪记录**。假设被实测推翻就得改规则，MUST NOT 为了保住规则去改记录。
   - 不判 ≠ 不看：它 MUST 被计进 `undefinedReferences`。边界要数得出来，否则「域外」在读者那里
     会退化成「已覆盖」。
   - 为什么不按标签形状开豁免（例如 `^S\d+$`）：那是**照着今天的语料改判据**，明天换个标签名就失效。

4. **带 `#` 碎片的指针：拒绝，不跳过。**
   `[x](#a)` 与 `[x](b.md#a)` **都是** inline link ⇒ 在域内；但碎片怎么生成由渲染器决定
   （GitHub 的 `github-slugger`、GitLab、编辑器预览、静态站生成器各一套，中文标题各写各的）⇒
   判据**无法**判断那个位置存不存在 ⇒ 拒绝。`跳过` 的意思是「这条我看不了，但我把它算进绿里了」。
   - 带文件名的：文件部分照判，碎片单独失败。文件与碎片同时坏时 MUST 报**两条**——
     那是两个缺陷，合并成一条会让修的人只改一半。
   - **与第 3 条并不矛盾，理由是同一个**：按「它是不是链接」分。`[x](#a)` 是链接（只是落点不可判）
     ⇒ 拒绝；`[x][y]`（y 无定义）不是链接 ⇒ 不在域内。同一个原则，两个方向。

5. **shortcut `[label]` 仍在域外**：它与普通方括号（数组下标、清单勾选框、`[待办]`）字形上
   不可区分，自造正则去猜只会产出成片的假指针。这是一条**声明的域边界**，不是「已覆盖」。
   推论：第 3 条的数与第 4 条的拒绝都不会波及它——`见 [S2] 与 [S3]` 永远静默，这是代价，
   写在这里而不是留在读者那里当疑问。

6. **计数分开报，不合并。** `linksChecked` / `definitionsChecked` / `referencesChecked` /
   `undefinedReferences` / `anchorsChecked`。合并成一个 `linksChecked` 会让「域边界在哪儿」
   在报告里消失；而每条判据的边界都 MUST 说得出数（W122 起的一贯要求）。

## 后果

- 用例 **11 → 16**：新增「定义行与内联链接同一套判定」「引用式使用只在 label 有定义时是指针」
  「代码段对定义与用法同样豁免」「扫描器形状」，并重写原「锚点在域外」那条为「碎片被拒绝」。
- **8 条注入**（逐次 `sha256` 还原，基线 `e916ef99…`（判据）/ `09749257…`（用例））：每条规则都有一个「只有它错时才红」的样本。
  其中 I3（把无定义用法改回失败）同时打红**真实语料**用例——那 6 处就在语料里，证明这条真实断言
  对本规则也有牙。I6 的第三条红是跑完补进预期的（成因同一：旧守卫在「只有定义、没有内联链接」
  的文档上同样触发），预写不全，实测补全，如实记在这里。
- **零份文档被改**。这是本轮与 W151/W152 的形态差别：前两轮先量出一批红再修，本轮量出来的
  6 处**不是红**，唯一的产出是判据本身。
- **诚实的空白**：定义行与锚点今天仍是 **0** 条真实样本 ⇒ 这两条规则的全部证据是合成样本 + 注入。
  它们不是「已被真实语料检验过的判据」，只是「已经会喊的判据」。下一次有人真的写下 `[x]: url`
  或 `[x](#a)`，才是它们第一次被真实语料检验。

## 残余（具名，本轮不做）

1. **链接里再嵌图片**（`[![alt](a.png)](b.md)`）：`linkTargetsOf` 只取到内层 `a.png`，外层 `b.md`
   取不到。W153 实测全仓 **0** 处，未修。
2. **转义方括号**：`\[` 全仓 **56** 处（都是 `evidence\[\]` 这类），没有一处落在定义行或引用式
   使用的位置 ⇒ 今天不产生误判。将来 `\[x\]\[y\]` 会被当成一条引用 ⇒ 落在**拒绝**一侧，不会放行。
3. **定义行的 URL 折到下一行**（CommonMark 允许）：全仓 **0** 处。不实现即落向「label 无定义」，
   方向是拒绝。
4. **「用了引用式写法但其实想写链接」**：与引注写法机械上不可区分（第 3 条的全部理由）。
   这一格**永远判不了**，MUST NOT 记作「已覆盖」。
5. ADR 0125 的残余 3（`docs/` 之外的 markdown 未判）已由 ADR 0126 结清，ADR 0126 的残余 1
   （围栏豁免没有真实样本）不变；残余 4（可达性 ≠ 内容正确）与残余 5（外部链接可达性）
   **状态不变**。

## 勘误（W154，2026-10-19 追加；上文一字未改）

- **残余 4 的前半句已由 [ADR 0128](0128-undefined-reference-claims.md) 结清，后半句仍然成立**。
  「用了引用式写法但其实想写链接」与引注写法机械上**仍然**不可区分，这一点没变；变的是处置：
  原先「判不了」等于**放过**（只计数），ADR 0128 把它改成「判不了，所以 MUST 要求有人具名认领」，
  且认领本身要付一条可被机械否证的声称。⇒ 这一格不是「已覆盖」，是「已有人负责」。
- **本文「后果」里 I3 那句的描述不再是当前状态**。I3 当时把「无定义用法改回失败」当作注入，
  用以证明真实语料对规则有牙；ADR 0128 之后，无定义用法**默认就是失败**，唯一的变化是它可以被
  `tests/undefined-references.yaml` 认领。本文那句作为 W153 当时的记录仍然准确，此处只标出
  它已不是现状。
- **背景里「6 处 `[Sx][Sy]` 全是这一种：标签就活在同一份文档的资料清单里」经 W154 逐份核对成立**，
  但 W154 第一次量清单时因写法不同量出 **0**（V3.5 写成 `- [S1 标题](url)`）⇒ 补一句量法提醒，
  不改结论。
