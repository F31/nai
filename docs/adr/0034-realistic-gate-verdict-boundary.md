# ADR 0034：写实准入 Gate 的边界——四门独立、缺测非过、回退非验收

- 日期：2026-10-10
- 状态：Accepted
- 基线：V3.7 §8.1（形象档位）、§8.2（写实模型准入 Gate）、§8.4（待机与降级）、§26.5（GPU 与执行后端）、§12.5（写实出帧与音画偏差目标）、§655（B02 验收）、§1311（NotApplicable 与 Blocked 纪律）
- 变更：`openspec/changes/w32-realistic-gate-verdict/`
- 判据：`tests/registry.yaml` B02「写实 Gate G0–G3 与肖像、声线授权证据齐全」；回指 D12

## 背景

B02 的**真值**（合法完整模型 + Windows/CUDA 目标机 + 与直播工具并发实测）需要外部条件，本轮不可达，B02 与 D12 保持 `blocked`。但 §8.2 的表只有四行，每行的**判据**都可以现在落成代码，此前没有落点：

1. 四门是**合取**还是可合成？
2. 缺测（没测温度 / 没跑某场景）怎么表达？
3. 「全 GPU」的判据是本次**运行回执**还是**放置记录**？
4. 2D 回退与准入是什么关系？
5. 没有模型时标什么？
6. 「不适用」在什么条件下才成立？
7. 审计会不会被判定函数架空？

九项决策必须先回答：落**哪个 crate**；四门**怎么组织**；缺测**怎么表达**；「全 GPU」**由什么得出**；回退**与准入什么关系**；缺模型**标什么**；不适用**边界在哪**；精度**怎么有序**；审计**怎么才不成为死代码**。

## 决策

### D1 放进 `crates/nai-kernel`（`realistic.rs`）

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 放进 `nai-plugin-sdk`（与 D12 完整性检查同住） | 复用模型清单类型 | **否决**：G0–G3 是纯判定，需要复用 kernel 的 `LatencySamples`（G2 音画偏差 P95）。放 SDK 会把 kernel 的分位实现反向引到 SDK，或复制一份——后者会在两次口径调整后产生两个 P95。 |
| B. 新增 `nai-realistic-gate` crate | 独立成包 | **否决**：改动 workspace 组成（18 包）与依赖方向，而本模块只依赖 `ErrorCode` 与 `std`。 |
| C. 放进 `crates/nai-kernel` | 与 `metrics.rs`/`golden.rs` 同 crate | **采纳**：复用 `LatencySamples` 与 `golden::Finding`（同一报告词汇），一个真相；依赖方向不变。 |

### D2 四门是**合取**，且各自独立判定

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 一个 0–100 的「认证度」 | 四门加权求和 | **否决**：无法回答「卡在哪一门」，与 §8.2 的表格结构相悖。 |
| B. 四门合取但不暴露单门结果 | 只给通过/不通过 | **否决**：看不出是授权缺、对齐缺、实时缺还是稳定缺，修法完全不同。 |
| C. 四门各自 `Passed/Failed/Unmeasured`，总体派生 | 任一失败即不通过；任一缺测即不通过 | **采纳**：`Acceptance` 由四门派生，无单分数。 |

### D3 缺测是**第三种状态**，不是零、也不是通过

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 缺测填默认值（帧率 0、温度 0） | 省事 | **否决**：把「没测」读成「测得 0」，正是 §12.5 与 §8.2 反复禁止的把戏。 |
| B. 缺测算通过 | 「没有证据反对」 | **否决**：§8.2 要求**实测**帧率/延迟/显存/CPU/温度，缺一即未测。 |
| C. 缺测 = `Unmeasured` 且阻断 `Accepted` | 与 W26/W29/W30 同形 | **采纳**：三态一致。 |

### D4 「全 GPU」是**放置记录**的性质，不是运行回执

| 方案 | 做法 | 结论 |
|---|---|---|
| A. `cuda_ep_registered: bool` 即全 GPU | 由运行回执推断 | **否决**：§26.5 原文点名——「不以 CUDA EP 注册成功宣称全 GPU」。 |
| B. 只记 `gpu_copies` 计数 | 复制次数多即全 GPU | **否决**：复制恰恰是**回落**的迹象，方向反了。 |
| C. `is_full_gpu()` 由节点放置记录（非空且全 GPU）得出，注册信息另存为审计线索 | 全 GPU 成为记录的性质 | **采纳**：注册而无记录被审计报出。 |

### D5 2D 回退与准入**正交**

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 回退可补足未过的门 | 「反正能播」 | **否决**：§8.2 明说「自动回退 2D 不等于写实验收通过」。 |
| B. 回退使报告无效 | 一票否决整份报告 | **否决**：回退是 §8.4 允许的**运营动作**（需授权、句间、记日志），不该被当成违规本身。 |
| C. 回退是运营记录，与准入门控正交；「以回退构成验收」才是违规 | 只在声明越界时审计报出 | **采纳**。 |

### D6 没有模型 → `Blocked`；「不适用」只用于不要求写实的档位

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 缺模型标「不适用」 | 绕过 | **否决**：§1311「NotApplicable 不能代替未完成的目标能力」。 |
| B. 缺模型按现有证据给分 | 「部分通过」 | **否决**：§1311「没有合法完整模型时，写实认证标 Blocked」。 |
| C. `model_present = false` → `Blocked`；Lite 档未启用 → `NotApplicable`；Standard/Pro 声明不适用被审计报出 | 档位决定适用性 | **采纳**。 |

### D7 精度认证有序，量化为单独条件

§26.5「先用 FP32 与原流程逐段对齐，再认证 FP16；INT8 必须有量化与校准及质量报告」。落为两条独立拒绝：认证任何非 FP32 精度而 FP32 未通过 → `Failed`（`precision_without_fp32_baseline`）；认证 INT8 而无校准报告 → `Failed`（`int8_without_calibration`）。

### D8 审计是报告字段的纯函数

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 只靠判定函数保证 | 不单独审计 | **否决**：报告字段公开，一份被**拼装**而非测得的报告能绕过判定路径。 |
| B. 审计只查少数几条 | 覆盖不全 | **否决**：与 W30 一致，应报出**全部**命中项。 |
| C. 对报告自身字段做纯函数，逐条可构造 | 复用 `golden::Finding` | **采纳**：`Finding::new` 提升为 `pub`，两模块共享同一 `{token, subject}` 词汇。 |

### D9 不新增 xtask 命令与证据目录

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 新增 `check --realistic-gate --dir tests/realistic-gate` | 仿 W31 | **否决**：§30.1 只为 RAG 黄金集指定了 `tests/rag-golden`；为写实 Gate **臆造**一个证据目录属于过度绑定。G2 的真值来源是目标机实测，不是仓库内载荷。 |
| B. 不加载体，只落判定骨架 | 由调用方（未来的模型轨工具/装配根）提供证据 | **采纳**：待真实模型轨立项并确定证据落点后再补载体，**无需改本模块判定**。 |

## 否决方案

| 方案 | 否决理由 |
| --- | --- |
| 单分数「认证度」 | 无法回答卡在哪一门；与 §8.2 表格结构相悖 |
| 缺测填 0 | 把「没测」读成「测得 0」 |
| 缺测算通过 | §8.2 要求帧率/延迟/显存/CPU/温度四项实测 |
| CUDA EP 注册即全 GPU | §26.5 原文点名禁止 |
| GPU 复制次数即全 GPU | 复制是回落的迹象，方向反了 |
| 回退可补足未过的门 | §8.2「自动回退 2D 不等于写实验收通过」 |
| 回退使整份报告无效 | 回退是 §8.4 允许的运营动作，非违规本身 |
| 缺模型标「不适用」 | §1311「NotApplicable 不能代替未完成的目标能力」 |
| 缺模型按现有证据给分 | §1311「没有合法完整模型时，写实认证标 Blocked」 |
| 只靠判定函数、不做审计 | 报告字段可被拼装，绕过判定路径 |
| 臆造 `tests/realistic-gate` 证据目录 | §30.1 未指定；G2 真值来自目标机实测而非仓库载荷 |
| 落进 plugin-sdk | 需复用 kernel 分位实现，会造成反向依赖或两份 P95 |

## 后果

- §8.2 的四门**口径**有了单一落点：给定一份证据，四门各自如何判、总体如何派生、缺测/回退/缺模型/不适用如何表达，都可执行、可测试（`tests/realistic.rs` 37 项）。
- 「全 GPU」不再是运行回执的同义词；「缺测」不再可能被读成通过；「2D 回退」不再可能被读成验收。
- registry 的 **B02 与 D12 保持 `blocked`**——判定机制已交付，但证据齐全是外部真值。
- 遗留：真实权重与授权文件、Rust/ORT 推理、Windows/CUDA 目标机实测、与直播工具并发测量、证据载荷落点，全部待外部投入与后续里程碑。
