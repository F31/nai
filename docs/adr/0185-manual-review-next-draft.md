# ADR0185：人工复盘生成独立下场草稿

- 日期：2026-10-27
- 状态：采纳
- 基线：V4.8 / V48-08；首个工程切片，不代表两场实际复用验收通过。

## 决策

先提供无模型依赖的人工路径：已结束的手动记录或数字人队列 → 最多三项人工重点 → 单FAQ修改对照 → 确认后创建独立产品与节目草稿。人工记录使用 `self_reported`，不推断观众效果、实际采用或商业指标。新草稿须重新走既有发布流程，不复制旧批准、会话或媒体租约。

`nai-live` 是有实际业务职责的纯领域 crate：检查FAQ依据、重复问题与容量，生成保留事实、条件、禁述和无关表达的草稿变更。它只依赖契约/JSON，无数据库、Tauri、具体插件或设备依赖。存储适配器负责当前权限、证据复检、受保护索引、版本CAS、事务与关键审计；composition root沿既有认证IPC装配。内核不依赖该业务模块。

先修改Protobuf和严格JSON Schema并生成Rust/TS/C++消费者。`publication_review_index/note/draft_job` 沿用对象存储，不新增数据库表或兼容层；普通读写接口不能绕过证据校验取得复盘正文。

## 一致性边界

预览绑定来源运行版本、发布哈希、人工重点版本、源产品/节目版本与提议。事实/禁述或节目产品身份变化须先人工核对；普通并发草稿变化提供原文/当前/提议三方差异，拒绝自动合并。

确认应用时重新核验来源、权限和全部版本。新产品、新节目及任务结果与critical审计同事务提交；目标碰撞或审计失败不留下半套数据库草稿。内容寻址的未引用文件仍按既有存储回收机制处理，不等于事务内文件系统回滚。

同一来源/重点/草稿base重复预览返回已有任务，同任务重复应用返回原目标。复用任务ID改变参数拒绝。来源撤销/删除后，即使有旧任务或幂等响应也必须重新拒绝正文。已删除的目标不会因重试被重建。
