# ADR 0105：从决策日志重建装配以**条目**为单位（H02 口径收紧）

- 状态：Accepted｜日期：2026-10-16｜归属：W127（H02「装配可重建」的判定面口径）
- 关联：ADR 0082（装配记录落链）、ADR 0084（装配判定接线，决策 6/8 把这处推迟为独立一轮）、
  ADR 0065（V3.11 基线）、`runtime-composition` spec、`tests/registry.yaml` H01/H02、
  `admission-registry` §Honest backfill mapping with traceable evidence

## 背景
H02 的验收口径登记在 `tests/registry.yaml`：「装配可重建：由决策日志的片段引用重建**同一**上下文，
不依赖当时内存」。W104 落地 `Composition::rebuild_assembly_from_log` 时，把读回的多个 `assembly`
条目的片段**合并成一个池**再交给判定，并把这一点在代码注释、报告、`docs/runtime.md`、ADR 0082/0084
里**具名登记**为弱化：它把问题从「日志能否重建**这一次**装配」降为「日志能否拼出**某一次**装配」。
ADR 0084 决策 6/8 明确「改它属 W104 既有行为的变更，需要独立一轮」。本轮即是它的对象。

本轮先跑会红的判据，实测确认弱化可复现：链上两个条目分别只承载 `frag-a` 与 `frag-b`，
记录声明 `[frag-a, frag-b]` ⇒ 当前实现返回 `rebuildable = true` 且**零拒绝名**。

## 决策

### 决策 1：口径来源是 H02 标题，不是对 §41.5 散文的外推
基线 §41.5（`docs/直播数字人 + 智能体系统技术方案 V3.11.md:1971`）只说「装配 MUST 落决策日志：……」
与「装配记录 MUST NOT 含明文凭据（INV-11）」，**没有**明文写「单个日志条目」。
把「跨行合并」判为不达标的依据是 registry 里登记在册的 H02 标题那四个字「**同一**上下文」——
由两行拼出的、从未被装配过的上下文不是「同一上下文」。
⇒ 若换掉这条依据，本轮就不是「按已登记口径收紧实现」而变成「新增需求」。故本 ADR 与报告 MUST 写出这条依据链，
MUST NOT 把结论说成「§41.5 要求单条目」。

### 决策 2：条目就是装配，因为写路径就是这么写的
`ordered_fragments` 按 `record.fragment_ids` **逐项**写出 id／来源标识／字面正文，四项一起落进**一条**条目。
两条推论：①**一条已被真实写入的行，其片段标识序列 == 那次写入的 `record.fragment_ids`**（含重复项）
⇒ 对任何真的被记录过的记录，按条目选择必然找到它自己那一行，**逐条目判定与池化判定结论相同**
⇒ 本轮**不为合法用例引入假阴性**；②反过来池化**引入假阳性**。

### 决策 3：承载判据用**标识多重集**，且**不计顺序**
- 按**确切顺序**选行 ⇒ `rebuild.order_differs` **不可达**（顺序不同的行只是「不被选中」），
  一条具体原因被换成更模糊的，而守卫看不出（它只问「名字在不在被观察集合里」）——否掉。
- 按**集合**（忽略重复）⇒ 「集合层对划分是瞎的」：`[f1, f1]` 会被 `[f1]` 一行承载——否掉。
- 按「**超集**即可」⇒ 超集条目是**另一次**装配，用它重建较窄的记录＝凭历史改写出不曾发生的上下文——否掉。

⇒ `entry_carries_assembly` = 长度相等 **且** 一对一配对（`taken` 数组），即「多重集相等」，顺序不参与。

### 决策 4：跨条目结论是**存在性**的；失败时拒因取**并集**、`rebuilt` 取**第一个**承载条目
一个承载条目能重建 ⇒ 可重建：否则后一个「顺序不同」的条目会否掉前一个**正确**的条目，与事实相反。
一个都不行时拒因取所有承载条目的并集（每个名字都对**某一个**为真），而 `rebuilt` 与三类 id 清单
取**第一个**承载条目的——序列必须说清按哪份顺序读出。
后者不是审美：既有用例 `the_logs_own_order_decides_and_a_difference_is_named` 断言拒绝时 `rebuilt`
仍等于日志自己的顺序；失败分支置空会立刻让该用例变红，它正是「失败 ≠ 什么都没读到」的守卫。

### 决策 5：没有条目承载时，`unlogged_ids` 必须对**整条链**重新派生
朴素写法是对空池跑判定 ⇒ 每个标识都被报成「未落日志」。在 `[A]`／`[B]` 两行的链上，
`A` 与 `B` **都在链上**，这句话是**假**的（不是保守的）。
⇒ 该分支只对「在整条链任何一行都不出现的标识」报 `fragment_not_logged`，并**始终**追加
`not_in_one_entry`。两条原因互不短路。

### 决策 6：写路径**不改**，且这不构成「同一件事两处定义」
`record_assembly` 的输入是「本次要落盘的**素材**」，不是「链上的一个条目」：素材的标识多重集可能与记录不同
（既有 `a_referenced_fragment_absent_from_the_log_is_refused_by_name` 正是记录 `[a, b]`、素材 `[a]`，
期望 `fragment_not_logged`）。若把写路径也改成 `rebuild_assembly_from_entries(record, &[fragments])`，
该用例的拒因会被换成 `not_in_one_entry` ⇒ 一次「统一」把一条具体原因换成更笼统的。
⇒ 两条路径都调**同一个** `rebuild_assembly`（判定只有一处），区别只在**传给它的池怎么来**。
「版本齐备」抽成 `version_rejections` 由两条路径共用，正是为了不出现第二份。

### 决策 7：非空洞守卫必须按**面**取样，并写明这一不对称
`not_in_one_entry` 是**链级**事实：写路径一次只交**一个**条目，结构上产生不出它。
⇒ 该变体改走**读回面**取样（两次 `offer` 造两行，再 `rebuild_assembly_from_log`）。
「一个入口能产出全部重建拒因」是做不到也没必要的；真正的风险是**悄悄换成一个恒真的样本**，
故守卫里写明这处不对称是**结论**（链级 vs 单次写入级）。

## 后果
- 正向：H02 的判定从「能否拼出某一次装配」回到「能否重建**同一**上下文」，与 registry 的 H02 标题一致；
  `rebuild.not_in_one_entry` 是新的一条具名原因，且**没有把链上存在的标识误报成未落日志**（有专门判据钉它）。
- 正向：kernel 判据 36 → **40**，runtime 判据 **25** → **27**；两处新增各有独立注入使其变红（**7** 组注入）。
- **如实披露（本轮未达标的部分）**：H01/H02 的 `status` **维持 `pending`**。本轮闭合的是判定面口径，
  **不是**验收达标——装配器的**真实产生者**（把九段片段喂给模型、§41.2 分段预算初值标定、
  §47.2 六类回归属 **H16**）仍未接线。**报告 MUST NOT 出现「装配器已接入运行期」「已不依赖当时内存」**
  这类运行期断言。
- **如实披露（一处测试纪律的收获）**：注入 I7（把一对一配对退化为「可复用匹配」）**首跑全绿**——
  原因是最初那条 `[f1, f1]` vs `[f1]` 断言其实被**长度闸门**挡下，一对一配对逻辑**当时无覆盖**。
  改成**等长不同重数**（`[f1, f1]` vs `[f1, f2]`）后同一注入**变红**。
  ⇒ 「守卫都要注入验证」不是形式：**不注入就不知道哪条断言真的在拦。**
- 零新增依赖、零契约字段改动、零迁移、零 schema 改动、零前端改动。
- 一处测试失败（`DeadlineExceeded`，发生在 `open_store` 的 bring-up 夹具）判为宿主并行瞬态：
  错误类与位置都在夹具、该文件注释已具名记载同一现象、失败集合不绑定本轮改动领域、
  同一份代码在 `--test-threads=2` 下全绿 ⇒ **处置 = 限并发，不改代码**。
